Why this exists: the label doesn't tell you how it performs

"MM" is not one thing. What performs is the delivered intent-tier mix, and that's set by two things this view separates:

  1. The config's reachable-tier profile — which tiers its DS leaves can even bid. A DS19-only ("MM Core") campaign reaches HI / MI / Max Reach but not PP; a DS46-only campaign is PP-only; the flagship reaches all four.
  2. How modified the campaign is — which erodes how much of that profile actually delivers. Turn the gate off and it bids broadly including Max Reach; narrow to a ZIP or AND-intersect a weak 3P segment and the high-intent supply starves, so the bidder falls through to lower tiers to pace.

So two campaigns both labelled "MM" can deliver completely different tier mixes. This view grades both, so performance readouts compare like with like.

How big is the gap? Active (Live) Stage 1 prospecting spend (trailing 45d, $39.5M):

What the view does

One row per campaign. LEFT JOIN on campaign_id (or roll up by campaign_group_id) and filter. Two independent axes plus the raw components, so you can set your own bar.

  • Axis A — which config / tier profile (mm_class, tiers_reachable).
  • Axis B — how modified (restriction_level + geo / 3P / 1P / gate flags).

Scope: Stage 1 (funnel_level = 1) only. Only Stage 1 carries the DS audience expression — Stage 2/3 campaigns are subsets of Stage 1 and hold no audience detail (verified: funnel 2/3/4 are 100% non-MM). To classify a Stage 2/3 campaign, join by campaign_group_id to the group rollup (the audience is defined at Stage 1 and applies to the whole group; 100% of Stage 2/3 spend that actually delivers resolves to a Stage 1 in its group — the ~13.5% that don’t are dormant orphans with zero delivery). The view is scoped to active (Live) Stage 1 campaigns.

Axis A — config → reachable tiers

MM = any of DS13/19/46 (taxonomy §4; a "has DS19" test undercounts ~7.6% — the vertical-only cells are MM too). "MM Core" = DS19 is a component inside MM, not the definition. The vertical anchor (DS13/DS46) is the scoring engine; the keyword layer (DS19) is what makes the top (HI) tier reachable. Tiers are per-IP; a config's DS leaves decide which are biddable:

The clean rule: HI (10000) needs the keyword layer (DS19); PP (8000) needs the vertical anchor. So both vertical-only configs (DS13-only and DS46-only) cap at PP — verified 2026-07-22 on RTC-excluded delivered scores (DS13-only: 83.9% at exactly 8000, 0% at 10000). This corrects the taxonomy's "DS13-only → HI+PP" (that HI was RTC firing, not categorical). v1 pins at 8000; v2 spreads 6666–8000 — same PP ceiling. The label doesn't rank quality: only the keyword-bearing configs reach HI.

Axis B — how modified

restriction_level (most-severe wins): none / geo (narrower-than-country include, or a radius) / audience (AND-3P or seeded 1P intersection) / geo+audience. Cosmetic layers do NOT demote: an OR-additive 3P is bidder-inert under a live gate, and a CRM-exclude is hygiene — both stay unmodified.

Design decisions (feedback welcome)

  • Gate is NOT required for is_unmodified_mm. HHST flips daily for pacing/deliverability, so it's an operational lever, not a structural modification — exposed separately as hhst_gated. (98% of clean-config MM is gated anyway, so including it only added ~0.8pp.)
  • Geo: binary in v1. Any positive sub-country include flags restriction_level='geo' (exclusions don't count); geo_narrowest_type is exposed so you can set a zip/city-only bar. Exact geo_reach_pct (% of US HH reachable) is a v2 add — no clean per-location HH table exists yet; candidate source is the bidder's per-campaign campaign_bucket_population.
  • Grain: campaign-level, plus a companion group-level rollup (all-flagship vs mixed, spend-weighted modal mm_class).
  • Materialization: daily SQLMesh FULL model (a live view would recompute JS-UDF JSON parsing on every join) with a snapshot_date. Feature branch in airflow-ti; scheduling wired by the pipeline owner. Exact dataset TBD.

Still want your input on: any columns missing for how you'd use this, and whether the binary geo flag is good enough or needs the exact reach %.
