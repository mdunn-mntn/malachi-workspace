Operationalizes the MM Taxonomy page.

The problem

"MM" can't be identified by DS13/DS19/DS46 presence alone. A keyword campaign narrowed to a single ZIP, or hard-intersected with a 3P segment, or with the intent gate off, still reads as "MM" under datasource-existence filtering. Presence both over-counts (a 1-ZIP DS19 campaign) and under-counts MM (DS46-only carries no DS19). We need a systematic grade that stays robust as the model generation changes (Fangorn today, more later).

How big is the gap? On live prospecting spend (trailing 45d, $43.2M):

CutSpendShare of prospecting
MM-labelled (has_mm — any DS13/19/38/46)$30.6M70.9%
Unmodified MM (is_unmodified_mm)$14.0M32.5%
Clean flagship Fangorn (is_flagship)$2.9M6.7%

Of every dollar labelled "MM," less than half is actually unmodified. That gap is what this view exposes.

What the view does

One row per campaign. LEFT JOIN it on campaign_id (or roll up by campaign_group_id) and filter. It grades two independent things — kept separate on purpose, because collapsing them into one score hides signal:

  • Axis A — which MM engine (mm_class): the datasource config, named per the settled taxonomy grid.
  • Axis B — how carved-down the pool is (restriction_level + component flags): geo narrowing, AND-3P/1P intersection, and the intent gate.

Then two composable booleans everyone actually filters on: is_unmodified_mm (real, well-configured MM of any engine) and is_flagship (that, on the current flagship config).

Axis A — the mm_class taxonomy (6 live cells)

DS19 (keywords) × vertical anchor {none / DS13 legacy / DS46 Fangorn}. DS13 and DS46 never co-occur (same slot, two model generations).

Quality ladder is captured in mm_engine_rank: 3 = Fangorn (DS46) > 2 = Peak Performance (DS13) > 1 = keywords-only / Max Reach > 0 = non-MM. Flagship = DS19+DS46 specifically — DS46-only ("fangorn_vertical_only") is real MM but caps at the Peak Performance band (the High-Intent band needs the keyword layer), so it is not flagship.

Axis B — the restriction components

restriction_level (most-severe wins): none / geo (narrower-than-country positive include, or a radius) / audience (AND-3P or seeded 1P intersection) / geo+audience. Cosmetic layers do NOT demote: an OR-additive 3P is bidder-inert under a live gate, and a CRM-exclude is hygiene — both stay flagship.

Open questions (please comment)

  1. Flagship = DS19+DS46 only? I excluded DS46-only ("fangorn_vertical_only") from is_flagship because it caps at the Peak Performance band. Agree, or should flagship include DS46-only?
  2. Should is_unmodified_mm require the gate? Gate-off MM bids broadly like Max Reach. I treat gate-off as not-unmodified. Right call?
  3. Geo threshold. Today any narrower-than-country positive include flags restriction_level='geo'. Should a light narrowing count, or only material shrinkage? The v2 geo_reach_pct (exact % of US HH reachable) would let us set a real cutoff — is that worth building? (Candidate source: the bidder's per-campaign campaign_bucket_population.)
  4. Is keyword-only "real MM"? mm_keywords_only (Max Reach) counts toward is_unmodified_mm. Keep it, or should "unmodified MM" require a vertical anchor?
  5. Grain + rollup. Campaign-level, with a companion group-level view (all-flagship vs mixed). Right grain?
  6. Where should it live / be materialized (SQLMesh view vs scheduled table), and any columns missing?
