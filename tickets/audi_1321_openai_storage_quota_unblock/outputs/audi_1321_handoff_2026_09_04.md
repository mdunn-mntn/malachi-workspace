## The durable fix, not yet built

Age is the wrong key. The receipts under `openai_batch_submissions/dt=<D>/` already carry
`was_downloaded` and `batch_submit_time`, so the correct rule needs no API calls:

> take the oldest `batch_submit_time` among receipts where `was_downloaded == False`, and delete every
> OpenAI file created before it.

Everything older than that cutoff provably belongs to a day that has already been fetched, so it is
safe to delete at any age, and it frees more space sooner than any fixed window. #307 stays as the
manual override for emergencies. Malachi's framing of the goal (2026-09-04): "there's so many jobs we
literally max out OpenAI's storage so we have to delete it to make room for more submits."

## Date arithmetic, which cost three wrong triggers

- `dt read = data_interval_start - 1 day` (`{{ data_interval_start.subtract(days=1) }}`).
- `run_after = data_interval_end`, so a run whose interval ends in the future just sits queued.
- For a SCHEDULED run, logical date == interval start. For a MANUAL one it does NOT: Airflow assigns
  the interval containing the logical date, which puts interval start one period earlier.
- To replay a past partition immediately, POST the dag run with an explicit `data_interval_start` (the
  dt you want, plus one day) and a `data_interval_end` in the past.

## Gotchas worth keeping

- **`keyword_ddp_reporting`'s sensor cannot see a manual producer run.** `execution_delta=6h` makes it
  look for a fetch run at exactly `keyword_logical - 6h`, and a manual fetch has an off-schedule
  logical date. Verify `batch_post.product_categorization` succeeded, then mark
  `wait_for_product_categorization` success by hand with a note saying why.
- **`batch_fetch` succeeds while downloading nothing.** When the batches are still `in_progress` it
  logs "not completed yet; leaving for a later run" and exits green;
  `batch_post.openai_batch_joined` then fails on `PATH_NOT_FOUND` for the results partition. That is
  the batches being slow, not a defect. Do not chase it.
- The `404 No such File object` skips in the cleanup log are the submit and fetch cleanups racing on
  the same `0 9 * * *` slot. Benign.
