Four possible outcomes from a lift test

α controls how often we cry wolf. β controls how often we miss the real thing. Power = 1 − β.

Power is how cleanly two distributions separate

Mouse-diet visual from StatQuest, redrawn on MNTN axes (treated visit rate − holdout visit rate).

You have four levers

Sample size ↑

More impressions, more IPs, more spend. The lever we usually pull.

Variance ↓

CUPED, ghost-ad conditioning, stratification. Combined ≈ 40% SE reduction.

Effect size ↑

Retargeting at +21 pp is easy. Pure prospecting at <1 pp is hard.

Alpha ↑

Loosen the false-positive bar. We don't — the room ships on this.

The trap nobody talks about

An underpowered test usually fails to reject the null — even when there's a real effect. A null result from an underpowered test is meaningless.

"We saw no significant lift" is not "there is no lift." Without power, it's "we didn't have the statistical equipment to see it."

This is the bridge to the screening rule. We need to know before the test whether we'd have detected the lift we expect.

From "I want power" to "what's the smallest lift I can see?"

Solve the Lewis-Rao power equation for the effect size:

MDEabs  =  (zα/2 + zpower) · σ · √(1/nt + 1/nc) · var_reduction

At MNTN defaults: α = 0.05, power = 0.80  →  zα/2 + zpower = 2.80.

For visits / CVR (binomial): σ = √(p · (1 − p)).

Given the N we have (spend → impressions → IPs), we solve for the smallest lift we could reliably detect. That's the MDE.

What if every advertiser is too small?

TI-933 Select cohort. 23 individually-underpowered advertisers. Pooled lift +2.055 pp [+2.011, +2.100]. Pool, extend the window, or larger holdouts — design choices recover what spend can't.

Across our top-50 advertisers

Most iROAS lift reporting at MNTN is mathematically undetectable. Visits we can measure for almost everyone. CVR is hit-or-miss. iROAS is a different game.

Three questions, asked before we commit budget

  1. What's the metric? Visits, CVR, or iROAS — each has its own MDE. Don't promise iROAS measurement when only visits will be detectable.
  2. What's the expected effect size? Use prior MNTN results as the prior. Retargeting: big. Pure prospecting: small. Awareness-only Select: in between.
  3. Does this advertiser's spend put MDE below the expected effect? If yes, run it. If no, pool, extend the window, or don't run.

No question 4. If you can't answer these three, don't launch the test — you'll learn nothing.

Appendix · Lewis-Rao derivation

Two-arm test of proportions. Want: smallest δ (effect size) that we'd reject H₀ for, with probability ≥ power.

Under H₀ (no effect), the test statistic is N(0, 1). Under H₁ (δ true effect), it's N(δ/SE, 1) where SE = σ · √(1/nt + 1/nc).

Reject when |Z| > zα/2. Probability of rejection under H₁ is ≥ power when:

δ  ≥  (zα/2 + zpower) · SE

That's the MDE. Plug var_reduction in as a multiplier on SE for the variance stack.

For binomial outcomes, σ = √(p(1−p)). For continuous outcomes (iROAS, revenue per IP), σ is the per-unit SD of the outcome.
