# DeepSeek Harness (DSH) Plugin Ecosystem Survey — 2026-08-21

**Context.** DSH is [deepseek-ai/deepseek-harness](https://github.com/deepseek-ai/deepseek-harness) (177,221★, TypeScript, MIT), an "everything is a plugin" agent harness built on the [Cordis](https://github.com/cordiverse/cordis) plugin framework, launched into developer preview 2026-08-13 and explicitly warning of breaking changes. Run via `npx @deepseek-ai/dsh web` (Web UI on :3080). The GitHub topic [`dsh-plugin`](https://github.com/topics/dsh-plugin) is the *official* discoverability mechanism — the README says "Add the `dsh-plugin` topic to your plugin repository for discoverability." The topic now has **9,958 repos** (GitHub search `topic:dsh-plugin`, 2026-08-21), one week after launch. The curated [awesome-dsh-plugin](https://github.com/awesome-dsh-plugin/awesome-dsh-plugin) list holds ~1,840 verified-installable entries.

**Caveat on star counts:** most of the top-starred `dsh-plugin` repos are pre-existing multi-host projects that added the topic for discoverability; their DSH integration is usually a subpackage (e.g. WeKnora's `packages/dsh-weknora`, OpenViking's `examples/dsh-memory-plugin`). DSH-native plugins are all ≤ ~17k★ and mostly < 200★ because the ecosystem is 8 days old.

## 2. Deep dives

### 2.1 OpenViking — memory/RAG ([volcengine/OpenViking](https://github.com/volcengine/OpenViking), 31,267★)
- **What:** open-source "context database": memories, resources, and skills stored as one virtual filesystem under `viking://` URIs; agents browse context with `ls`/`tree`/`find` instead of a black-box vector store. Everything is processed on write into three tiers (L0 ~100-token abstract, L1 ~2k-token overview, L2 full detail) and loaded only as deep as needed; retrieval is directory-recursive and leaves an inspectable trajectory. Sessions auto-commit: preferences and agent experience are asynchronously extracted to long-term memory. Benchmarks (their own [report](https://blog.openviking.ai/post/openviking-benchmark-results/)): LoCoMo memory accuracy 80–83% vs 24–57% native across three agent hosts, with 34–91% input-token reduction; tau2-bench +6.9pp retail / +11.9pp airline.
- **How it plugs in:** client-server. Python server (`pip install openviking`, `openviking-server init/doctor`, config at `~/.openviking/ov.conf`); `ov` CLI client included. DSH integration is the bundled [`examples/dsh-memory-plugin`](https://github.com/volcengine/OpenViking/tree/main/examples/dsh-memory-plugin): "pre-step auto-recall and profile injection, session capture, `viking://` URI guarding, and recall/write memory tools backed by an OpenViking server" ([awesome-list entry](https://github.com/awesome-dsh-plugin/awesome-dsh-plugin)). A richer community alternative exists: [Rxiain/dsh-openviking](https://github.com/Rxiain/dsh-openviking) (memsearch/memfind/memread/membrowse/memgrep/memglob tools over `viking://`, memcommit session capture, memlearn skill minting). Also integrates with Claude Code, Codex, Cursor, MCP clients, LangChain.
- **Config:** interactive `init` wizard writes `ov.conf`; providers: Volcengine, OpenAI, Codex OAuth, Kimi, GLM, local Ollama (auto-installs runtime). Docker + standalone HTTP service for production.
- **Maturity:** highest of any DSH-adjacent memory system. Backed by ByteDance/Volcengine; VLDB 2026 paper (VikingMem, [arXiv:2605.29640](https://arxiv.org/abs/2605.29640)); AGPLv3 with managed SaaS and self-hosted commercial editions; hosted [Studio demo](https://openviking.ai/studio); desktop Helper app in beta. Self-describes as "still in its early stages"; DSH plugin lives under `examples/`, i.e. newest part of the project.

### 2.2 colleague-skill / dot-skill — skill distribution ([titanwings/colleague-skill](https://github.com/titanwings/colleague-skill), 23,690★)
- **What:** a meta-skill that *generates* skills: distills a person (colleague / relationship / celebrity families) into an AI skill from source material — Feishu/DingTalk/Slack auto-collection, WeChat SQLite exports, email, PDFs, pasted text. Output is a Persona + Work two-layer skill invoked as `/{character}-{slug}` (with `-work` / `-persona` variants). Ships a celebrity research toolchain (subtitle download → transcript → six-dimension research merge → quality check), versioning with rollback, and conversation-driven correction ("they wouldn't say that" writes to a Correction layer). Backed by a technical report ([arXiv:2605.31264](https://arxiv.org/abs/2605.31264)); community gallery of 215+ generated skills.
- **How it plugs in:** *not* a Cordis plugin — it rides DSH's **native filesystem skill discovery** (added 2026-08-13, same day DSH launched): clone to `~/.dsh/skills/dot-skill` (global) or `.dsh/skills/dot-skill` (project), then `/dot-skill` works. Generated skills drop into `~/.dsh/skills/<skill-name>` with no host-specific wrapper. Follows the [AgentSkills](https://agentskills.io) standard (`SKILL.md` + frontmatter); the same repo installs into Claude Code, Hermes, OpenClaw, and Codex — this is the skill-distribution pattern for DSH: git-clone into a skills directory, no registry.
- **Config:** none beyond credentials for auto-collectors (Feishu app bot, Slack admin-installed bot); Python 3.9+, MIT.
- **Maturity:** 20k★ milestone 2026-08-13, active roadmap and Discord, but self-labels "still a demo version."

### 2.3 Workflow/orchestration + scheduling — [omdsh-dev/dsh_workflow](https://github.com/omdsh-dev/dsh_workflow) (91★) is the flagship
- **What:** `@dsh-external/workflow` upgrades DSH's built-in one-shot multi-agent `workflow` tool into a persistent workflow *layer*: named/saved/discoverable workflows, pause/resume, rerun/resume-run with effect cache, durable run graphs, cost accounting, and governance. Full WorkflowApi (`spawnAgent`, `parallel`, `pipeline`, `synthesize`, budgets, artifacts), six standard patterns (classify-and-act, fan-out-and-synthesize, adversarial-verification, generate-and-filter, tournament, loop-until-done), two built-ins (`parallel-investigation`, `scoped-review`). Generated workflow scripts run in a **QuickJS WebAssembly sandbox** with JSON-capability RPC only (no import/process/fs/net/timers); read-only agents get parent-tools ∩ allow-list; 179 tests, feature-parity matrix vs KodaX.
- **How it plugs in:** official bundle form, zero core patches: `dsh plugin --profile web add "github:dsh-external/dsh_workflow#main"` (prebuilt `lib/` committed, no user-side compile). Surfaces as `/workflow` slash commands plus three model-callable tools (`workflow_list`, `run_workflow`, `workflow_manage`). Discovery order: built-ins → project `.dsh/workflows` → personal `$DSH_HOME/workflows`; runs persist under `.dsh/workflow-runs/<run-id>/` (run.json, events.jsonl, immutable capsule snapshot, results cache, artifacts).
- **Config:** YAML plugin block — `approvalMode` (never / generated-and-local / always), `maxAgents: 64`, `maxConcurrency: 8`, `maxRetainedRuns`, fast/balanced/deep provider+model+token routing, `readOnlyAllowedTools`, deployment capability manifests (`availableTools/Mcp/Skills`) with fail-loud preflight.
- **Maturity:** Node ≥22.19, pinned to DSH snapshot `0.0.1-rc.2` via `compatibility.json` — tightly version-coupled to a preview harness; MIT; unusually rigorous (80% coverage gates, security model doc) for a week-old ecosystem.
- **Schedulers** (all young/fragmented): [omdsh-dev/dsh-cron](https://github.com/omdsh-dev/dsh-cron) (2★, model- and human-callable cron firing followup/inject into sessions), [Jesse-njx/dsh-routines](https://github.com/Jesse-njx/dsh-routines) (scheduled prompts with overlap/missed-run/timeout safety), [534119219/chicheng-cron](https://github.com/534119219/chicheng-cron) (sidebar cron UI for shell/Python/Node/skills/agent tasks + push notifications), [Ceelog dsh-plugin-scheduled-tasks](https://github.com/Ceelog/dsh-plugins/tree/main/src/plugins/dsh-plugin-scheduled-tasks) (per-project one-time/interval/cron prompts as fresh headless sessions). Orchestration alternatives: [toolclub/dsh-agent-team-gui](https://github.com/toolclub/dsh-agent-team-gui) (112★, bounded-DAG multi-model teams), [apheli0os/deepseek-harness-orchestrate](https://github.com/apheli0os/deepseek-harness-orchestrate) (declarative task-DAG).

### 2.4 Data/SQL — [omdsh-dev/dsh-data-agent](https://github.com/omdsh-dev/dsh-data-agent) (103★); **no BigQuery plugin exists**
- **What:** conversational data analysis over real databases: DSH inspects schemas, writes and executes SQL, iterates on errors/results, and produces business conclusions. A `render-analysis` tool generates versioned offline HTML dashboards (1–6 datasets, 1–8 views: metric/line/bar/pie/scatter/table) saved to `analysis-reports/`; Web UI adds a database workbench modal (connections, table browsing, ad-hoc SQL, 100-row paginated results, export to .xlsx/CSV, 50k-row cap). Engines: **MySQL, PostgreSQL, SQLite, Oracle, Hive, Impala, ClickHouse, Apache Doris, SQL Server** — no BigQuery, Snowflake, Redshift, or DuckDB.
- **How it plugs in:** installs a "data mode" agent preset with tools `sql-query`, `sql-write`, `sql-cmd`, `render-analysis` and a `/database` command family (connect/status/test/disconnect); shared protocol across Web, Desktop, dsh-tui, and headless profiles; no DSH source modification. Shells out to local DB CLI clients (`mysql`, `psql`, `sqlcmd`, etc., with cross-platform PATH auto-discovery) except ClickHouse (bundled official HTTP client).
- **Config:** connections per session (isolated), read-only mode toggle, credentials via env vars / DSH credential references (never URL or argv); per-profile `clients.<engine>.searchPaths`/`command`/`args` YAML for custom client paths. Guards: SQL Server `GO`/`:cmd`/`$(var)` injection rejected pre-launch, TUI password masking.
- **Maturity:** npm-published `@yejiming/dsh-data-agent@0.0.13`, MIT, trusted in-process (not sandboxed); carries an *experimental* [dsh-ecosystem-spec](https://github.com/T-Auto/dsh-ecosystem-spec) Community v0.15 manifest (`dsh-plugin.json`) — a draft standardization effort. Runs in-process with your permissions.
- **Other data plugins, all tiny:** [STARDUSTLC666/dsh-sql](https://github.com/STARDUSTLC666/dsh-sql) (2★, SQLite/MySQL/Postgres list/query/exec/schema with lexer-grade read-only protection, row caps, approval-gated writes), [duyanta123/dsh-data-insight](https://github.com/duyanta123/dsh-data-insight) (2★, CSV → DuckDB queries → Markdown report with charts), [kaiwangleo/xiwen dsh-xiwen](https://github.com/kaiwangleo/xiwen/tree/master/plugins/dsh-xiwen) (semantic-layer analytics: curated table/column/metric metadata + Qdrant/Elasticsearch recall → validated MySQL queries), [JohnXu22786/db-connector](https://github.com/JohnXu22786/db-connector) (0★, JSONL SQL audit trail), [strukto-ai/mirage dsh package](https://github.com/strukto-ai/mirage/tree/main/typescript/packages/dsh) (3,545★ parent, virtual filesystem mounting S3/Redis/Postgres/Slack/Gmail/Notion as the agent's workspace). GitHub search `topic:dsh-plugin sql OR bigquery OR database OR duckdb` returns 24 repos total; besides dsh-data-agent everything is 0–2★ and created 2026-08-14 or later. **A BigQuery user today would wire DSH to `bq` via a skill or MCP server, not an existing plugin.**

## 4. Distribution & installation

- **Primary discovery = the GitHub topic tag.** Officially: "Add the `dsh-plugin` topic to your plugin repository for discoverability" ([harness README](https://github.com/deepseek-ai/deepseek-harness)). There is no central official registry.
- **Install command:** `dsh plugin --profile <web|desktop|dsh-tui> add <source>` where source is an **npm package name** (`dsh plugin --profile web add @yejiming/dsh-data-agent`) or a **GitHub specifier** (`dsh plugin add github:omdsh-dev/dsh-data-agent`, branch pinning via `#main`). Verify with `dsh --profile web --dump-config`. Plugins declare a **`dsh.bundle` manifest in package.json** — the awesome list's admission bar is exactly "installs with `dsh plugin add` and declares a `dsh.bundle` manifest" ([awesome-dsh-plugin](https://github.com/awesome-dsh-plugin/awesome-dsh-plugin)).
- **npm scoping:** core is `@deepseek-ai/dsh`; community plugins use arbitrary personal scopes (`@yejiming/…`, `@dsh-external/…`) — no reserved community scope. Marketplaces treat "npm registry + dsh-plugin topic" as the authoritative catalog and add anti-squatting same-source checks ([dsh-plugin-mall](https://github.com/1e0zj/dsh-plugin-mall), [dsh-store](https://github.com/huguangyu666/dsh-store)).
- **In-app marketplaces:** the de-facto standard is [dsh-market](https://github.com/dsh-market/dsh-market) (`dsh plugin --profile web add dshmarket`) — one-click install/update inside Settings, bundled by default into the dsh-desktop clients; a dozen competitors add quality scoring, security static-scans, and recipe bundles ([dsh-plugin-audit](https://github.com/863683348/dsh-plugin-audit), [dsh-recipe](https://github.com/863683348/dsh-recipe)).
- **Skills are a separate, registry-less channel:** filesystem discovery at `~/.dsh/skills/<name>` (global) or `.dsh/skills/<name>` (project), populated by `git clone` — the AgentSkills `SKILL.md` convention shared with Claude Code/Codex ([colleague-skill install docs](https://github.com/titanwings/colleague-skill)).
- **Standardization in flight:** [dsh-ecosystem-spec](https://github.com/T-Auto/dsh-ecosystem-spec) (Community v0.15, Draft/Experimental) defines a `dsh-plugin.json` manifest with permission declarations; adoption so far is token (dsh-data-agent ships one but flags it non-normative).
- **Security posture:** plugins run **in-process with your permissions** — "tool approvals don't sandbox plugin code… Being on this list is not a security review" ([awesome-dsh-plugin warning](https://github.com/awesome-dsh-plugin/awesome-dsh-plugin)). Only dsh_workflow-style generated scripts get real sandboxing (QuickJS/WASM). Compatibility churn is the other operational risk: plugins pin exact harness snapshots (`compatibility.json`) because DSH is at 0.0.1-rc.2 with promised breaking changes.
