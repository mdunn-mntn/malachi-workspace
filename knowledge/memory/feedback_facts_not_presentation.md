For internal data work (analysis tickets, war-room investigations, methodology audits) the user wants **facts-first documents**, not presentation-style artifacts. Drop:
- Power Line / one-sentence headline
- Three-act structure (Disruption / Revelation / Resolution)
- Cialdini persuasion checklist (social proof, scarcity, commitment ladder)
- Kindra Hall story framework / character moments
- Greene's Laws boldness framing
- Bookended openers and closes

**Why:** Internal audiences (engineers, DS, TPMs, leadership) read these docs to understand what was found and decide what to do — they don't need to be persuaded into a position. Persuasion framing adds noise that obscures the underlying facts and forces them to mentally strip the rhetoric. The presentation playbook applies to external/buyer-facing or hostile-audience presentations, NOT to internal investigative work.

**How to apply:**
- Default to plain prose / tables / methodology sections
- Lead with the question being answered, then the answer, then how it was computed, then caveats
- Cite specific numbers with their `n` and CIs
- State limits and selection bias inline, not as a denouement
- No emoji, no bold-headline sentences, no "Power Line" callouts
- It's OK for the deliverable to be boring; it should be correct and complete

**Exception:** if the user explicitly says "build a deck" or "this is going to leadership / external audience for buy-in," use the playbook. Otherwise, default to facts.

**2026-07-16 extension — applies to stakeholder DECKS for technical teams too:** user rejected a
playbook-style deck (hero numbers, narrative titles) as "way too much filler, reads like a
presentation deck" for a DS/DA/MLE audience. Technical-stakeholder decks = neutral descriptive
titles, dense full tables with exact values, definitions slide up front, per-slide query citations,
no Power Line / no hero-number slides. Playbook style stays reserved for exec/persuasion decks.
