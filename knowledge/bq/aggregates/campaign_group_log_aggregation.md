# aggregates.campaign_group_log_aggregation

## Purpose
The bidder's **per-candidate decision log**. Every RTB auction the bidder sees is fanned out to each
eligible campaign, and each **(auction x campaign)** evaluation is written here with the pacing state
and eligibility outcome *at that instant*. Reach for it to explain **why the bidder did or did not bid**
on a given auction: threshold/eligibility failures (intent-score gating, pacing caps, bid floor),
the realized bid price, PMP-deal selection, and per-term throttling. It is the raw source behind
ghost-bid / pacing analyses. **Despite the "aggregation" name it is NOT a roll-up** — it is the raw
candidate grain (~1M rows/sec); the `*_agg_min` sibling views are the actual minute roll-ups.

## Grain & keys
- **Grain:** one row per **bid candidate = (auction_id x campaign_id)** evaluated by the bidder.
  Verified over a 10-second window: distinct `(auction_id, campaign_id)` = 10,077,106 ≈ n_rows 10,080,125
  (~0.03% exact dupes); distinct `auction_id` = 2,259,134, so **each auction fans out to ~4.5 campaigns**.
- **Volume:** ~1M rows/sec (~10.08M rows per 10s window). **~98.3% are `has_price=false`** (candidates the
  bidder filtered out); only ~1.7% actually emit a bid.
- **Key columns:** `auction_id` + `campaign_id` identify a row. `campaign_group_id`, `advertiser_id`,
  `flight_id` are higher-level attributes (each candidate row → exactly one of each).

## Column meanings (only the non-obvious ones)
- **`bid_time`** — bidder decision time; the **PARTITION** column (HOUR granularity). **`auction_time`** —
  when the auction/impression opportunity occurred (≈ `bid_time`, usually the same second).
  **`bid_time_minute`** — `bid_time` truncated to the minute; the **CLUSTER** key.
- **`has_price`** BOOL — whether the bidder emitted a bid for this candidate. `TRUE` ⇒
  `threshold_failure_reasons = ''` (verified: all `has_price=true` rows have `tfr=''` and `price>0`).
  `FALSE` (~98% of rows) ⇒ candidate filtered, `threshold_failure_reasons` populated. **To isolate
  emitted bids use `has_price=TRUE` (or `threshold_failure_reasons=''`) — do NOT use `price>0`**
  (`price` is populated on filtered rows too; see below).
- **`price`** INT64 — the **computed candidate bid price** in **micro-USD per impression (µ$)**.
  **CPM = price / 1000** (µ$/imp x 1000 imp / 1000). **Populated on essentially all rows — NOT zeroed
  when `has_price=false`.** In a 3-second sample only **0.04%** of `has_price=false` rows had `price=0`
  (0 were NULL); **99.96% had `price>0`** with quartiles 0 / 7020 / 7520 / 9520 / 48000 (median ~7520 µ$
  — *higher* than the emitted-bid median), because it is the *would-be* bid the bidder priced before the
  candidate was filtered. **Consequence: `price>0` does NOT isolate emitted bids** — it also returns the
  ~98% suppressed candidates (a ~55x overcount vs. real bids); use `has_price=TRUE` /
  `threshold_failure_reasons=''` instead. Observed quartiles on *emitted* bids (`has_price=true`):
  240 / 1220 / 6550 / 8020, max 48378 → ≈ **$0.24–$48 CPM, median ~$6.55** (1220 is a very common floor bid).
- **`threshold_failure_reasons`** STRING — comma-separated list of the eligibility/pacing filters that
  blocked the bid; **`''` when the bid succeeded**. Observed top values (fraction of a 3s window):
  `invalidCampaignIntentScore` (dominant), `missingIntentScore`, `dailySpendPacing, cappedOrPaced`,
  `dailyTermSpendRateLimited, cappedOrPaced`, `invalidRecency`, `bidPriceBelowImpressionBidFloor`,
  `dailyImpressionPacing, cappedOrPaced`, `dailyTermSpendCap, cappedOrPaced`,
  `dailyTermImpressionRateLimited, cappedOrPaced`, `invalidAdvertiserIntentScore`, `ghostBid`.
  **NOTE: `ghostBid` is camelCase here** (Beeswax bidder) — distinct from the `'ghost-bid'` string used in
  `bid_logs_enriched` / the Rust bidder. Match reasons with `LIKE`/`CONTAINS`, not `=`, since a reason
  usually co-occurs with `cappedOrPaced`.
- **`inventory_source`** STRING — bidder/source. This general view is **Beeswax-dominated** (every sampled
  row = `"beeswax"`). The sibling view `campaign_group_log_aggregation_mntn_bidder` filters to the MNTN bidder.
- **`publisher`** STRING — publisher id; **`"-1"` is the unset/unknown sentinel** in sampled rows.
- **`pmp_deal_ids`** STRING — comma+space-separated list of **all** PMP deal ids the auction matched
  (eligible). **`selected_pmp_deal_id`** STRING — the single deal actually used for the bid
  (e.g. `IXIVPMNTNDISPLAYUS`).
- **Pacing block** (`{flight,daily}_{campaign_group,campaign}_{spend,spend_cap,impression,impression_cap}`) —
  the **live running totals & caps carried on every candidate row** (what pacing gating reads at decision
  time). `*_spend` / `*_spend_cap` are FLOAT64 in **micro-USD**; `*_impression` / `*_impression_cap` are
  FLOAT64 **impression counts**. Two windows (`flight`, `daily`) x two levels (`campaign_group`, `campaign`).
  **`cap = 0.0` means "no cap set at that scope"** (falls back to another scope's cap) — NOT a $0 cap.
- **`terms`** ARRAY<JSON> — declared **NOT NULL but usually `[]`** (empty on pure-RTB rows; populated on
  segment/term-targeted candidates, ~1–2% of rows). Each element = one targeting term's pacing state:
  `{id, dimension (e.g. COUNT), cap, value, win_rate, bid_volume_percentage, throttling_percentage,
  current_spend_percentage, current_spend_cap_percentage, estimated_additional_value, rate_limited (bool),
  spend_capped (bool), update_time, optional random_number}`. **`update_time` inside the JSON is epoch
  SECONDS** (e.g. 1784375888 = 2026-07-18 ~11:58 UTC).
- **`eligible_term_id`** STRING — string-encoded array of the eligible term ids for the auction
  (e.g. `"[22953, 22954]"`). **`picked_term_id`** STRING — the term chosen for attribution; **NULL on the
  vast majority of rows** (only a tiny subset picks a term).

## Joins & relationships
- **`campaign_id` → `campaigns`** (silver.core / integrationprod dims): **N:1** (one campaign per row).
  Fan-out risk is on the *reverse* join — one campaign has billions of candidate rows here; always filter
  `bid_time` first. Use `campaigns.name` (not `campaign_name`); `funnel_level` for stage, not `objective_id`.
- **`campaign_group_id` → `campaign_groups`**: **N:1**. `product_id` (1=PTV / 2=Select / 3=QuickFrame) lives there.
- **`advertiser_id` → `advertisers`**: **N:1**; join `company_name` (fpa_advertiser_verticals.advertiser_name
  is unreliable/empty). **`flight_id` → `flights`**: **N:1** (the pacing window the campaign_group runs in).
- **`auction_id`** → the auction across bidder logs (`bid_logs`, `win_logs`, `bidder_bid_events`). One
  auction : N candidate rows here (1:N). The value carries a source suffix (e.g. `".steelhouse"`); it is
  not a cheap cross-physical-table join key in BQ.
- **Sibling views (same schema / roll-ups):** `campaign_group_log_aggregation_mntn_bidder` (MNTN-bidder
  only), `campaign_group_log_agg_min` (minute roll-up per campaign_group/flight), `campaign_log_agg_min`
  (campaign level), `terms_log_agg_min` (term level). **This table is the raw candidate grain those
  `*_agg_min` views summarize** — prefer them for anything minute-or-coarser.

## Gotchas
- **Name lies:** "aggregation" but it is **NOT aggregated** — raw per-candidate grain (~1M rows/sec).
  Use the `*_agg_min` sibling views for minute roll-ups.
- **7-DAY TTL** (partition expiration 604,800,000 ms on `bid_time` HOUR) — only the **last 7 days** exist.
  No history beyond that; for longer windows use the roll-up views or other tables.
- **~98% of rows never bid** (`has_price=false`). Filter `has_price=TRUE` for actual bids, or
  `threshold_failure_reasons=''` for successes. **NOT `price>0`** — `price` is the *computed candidate*
  bid and is populated (median ~7520 µ$) even on filtered rows, so `price>0` overcounts bids ~55x.
- **`ghostBid` is camelCase** here (differs from `'ghost-bid'` elsewhere).
- **Monetary fields are micro-USD** (÷1e6 for USD; CPM = `price`/1000). Impression fields are counts.
  `cap = 0.0` ≠ "$0 cap" → it means "no cap at that scope."
- **`publisher = "-1"`** = unset sentinel.
- **Beeswax-dominated** — use the `_mntn_bidder` sibling for the MNTN bidder.
- **`terms` is ARRAY<JSON> declared NOT NULL but is `[]` on most rows**; `picked_term_id` is NULL on most rows.

## Cost & partitioning notes
- **Always filter `bid_time`** (partition column, HOUR granularity). `require_partition_filter` is **FALSE**
  (an unfiltered query validates rather than erroring), but unfiltered = full 7-day scan.
- **Dry-run estimates** (`bq_run.sh --dry_run`, re-derived 2026-07-19; each figure labeled by its exact
  column set — only same-column-set figures are comparable):
  - **1 column** (`campaign_group_id`), `bid_time` 1-hour filter → **46.6 GB**
  - **same 1 column, NO filter** (full 7-day retained) → **3,625 GB (3.63 TB)** — same column set ⇒
    **~78x prune** from the partition filter alone
  - **`SELECT *`**, `bid_time` 1-hour filter → **762.8 GB** (~16x the one-column cost — **never `SELECT *`**)
- **Sub-hour windows prune below the dry-run estimate at RUNTIME, not in the estimate.** A `bid_time`
  range inside a single hour partition (a 2-3 second sample) *dry-runs* at the full hour-partition size,
  but the **billed** bytes are far lower thanks to `bid_time_minute` clustering + block min/max stats.
  Measured 2026-07-19: 3 cols (`has_price, price, threshold_failure_reasons`) over a **3-second** window
  **billed 2.34 GB**. So narrow `bid_time` to seconds/minutes when sampling — but check *billed*, not
  dry-run, bytes to see the clustering benefit.
- Approx storage: **~120 TB / ~453B rows** (the 7-day retained window; physical
  `sqlmesh__aggregates.aggregates__campaign_group_log_aggregation__258842102`).

## Example queries
```sql
-- Why a campaign group did / didn't bid in one minute (narrow bid_time to keep it cheap)
SELECT campaign_id, has_price, price, threshold_failure_reasons, selected_pmp_deal_id
FROM `aggregates.campaign_group_log_aggregation`
WHERE bid_time BETWEEN TIMESTAMP('2026-07-18 12:00:00') AND TIMESTAMP('2026-07-18 12:01:00')
  AND campaign_group_id = 76848
LIMIT 100;

-- Bid vs threshold-failure breakdown for a short window
SELECT has_price, threshold_failure_reasons, COUNT(*) n
FROM `aggregates.campaign_group_log_aggregation`
WHERE bid_time BETWEEN TIMESTAMP('2026-07-18 12:00:00') AND TIMESTAMP('2026-07-18 12:00:05')
GROUP BY has_price, threshold_failure_reasons
ORDER BY n DESC;
```
