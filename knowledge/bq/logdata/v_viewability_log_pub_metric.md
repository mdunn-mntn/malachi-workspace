# logdata.v_viewability_log_pub_metric

## Purpose
Synthetic view that fuses **impression** and **viewability** events into a single stream shaped for **publisher-level viewability metrics** (the `_pub_metric` suffix). It is a 3-way `UNION ALL`:

1. **CTV, measurable (`viewability_type_id = 1`):** rows from `cost_impression_log`, filtered to campaigns with `channel_id = 8` (CTV). CTV impressions are treated as inherently measurable.
2. **CTV, viewable (`viewability_type_id = 2`):** the *same* `cost_impression_log` CTV rows, re-emitted as viewable. So every CTV impression contributes **two** rows (measurable + viewable) — CTV completed impressions count as both.
3. **Display, viewable only (`viewability_type_id = 2`):** rows from `viewability_log` where `viewability_type_id = 2` (viewable). Measurable-but-not-viewable display events are **excluded**.

Reach for it when you need unified per-publisher (`domain`/`subdomain`) viewable-event counts across CTV and display — but mind the channel asymmetry: CTV viewability is definitional (measurable == viewable == 100%) while display carries viewable events only (no measurable denominator here), so a single cross-channel "viewable rate" is NOT a like-for-like measurement (see gotchas + example query). Do **not** use it as a raw impression log (CTV is double-counted by design) or as a real-exchange breakdown (`exchange_id` is a constant — see gotchas).

## Grain & keys
- **Grain:** one row per **(impression/viewability event x `viewability_type_id`)**. CTV impressions from `cost_impression_log` appear **twice** (once as type 1, once as type 2); display viewable events from `viewability_log` appear **once** (type 2). Verified on 2026-07-10: 41.46M type-1 rows (all CTV) and 53.17M type-2 rows (= ~41.46M CTV + ~11.7M display).
- **Key(s) / join columns:** `ad_served_id` = the impression identifier (near-unique within a `viewability_type_id` for the CTV branch: 41,460,624 distinct vs 41,461,209 rows on 2026-07-10). `guid` = event GUID. Standard dims for joins: `campaign_id`, `advertiser_id`, `creative_id`, `group_id`, `ip`, `domain`/`subdomain`.
- To count a distinct CTV **impression** collapse the two rows: filter to a single `viewability_type_id` (or use `DISTINCT ad_served_id`).

## Column meanings (only the non-obvious ones)
- **`viewability_type_id`** — `1` = measurable, `2` = viewable (same encoding as `viewability_log`). Its mechanism differs by branch: on the two **CTV** branches it is a **synthesized literal** (`1 AS viewability_type_id` and `2 AS viewability_type_id` — each CTV impression emits both); on the **display** branch it is the **passthrough real column** `vl.viewability_type_id`, constrained by `WHERE vl.viewability_type_id = 2`, so display rows are always `2`. Base `viewability_log` also carries measurable-only (type-1) display rows, but that filter drops them, so there is no measurable-only display row in this view.
- **`exchange_id`** — **constant literal `131` on every row** (`131 AS exchange_id` in all three UNION branches). Verified 2026-07-10: `COUNT(DISTINCT exchange_id) = 1`. It does NOT identify the real SSP/exchange — ignore it for exchange analysis; join to `bid_logs`/`win_logs` if you need the true exchange.
- **`time`** — TIMESTAMP, the partition column (DAY). Sourced from the underlying event's `time` (impression time for CTV, viewability-event time for display). No int-epoch column is exposed here (`viewability_log.epoch_time` is dropped by this view).
- **`ip`** — for the **display** branch, CIDR/suffix is stripped: `split(ip,'/')[OFFSET(0)]`. For the **CTV** branch it is `cost_impression_log.ip` as-is. There is no `ip_raw`/`bid_ip`/`original_ip` in this view (unlike base `viewability_log`).
- **`city`, `country`, `metro_id`, `postal_code`, `region`** — populated only for **CTV** rows (from `cost_impression_log` geo). For **display** rows they are **hardcoded NULL** in the view SQL. Verified 2026-07-10: of the 53.17M type-2 rows, 11.7M had NULL city/country — exactly the display subset. Never assume geo coverage on viewable/display rows.
- **`user_agent`** — display branch is explicitly `CAST(... AS STRING)`; a harmless normalization, values unchanged.
- **`domain` / `subdomain`** — the publisher site and path; this is the natural group-by key for publisher viewability metrics.
- **`ad_served_id`** — impression/served-ad id (STRING); the event key. `creative_id`, `group_id`, `campaign_id`, `advertiser_id` are MNTN integer ids (from the underlying logs, not Beeswax ids).

## Joins & relationships
- **`cost_impression_log`** (CTV branch source; **1:2** — the view re-emits each CTV `cost_impression_log` row TWICE, once as `viewability_type_id=1` and once as `=2`): joins on `ad_served_id` / `guid`. Because of this doubling, joining back on `ad_served_id` without also constraining `viewability_type_id` fans out **2x** on the CTV side.
- **`viewability_log`** (display branch source; **1:1** on the type-2 subset): `ad_served_id` / `guid`. Base `viewability_log` also holds type-1 (measurable) display rows that this view drops — do not expect them here.
- **`public.campaigns`** (dim; **N:1**, `campaign_id` -> one campaign): the view's own definition filters CTV via `campaign_id IN (SELECT campaign_id FROM public.campaigns WHERE channel_id = 8)`. If you re-join `campaigns` for `funnel_level`/`name`, filter `deleted=FALSE AND is_test=FALSE`; `campaign_id` is unique so no fan-out.
- **`advertisers` / `campaign_groups`** (dims; **N:1** via `advertiser_id` / `group_id`): safe, no fan-out. `advertisers.company_name` is the reliable name (per `fpa_*` gotcha).

## Gotchas
- **CTV is double-counted by design.** Every CTV impression is one row as `viewability_type_id=1` AND one as `=2`. A naive `COUNT(*)` overcounts CTV impressions 2x. To count impressions, pin one `viewability_type_id` or use `COUNT(DISTINCT ad_served_id)`.
- **`exchange_id = 131` is a hardcoded literal**, not the real exchange. See column meanings.
- **Geo is CTV-only.** `city/country/metro_id/postal_code/region` are NULL for all display (`viewability_log`) rows.
- **Asymmetric viewability semantics across channels.** CTV contributes both measurable and viewable (100% viewable by construction); display contributes viewable only. A cross-channel "viewable rate" computed from this view is therefore **not** a like-for-like measurement — CTV viewability is definitional, display viewability is measured.
- **Two different history depths — but the display side is NOT short.** CTV branch (`cost_impression_log`) has data back to **2023-10-01** (fixed floor). The display branch (`viewability_log`) has data back to **2024-04-02** — the floor of its backing history table `bronze.history.viewability_log_physical` (partitions <= 2025-12-31), which carries **no TTL** and is permanently retained. Only the raw side (partitions >= 2026-01-01, table `sqlmesh__raw.raw__viewability_log`) carries a **365-day TTL**, and none of it has aged out yet (the earliest raw partition the view reads is 2026-01-01, ~6.5 months old). Verified 2026-07-19: querying the view for **2024-06-01** returns **14,074,987** display rows — so **do NOT filter `time >= 2025-04-08`** (or any 2025 floor); that silently drops ~15 months (2024-04 → 2025-04) of real, retained display viewability data. Future risk only: once a raw partition exceeds 365 days (starting ~2027-01-01) a gap could open at the 2026-01-01 history/raw boundary.
- **Not a lightweight view.** It scans the ~62 TB `cost_impression_log` (CTV subset) plus the ~17.6 TB `viewability_log` union. Always bound `time` (see cost notes).
- **`ad_served_id` is not globally unique across branches** — a CTV and a display event could in principle collide; disambiguate by `viewability_type_id`/geo-nullness if joining raw.

## Cost & partitioning notes
- **Partition: `time` (DAY). Cluster: none on the view** (underlying `cost_impression_log` is clustered `advertiser_id, impression_id`, but `impression_id` is not exposed here and clustering does not survive the UNION+subquery for `advertiser_id`). **Always filter `time`** — it is not `require`d (an unfiltered query validates), so the guardrail is discipline, not enforcement.
- **Dry-run byte figures (view-level, labeled by column set):**
  - `SELECT guid` (view still reads `campaign_id` + `viewability_type_id` for its internal filters), **no time filter**: **5.57 TB** (re-derived 2026-07-19: 5,571,454,036,544 B; grows daily).
  - `SELECT guid`, **one-day** `time` slice: **5.36 GB** (5,356,165,872 B). ~**1040x** reduction — this is the empirical proof that `time` is the partition column.
  - Actual run, `guid, ad_served_id, exchange_id, viewability_type_id, city, country`, one day + `GROUP BY`: **9.89 GB** billed, 7.6s wall (2026-07-10 slice).
- **`approx_logical_bytes` (79,571,013,930,706 B ~= 72.4 TiB)** = sum of the three backing physicals' `numBytes`: `cost_impression_log` 61.95 TB + raw `viewability_log` 5.30 TB + history `viewability_log_physical` 12.32 TB. This is **full backing storage**; the view reads only the CTV subset of `cost_impression_log` and the type-2 subset of `viewability_log`, so real scan on a bounded query is far smaller (see dry-run figures).
- **Physical chain:** view -> `sqlmesh__logdata.logdata__v_viewability_log_pub_metric__148094099` (VIEW) -> UNION of `sqlmesh__logdata.logdata__cost_impression_log__2498930125` (TABLE, 61.9 TB, part `time` DAY) + `sqlmesh__logdata.logdata__viewability_log__2666508487` (VIEW -> `bronze.sqlmesh__raw.raw__viewability_log__2998484813` [>= 2026-01-01, 365d TTL] UNION `bronze.history.viewability_log_physical` [<= 2025-12-31, floor 2024-04-02, **no TTL** — permanently retained]).

## Example queries
```sql
-- Per-publisher viewable-event volume BY CHANNEL, one day.
-- The view exposes no channel_id, but geo separates the channels: CTV rows carry geo
-- (country populated), display rows are geo-NULL (the view hardcodes city/country/... to NULL).
-- Do NOT compute SAFE_DIVIDE(COUNTIF(type=2), COUNTIF(type=1)) as a "viewable rate": type-2
-- mixes CTV + display while type-1 is CTV-only, so it conflates channels and can exceed 1.0.
-- This view cannot yield a display viewability *rate* (measurable-display type-1 is dropped),
-- and CTV viewability is definitional (type-2 CTV count == type-1 count, i.e. 100%).
SELECT domain,
       COUNTIF(viewability_type_id = 1)                         AS ctv_measurable,   -- type-1 branch is CTV-only
       COUNTIF(viewability_type_id = 2 AND country IS NOT NULL) AS ctv_viewable,     -- == ctv_measurable (definitional)
       COUNTIF(viewability_type_id = 2 AND country IS NULL)     AS display_viewable  -- display viewable events (no denom here)
FROM `logdata.v_viewability_log_pub_metric`
WHERE time >= TIMESTAMP('2026-07-10') AND time < TIMESTAMP('2026-07-11')
GROUP BY domain
ORDER BY ctv_measurable DESC
LIMIT 100;

-- Distinct CTV impressions on a publisher (collapse the doubled rows)
SELECT COUNT(DISTINCT ad_served_id) AS ctv_impressions
FROM `logdata.v_viewability_log_pub_metric`
WHERE time >= TIMESTAMP('2026-07-10') AND time < TIMESTAMP('2026-07-11')
  AND viewability_type_id = 1;   -- type 1 == CTV-only branch
```
