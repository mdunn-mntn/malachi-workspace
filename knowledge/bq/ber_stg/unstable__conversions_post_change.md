# ber_stg.unstable__conversions_post_change

## Purpose
Non-canonical BER (backend-reporting) **staging intermediate** for budget-change impact analysis. Each row is a conversion attributed in the observation window **AFTER** a significant flight budget change, tagged with the change event (`change_id`) and its day offset within the window (`conversion_day`). Analysts compare this against the `_pre_change` sibling (identical schema, the window **before** the change) to measure how a budget change moved conversion volume/value.

- The change events are driven by `ber_stg.unstable__budget_changes`.
- This is **NOT a canonical conversion source** and does **not** hold all conversions — only those falling inside budget-change windows for "unstable" (budget-changed) advertisers (~464 advertisers / week). For authoritative conversion counts use `summarydata.conversions` or the offline pipeline's `ber_stg.offline__conversions_final`.
- Short history: physical data starts **2026-03-27** (~117 daily partitions) — no long lookback.

## Grain & keys
- **Grain:** one row per **attributed conversion event**, scoped to a post-budget-change observation window. A conversion can appear on multiple rows (attribution assists / competing attribution): over one week 117,805 rows carried only 79,122 distinct `order_id` (~1.4% NULL `order_id`). Do not treat `order_id` as a unique key.
- **Analysis unit:** `change_id` (the budget-change event) — globally unique, 1:1 with `(advertiser_id, change_time)`. Each row also carries `conversion_day` (1..14 observed) = day offset within the window.
- **Cluster keys:** `advertiser_id`, `change_id`. **Partition:** `time` (DAY, `require_partition_filter=true`).

## Column meanings (only the non-obvious ones)
Change / snapshot metadata (what makes this table a "change" snapshot):
- **change_id** — surrogate id of the budget-change event being analyzed. Globally unique, 1:1 with `(advertiser_id, change_time)`; a cluster key. NOT present in `unstable__budget_changes` (no shared surrogate — join that table on `advertiser_id + change_time`).
- **conversion_day** — INT day offset of the conversion within the post-change observation window (observed 1..14). Use with `change_id` to align pre vs post.
- **change_time / change_epoch** — when the budget change occurred. `change_epoch = UNIX_SECONDS(change_time)` → **SECONDS** (differs from the event epochs below). Can be months earlier than `time` (a conversion on 2026-07-19 may reference a change from 2026-05-13).
- **batch_epoch** — pipeline batch time in **SECONDS** (no matching TIMESTAMP column). **batch_source** — constant tag `"post_change"` for this table (the `_pre_change` sibling carries `"pre_change"`); identifies which snapshot side a row belongs to.

Timestamps / epochs (units differ per column — verified against their TIMESTAMP anchors):
- **time / epoch** — conversion record timestamp; `epoch = UNIX_MICROS(time)` → **microseconds**. `time` is the partition column.
- **event_time / event_epoch** — the conversion event time; `event_epoch = UNIX_MICROS(event_time)` → **microseconds**.
- **impression_time / impression_epoch** — attributed impression time; `impression_epoch = UNIX_MICROS(impression_time)` → **microseconds** (millisecond precision, trailing `000`).
- **elapsed_time** (INTERVAL) — `time − event_time` (record latency after the event).
- **impression_elapsed_time** (INTERVAL) — `time − impression_time` (impression-to-record lookback / attribution latency).
- **recency_elapsed_time** (INTERVAL) — another elapsed window (recency / last-touch reference); exact anchor not pinned.

Dimensions / flags:
- **channel_id** — `8` = CTV, `1` = display.
- **objective_id** — funnel objective: `1` = Prospecting, `4` = Retargeting, `6` = mid-funnel stage-3 (observed). Note the global gotcha: `objective_id` is unreliable for stage — join `campaigns.funnel_level` for canonical stage.
- **conversion_type** — advertiser-defined pixel event label, free text (`Purchase`, `Lead`, `Confirmation`, `Job Booked`, …). Sentinel `"-101"` dominates (~87%) = default/site-level conversion code.
- **attribution_model_type_id** — attribution model type (observed `1`–`4`). **is_pa** — post/probabilistic-attribution flag. **is_competing** — TRUE when attributed against a competing impression. **conversion_assist** — assist-attribution flag. **is_cross_device** — cross-device attribution.
- **order_amt / order_curr** — conversion order value (NUMERIC) and currency; `order_amt` can be NULL. (This table exposes `order_amt` directly — unlike canonical `ui_conversions` where `order_amt_usd` is NULL and `order_amt` is the usable field.)
- **ip vs impression_ip** — the conversion IP vs the attributed impression's IP. **from_verified_impression** — conversion tied to a verified impression.

## Joins & relationships
- **`ber_stg.unstable__budget_changes`** (the change driver) — join on `advertiser_id + change_time`. **Fan-out risk: ~4:1.** `budget_changes` grain is one row per **flight** per change; this table has **no flight_id**, so joining fans out (6,160 flight-change rows matched 1,510 conversion change-units in a 2-day sample). Pre-aggregate `budget_changes` to `(advertiser_id, change_time)` first, or accept the multiplicity. There is no shared `change_id`.
- **`ber_stg.unstable__conversions_pre_change`** (sibling) — identical schema, the pre-change window for the same events. Compare/UNION on `change_id + conversion_day` for pre-vs-post impact (batch_source distinguishes the two).
- **`advertisers`** (integrationprod dim) — `advertiser_id` → `advertisers` (filter `deleted=FALSE AND is_test=FALSE`); 1:1, no fan-out; use `company_name` for labels (`fpa_advertiser_verticals.advertiser_name` is unreliable/empty).
- **`campaigns`** — `campaign_id` → `campaigns` for `funnel_level` (authoritative stage); 1:1 per campaign_id.
- **Canonical conversions** — `summarydata.conversions` / `ber_stg.offline__conversions_final` for absolute totals; this snapshot is a filtered slice, not a source of truth.

## Gotchas
- **NON-CANONICAL.** Only holds conversions inside budget-change observation windows for budget-changed advertisers — do NOT use for absolute conversion totals or advertiser-wide rates.
- **`require_partition_filter = TRUE`** — every query MUST filter `time` or it errors.
- **`order_id` is NOT unique** (assist + competing rows); ~1.4% NULL `order_id`. De-dup with care.
- **Mixed epoch units in one row:** record/event/impression epochs are **microseconds**, but `change_epoch` and `batch_epoch` are **seconds**. Never apply a single `UNIX_*` conversion across all epoch columns.
- **`time` bounds the conversion date, not the change date.** `change_time` can be months before `time`; filtering `time` does not bound `change_time`.
- **Short history** — physical data begins 2026-03-27 (~117 daily partitions).
- **SQLMesh view** — query the clean name `ber_stg.unstable__conversions_post_change`; the physical hash `...__2857904261` changes on rebuild.

## Cost & partitioning notes
- **Partition `time` (DAY, require_partition_filter=true); cluster `advertiser_id, change_id`.** Always filter `time`; add `advertiser_id` to exploit cluster pruning.
- Labeled dry-run estimates (2026-07-20):
  - 3 narrow cols (`advertiser_id, order_amt, time`): **1 day = 0.43 MB** (454,336 B) vs **30 days = 16.4 MB** (17,168,064 B) → `time` filter prunes, ~linear in days.
  - `SELECT *` (all 58 cols), **1 day = 29.7 MB** (31,125,275 B) → ~68× the 3-col day. Select only needed columns; never `SELECT *`.
- Physical backing (`bq show` numBytes): **~2.45 GB** (2,452,320,321 B) across ~1.10M rows total.

## Example queries
```sql
-- Post-change conversions + value by day offset for one advertiser's change events
SELECT change_id, conversion_day,
       COUNT(*) AS conversions, SUM(order_amt) AS order_value
FROM `ber_stg.unstable__conversions_post_change`
WHERE time >= '2026-07-01' AND time < '2026-07-20'
  AND advertiser_id = <adv_id>
GROUP BY change_id, conversion_day
ORDER BY change_id, conversion_day
```
