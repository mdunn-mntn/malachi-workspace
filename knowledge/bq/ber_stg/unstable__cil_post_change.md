# ber_stg.unstable__cil_post_change

## Purpose
**Non-canonical BER (backend-reporting) staging / pipeline intermediate — do not treat as a fact source.** This view snapshots `logdata.cost_impression_log` won impressions that fall in the window **AFTER** an advertiser budget change, tagging each impression with the change event (`change_id`, `change_epoch`, `new_daily_budget`, `prior_daily_budget`, `pct_unstable`). It exists to measure the delivery impact of "unstable" (frequently/significantly changed) budgets — you diff it against the before-window mirror `ber_stg.unstable__cil_pre_change`. The change catalog it draws from is `ber_stg.unstable__budget_changes`. For real per-impression/spend facts go to the canonical **`logdata.cost_impression_log`**; for the change events go to **`ber_stg.unstable__budget_changes`**.

## Grain & keys
- **Grain:** one row per **(won CIL impression × budget-change event it is attributed to)**. NOT one row per impression — an impression served in a window that overlaps multiple change events appears once per `change_id`. Observed 2026-07-01: 14.39M rows vs 9.81M distinct `impression_id` (~1.47x fan-out).
- **Key(s) / join columns:** `impression_id` (CIL impression id) + `change_id` (the change event). `ad_served_id`, `ip`, `guid` are the inherited CIL identity keys. `change_epoch` / `advertiser_id` link to the change catalog.

## Column meanings (only the non-obvious ones)
**Change-attribution columns (this table's reason for existing):**
- `batch_source` — constant **`"post_change"`** across the whole view (verified: 1 distinct value on 2026-07-01). This is the tag that distinguishes it from the mirror `unstable__cil_pre_change` (`"pre_change"`); UNION the two on this column for a before/after diff.
- `change_id` — surrogate id of the budget-change event this impression is attributed to. Cluster key #2. 1:1 with a single `change_epoch` (verified: `COUNT(DISTINCT change_id)` = `COUNT(DISTINCT change_id×change_epoch)` = 1,282 on 2026-07-01). Finer than `change_epoch` (645 epochs same day) because different advertisers change budgets in the same hour.
- `change_epoch` — **SECONDS** (= `UNIX_SECONDS(change_time)`, verified: 1782882000 = `c_usec`). Hour-aligned in samples (1782882000 is an exact hour boundary) — changes are bucketed to the hour. `change_time` is the TIMESTAMP form of the same value.
- `new_daily_budget` / `prior_daily_budget` — NUMERIC dollars, daily budget after / before the change; constant within a `change_id`. (In the change catalog `unstable__budget_changes` the same columns are FLOAT64.)
- `pct_unstable` — NUMERIC fraction 0–1, the change's "instability" measure (e.g. 0.3568); constant within a `change_id`.
- `hash_pct` — FLOAT64 in [0,1], a **per-row** deterministic hash used for sampling/bucketing (varies row to row; not a rate).

**Epoch units differ per column — do not mix:**
- `epoch` — **MICROSECONDS** since Unix epoch of the impression's served time (= `UNIX_MICROS` at full precision; verified 1782905779538000). It carries sub-second precision that `time` loses (see below). This is the front-matter `time_unit`.
- `source_batch_epoch` — **SECONDS**; the source pipeline batch that produced the row (constant within a source batch).
- `batch_epoch` — **SECONDS**; per-row processing/ingest batch timestamp (varies per row).

**Inherited from `cost_impression_log` (same meanings as the canonical CIL):**
- `time` — partition column, DAY-partitioned, **UTC**. Observed **truncated to whole seconds** (`UNIX_MICROS(time)` ends in `000000`); for sub-second ordering use `epoch`.
- `ip` — the bid IP (CIL `ip` = `bid_ip` at 100%, per TI-650); `partner_ip` = exchange-reported IP.
- `unlinked` — BOOL; FALSE = linked to `impression_log` (`impression_id`/`ad_served_id` present, the normal won-impression case); TRUE = no impression_log match (`ad_served_id` NULL).
- `household_score` / `advertiser_household_score` — INT 0–10000, **−1/NULL = unscored** (same CIL semantics; scores also mirrored in `model_params` as `key=value`). `model_params` also carries `realtime_conquest_score=` (RTC genuine only at `=10000`).
- `device_type` — STRING in silver (`"CONNECTED_TV"`, `"PC"`, `"-1"`=unknown) — INT in bronze.
- `partner_ad_format` — `"VIDEO"` / `"BANNER"` / `"UNKNOWN"`.
- `media_cost` NUMERIC and `media_spend`/`data_spend`/`platform_spend` BIGNUMERIC = per-impression cost components (customer-centric; PSAs excluded upstream).
- `recency_elapsed_time` — INTERVAL type (limited BQ support in some contexts).
- `view_*` / `vast_*` — viewability + VAST quartile counts inherited from CIL's viewability enrichment.

## Joins & relationships
- **`ber_stg.unstable__budget_changes`** (the change catalog) — join on **`advertiser_id` + `change_epoch`**. Partner grain = campaign_group/flight × change (columns `parent_campaign_group_id`, `campaign_group_id`, `flight_id`) and it has **no `change_id`**, so it is finer than the advertiser-level change here → **N:1 fan-out** (multiple budget-changes rows per one impression's change). Both are staging views; use directionally. `new/prior_daily_budget` are FLOAT64 there vs NUMERIC here.
- **`ber_stg.unstable__cil_pre_change`** (before-window mirror) — near-identical schema (column order differs slightly), tagged `batch_source="pre_change"`, same `change_id` space. UNION the two for a before/after delivery diff on the same changes.
- **`logdata.cost_impression_log`** (canonical base) — every row is a CIL won impression re-emitted with change attribution. Link back on `impression_id` / `ad_served_id` / `ip`. **Fan-out warning:** because grain is impression × `change_id`, a raw join or count over-counts impressions ~1.47x/day — dedup on `impression_id` (or `ad_served_id`) for unique-impression metrics.

## Gotchas
- **Non-canonical staging.** For impression/spend/reach facts use `logdata.cost_impression_log`; for change events use `ber_stg.unstable__budget_changes`. This view is a change-impact intermediate only.
- **Grain ≠ one row per impression.** Same impression is duplicated once per `change_id` whose post-change window it overlaps (~1.47x on 2026-07-01). Dedup on `impression_id` for unique impressions.
- **Three epoch units in one row** (`epoch`=µs event time; `change_epoch`, `batch_epoch`, `source_batch_epoch` = seconds). Convert with the matching `UNIX_*` function; never compare across units.
- **`time` is truncated to whole seconds** — use `epoch` (µs) for ordering within a second.
- **Recent history only:** partitions run **2026-03-27 → present** (~113 daily partitions), NOT the multi-year floor of base CIL. No usable NULL/streaming partition (0 rows).
- **`batch_source` is always `"post_change"`** here — the before side lives in `unstable__cil_pre_change`.
- **UTC** (inherited CIL timezone) — convert to Arizona Time before matching MNTN UI / external reports.
- **PSA-excluded** (inherited CIL "customer-centric spend" behavior — PSAs absent, so spend won't match raw Beeswax/cache).
- SQLMesh VIEW → hashed physical `sqlmesh__ber_stg.ber_stg__unstable__cil_post_change__3518197138`; query the clean name `ber_stg.unstable__cil_post_change`.

## Cost & partitioning notes
- **The one filter to always apply:** `DATE(time) = ...` or `time BETWEEN ...`. Partition = `time` (DAY), confirmed empirically by dry-run diff (advertiser_id column only): full-table **6.95 GB** (7,468,408,544 B) vs one day **0.22 GB** (230,313,152 B) — ~32x prune. Same-column-set comparison.
- Clustered on **`advertiser_id`, `change_id`** — add an `advertiser_id` and/or `change_id` predicate to prune within a day.
- **Never `SELECT *`** — 57 wide columns including `model_params`, `user_agent`, `domain` strings; the dry-run figures above are for a single narrow column and understate a full-row scan by 10–50x.
- Physical backing (single table): ~933.6M rows, ~1.05 TB (1,048,468,977,845 B) storage.

## Example queries
```sql
-- Post-change delivery for one advertiser's changes on a day (deduped to unique impressions)
SELECT change_id, ANY_VALUE(new_daily_budget) AS new_budget, ANY_VALUE(prior_daily_budget) AS prior_budget,
       COUNT(DISTINCT impression_id) AS impressions, SUM(media_cost) AS media_cost
FROM `dw-main-silver.ber_stg.unstable__cil_post_change`
WHERE DATE(time) BETWEEN '2026-07-01' AND '2026-07-02'
  AND advertiser_id = 31357
GROUP BY change_id
ORDER BY impressions DESC
```
