# ber_stg.unstable__visits_post_change

## Purpose
Non-canonical BER (backend-reporting) **staging intermediate** — the *post-change* snapshot of the
visits-attribution stream, re-computed for **change-impact analysis**. Each budget/config change
(identified by `change_id`, sourced from the change-detection feed behind
`ber_stg.unstable__budget_changes`) gets its attributable visits recomputed as-of *after* the change;
this table holds that "after" version. Pair it 1:1 with **`ber_stg.unstable__visits_pre_change`**
(identical schema minus the `change_*`/`batch_*` tag columns) to measure how a change moved attributed
visits. Sibling snapshots exist for the CIL and conversions streams
(`unstable__cil_*_change`, `unstable__conversions_*_change`).

**Do NOT use this for canonical visit reporting.** The canonical attributed-visit ledger is the
`summarydata` visits / `logdata.ui_visits` family (and `logdata.cost_impression_log` for impressions).
Reach for this table *only* when analyzing the delta a specific change caused.

No prose oracle existed in `data_catalog.md`/`data_knowledge.md` — this doc was enriched from the LIVE
physical table + empirical probes (see Changelog).

## Grain & keys
- **Grain:** one row per **attributed visit × `change_id` × attribution stream/model**. Empirically NOT
  unique even on `(guid, impression_id, change_id)` — on 2026-07-05, 480,170 rows vs 472,562 distinct
  `(guid, impression_id, change_id)`; `source_type`/`attribution_model_type_id` split a single visit
  across the display and CTV-last-touch streams (competing vs non-competing).
- **Analysis key:** `(advertiser_id, change_id)` — the two cluster columns. `change_id` is the analysis
  unit (2,282 distinct changes / 545 advertisers on 2026-07-05).
- **Partition column:** `time` (visit timestamp), DAY, `require_partition_filter = TRUE`.

## Column meanings (only the non-obvious ones)
Epoch columns carry **different units per column** (all verified by anchoring to the paired TIMESTAMP):
- `epoch` = **UNIX_MICROS(`time`)** — microseconds since epoch (visit time). It keeps the true sub-second
  precision; `time` (the TIMESTAMP) is stored truncated to whole seconds, so `epoch` is the higher-resolution
  source. Anchor: `epoch = UNIX_MICROS(time)` at second granularity, plus micros.
- `impression_epoch` = **UNIX_MICROS(`impression_time`)** — microseconds (time of the credited impression).
- `change_epoch` = **UNIX_SECONDS(`change_time`)** — **seconds** (not micros). `change_time`/`change_epoch`/
  `change_id` are a fixed 1:1 triple identifying the change event; the change is dated to the change moment
  and typically predates the visit day by weeks.
- `batch_epoch` — observed **NULL** in sampled partitions; `batch_source` is a constant tag (`'post_change'`
  here; the pre-change table tags `'pre_change'`).
- `source_type` — attribution **stream label**, NOT constant. Domain (2026-07-05): `'visits'` (display /
  standard) and `'last_tv_touch_visits'` (CTV last-touch). Maps to `attribution_model_type_id`:
  1,3 → `visits`; 2,4 → `last_tv_touch_visits`.
- `attribution_model_type_id` ∈ {1,2,3,4} — encodes stream × competing: {1,2} co-occur with
  `is_competing = false`, {3,4} with `is_competing = true`. `attribution_model_id` is a finer model id.
- `is_competing` — visit also attributable to another advertiser (competing/multi-touch), same semantics as
  the canonical visits table.
- `is_pa` / `pa_model_id` — probabilistic-attribution flag; `pa_model_id` is populated (non-zero) **only**
  when `is_pa = true`, else 0.
- `visits_assist` — assisted-visit flag; observed **NULL** for the `last_tv_touch_visits` stream (type 2/4),
  boolean for the standard `visits` stream.
- `elapsed_time` (INTERVAL) = `time − impression_time`, the attribution lag (impression → visit). Ranges
  `0:0:0` up to ~720h (30-day window), occasionally ~1191h (~49d). `recency_elapsed_time` (INTERVAL) is a
  related sub-second-precision recency lag, sometimes NULL.
- `visit_day` (FLOAT64) ≈ `elapsed_time` expressed in **whole days** (attribution-window day bucket); e.g.
  elapsed ~314–334h → `visit_day = 14.0`.
- `ip_raw` / `ip` / `impression_ip` — three IP columns: `ip_raw` = raw as-seen visit IP, `ip` = resolved/
  normalized visit IP, `impression_ip` = IP of the credited impression. (No IP→IP bridging in BQ.)
- `ad_served_id` = the impression/ad-serve this visit is attributed to (last touch); `first_touch_ad_served_id`
  = first impression in the path.
- `channel_id` — 8 = CTV, 1 = display (standard MNTN convention); consistent with the CTV `last_tv_touch`
  stream. `is_new` = client-JS "new visitor" pixel flag (same caveat as `ui_visits.is_new`).

## Joins & relationships
- **→ `ber_stg.unstable__budget_changes`** on `(advertiser_id, change_epoch)` (equivalently `change_time`):
  **100% matched** in test (2026-07-05: 1,670/1,670 distinct visit change-keys found in budget_changes).
  This confirms `change_id`/`change_epoch` here correspond to detected budget/flight-change events.
  Partner grain ≈ one row per `(advertiser_id, campaign_group/flight, change event)`, so visits→budget_changes
  is **N:1**, BUT budget_changes can hold **>1 row per `(advertiser_id, change_epoch)`** (multiple campaign
  groups/flights changed at the same instant) → **fan-out risk**: dedup or join on the campaign-group grain.
- **↔ `ber_stg.unstable__visits_pre_change`**: identical column set minus `change_id/change_epoch/change_time/
  batch_*` and the stream tags. Diff pre vs post per `(advertiser_id, change_id)` to get the change delta.
- **advertiser_id / campaign_id / group_id / creative_id** → `bronze.integrationprod` dims
  (`advertisers`, `campaigns`, `campaign_groups`, `creatives`), each **N:1** (filter `deleted=FALSE AND
  is_test=FALSE`). Standard fan-out is negligible (dim side is 1 row per id).

## Gotchas
- **`require_partition_filter = TRUE` on `time`** — a query with no `time`/`DATE(time)` predicate **errors**
  ("Cannot query over table … without a filter over column(s) 'time'"), verified via dry-run.
- **`time` is truncated to whole seconds**; use `epoch` (microseconds) when you need sub-second resolution.
- **Mixed epoch units** — `epoch`,`impression_epoch` = microseconds; `change_epoch` = **seconds**. Don't
  apply the same UNIX_* conversion across them.
- **`source_type` is not constant** — a visit can appear under both `visits` and `last_tv_touch_visits`;
  a raw `COUNT(*)` overcounts visits. Dedup by `(guid, impression_id)` within a single `source_type`.
- **Change events predate the visit day by weeks** — filtering `time` (the visit day) still pulls changes
  from prior weeks via the up-to-30-day (occasionally ~49-day) attribution window.
- **NULL `time` partition exists** — some rows have NULL `time` and land in the `__NULL__` partition
  (max non-null `partition_id` reported as NULL in INFORMATION_SCHEMA.PARTITIONS).
- **Rolling staging window** — physical partitions start **2026-03-27** (~117 partitions), not full history.
  Early partitions are sparse (39 rows across 2026-03-27→29) vs ~400–480K/day recently. This is a
  regenerated staging intermediate, not a durable ledger — do not treat counts as canonical.

## Cost & partitioning notes
- **The one filter to always apply:** `DATE(time) = '<day>'` (or a `time` range). Partition = `time`, DAY,
  `require_partition_filter = TRUE`. Cluster = `(advertiser_id, change_id)` — add `advertiser_id` and/or
  `change_id` predicates to prune within a day.
- **Dry-run cost figures** (all for the single day 2026-07-05; labeled by exact column set):
  - `SELECT *` (all 48 columns): **232,047,982 bytes ≈ 0.216 GiB**.
  - 3 narrow columns `(advertiser_id, change_id, time)`: **11,524,080 bytes ≈ 0.011 GiB** — `SELECT *` is
    ~**20×** the 3-column scan, so **prune columns**.
  - No `time` filter: **ERROR** (require-partition-filter) — cannot estimate/run.
- **View is a straight passthrough** (`SELECT * FROM` the SQLMesh physical, no UNION). `approx_logical_bytes`
  = physical `numBytes` = **10,921,496,518 bytes ≈ 10.17 GiB** across **22,854,495 rows / 117 partitions**
  (bq show on `sqlmesh__ber_stg.ber_stg__unstable__visits_post_change__1748979808`).

## Example queries
```sql
-- change-impact delta: attributed visits per change (partition + cluster pruned)
SELECT change_id, source_type, attribution_model_type_id, COUNT(*) AS n_rows
FROM `dw-main-silver.ber_stg.unstable__visits_post_change`
WHERE DATE(time) = '2026-07-05'          -- required partition filter on `time`
  AND advertiser_id = <advertiser_id>    -- cluster prune
GROUP BY 1, 2, 3
ORDER BY n_rows DESC;
```
