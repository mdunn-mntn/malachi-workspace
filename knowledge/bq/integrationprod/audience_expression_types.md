# integrationprod.audience_expression_types

## Purpose
Tiny reference/seed dimension that decodes the `expression_type_id` foreign key carried on every
audience-targeting row. It maps the surrogate id to a short name that identifies *which form* an
audience expression is stored in:

- **1 = opm** — the raw **source representation** of an audience expression, as authored/stored per
  advertiser. This is the "unwrapped" form; it gets wrapped into the type-2 (tpa) form at bidder
  evaluation. In `audience_segments` and `audience_standalone_segments` **every** live row is type 1.
- **2 = tpa** — the **compiled/evaluated Third-Party-Audience targeting expression** the bidder reads.
  This is the form that carries the 4-AND-clause targeting JSON (selects · categories DS19/CRM/lookbacks
  · geos · holdout) and the holdout hash `MD5('{advertiser_id}:{ip}') mod 1000` (buckets 0-99 = 10%
  holdout). It dominates the per-campaign / per-audience tables. **The standard "actively targeted"
  filter is `expression_type_id = 2 AND is_targeted = TRUE`** (verified TI-837).
- **3 = sga** — a third expression form that is **essentially unused**: only 2 live rows exist
  (both in `audience_audiences`), 0 in every other referencing table. Its acronym expansion is not
  documented anywhere in the prose oracle; treat it as a rare/legacy form, not a form to filter on.

Reach for this table only to attach the human-readable name to a `expression_type_id` — in practice
analysts hard-code the map because it has been static since seed.

## Grain & keys
- **Grain:** one row per audience-expression type. Exactly 3 rows (ids 1, 2, 3).
- **Primary key / join column:** `expression_type_id` (surrogate INT, also the sole cluster key).
- **Natural key:** `name` (lowercase code: `opm` / `tpa` / `sga`).

## Column meanings (only the non-obvious ones)
- **expression_type_id** — surrogate id; the FK target for all audience tables. Live domain = {1,2,3}.
  Clustered, but clustering is cosmetic on a 3-row table.
- **name** — lowercase type code: `opm`, `tpa`, `sga`. Match **case-insensitively** — prose/UI often
  uppercases (OPM/TPA/SGA).
- **create_time** — row seed time. All 3 rows = `2024-07-09 20:47:10` (single seed load). This is the
  business insert time.
- **update_time** — **NULL for all 3 rows** (the table has never been mutated since seed). Do not use
  it for freshness — it will always be NULL.
- **datastream_metadata.source_timestamp** — INT64 **milliseconds** CDC-capture epoch, NOT business
  time. Anchor: `TIMESTAMP_MILLIS(source_timestamp)` = `2025-12-19 01:08:53` for all 3 rows (a
  full-table CDC re-snapshot; `TIMESTAMP_MICROS` gives 1970 = wrong). `datastream_metadata.uuid` is the
  Datastream event id.

## Joins & relationships
This is the **"1" side** of a 1:N lookup — 3 rows fanning out to many audience rows. Joining a partner
table onto `audience_expression_types` on `expression_type_id` is a **safe name-enrichment**: it adds
one string column and **never fans out** the partner (each partner row matches exactly one dim row).

`expression_type_id` FK appears on (partner grain → this dim = N:1):
- **audience_segments** (per-advertiser source segments; all type 1 = opm) — N:1.
- **audience_audience_segments** (per-campaign segments; type 2 dominant 322.9K, type 1 123.1K) — N:1.
  This is the table catalog prose also calls `audience_segment_campaigns` (silver `audience.` view).
- **audience_audiences** (per-audience; type 2 = 64.4K, type 1 = 95, type 3 = 2) — N:1.
- **audience_standalone_segments** (all type 1) — N:1.
- **audience_segmentation_templates** / **audience_segmentation_defaults** (handful of rows) — N:1.
- **archives_audiences_archives**, **archives_audience_segment_archives**, **audience_segment_archives**
  (versioned history snapshots; `version` is NON-monotonic — order by `create_time`/`update_time`) — N:1.

There is no reverse fan-out concern: the dim cannot multiply a partner. The only "risk" is forgetting
the `expression_type_id = 2 AND is_targeted = TRUE` filter when reading live targeting from the partner
tables (types 1/3 are source/legacy forms, not the served expression).

## Gotchas
- **No `deleted` / `is_test` columns** — the dataset-wide `deleted=FALSE AND is_test=FALSE` live filter
  does NOT apply here (and isn't needed; all 3 rows are canonical seed rows).
- **`update_time` is always NULL** — never mutated since the 2024-07-09 seed. Use `create_time` or
  `datastream_metadata.source_timestamp` if you need a timestamp.
- **`name` is lowercase**; downstream code/UI uppercases it. Compare case-insensitively.
- **Two different enums share the "OPM" label — do not conflate.** `expression_type_id=1` ("opm") is an
  *expression-form* enum; it is unrelated to `data_source_id=2` ("MNTN First Party / OPM") which is a
  *data-source* enum. Likewise the type-2 "tpa" expression form is related-to but distinct-from the
  broader `bronze.tpa` third-party-audience upload dataset.
- **Type 1 (opm) is a source rep, not the served form.** For live targeting always read type 2 (tpa).
  Type 3 (sga) is effectively dead (2 rows) — don't build logic around it.
- **`source_timestamp` is ms CDC-capture, not business time** (all 3 rows re-snapshotted 2025-12-19).

## Example queries
```sql
-- Decode expression type on live per-campaign targeting rows
SELECT aet.name AS expression_type, COUNT(*) AS n
FROM `dw-main-bronze.integrationprod.audience_audience_segments` aas
JOIN `dw-main-bronze.integrationprod.audience_expression_types` aet
  ON aas.expression_type_id = aet.expression_type_id
WHERE aas.is_targeted = TRUE          -- served form only
GROUP BY 1 ORDER BY 2 DESC;

-- Full dim dump (201 bytes)
SELECT expression_type_id, name FROM `dw-main-bronze.integrationprod.audience_expression_types`
ORDER BY expression_type_id;
```
