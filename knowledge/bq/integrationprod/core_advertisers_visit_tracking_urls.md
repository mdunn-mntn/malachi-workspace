# integrationprod.core_advertisers_visit_tracking_urls

## Purpose
Stores the third-party **visit** tracking URLs (pixels/postbacks) configured for an advertiser — fired
to log/verify a site visit with an external partner. Postgres CDC dim landed via Datastream. Sibling of
`core_advertisers_impression_tracking_urls` (same shape, minus a `server_side` flag), for the visit
event rather than the impression event. Exposed as the `silver.core.advertisers_visit_tracking_urls`
view (`SELECT * FROM` this table, verified 2026-07-29).

## Grain & keys
- **Grain:** one row per visit tracking URL. 382 rows, 350 distinct advertisers (an advertiser can have
  multiple URLs; `visit_tracking_url_id` unique, verified 2026-07-29).
- **Primary key:** `visit_tracking_url_id` (sole cluster key).
- **Foreign keys:** `advertiser_id` → `advertisers.advertiser_id`; `user_id` → the internal user who
  added it.

## Column meanings (only the non-obvious ones)
- **`visit_tracking_url`** — the tracking endpoint fired on a visit; typically a partner pixel/postback.
- **`is_post`** — TRUE = HTTP POST (uses `request_body`); FALSE = GET. Only 2 of 382 rows are POST.
- **`request_body`** — payload template for POST-style trackers (only relevant when `is_post` is TRUE).
- **Note:** unlike the impression sibling, this table has **no `server_side` column.**
- **`create_time`** — CDC write timestamp in source Postgres.
- **`datastream_metadata`** — Datastream CDC lineage RECORD; not business data.

## Joins & relationships
- **`advertiser_id` → `advertisers.advertiser_id`** — N:1 into this table. Joining advertisers to this
  table **fans out** (multiple URLs per advertiser). Aggregate or filter to keep grain.
- `silver.core.advertisers_visit_tracking_urls` is a `SELECT *` view over this table.
- Sibling table: `core_advertisers_impression_tracking_urls` (impression tracking; adds `server_side`).

## Gotchas
- **Fan-out on advertiser joins** — one advertiser can have many tracking URLs.
- **`request_body` only matters when `is_post` = TRUE** (only 2 POST rows currently).
- **No `deleted`/`is_test` columns** — standard bronze soft-delete filter does not apply.

## Cost & partitioning notes
- **Non-partitioned dim: 382 rows / ~56 KB.** No partition, no TTL, no `require_partition_filter`.
  Clustered on `visit_tracking_url_id`. Full `SELECT *` bills the tier-1 10 MB minimum.

## Example queries
```sql
-- Visit trackers configured for an advertiser
SELECT visit_tracking_url_id, visit_tracking_url, is_post
FROM `dw-main-bronze.integrationprod.core_advertisers_visit_tracking_urls`
WHERE advertiser_id = @advertiser_id;
```
