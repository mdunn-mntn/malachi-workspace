# integrationprod.core_hotels

## Purpose
Datastream-CDC mirror of MNTN's **hotel** dimension. A "hotel" is MNTN's *hoteling* grouping entity: it
ties multiple advertiser accounts that belong to the same brand / share a domain (franchise brands such
as Orange Theory) to a single named root, so they can be treated as one advertising entity. Reach for
this table to attach a human name to a `hotel_id`, or to enumerate the hotels. The advertiser↔hotel
membership itself is NOT in this table — it lives in the bridge `silver.core.advertisers_x_hotels`. The
related domain-based hoteling map used by the autopilot regeneration flow is `fpa.mm_domain_map`
(domain → root advertiser). `silver.core.hotels` is a plain `SELECT *` view over this base table.

## Grain & keys
- **Grain:** one row per hotel. 36,219 rows; `hotel_id` runs 2–37502 (not contiguous — starts at 2).
- **Primary key:** `hotel_id` (surrogate INT, also the sole cluster key).
- **Self-FK:** `parent_hotel_id` → `hotel_id` (same table) for a hotel hierarchy — **currently 100% NULL**
  (the hierarchy feature is unused; every hotel is a flat root).
- **Bridge to advertisers:** no advertiser column here; join via `silver.core.advertisers_x_hotels`
  (`advertiser_id` ↔ `hotel_id`).

## Column meanings (only the non-obvious ones)
- **hotel_id** — surrogate PK; clustered (cosmetic on a 36K-row dim).
- **hotel_type_id** — hotel category code. **Single-valued: every row is `1`** in the live table. There is
  no `core_hotel_types` lookup in bronze; the type meaning is not decodable from source today.
- **name** — human label; follows the `<Brand> Hotel` / `<Brand> CTV Hotel` convention, e.g.
  "Adventist Health - North Pinellas CTV Hotel", "DonJoy Performance Hotel", "Olivela Hotel".
- **parent_hotel_id** — self-referential FK for a hotel hierarchy; **100% NULL today** (unused).
- **user_id** — the app user who created the hotel; NULL on the original 2020 seed rows.
- **create_time / update_time** — business TIMESTAMP (UTC) from source Postgres. Large seed cohort shares
  `create_time = 2020-08-05 23:36:22`; `update_time` is NULL on rows never edited.
- **datastream_metadata.source_timestamp** — INT64 **milliseconds** CDC-capture epoch, NOT business time.
  Anchor with `TIMESTAMP_MILLIS(source_timestamp)` (MICROS → 1970 = wrong).

## Joins & relationships
- **`silver.core.advertisers_x_hotels`** (bridge, M:N): `hotel_id` ↔ `advertiser_id`. This is how a hotel
  is tied to its member advertiser accounts. One hotel can hold many advertisers → fan-out on that side.
- **`silver.core.hotels`** is a VIEW `SELECT * FROM core_hotels` — either name resolves to identical rows.
- Conceptually related (not a key join): `fpa.mm_domain_map` — domain→root-advertiser hoteling used by
  the autopilot profile regeneration flow.

## Gotchas
- **`hotel_type_id` is single-valued (`1`)** and has no lookup dim — do not build logic around type codes.
- **`parent_hotel_id` is 100% NULL** — the hierarchy is unused; treat the table as flat.
- **No `deleted` / `is_test` columns** — the dataset-wide `deleted=FALSE AND is_test=FALSE` hygiene
  filter does not apply and is not needed here.
- **`update_time` is frequently NULL** (row never edited since seed) — do not use it as a recency signal.
- **`source_timestamp` is ms CDC-capture, not business time** — use `create_time` for hotel age.
- **No advertiser column** — this dim alone cannot answer "which advertisers are in this hotel"; join the
  `advertisers_x_hotels` bridge.

## Cost & partitioning notes
- **BASE TABLE, physical `self`**, no partition, cluster=[hotel_id], no TTL. `bq show`: numRows=36,219,
  numBytes=3,788,767 (~3.6 MiB). `require_partition_filter: false` — nothing to prune.
- `SELECT *` scans the whole ~3.6 MiB (billed at the 10 MB minimum). Safe to read freely; project
  `hotel_id, name` when you only need the label.

## Example queries
```sql
-- Full hotel dim (whole table, ~3.6 MiB)
SELECT hotel_id, name, hotel_type_id, create_time
FROM `dw-main-bronze.integrationprod.core_hotels`
ORDER BY hotel_id;

-- Hotel name for the advertisers in a hotel (via the bridge view)
SELECT h.hotel_id, h.name, x.advertiser_id
FROM `dw-main-bronze.integrationprod.core_hotels` h
JOIN `dw-main-silver.core.advertisers_x_hotels` x ON x.hotel_id = h.hotel_id
WHERE h.hotel_id = 6;
```
