# integrationprod.core_campaign_statuses

## Purpose
Static reference enum that maps `campaign_status_id` → human label (`name`) for a campaign's lifecycle
status. Reach for it to decode `campaigns.campaign_status_id` (and `public_campaigns.campaign_status_id`)
into a readable status like Live / Paused / Deleted. **7 rows, effectively constant** (last real content
add was id 9 "Legacy Archived" on 2020-06-29). Exposed as the `silver.core.campaign_statuses` view
(a plain `SELECT * FROM this table`).

**To find currently-delivering campaigns, filter `campaign_status_id = 3` ("Live")** — do NOT infer
"live" from `deleted=FALSE` alone (paused 4/5 and inactive 7 rows are also non-deleted), and note that
Deleted (8) and Legacy Archived (9) both slip past the `deleted` BOOLEAN (see Gotchas).

## Grain & keys
- **Grain:** one row per campaign lifecycle status. Static enum, 7 rows (verified 2026-07-29).
- **Primary key:** `campaign_status_id` (INT). Unique, no NULLs. Also the sole cluster key.
- **Join column:** `campaign_status_id` — FK target for `campaigns.campaign_status_id` and
  `public_campaigns.campaign_status_id`. This table is always the **1-side** of any join.

## Column meanings (only the non-obvious ones)
- **`campaign_status_id`** — the enum code, PK, and cluster key. Live domain (verified full dump
  `SELECT * ... ORDER BY campaign_status_id`, 2026-07-29):

  | campaign_status_id | name | delivering? | meaning |
  |---|---|---|---|
  | 1 | Ready | no | set up but not started |
  | 3 | **Live** | **yes** | actively delivering — the only status that delivers materially |
  | 4 | Pause By Advertisers | no | paused by the advertiser/agency |
  | 5 | Pause By MNTN | no | paused by MNTN ops |
  | 7 | Inactive | no | ended / off |
  | 8 | Deleted | no | soft-deleted — **NOT caught by the `deleted` flag** (see Gotchas) |
  | 9 | Legacy Archived | no | archived legacy campaign — **also NOT caught by `deleted`** |

  **ids 2 and 6 do not exist** — the enum is sparse (1,3,4,5,7,8,9). Never assume a contiguous range.
- **`name`** — the clean, authoritative status label. Unique per id here.
- **`created_at`** — TIMESTAMP the enum ROW was inserted in the source Postgres (dim-management metadata),
  **not** any campaign's status-change time. ids 1–8 all seeded 2018-04-17; id 9 added 2020-06-29.
- **`datastream_metadata`** — Datastream CDC lineage RECORD (`uuid`, `source_timestamp`) stamped by the
  bronze CDC pipeline. Not business data; ignore for decode.

## Joins & relationships
- **`campaigns.campaign_status_id` → `core_campaign_statuses.campaign_status_id`** — **N:1**
  (`campaigns` is the many-side; this table is the one-side). Used as a decode lookup it **cannot fan
  out** the fact/dim it joins to (1 row per id). Same for `public_campaigns.campaign_status_id`.
- **`silver.core.campaign_statuses`** is a VIEW = `SELECT * FROM dw-main-bronze.integrationprod.core_campaign_statuses`
  (verified 2026-07-29). Content-identical; use whichever project you're already in.
- Consumed as a filter, not usually a join, in delivery/ranking work: the rankability gate uses
  `campaigns.campaign_status_id IN (1,3)`, and "currently-delivering" = `campaign_status_id = 3`.

## Gotchas
- **`campaign_status_id` 8 ("Deleted") and 9 ("Legacy Archived") are NOT caught by the `deleted`
  BOOLEAN** on `campaigns` — `deleted=FALSE` still returns them. To fully exclude dead campaigns add
  `campaign_status_id NOT IN (8,9)`. This is the single most important gotcha for this enum.
- **Only status 3 "Live" delivers materially** (13,906 of ~16K delivered-45d campaigns, AUDI-1083).
  Paused (4/5), Ready (1), and Inactive (7) rows exist but do not serve impressions.
- **`created_at` is dim-seed metadata, not a status-change timestamp** — do not use it for campaign
  lifecycle timing. A campaign's status history is not in this table (this is just the label lookup).
- **Sparse ids** (no 2, no 6) — do not generate the range; decode on the literal id.
- **Standard soft-delete dim filter does not apply to THIS table.** It has no `deleted`/`is_test`
  columns of its own — read all 7 rows. (The `deleted=FALSE AND is_test=FALSE` convention applies to
  the *campaigns* table you join to, not to this enum.)

## Cost & partitioning notes
- **Non-partitioned static dim: 7 rows / ~520 bytes backing storage.** No partition, no TTL, no
  `require_partition_filter`. Clustered on `campaign_status_id`, but clustering is a no-op at this size.
- Full `SELECT *` bills the tier-1 10 MB minimum (0 real bytes scanned). Cost is negligible —
  broadcast-join it freely against any fact/dim; there is nothing to prune.
- Prefer selecting `campaign_status_id, name` (skip `created_at`/`datastream_metadata`).

## Example queries
```sql
-- Decode campaign statuses (N:1 lookup; this table never fans out)
SELECT c.campaign_id, c.campaign_status_id, s.name AS status
FROM `dw-main-bronze.integrationprod.campaigns` c
LEFT JOIN `dw-main-bronze.integrationprod.core_campaign_statuses` s USING (campaign_status_id);

-- Currently-delivering campaigns only
SELECT campaign_id FROM `dw-main-bronze.integrationprod.campaigns`
WHERE campaign_status_id = 3;

-- Exclude dead campaigns (deleted flag misses 8/9)
SELECT campaign_id FROM `dw-main-bronze.integrationprod.campaigns`
WHERE deleted = FALSE AND campaign_status_id NOT IN (8, 9);
```
