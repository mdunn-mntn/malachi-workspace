# integrationprod.core_partners

## Purpose
Reference dimension for the advertising/measurement partners MNTN transacts with — DSPs, SSPs/exchanges,
and mobile-attribution vendors. Reach for it to decode a `partner_id` (used in `spend_log`, bidder tables,
and `private_marketplace_deals.partner_id`) into a partner name and its category. **~79 rows, grows only
when a new exchange/partner is onboarded.** Exposed as the `silver.core.partners` view.

## Grain & keys
- **Grain:** one row per partner. 79 rows (verified 2026-07-29; `partner_id` runs contiguous 1..79).
- **Primary key:** `partner_id` (INT). Unique, no NULLs. Also the sole cluster key.
- **Foreign key:** `partner_type_id` → `core_partner_types.partner_type_id` (N:1).
- **Join column (as 1-side):** `partner_id` — FK target for `spend_log`, bidder tables, and
  `private_marketplace_deals.partner_id`.

## Column meanings (only the non-obvious ones)
- **`partner_id`** — the code, PK, and cluster key (contiguous 1..79). Notable ids: `2` = Trade Desk,
  `8` = Beeswax, `12` = Magnite, `61` = Pubmatic, `56` = OpenX, `79` = MNTN Bidder.
- **`partner_type_id`** — category FK → `core_partner_types`: 1 = DSP, 2 = SSP, 3 = Mobile Attribution.
  Current split: 8 DSP / 66 SSP / 5 Mobile Attribution (2026-07-29).
- **`name`** — clean partner label (authoritative for decode).
- **`description`** — free-text; often empty. Do not key logic on it.
- **`created_at`** — TIMESTAMP the partner ROW was inserted in source Postgres (onboarding metadata), not
  a transaction time. DSP rows seeded 2018–2020; SSP rows 2021–2025; mobile-attribution 2020–2021.
- **`datastream_metadata`** — Datastream CDC lineage RECORD; not business data.

## Joins & relationships
- **`core_partners.partner_type_id` → `core_partner_types.partner_type_id`** — **N:1** decode of category.
- **As the 1-side:** `spend_log.partner_id`, bidder-table `partner_id`, and
  `private_marketplace_deals.partner_id` all reference `core_partners.partner_id` (N:1); joining this dim
  in as a lookup cannot fan out the fact.
- **`silver.core.partners`** is a VIEW over this table.

## Gotchas
- **No soft-delete columns.** Only `partner_id, name, description, created_at, partner_type_id,
  datastream_metadata` — no `deleted`/`is_test`. Standard dim filter does not apply; read all rows.
- **`created_at` is onboarding metadata, not activity** — a partner may have a row but no recent spend.
- Small, slowly-changing dim — no partitions, no timezone traps.

## Cost & partitioning notes
- **Non-partitioned reference dim: ~79 rows / ~7.3 KB.** No partition, no TTL, no `require_partition_filter`.
  Clustered on `partner_id` (a no-op at this size).
- Full `SELECT *` bills only the tier-1 10 MB minimum. Broadcast-join freely.
- Prefer selecting `partner_id, name, partner_type_id` (skip `description`/CDC RECORD).

## Example queries
```sql
-- Decode partners with category (both lookups are N:1, never fan out)
SELECT p.partner_id, p.name AS partner, t.name AS partner_type
FROM `dw-main-bronze.integrationprod.core_partners` p
LEFT JOIN `dw-main-bronze.integrationprod.core_partner_types` t USING (partner_type_id)
ORDER BY p.partner_type_id, p.partner_id;
```
