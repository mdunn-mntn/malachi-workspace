# integrationprod.advertiser_frequency_caps

## Purpose
The advertiser-scoped frequency-cap config table: it would hold, per advertiser, a `(cap, window)` rule
limiting how many impressions a household/IP receives in a rolling window. It is a Postgres BASE table
replicated via Datastream CDC into `dw-main-bronze.integrationprod`. **In production it is EMPTY (0 rows,
0 bytes)** — advertiser-scoped frequency capping is a capability that exists in the schema but is **not
used**. The real, populated fcap config lives one and two levels down at **campaign_group** and **DSO**
scope (`integrationprod.campaign_group_frequency_caps`, `integrationprod.dso_frequency_caps`), which sync
to the bidder cache and are enforced pre-bid in `do_fcap` (SteelHouse/rtb-campaign-service) via Redis
counters keyed on IP. Reach for this table only to confirm that no advertiser-rollup cap exists — the
"no advertiser-level cap / cross-campaign leakage" behavior is a genuine gap, not a mis-set knob (AUDI-1173).

## Grain & keys
- **Grain:** one row per advertiser frequency-cap rule — expected `advertiser_id` × a `(impressions, duration_seconds)` cap pair, mirroring the campaign_group/DSO cap tables. **Cannot be verified empirically: the table is EMPTY (0 rows).**
- **Primary/natural key:** unverifiable while empty; presumed `advertiser_id` (+ `duration_seconds` if multiple caps per advertiser are allowed, as in the campaign_group table).
- **Foreign keys / join columns:** `advertiser_id` → `integrationprod.advertisers.advertiser_id` (N:1); `user_id` → `integrationprod.users` (the admin who created/last-set the cap).

## Column meanings (only the non-obvious ones)
- **`impressions`** (INT) — the cap value: the maximum number of impressions allowed within the window. This is the `cap` half of the `(cap, duration_secs)` pair used across the fcap system.
- **`duration_seconds`** (INT) — the rolling window length in **seconds** (the `duration_secs` half of the pair). E.g. a 14-day cap = 1,209,600. Enforcement elsewhere counts impressions per IP over this window.
- **`advertiser_id`** (INT) — the advertiser this cap would apply to; join to `advertisers` for the label. This is the advertiser *rollup* scope that is currently unpopulated (caps only exist at campaign_group/DSO).
- **`user_id`** (INT) — the admin/operator user who created or last modified the cap row (audit FK → `users`), not an end-consumer/household id.
- **`create_time` / `update_time`** (TIMESTAMP) — Postgres CDC audit timestamps. As with other integrationprod dims, `update_time` reflects the Datastream backfill floor for rows untouched since CDC onset; use `create_time` for true row age. (Moot while the table is empty.)

## Joins & relationships
- `advertiser_id` → `advertisers` is an **N:1 lookup** (many cap rules per advertiser at most; one advertiser row).
- Sibling cap tables at finer scope carry the real config: `campaign_group_frequency_caps` (keyed on campaign_group) and `dso_frequency_caps` (keyed on DSO). The fcap system's `object_type` enum is `{campaign, campaign_group}` — advertiser is **not** an enforced scope, consistent with this table being empty.
- No fan-out risk in practice today: joining anything to this table yields **zero rows** (empty). Any query joining it will silently drop rows unless done as a LEFT JOIN.

## Gotchas
- **The table is EMPTY (0 rows) — verified 2026-07-29.** Not stale metadata: `COUNT(*) = 0`, `COUNT(DISTINCT advertiser_id) = 0`, `bq show` reports `numRows: 0 / numBytes: 0`, and a `LIMIT 5` returns nothing. Do not assume advertiser-level caps exist.
- **INNER-joining this table zeroes your result set.** Because it is empty, an INNER JOIN removes all rows. Use LEFT JOIN and expect NULLs, or better, do not depend on it for cap logic.
- **Advertiser-scoped capping is a real capability GAP, not a config oversight.** Per AUDI-1173, there is no advertiser rollup cap in prod; cross-campaign impression "leakage" at the advertiser level is expected. Cap *arms* / per-household caps require new bidder code (`CampaignModel` has no per-household cap field) — they cannot be enabled by populating this table.
- **Lives in bronze, not silver.** Query as `dw-main-bronze.integrationprod.advertiser_frequency_caps`; the default `dw-main-silver` project will not find it.
