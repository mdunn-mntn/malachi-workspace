# integrationprod.core_creative_groups_x_creatives

## Purpose
The **junction (bridge) table** linking creative groups to creatives — one row per
(`group_id`, `creative_id`) membership. This is the ONLY path between `core_creative_groups` and `creatives`;
neither carries a direct FK to the other. Beyond the two keys it stores **per-membership serving overrides**
(the click URL, active flag, URL prefix/suffix, and dynamic-product-placement fields that apply to this
creative *within this group*). Base Postgres-CDC replica; exposed as the
`silver.core.creative_groups_x_creatives` VIEW.

## Grain & keys
- **Grain:** one row per **(`group_id`, `creative_id`)** — verified composite PK (rows 5,688,008 ==
  COUNT(DISTINCT group_id‖creative_id), 2026-07-29). No duplicate memberships.
- **Composite primary key:** (`group_id`, `creative_id`) — also the cluster key (source order:
  `group_id` then `creative_id`).
- **Foreign keys / join columns:**
  - `group_id` → `core_creative_groups.group_id` (943,872 distinct groups present).
  - `creative_id` → `creatives.creative_id` / `core_creatives.creative_id` (5,687,876 distinct creatives).

## Column meanings (only the non-obvious ones)
- **`group_id`, `creative_id`** — the two link keys (composite PK). `group_id` joins `core_creative_groups`,
  `creative_id` joins `creatives`.
- **`active`** (BOOL) — whether this creative is active *within this group* (membership-level, independent of
  `creatives.active` and `core_creative_groups.active`).
- **`click_url` / `url_prefix` / `url_suffix`** — per-membership landing/click destination and wrappers,
  overriding the group-level equivalents on `core_creative_groups`.
- **`impression_tracking`** (STRING) — per-membership impression-tracking markup.
- **`dpp_id` (STRING) / `dpp_filter` (STRING)** — dynamic-product-placement id/filter for this membership.
- **`user_id`** (INT64) — user who created the membership.
- **`datastream_metadata`** — Datastream CDC lineage RECORD; not business data.
- **No timestamp columns** — this junction has no `create_time`/`update_time`; recency is only inferable from
  `datastream_metadata.source_timestamp` (CDC).

## Joins & relationships
- **`group_id` → `core_creative_groups.group_id`**: N:1 to the group dim.
- **`creative_id` → `creatives.creative_id`**: N:1 to the creative dim.
- **Effectively 1:~1 on the creative side:** 5,687,876 distinct creatives across 5,688,008 rows — **only ~132
  creatives belong to more than one group.** A creative almost always lives in exactly one group. On the group
  side it is genuinely many (943,872 distinct groups, many creatives each). So `creative_id → group` behaves
  near-1:1, but `group_id → creatives` fans out — aggregate accordingly.
- **This is the junction referenced from `creatives.md`** as the sole creative↔group path.
- **`silver.core.creative_groups_x_creatives`** is a VIEW over this table (verified present 2026-07-29).

## Gotchas
- **Membership-level `active` ≠ creative-level or group-level `active`.** Filtering serviceable memberships
  needs this table's `active` AND the parent group's `active` AND the creative's `active`.
- **Composite key** — dedup/join on BOTH `group_id` and `creative_id`; a single-column join fans out.
- **No `create_time`/`update_time`** — use `datastream_metadata.source_timestamp` if you need recency.
- ~132 creatives sit in >1 group — do not assume `creative_id` alone is unique here.

## Cost & partitioning notes
- **No partition, no TTL** (base junction). ~5.69M rows / ~360 MB; clustered on (`group_id`, `creative_id`) —
  filtering by `group_id` (leading key) prunes blocks. Avoid `SELECT *` — the STRING override columns
  (`click_url`, `impression_tracking`, url wrappers) dominate; select just `group_id, creative_id` for a link
  scan. `require_partition_filter: false`.

## Example queries
```sql
-- All creatives in a group (link scan, cheap)
SELECT creative_id, active AS membership_active, click_url
FROM `dw-main-bronze.integrationprod.core_creative_groups_x_creatives`
WHERE group_id = @group_id;

-- Which group(s) a creative belongs to (near-always exactly one)
SELECT group_id
FROM `dw-main-bronze.integrationprod.core_creative_groups_x_creatives`
WHERE creative_id = @creative_id;
```
