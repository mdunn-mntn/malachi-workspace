# integrationprod.archives_campaign_group_channel_margin_archives

## Purpose
Audit-history (versioned snapshot) table for **campaign-group x channel margin & pricing configs**. Each time the app snapshots a `campaign_group_channel_margin` record, a new row is written with an incremented `version`, capturing the margins/fees/CPMs then in effect. Reach for it to answer "**what were the margins/CPM settings for this campaign group on date X**" or to see how a config changed over time. This is a **SENSITIVE margin table** — surface schema/grain only; never put rate values in shared artifacts.

This is a real BASE TABLE (Datastream/Postgres CDC mirror), not a view. The doubled name is intentional: the Postgres source table is itself the app's audit table `campaign_group_channel_margin_archives`, and BQ prefixes the CDC mirror with `archives_`.

## Grain & keys
- **Grain:** one row per **(campaign_group_channel_margin_id, version)** — one audit snapshot of one margin config. Verified: 2719 rows = 2719 distinct `campaign_group_channel_margin_archive_id` = 2719 distinct `(margin_id, version)` pairs. 388 distinct `campaign_group_channel_margin_id` (~7 versions each on average, up to 65).
- **Primary key:** `campaign_group_channel_margin_archive_id` (surrogate, unique; the cluster key).
- **Logical versioning key:** `(campaign_group_channel_margin_id, version)`.
- **FK columns:** `advertiser_id` (124 distinct), `campaign_group_id` (387 distinct), `channel_id` (all rows = 8 / CTV in current data), `margin_source_id`.

## Segmentation of the current data (verified)
- `channel_id`: **only 8 (Television / CTV)** appears in all 2719 rows — this archive is effectively CTV-margin history today (schema permits others).
- `margin_source_id`: domain **{-1, 1, 2}** — `-1` is a sentinel/unset (1 row), `1` (1064 rows), `2` (1654 rows). No `margin_source` lookup table exists in `integrationprod`, so these ids are unresolved to names.

## Column meanings (only the non-obvious ones)
- **campaign_group_channel_margin_archive_id** — surrogate PK, one per snapshot row (cluster key). Not the config id.
- **archive_time** — when the audit snapshot row was written (µs precision). Effectively the business/replication time of this version. Snapshots occur roughly **daily around 12:00 UTC** (periodic re-archive) plus event-driven writes. Equals `datastream_metadata.source_timestamp` to the second.
- **campaign_group_channel_margin_id** — FK to the live `campaign_group_channel_margin` config being versioned. **Not unique** here (many versions per id).
- **channel_id** — FK -> `channels.channel_id`. All current rows = 8 (Television/CTV). See `channels` enum (1=Multi-Touch, 5=Platform Fee, 8=Television/CTV, ...).
- **margin_source_id** — which source set the margin; domain {-1 sentinel, 1, 2}; no lookup table.
- **create_time** — creation time of the underlying margin **record**, **constant across all versions of a given `campaign_group_channel_margin_id`** (verified on margin_id 7: same create_time across 65 versions). Do NOT use it to order the version history.
- **update_time** — last-modified time of the margin record captured in this snapshot; in the periodic-snapshot pattern it equals the **previous** snapshot's `archive_time`.
- **version** — per-`campaign_group_channel_margin_id` snapshot sequence number (1..N). Monotonic with `archive_time` (verified: margin_id 7 runs version 1->65 in `archive_time` order).
- **budget_margin / platform_fee / data_margin** — margin/fee fractions, NUMERIC(5,4) (stored as a decimal fraction). **SENSITIVE — do not surface values.**
- **target_cpm / ad_buying_cpm** — CPM dollar amounts, NUMERIC(7,4). **SENSITIVE — do not surface values.**
- **datastream_metadata.source_timestamp** — INT64 **milliseconds** CDC-capture epoch (`= UNIX_MILLIS(...)`; verified 1784335010993 -> 2026-07-18 00:36:50 = row's `archive_time`). `.uuid` = CDC row id, not business.

## Joins & relationships
- **campaign_group_id -> `integrationprod.campaign_groups.campaign_group_id`** — partner grain 1 row/CG (129,374 rows). This table is **N:1** into `campaign_groups` (many version-snapshots per CG). Fan-out risk if you join snapshots to CG facts without first collapsing to the latest version per margin id.
- **advertiser_id -> `integrationprod.advertisers.advertiser_id`** — partner grain 1 row/advertiser (38,449 rows). **N:1**; safe direction. Join `advertisers.company_name` for a name (per the `advertiser_name`-unreliable gotcha elsewhere).
- **channel_id -> `integrationprod.channels.channel_id`** — 10-row enum, **N:1**, safe.
- **campaign_group_channel_margin_id -> the live `campaign_group_channel_margin` config** — that live/current-state table is **not mirrored in `integrationprod`** (no `campaign_group_channel_margins` table; `bq show` = not found), so this FK cannot be live-verified here; this archive is the queryable history surface.
- **margin_source_id** — no resolvable lookup table in `integrationprod`.

## Gotchas
- **SENSITIVE (margin table):** budget_margin / platform_fee / data_margin / target_cpm / ad_buying_cpm are rate values — schema/grain only in any shared output.
- **No `deleted` / `is_test` columns** — the standard `deleted=FALSE AND is_test=FALSE` filter does NOT apply (columns absent); do not add it.
- **Latest state as of date D:** filter `archive_time <= D`, then take `MAX(version)` (equivalently latest `archive_time`) **per `campaign_group_channel_margin_id`** — the table holds every snapshot, so an unfiltered join multiplies rows ~7x per config.
- **create_time is constant per margin_id** — contra the generic `archives_*` advice to "order by create_time," here you must order history by **`version` (or `archive_time`)**; create_time will not sort versions.
- **archive_time is µs-precision and near-unique per row** — rows from one snapshot run share the same second but differ in microseconds; don't treat a second-truncated `archive_time` as a batch key.
- **CTV-only today:** all rows `channel_id=8`; don't assume other channels are represented.
- **`version` is per-margin_id, not global** — max version 65 belongs to one config; it is not a table-wide sequence.
- **`datastream_metadata.source_timestamp` is ms CDC-capture, not business time** (though here it tracks `archive_time` closely). Use `archive_time` for business/effective time.

## Cost & partitioning notes
- **No partition** (real base table, `timePartitioning=null`, `requirePartitionFilter=null`). Clustered on `campaign_group_channel_margin_archive_id` (helps only point lookups by that surrogate PK).
- **Tiny table** — full scans are cheap. Dry-run (2026-07-20): `SELECT *` full scan = **438,994 bytes (~0.42 MB)**; single narrow column (`campaign_group_channel_margin_id`) = **21,752 bytes (~21 KB)**. `approx_logical_bytes` (bq show numBytes) = 438,994 = the `SELECT *` figure since the whole table is sub-MB.
- **The one thing to always do:** there is no partition to filter, but when joining to fact/CG tables, **pre-collapse to one row per `campaign_group_channel_margin_id`** (latest `version` <= your as-of date) to avoid ~7x fan-out; the scan itself is negligible.

## Example queries
```sql
-- Latest margin config per campaign group as of a date (structure only; do not export rates)
SELECT campaign_group_channel_margin_id, campaign_group_id, advertiser_id, channel_id, margin_source_id, version, archive_time
FROM (
  SELECT *, ROW_NUMBER() OVER (PARTITION BY campaign_group_channel_margin_id ORDER BY version DESC) AS rn
  FROM `dw-main-bronze.integrationprod.archives_campaign_group_channel_margin_archives`
  WHERE archive_time <= TIMESTAMP('2026-07-01')
)
WHERE rn = 1
```
