# integrationprod.integrations_advertiser_integrations

## Purpose
Config/junction table linking each MNTN advertiser to the third-party integrations it has connected — measurement, attribution, analytics, and CRM vendors (AppsFlyer, Northbeam, Upwave, LiftLab, mParticle, HubSpot, Google Analytics 4, DoubleVerify, iSpot, "MNTN Audience", etc.). One row = one connection an advertiser set up to a given vendor. Reach for it to answer "which advertisers have integration X connected / active", to enumerate a vendor's advertiser footprint, or to join advertiser-level data to external-tool connections. Small Postgres dim mirrored via Datastream CDC.

## Grain & keys
- **Grain:** one row per advertiser–integration connection. Verified 1246 rows / 1246 distinct `id` → **`id` is the surrogate PK (1:1)**.
- **Key(s) / join columns:** `id` (PK) · `integration_id` (FK → `integrations_integrations.id`, the vendor catalog) · `advertiser_id` (FK → advertisers). `advertiser_id` is **not** unique: 801 distinct advertisers across 1246 rows, and (advertiser_id, integration_id) = 936 distinct pairs → an advertiser can hold multiple rows for the **same** vendor (re-connects, multiple accounts, or active + soft-deleted history).

## Column meanings (only the non-obvious ones)
- **integration_id** — FK → `integrationprod.integrations_integrations.id` (the vendor catalog). Verified id→name map (live, 34 vendors): 1=CallRail, 2=Google Analytics, 3=Rockerbox, 4=CDK Global, 5=Northbeam, 6=Kochava, 7=Singular, 8=AppsFlyer, 9=Adjust, 10=Google Analytics 4, 11=Freshpaint, 12=Haus, 13=HubSpot, 14=LiftLab, 15=Zapier, 19=Campaign Manager 360, 20=Funnel, 21=Triple Whale, 22=Upwave, 23=Quorum, 24=Looker, 25=Cuebiq, 26=Foursquare, 27=Precisely, 28=TapClicks, 29=DoubleVerify, 30=Tealium, 31=iSpot, 32=Innovid, 33=mParticle, 1015=OursPrivacy, 1016=WorkMagic, **1017=MNTN Audience**, 1018=Klaviyo.
- **advertiser_id** — the MNTN advertiser (AID) that connected this vendor. FK → advertisers.
- **active** — BOOL enable flag: 820 true / 426 false / 0 null. **Independent of soft-delete** — a row can be `active=false` without being deleted.
- **t_created_ns / t_updated_ns / t_deleted_ns** — Unix **NANOSECONDS** (19 digits). Anchor verified: `TIMESTAMP_MICROS(t_created_ns/1000)` = `create_time` (i.e. `t_created_ns = UNIX nanos`). `t_deleted_ns` is the soft-delete tombstone: **NULL = live**; 453/1246 rows are soft-deleted. `create_time`/`update_time` are the native-TIMESTAMP mirror, but `update_time` is NULL on ~96% of rows (only 49 populated) — use `t_updated_ns` for last-modified.
- **datastream_metadata.source_timestamp** — Datastream CDC-capture epoch in **MILLISECONDS** (13 digits), ~1s after business time. This is capture time, **not** business time. `uuid` = CDC event id.
- **connection_id** — STRING transport/orchestration-path label, **not a numeric FK**. Domain: `orca-integration` (current orchestrator path), `legacy-integration` (old path), `""` (empty), plus per-connection random two-word tokens (e.g. `grounded_boundary`, `skies_vexingly`, `giggle_rapidity`) that look like generated connection handles (all `active=0`, `integration_id=1`) — possible test/placeholder artifacts (no `is_test` column to exclude them).
- **connection** — JSON connection config, populated on all 1246 rows. **auth_credentials** — JSON secrets, populated on only 373 rows.
- **global_key / local_key** — STRING(512) routing keys. `global_key` holds an advertiser reference (`aid:32167` or bare `57984`); `local_key` holds either the integration id echoed as text (`10`,`13`,`5`) or a vendor-dated config slug (`appsflyer-202605`, `upwave-202604`, `liftlab-202605`, `mparticle-202604`). `connection_group_key` groups related connections (mostly NULL).
- **distribution_point** — FLOAT64 in [0,1), **sparse** (only 19/1246 populated, all on recent `orca-integration` rows); resembles a hash/sampling bucket value. Meaning not documented in source — treat as unverified; do not use as a key.
- **parent_id** — self-reference to `id` (parent connection); 125 rows populated.
- **hotel_id / hotel_integration_id / integration_account_id / secondary_integration_account_id** — hospitality-vertical + external-account linkage fields; almost always NULL (`hotel_id` on 8 rows). **user_id / last_update_user_id** — creating / last-editing user (users dim); `user_id` NULL on most rows. **last_connected_at / last_disconnected_at** — connection lifecycle timestamps (mostly NULL).

## Joins & relationships
- **integration_id → `integrationprod.integrations_integrations.id`** — vendor lookup dim (~34 rows, PK `id`). N:1 (many advertiser rows → one vendor); **fan-out safe**. `integrations_integrations` also carries `data_source_id` → `data_sources` (DSxx taxonomy) if you need the DS mapping (two hops).
- **advertiser_id → advertisers.id** (`integrationprod.advertisers` / core advertisers dim, 1 row per AID). One advertiser → many integration rows (up to N connections), so **joining advertisers → this table fans out per advertiser** — dedup/aggregate if you only want a per-advertiser flag.
- **parent_id → self.id** — parent connection (child/secondary connections point back).
- **user_id / last_update_user_id → users dim** — creator / last editor.
- No partner table here is mid-SQLMesh-rebuild; `integrations_integrations` resolved live (34 vendors).

## Gotchas
- **No `deleted` / `is_test` columns.** The standard integrationprod `deleted=FALSE AND is_test=FALSE` filter **does not apply** to this table. For live rows use `t_deleted_ns IS NULL` (453/1246 are soft-deleted). `active` is a **separate** enable flag — 426 `active=false` rows are not deleted.
- **`update_time` is NULL on ~96% of rows** (49/1246 populated) — use `t_updated_ns` (nanoseconds) for last-change, not `update_time`.
- **Epoch units differ by column:** `t_*_ns` = nanoseconds (19 digits); `datastream_metadata.source_timestamp` = milliseconds (13 digits) and is CDC-capture, not business time.
- **`advertiser_id` is not unique** — the same advertiser can appear multiple times for the same `integration_id` (active + historical soft-deleted rows). Filter `active` and/or `t_deleted_ns IS NULL` before counting distinct advertisers per vendor.
- **`connection_id` free-text tokens** (`grounded_boundary`, `skies_vexingly`, …) look like generated/placeholder handles; with no `is_test` column they can't be filtered out by flag — filter on `active`/`t_deleted_ns` instead.
- **`distribution_point`** is populated on only 19 rows and its meaning is undocumented in source — do not build logic on it.

## Cost & partitioning notes
- **No partition, no TTL**, clustered by `id`. Tiny dim: full table = **274,137 bytes (~0.27 MB)**. Every query scans the whole table (no partition column to prune), but cost is negligible.
- Labeled dry-runs (2026-07-20): `SELECT *` (all 26 cols) = **274,137 B**; `SELECT advertiser_id, integration_id` (2 cols) = **19,848 B**. Columnar pruning scales cost ~14x but absolute is trivial — comparable only when the same column set is measured.
- **The one filter to always apply:** `t_deleted_ns IS NULL` (live rows) — there is no partition column. Add `active` if you want only currently-enabled connections.

## Example queries
```sql
-- Live vendor connections per advertiser (vendor names resolved)
SELECT a.advertiser_id, i.name AS vendor, a.active, a.create_time
FROM `dw-main-bronze.integrationprod.integrations_advertiser_integrations` a
JOIN `dw-main-bronze.integrationprod.integrations_integrations` i
  ON i.id = a.integration_id
WHERE a.t_deleted_ns IS NULL          -- live rows (no deleted/is_test cols on this table)
ORDER BY a.advertiser_id, vendor
```
