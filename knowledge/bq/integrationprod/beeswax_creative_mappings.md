# integrationprod.beeswax_creative_mappings

## Purpose
Bridge/junction table that translates each **MNTN creative** into its counterpart in **Beeswax** (the DSP MNTN historically bids through). MNTN pushes creatives into Beeswax; this table reconciles the two ID spaces so you can join MNTN-side spend/creative data to Beeswax creative/line-item ids and back. It also carries a denormalized copy of the creative's physical attributes (type, size code, dimensions, video duration), so basic creative-shape questions can be answered without joining `core_creatives` / `core_creative_sizes`.

One of the `beeswax_*_mappings` family: `beeswax_advertiser_mappings` (advertiser_id), `beeswax_campaign_mappings` (campaign_group_id), `beeswax_creative_mappings` (this, creative_id), `beeswax_line_item_mappings` (campaign_id), `beeswax_segment_mappings` (segment_id×advertiser_id). This family is **transitional** — it goes away once MNTN Bidder is fully released and all campaign groups migrate off Beeswax.

## Grain & keys
- **Grain:** one row per **MNTN `creative_id`**. Verified strict 1:1: 1,585,655 rows = 1,585,655 distinct `creative_id`, zero NULL `creative_id`. `creative_id` is the primary key and the cluster key.
- **Key(s) / join columns:** `creative_id` (MNTN side, PK) ↔ `beeswax_creative_id` (Beeswax side). Note the Beeswax id is **not** unique here — do NOT use it as a join PK (see Gotchas). `campaign_id`, `advertiser_id`, `media_size_id` are foreign keys into MNTN dims.

## Column meanings (only the non-obvious ones)
- **`creative_id`** — MNTN creative dim key (= `core_creatives.creative_id`). PK of this table. Nullable in schema but empirically never NULL.
- **`beeswax_creative_id`** — Beeswax's internal creative id. **Not unique in this table:** 19,265 Beeswax creative ids are shared by >1 MNTN creative (max 71 MNTN creatives per Beeswax id). Treat as a lookup value, not a key.
- **`beeswax_creative_line_item_id`** — Beeswax creative↔line-item association id. Effectively 1:1 with `beeswax_creative_id` (same distinct count; only 104 Beeswax creatives span >1 line item). This is the Beeswax-side line-item binding, distinct from the MNTN `campaign_id` below.
- **`campaign_id`** — MNTN `campaigns.campaign_id` = a **line item / MNTN campaign** (NOT a campaign group; `funnel_level` on `campaigns` is authoritative for stage). 198,954 distinct → a campaign owns many creatives.
- **`advertiser_id`** — MNTN `advertisers.advertiser_id`. 8,684 distinct advertisers have Beeswax-mapped creatives.
- **`media_size_id`** — MNTN creative-size code → `core_creative_sizes.creative_size_id`. **Not a bitmask** despite large values. Verified decode: 93=HD Video (1920×1080, CTV), 39=Vertical HD Video (1080×1920, CTV), 1=Medium Rectangle (300×250), 16384=Leaderboard (728×90), 131072=Half Page Ad (300×600), 32768=(160×600), 768=Mobile Ad 2 (320×50), 384=(300×50).
- **`creative_type`** — domain (full DISTINCT): `THIRD_PARTY` (1,066,440 ≈ 67%, display served via 3rd-party ad tags), `CTV` (518,963 ≈ 33%, video), `Image` (222), `Flash` (18), `Dynamic CTV` (12). No NULLs observed.
- **`height` / `width`** — creative pixel dimensions, a **denormalized copy** of the `core_creative_sizes` row for `media_size_id`. Trust `core_creative_sizes` as canonical if they ever disagree.
- **`duration`** — video length in **seconds** (30 typical for CTV). NULL for non-video types (Image/Flash). ~354 CTV rows carry duration=0 (data-quality noise).
- **`create_time` / `update_time`** — business TIMESTAMPs (UTC). `update_time` never precedes `create_time` (0 violations). History floor = 2024-03-12; max = present day (table is actively written).
- **`datastream_metadata.source_timestamp`** — CDC-capture epoch in **MILLISECONDS** (anchor: `TIMESTAMP_MILLIS(source_timestamp)` ≈ `update_time` for freshly-written rows). This is Datastream WAL-capture time, **not** business time — backfilled re-captures push it up to ~646 days after `update_time`. Use `update_time`, never this, for change dating.

## Joins & relationships
- **`creative_id` → `core_creatives.creative_id`** — MNTN creative dim. **1:1** (both sides PK on creative_id). Fan-out safe. Caveat: only Beeswax-served creatives appear here, so this is a subset of `core_creatives` — an inner join drops non-Beeswax / pre-2024-03-12 creatives.
- **`creative_id` → `core_creative_groups_x_creatives.creative_id`** — creative→group membership junction; **1:N** (a creative can belong to multiple creative groups). Fan-out risk on join.
- **`media_size_id` → `core_creative_sizes.creative_size_id`** — size dim (PK `creative_size_id`; columns `description`, `width`, `height`, `video`, `ctv`). **N:1** from this table; safe (dim side is 1).
- **`campaign_id` → `campaigns.campaign_id`** — MNTN line item. This table is the **N** side (many creatives per campaign); joining FROM `campaigns` fans out 1:N. Sibling `beeswax_line_item_mappings` maps the same `campaign_id` → Beeswax line item id.
- **`advertiser_id` → `advertisers.advertiser_id`** — advertiser dim. This table is the **N** side; joining FROM `advertisers` fans out 1:N. Sibling `beeswax_advertiser_mappings` maps `advertiser_id` → Beeswax advertiser id.
- **`beeswax_creative_id`** — do **not** join on this as a key; it is many-to-one from MNTN creatives (see Gotchas). Related staging table `sync_beeswax_creative_mapping` (PK `beeswax_creative_mapping_id`) exists but is a separate sync/staging object, not verified here.

## Gotchas
- **No `deleted` / `is_test` columns.** The dataset-wide "filter `deleted=FALSE AND is_test=FALSE`" does **not** apply — those columns don't exist here. You cannot exclude test/deleted creatives from this table alone; join `core_creatives` if you need that hygiene filter.
- **Live-mutating table.** Rows are added continuously (distinct-Beeswax-id count drifted 1,544,745 → 1,544,753 within seconds between two queries; max `create_time` = today). Any `COUNT(*)`/snapshot is a moving target, not a stable figure.
- **`beeswax_creative_id` is not unique** — 19,265 shared by >1 MNTN creative (max 71). Join MNTN→Beeswax on `creative_id`; never assume Beeswax id is a 1:1 key.
- **`source_timestamp` is CDC ms, not business time** — standard Datastream caveat; backfill re-captures can sit ~646 days after `update_time`. Date changes off `update_time`.
- **History floor 2024-03-12** — creatives created before that, or never pushed to Beeswax, are absent. Inner-joining this to `core_creatives` silently drops them.
- **Transitional table** — the whole `beeswax_*_mappings` family is slated to disappear once MNTN Bidder fully replaces Beeswax; don't build durable pipelines assuming it persists.
- **`width`/`height`/`duration` are denormalized** and can carry noise (duration=0 on some CTV); `core_creative_sizes` is canonical for size.

## Cost & partitioning notes
- **No date partition.** This is a BASE TABLE with no `timePartitioning` (front-matter `partition_by: none`, `require_partition_filter: false`) — there is no date column to filter and none is required. It is **clustered by `creative_id`**, so the one prune available is a filter on `creative_id` (equality or `IN`/range), which lets clustering skip blocks.
- **The one filter to always apply:** `WHERE creative_id IN (...)` (or a `creative_id` range) — the only pruning lever. There is no date filter to apply.
- **Whole-table scan (all 13 columns, `SELECT *`):** ~220 MB — `bq_run.sh --dry_run` upper bound = 220,383,733 bytes. Small table; a full scan is cheap, but note it still reads everything (no partition), so prefer projecting only needed columns and filtering `creative_id` when embedding in larger jobs.
- **`approx_logical_bytes` = 220,384,845** (`bq show` numBytes, physical backing storage; grows as the table is written live).

## Example queries
```sql
-- MNTN creative → Beeswax ids + resolved size (clustering prune on creative_id)
SELECT m.creative_id,
       m.beeswax_creative_id,
       m.beeswax_creative_line_item_id,
       m.creative_type,
       s.description AS size_name,
       m.width, m.height, m.duration
FROM `dw-main-bronze.integrationprod.beeswax_creative_mappings` m
LEFT JOIN `dw-main-bronze.integrationprod.core_creative_sizes` s
  ON m.media_size_id = s.creative_size_id
WHERE m.creative_id IN (6440615, 6440614, 6440613);
```
