# integrationprod.core_creative_video_meta_informations

## Purpose
Per-creative **rendered video-asset metadata** — one row per transcoded video rendition (size/resolution
variant) produced for a video creative: its `video_size`, pixel dimensions, `file_type`, duration, bitrate,
fps, and the asset `url`. Reach for it to get the technical specs / hosted URL of a creative's video
rendition(s). Child of `creatives` (via `creative_id`); exposed as the
`silver.core.creative_video_meta_informations` VIEW.

## Grain & keys
- **Grain:** one row per **`creative_video_meta_information_id`** — PK (rows 777,461 == distinct id, 2026-07-29).
  Multiple renditions per creative: **~7 rows per creative** (111,033 distinct `creative_id`).
- **Primary key:** `creative_video_meta_information_id` (INT64); sole cluster key.
- **Foreign key:** `creative_id` → `creatives.creative_id` / `core_creatives.creative_id` — **N:1**, 0 NULL
  (only video-type creatives appear here).

## Column meanings (only the non-obvious ones)
- **`video_size`** (STRING) — resolution label; **observed "1080p" for all 777,461 rows** (currently the only
  value present).
- **`width` / `height`** (INT64) — pixel dimensions of the rendition (e.g. 1920×1080).
- **`file_type`** (STRING) — MIME type; **"video/mp4" for all rows** (single value).
- **`duration`** (STRING) — mostly NULL. **`duration_in_sec`** (FLOAT64) is the populated duration (e.g.
  30.03) — use this, not `duration`.
- **`bitrate`** (STRING) — encoded bitrate stored as a string (e.g. "1000", i.e. kbps).
- **`fps`** (NUMERIC) — frame rate; largely NULL.
- **`status`** (BOOL) — **FALSE for all 777,461 rows** (0 TRUE) — non-discriminating; do not treat as a
  ready/approved flag.
- **`video_adcode`** (JSON) — meant to hold ad-code config, but **empty in ~99.96% of rows** (only ~343 rows
  carry non-empty JSON). Guard for empty.
- **`url`** (STRING) — hosted location of the rendered video file.
- **`job_task_id`** (STRING) — the transcode job/task identifier that produced this rendition (rows sharing a
  `job_task_id` come from the same encode run).
- **`created_at`** — TIMESTAMP the rendition row was created; **no `update_time`**.
- **`datastream_metadata`** — Datastream CDC lineage RECORD; not business data.

## Joins & relationships
- **`creative_id` → `creatives.creative_id`**: **N:1** — a video creative has multiple renditions here, so
  joining `creatives` → this table is a **1:N fan-out** (~7×). Pre-aggregate (pick a rendition, or
  `ARRAY_AGG`) if you need one row per creative.
- Only creatives with video content appear (0 NULL `creative_id`; 111,033 of the platform's video creatives).
- **`silver.core.creative_video_meta_informations`** is a VIEW over this table (verified 2026-07-29).

## Gotchas
- **1:N per creative (~7 renditions)** — never assume one row per `creative_id`; a naive join inflates counts.
- **`status` all FALSE and `file_type`/`video_size` single-valued** — none of these three discriminate; don't
  filter on `status=TRUE` (returns nothing).
- **Use `duration_in_sec` (FLOAT), not `duration` (STRING, mostly NULL).**
- **`video_adcode` (JSON) is empty ~99.96% of the time** — check before parsing.
- **No `update_time`** — only `created_at`; use `datastream_metadata.source_timestamp` for later changes.

## Cost & partitioning notes
- **No partition, no TTL** (child dim). ~777K rows / ~181 MB; clustered on
  `creative_video_meta_information_id`. Avoid `SELECT *` — the `url` and `video_adcode` STRING/JSON columns
  carry most of the bytes; select `creative_id, video_size, width, height, duration_in_sec, url` for specs.
  `require_partition_filter: false`.

## Example queries
```sql
-- Video renditions for a creative (expect ~7 rows)
SELECT creative_video_meta_information_id, video_size, width, height, duration_in_sec, bitrate, url
FROM `dw-main-bronze.integrationprod.core_creative_video_meta_informations`
WHERE creative_id = @creative_id;

-- One representative rendition per creative (avoid fan-out)
SELECT creative_id, ANY_VALUE(duration_in_sec) AS dur_sec, MAX(width) AS max_w
FROM `dw-main-bronze.integrationprod.core_creative_video_meta_informations`
GROUP BY creative_id;
```
