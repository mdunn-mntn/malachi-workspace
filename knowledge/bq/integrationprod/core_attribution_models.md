# integrationprod.core_attribution_models

## Purpose
Small reference/seed dimension that decodes the `attribution_model_id` foreign key carried on attributed
conversion / visit / touch records. Each row names one **attribution model** — the specific logic used to
credit a touch to an outcome. Reach for this table only to attach a human-readable model name (and its
type / identity-key) to an `attribution_model_id`, or to enumerate which attribution models exist. It is a
Datastream-CDC copy of the Postgres `core.attribution_models` app table; `silver.core.attribution_models`
is a view over it.

## Grain & keys
- **Grain:** one row per attribution model. 30 live rows. Ids run 1–34 with one gap: 21–24 absent (1–20
  and 25–34 all present) — do not assume ids are contiguous.
- **Primary / natural key:** `attribution_model_id` (surrogate INT, also the sole cluster key).
- **Self-referential FK:** `counterpart_attribution_model_id` → `attribution_model_id` (same table).
- **Type FK:** `attribution_model_type_id` — a 4-value enum (no separate type-lookup table exists in
  bronze; decode from `name`, see below).

## Column meanings (only the non-obvious ones)
- **attribution_model_id** — surrogate PK; the FK target on attributed fact rows. Live domain is 30 ids in
  1–34 (with gaps). Clustered, but clustering is cosmetic on a 30-row table.
- **name** — human label encoding three things: (1) the **touch logic** — `Last Touch` (display/general)
  vs `Last TV Touch` (TV/CTV), and whether it is a **Competing** variant; (2) the **identity-resolution
  key** used to join a touch to the outcome — `guid`, `ip`, `ga_client_id`, `household id`, `IFA-IP
  winlogs`; (3) the **source/flavor** — `Offline Attribution`, `Impression`, `Freshpaint (Imp Attr)` /
  `Freshpaint (Visit Attr)`, `Conversion`. Example: `Last TV Touch Competing Conversion - Freshpaint (Imp
  Attr)`.
- **attribution_model_type_id** — 4-value enum (verified against `name`):
  - **1 = Last Touch** (non-TV / display / general last-touch) — 7 models
  - **2 = Last TV Touch** (TV / CTV last-touch) — 7 models
  - **3 = Last Touch Competing** (last-touch, competing-conversion variant) — 8 models
  - **4 = Last TV Touch Competing** (TV last-touch, competing variant) — 8 models

  So the low bit distinguishes **display (odd: 1,3)** vs **TV (even: 2,4)**, and 3/4 are the "Competing"
  counterparts of 1/2. There is no `core_attribution_model_types` lookup table in bronze — decode from
  this enum or from `name`.
- **counterpart_attribution_model_id** — self-reference pairing each model with its **display↔TV twin**
  (same identity key & competing status, opposite touch channel). E.g. `1 Last Touch - guid` ↔
  `4 Last TV Touch - guid`; `2` ↔ `5`; `9 Last Touch Competing - guid` ↔ `12 Last TV Touch Competing -
  guid`. Pairs are symmetric (A.counterpart = B and B.counterpart = A).
- **create_time** — business insert time of the model (TIMESTAMP, UTC). Ranges 2023-07-24 (original seed)
  → 2026-06-01 (household-id models). Newer models = newer attribution methodologies (Freshpaint, IFA-IP
  winlogs, household id).
- **datastream_metadata.source_timestamp** — INT64 **milliseconds** CDC-capture epoch, NOT business time.
  Anchor with `TIMESTAMP_MILLIS(source_timestamp)` (MICROS gives 1970 = wrong). `datastream_metadata.uuid`
  is the Datastream event id.

## Joins & relationships
- **This is the "1" side of a 1:N decode.** Joining a fact table onto `core_attribution_models` on
  `attribution_model_id` is a safe name-enrichment: it attaches the model name/type and **never fans out**
  the fact side (each fact row matches exactly one model). Attributed conversion / visit / touch records
  carry `attribution_model_id` to indicate which model produced the credit; use this dim to label them.
- **Self-join for the twin:** `t.counterpart_attribution_model_id = c.attribution_model_id` retrieves the
  display↔TV counterpart model.
- **`silver.core.attribution_models`** is a VIEW over this base table (same 30 rows) — either name resolves
  to identical data.

## Gotchas
- **No `update_time`, no `deleted` / `is_test` columns.** The dataset-wide `deleted=FALSE AND
  is_test=FALSE` live filter does NOT apply here and is not needed (all 30 rows are canonical). There is
  no way to detect a soft-deleted model from this table.
- **Ids are not contiguous.** 30 rows span ids 1–34; exactly one gap — 21–24 are absent (all other ids
  1–34 present). Never `generate_array(1,34)` to enumerate — read the table.
- **`attribution_model_type_id` has no lookup table** — the 4-value meaning lives only in `name`
  conventions (documented above). Don't expect a `*_types` dim to join to.
- **`source_timestamp` is ms CDC-capture, not business time** (all rows re-snapshot to a single recent
  timestamp on full CDC reloads). Use `create_time` for model age.
- **Model name ≠ what a downstream table actually used.** This dim only defines models; whether a given
  fact table populates a particular `attribution_model_id` is a property of that fact table, not this one.

## Cost & partitioning notes
- **BASE TABLE, physical `self`** (not a view / not SQLMesh): `bq show` reports `numRows=30`,
  `numBytes=3399`, `timePartitioning=None`, `clustering.fields=[attribution_model_id]`, Datastream
  `max_staleness=15m`.
- **Partition: none.** `require_partition_filter=false`. Nothing to filter — the whole table is ~3.4 KB.
- **Cost:** `SELECT *` is the metadata floor (~3.4 KB / billed at the 10 MB minimum). Safe to `SELECT *`
  freely, or hard-code the id→name map in application code and skip the join.

## Example queries
```sql
-- Full dim dump (whole table, ~3.4 KB)
SELECT attribution_model_id, name, attribution_model_type_id, counterpart_attribution_model_id
FROM `dw-main-bronze.integrationprod.core_attribution_models`
ORDER BY attribution_model_id;

-- Decode attribution model + its display<->TV twin on an attributed fact table
SELECT f.*, m.name AS model_name, m.attribution_model_type_id,
       tw.name AS counterpart_model_name
FROM `<attributed_fact_table>` f
JOIN `dw-main-bronze.integrationprod.core_attribution_models` m
  ON f.attribution_model_id = m.attribution_model_id
LEFT JOIN `dw-main-bronze.integrationprod.core_attribution_models` tw
  ON m.counterpart_attribution_model_id = tw.attribution_model_id;
```
