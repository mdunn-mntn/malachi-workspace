# integrationprod.dso_household_score_thresholds

## Purpose
The **current-state Household Score Threshold (HHST)** table: one row per campaign holding the minimum
household intent score a household must clear for that campaign to bid/serve. It is the **intent gate the
bidder enforces** on prospecting delivery. Source is the coredb `dso` schema (`dso.household_score_thresholds`),
replicated into `dw-main-bronze.integrationprod` via Datastream CDC (schema-qualified name flattened to
`dso_household_score_thresholds`). The live silver view is `silver.dso.household_score_thresholds`; the
append-only change-history counterpart is `silver.archives.household_score_threshold_archives` (one row
per write). Reach for this table to answer "what is the current intent gate on campaign X" — for a
time-series of gate flips (event studies), use the archives table instead. Gate flips drive overnight
delivery-composition inversions (AUDI-1070).

## Grain & keys
- **Grain:** one row per `campaign_id` — the current HHST for that campaign. Verified: 32,560 rows =
  32,560 distinct `campaign_id` (2026-07-29).
- **Primary/natural key:** `campaign_id` (declared `PRIMARY KEY (campaign_id) NOT ENFORCED` in the DDL).
- **Foreign keys / join columns:**
  - `campaign_id` → `integrationprod.campaigns.campaign_id` (1:1 with current state).
  - `campaign_group_id` → `integrationprod.campaign_groups.campaign_group_id` (N:1, denormalized).
  - `advertiser_id` → `integrationprod.advertisers.advertiser_id` (N:1, denormalized).

## Column meanings (only the non-obvious ones)
- **`threshold`** (INT) — the HHST value on the bidder's **0–10000 household-score scale**. A household
  must have `household_score >= threshold` for the campaign to be eligible to bid/serve. Encoding traps:
  **`0` or negative (observed down to `-100`) = NO gate / serve anyone** (65% of rows are `0`; treat any
  value ≤0 as "gate off"). **`10000` = HI-only** (only high-intent households; 2,398 rows / ~7%). Bidder
  score bands for context: **8001+ = HI, 6666–8000 = PP, 3333–6665 = MI, ≤3332 = MR**. Mirrors
  `sync.creative_metadata.household_score_threshold` (where **null OR zero → threshold not evaluated**).
- **`campaign_id`** (INT) — the PK and cluster key; join to `campaigns` for objective/funnel. Stage-1
  prospecting = `objective_id=1 AND funnel_level=1`.
- **`transaction_id`** (STRING) — UUID stamped by the DSO service on the write that set this row (one UUID
  per write batch). Same field appears on the archive rows; use it to tie a current row to its archive event.
- **`create_time`** (TIMESTAMP) — when the current HHST row was first created; use this for true row age.
- **`update_time`** (TIMESTAMP) — last-write timestamp per Postgres/CDC. **Unreliable for per-row change
  timing here**: a bulk CDC re-sync stamps many rows with one identical value (all sampled rows read
  `2026-07-30 00:10:15` UTC), the known integrationprod-dim backfill-floor artifact. For a real change
  history use `archives.household_score_threshold_archives`, not this column.
- **`datastream_metadata`** (STRUCT) — Datastream CDC bookkeeping: `uuid` (change id) + `source_timestamp`
  (source-DB commit epoch, INT). Bidding/analytics ignore it.

## Joins & relationships
- `campaign_id` → `campaigns` is **1:1** for current state (PK on both sides) — no fan-out.
- `campaign_group_id` and `advertiser_id` are **denormalized rollup keys** carried for convenience; joining
  to `campaign_groups` / `advertisers` is N:1 (many campaigns per group/advertiser). Do not treat a row as
  group- or advertiser-grained: the grain is the campaign.
- **Sibling `dso.*` threshold tables** (same scope/pattern, per data_catalog): `dso.recency_score_thresholds`,
  `dso.viewability_score_thresholds`, `dso.cpm_thresholds`, `dso.publisher_performance_thresholds`,
  `dso.network_performance_threshold`. HHST's IP score value source is `tpa`.
- **Change history:** `silver.archives.household_score_threshold_archives` is the append-only counterpart
  (one row per write, not per change). Collapse to true change points with
  `LAG(threshold) OVER (PARTITION BY campaign_id ORDER BY update_time)` keeping `threshold != prev`.

## Gotchas
- **`threshold ≤ 0` means the gate is OFF (serve anyone), not "score 0 required."** 65% of campaigns sit
  at `0`; negatives (down to `-100`) are also "no gate." Only `threshold > 0` is an active intent floor.
- **`update_time` is not a reliable change timestamp** — bulk CDC re-syncs collapse many rows onto one
  identical value. Use `archives.household_score_threshold_archives` (or `create_time` for age) for timing.
- **Current-state only.** This table holds the latest HHST per campaign; it does not retain prior values.
  Any gate-flip / event-study analysis must query the archives table.
- **Lives in bronze, not silver.** Query as `dw-main-bronze.integrationprod.dso_household_score_thresholds`;
  the default `dw-main-silver` project will not find it. The silver-facing name is `silver.dso.household_score_thresholds`.
- **`bq show` numRows (~33,013) slightly exceeds queryable rows (32,560)** — the delta is CDC staging under
  the 15-min `max_staleness` window, not real duplicate campaigns.
- **HHST is the delivered gate, but delivered score history is column-limited.** CIL `household_score` is
  100% NULL before 2025-06-01 (a logging cutover, recoverable from `model_params` back to 2025-05-06); do
  not use CIL typed score columns to reconstruct pre-2025-05 gate behavior (AUDI-1070).

## Cost & partitioning notes
- **BASE TABLE, unpartitioned, clustered on `campaign_id`, no TTL.** `require_partition_filter: false`.
  There is no partition column and none is needed — the table is tiny (~32.6k rows, ~4.36 MB).
- A full scan is ~**0.004 GB** (rounds to the tier-1 10 MB floor / effectively free). No date filter is
  required here (this is a config dim, not a log/event table).
- Clustered on `campaign_id`: an equality/`IN` filter on `campaign_id` prunes blocks. For lookups by
  advertiser or campaign_group, filter those columns directly (they are not cluster keys, but the table is
  small enough that it doesn't matter).

## Example queries
```sql
-- Current intent gate for a set of campaigns (cluster-pruned on campaign_id)
SELECT campaign_id, advertiser_id, campaign_group_id, threshold,
       CASE WHEN threshold <= 0 THEN 'no gate'
            WHEN threshold >= 8001 THEN 'HI+'
            WHEN threshold >= 6666 THEN 'PP+'
            WHEN threshold >= 3333 THEN 'MI+'
            ELSE 'MR+' END AS gate_band
FROM `dw-main-bronze.integrationprod.dso_household_score_thresholds`
WHERE campaign_id IN (630191, 638478);

-- Distribution of active gates across all campaigns
SELECT COUNTIF(threshold <= 0) AS no_gate,
       COUNTIF(threshold BETWEEN 1 AND 8000) AS partial_gate,
       COUNTIF(threshold >= 8001) AS hi_only
FROM `dw-main-bronze.integrationprod.dso_household_score_thresholds`;
```
