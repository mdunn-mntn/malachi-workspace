# integrationprod.core_margin_sources

## Purpose
Two-row seed/lookup dimension that decodes `margin_source_id` into a short **margin source code**. Reach
for it only to attach the source code to a `margin_source_id` foreign key carried on margin rows, or to
enumerate the margin sources. Datastream-CDC copy of the Postgres `core.margin_sources` app table;
`silver.core.margin_sources` is a view over it.

## Grain & keys
- **Grain:** one row per margin source. **2 rows:** `1 = DTR`, `2 = MSS`.
- **Primary key:** `margin_source_id` (surrogate INT, also the sole cluster key).

## Column meanings (only the non-obvious ones)
- **margin_source_id** — surrogate PK; the FK target on margin rows. Live domain: `{1, 2}`.
- **name** — the source code string. Verified values: `1 → "DTR"`, `2 → "MSS"` (short internal codes; this
  table stores only the codes, no long-form expansion).
- **datastream_metadata.source_timestamp** — INT64 **milliseconds** CDC-capture epoch (`TIMESTAMP_MILLIS`),
  not business time. This table has no `create_time`/`update_time`.

## Joins & relationships
- **This is the "1" side of a 1:N decode.** Margin/channel-margin rows carrying a `margin_source_id`
  join here to attach the source code; the join never fans out the fact side (each fact matches one source).
- **`silver.core.margin_sources`** is a VIEW over this base table (same 2 rows).

## Gotchas
- **Only 2 rows** and no timestamps beyond CDC metadata — a static code lookup.
- **`name` holds only the short code** (DTR / MSS); no long-form description column exists — do not
  attempt to expand the abbreviations from this table.
- **No `deleted` / `is_test` columns** — the dataset-wide hygiene filter does not apply here.

## Cost & partitioning notes
- **BASE TABLE, physical `self`**, no partition, cluster=[margin_source_id], no TTL. `bq show`: numRows=2,
  numBytes=118. Trivially below the billing floor — `SELECT *` freely, or hard-code the 2-value map.
