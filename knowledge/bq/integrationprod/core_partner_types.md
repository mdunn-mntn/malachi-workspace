# integrationprod.core_partner_types

## Purpose
Static reference enum that maps `partner_type_id` → human label (`name`) for the category of an
advertising/measurement partner. Reach for it to decode `core_partners.partner_type_id` into DSP / SSP /
Mobile-Attribution. **3 rows, effectively constant.** Exposed as the `silver.core.partner_types` view.

## Grain & keys
- **Grain:** one row per partner category. Static enum, 3 rows (verified 2026-07-29).
- **Primary key:** `partner_type_id` (INT, 1–3). Unique, no NULLs. Also the sole cluster key.
- **Join column:** `partner_type_id` — FK target for `core_partners.partner_type_id`. This table is
  always the **1-side** of any join.

## Column meanings (only the non-obvious ones)
- **`partner_type_id`** — the enum code, PK, and cluster key. Live domain (full dump, 2026-07-29):

  | partner_type_id | name | meaning |
  |---|---|---|
  | 1 | Demand Side Partner (DSP) | Demand-side platforms (e.g. Trade Desk, Beeswax, MNTN Bidder). |
  | 2 | Supply Side Partner (SSP) | Supply-side / exchange partners (Magnite, Pubmatic, OpenX, …). Bulk of partners. |
  | 3 | Mobile Attribution | Mobile measurement/attribution vendors (AppsFlyer, Adjust, Kochava, Branch, Singular). |

- **`name`** — the clean, authoritative label. Unique per id.
- **`datastream_metadata`** — Datastream CDC lineage RECORD (`uuid`, `source_timestamp`) from the bronze
  CDC pipeline. Not business data.

## Joins & relationships
- **`core_partners.partner_type_id` → `core_partner_types.partner_type_id`** — **N:1** (`core_partners`
  is the many-side; this table is the one-side). As a decode lookup it cannot fan out (1 row per id).
  Current distribution: type 1 = 8 partners, type 2 = 66, type 3 = 5 (2026-07-29).
- **`silver.core.partner_types`** is a VIEW over this table.

## Gotchas
- **No soft-delete columns.** Only `partner_type_id, name, datastream_metadata` — no `deleted`/`is_test`.
  The standard integrationprod dim filter does not apply; read all 3 rows.
- **Static enum** — no late-arriving data, no partitions. Treat as constant.

## Cost & partitioning notes
- **Non-partitioned static dim: 3 rows / ~236 bytes.** No partition, no TTL, no `require_partition_filter`.
  Clustered on `partner_type_id` (a no-op at this size).
- Full `SELECT *` bills only the tier-1 10 MB minimum. Broadcast-join freely.

## Example queries
```sql
-- Decode partner categories (N:1 lookup; never fans out)
SELECT p.partner_id, p.name AS partner, t.name AS partner_type
FROM `dw-main-bronze.integrationprod.core_partners` p
LEFT JOIN `dw-main-bronze.integrationprod.core_partner_types` t USING (partner_type_id);
```
