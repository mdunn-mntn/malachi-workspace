# integrationprod.core_advertiser_channel_margins

## Purpose
Per-advertiser, per-channel pricing/margin configuration: the margins and CPM targets applied to an
advertiser's spend on a given delivery channel. Postgres CDC dim landed via Datastream. Reach for it
to read an advertiser's `budget_margin`, `platform_fee`, `data_margin`, `target_cpm`, or
`ad_buying_cpm` on a channel. Exposed as the `silver.core.advertiser_channel_margins` view
(`SELECT * FROM` this table, verified 2026-07-29).

## Grain & keys
- **Grain:** one row per `(advertiser_id, channel_id)` margin config. 5,866 rows, 3,170 advertisers,
  2 channels; `(advertiser_id, channel_id)` is unique (5,866 pairs, verified 2026-07-29).
- **Primary key:** `advertiser_channel_margin_id` (unique; sole cluster key).
- **Natural key:** `(advertiser_id, channel_id)`.
- **Foreign keys:** `advertiser_id` → `advertisers.advertiser_id`; `channel_id` → `channels.channel_id`;
  `user_id` → the user who set the margin; `margin_reason_id` → `margin_reasons` (unused — all NULL).

## Column meanings (only the non-obvious ones)
- **`channel_id`** — FK to `channels`. Only two values present: **1 = Multi-Touch** (2,697 rows) and
  **8 = Television/CTV** (3,169 rows), per the `channels` decode (verified 2026-07-29).
- **`budget_margin`, `platform_fee`, `data_margin`** — `NUMERIC(5,4)` fractional margins (0.0000–9.9999
  scale; values are fractions, e.g. ~0.46 avg budget_margin on channel 8, ~0.36 on channel 1).
  **`platform_fee` is NULL for most rows.**
- **`target_cpm`, `ad_buying_cpm`** — `NUMERIC(7,4)` dollar CPMs. Avg `target_cpm` ~$18, avg
  `ad_buying_cpm` ~$8.3 across both channels.
- **`margin_reason_id`** — FK to a margin-reason lookup, but **NULL for every row** (0 distinct,
  verified 2026-07-29) — effectively unpopulated in this table.
- **`user_id`** — the internal user who set/last-edited the margin (not an advertiser).
- **`create_time` / `update_time`** — CDC write/update timestamps in source Postgres.
- **`datastream_metadata`** — Datastream CDC lineage RECORD; not business data.

## Joins & relationships
- **`advertiser_id` → `advertisers.advertiser_id`** — N:1 into this table. Joining advertisers to this
  table **fans out ~1.85× per advertiser** (one row per channel they run). Filter `channel_id` (or
  aggregate) to keep the grain.
- **`channel_id` → `channels.channel_id`** — N:1 decode; cannot fan out.
- `silver.core.advertiser_channel_margins` is a `SELECT *` view over this table.
- Related margin tables in the same family (not this table): `core_channel_margins`,
  `campaign_group_channel_margins`, `ttd_advertiser_channel_margins`, and the archive
  `archives_advertiser_channel_margin_archives`.

## Gotchas
- **Fan-out on advertiser joins** — up to 2 rows per advertiser (one per channel). Always constrain or
  aggregate `channel_id`.
- **`platform_fee` and `margin_reason_id` are largely/entirely NULL** — do not assume they carry data.
- **Margins are fractions, CPMs are dollars** — different `NUMERIC` scales; do not mix the two column
  families in one formula without unit care.
- **No `deleted`/`is_test` columns** — standard bronze soft-delete filter does not apply.

## Cost & partitioning notes
- **Non-partitioned dim: 5,866 rows / ~616 KB.** No partition, no TTL, no `require_partition_filter`.
  Clustered on `advertiser_channel_margin_id` (a no-op for advertiser/channel lookups at this size).
- Full `SELECT *` bills the tier-1 10 MB minimum. Broadcast-join it freely.

## Example queries
```sql
-- An advertiser's margins by channel
SELECT m.advertiser_id, c.name AS channel, m.budget_margin, m.data_margin,
       m.target_cpm, m.ad_buying_cpm
FROM `dw-main-bronze.integrationprod.core_advertiser_channel_margins` m
LEFT JOIN `dw-main-bronze.integrationprod.channels` c USING (channel_id)
WHERE m.advertiser_id = @advertiser_id;
```
