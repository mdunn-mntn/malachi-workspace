# integrationprod.archives_advertiser_channel_margin_archives

## Purpose
Versioned edit history (Postgres CDC archive via Datastream) of the per-advertiser, per-channel margin/pricing configuration held live in `core_advertiser_channel_margins`. Each time an advertiser's channel-level margin record is created or changed, a full snapshot of the row is written here. Reach for it to answer "what were advertiser X's CTV/display margin terms as-of date D?" or to reconstruct margin-change timelines. **SENSITIVE — margin/CPM values are pricing data; document schema/grain only, never surface the rate columns externally.**

## Grain & keys
- **Grain:** one row per **(advertiser_channel_margin_id, version)** — a point-in-time snapshot of a single advertiser×channel margin record. Verified: 9,779 rows = 9,779 distinct `advertiser_channel_margin_archive_id` = 9,779 distinct `(advertiser_channel_margin_id, version)` pairs.
- **Surrogate PK:** `advertiser_channel_margin_archive_id` (unique per snapshot; the sole cluster key).
- **Natural key:** `(advertiser_channel_margin_id, version)`.
- **Coverage:** 3,178 distinct base margin records across 2,337 advertisers. No NULLs in `advertiser_channel_margin_id`, `advertiser_id`, `channel_id`, or `version`.

## Column meanings (only the non-obvious ones)
- **advertiser_channel_margin_archive_id** — surrogate PK of the *archive snapshot* (unique per row, cluster key). NOT the base-record id; do not join on this.
- **advertiser_channel_margin_id** — FK to the base record in `core_advertiser_channel_margins`; the same value repeats across every version of that record. Half of the natural key.
- **advertiser_id** — FK to `advertisers.advertiser_id`.
- **channel_id** — delivery channel the margin applies to: **8 = CTV/Television** (7,980 rows), **1 = display / Multi-Touch** (1,798 rows), **0 = sentinel/default** (1 row). Margins are configured per advertiser × channel. Matches the standard MNTN channel map (8=CTV, 1=display).
- **version** — per-`advertiser_channel_margin_id` revision counter, starts at 1, increments on each edit/re-archive. In this table it tracks create/archive order **monotonically within a record** (e.g. acm_id 183 → v1…v15 in time order). `(advertiser_channel_margin_id, version)` is table-wide unique.
- **create_time** — the BASE record's creation timestamp; **CONSTANT across all versions** of a given `advertiser_channel_margin_id` (copied from the base row, not the snapshot write time). Do not use it to order versions.
- **update_time** — the base record's last-modified time as captured in this snapshot; advances across versions and **lags one version behind archive_time** (version N's `update_time` ≈ version N−1's `archive_time`).
- **archive_time** — when THIS snapshot row was written = the effective as-of moment for the version. Use this (or `version`) for as-of ordering.
- **budget_margin / platform_fee / data_margin** — NUMERIC(5,4) rate-fraction fields (margin/fee shares). **target_cpm / ad_buying_cpm** — NUMERIC(7,4) dollar CPMs. Together these are the advertiser×channel pricing/margin config. **SENSITIVE — schema only, never document actual values.**
- **datastream_metadata** — Datastream CDC metadata STRUCT. `.source_timestamp` = CDC-capture epoch in **MILLISECONDS** (verified: ≈ `UNIX_MILLIS(archive_time)` within 0–4 ms for organically-captured rows). NOT business time.

## Joins & relationships
- **→ `core_advertiser_channel_margins`** on `advertiser_channel_margin_id`. Base grain = **exactly 1 row per (advertiser_id, channel_id)** = current margin state (verified: 5,866 rows = 5,866 distinct PK = 5,866 distinct advertiser×channel, 3,170 advertisers). Relationship archive:base = **N:1** (N historical versions per one live record). **Fan-out:** joining base→archive explodes to every version — dedupe to latest with `QUALIFY ROW_NUMBER() OVER (PARTITION BY advertiser_channel_margin_id ORDER BY archive_time DESC) = 1`. Only **2,907 of the archive's 3,178** acm_ids still exist in the base table (271 orphaned — deleted/superseded records the archive retains) → use **LEFT JOIN**, not INNER, when you want full history.
- **.advertiser_id → `advertisers`** on `advertiser_id` (many archive rows : 1 advertiser; dim). Get the name from `advertisers.company_name` (advertiser_name fields are unreliable elsewhere in the stack).
- **channel_id** is a CTV(8)/display(1) indicator, **not a clean FK** to `core_channel_margins` (that dim is keyed on `channel_margin_id` at channel grain).
- **Siblings:** `archives_campaign_group_channel_margin_archives` = same CDC-archive pattern one level finer (campaign_group × channel margin history); `core_ttd_advertiser_channel_margins` = TTD-specific advertiser channel margins. This table is the **advertiser-wide default** channel margin; campaign-group margins override it.

## Gotchas
- **SENSITIVE margin table** — `budget_margin` / `platform_fee` / `data_margin` / `target_cpm` / `ad_buying_cpm` are pricing values; schema/grain only, never surface them externally.
- **No `deleted` / `is_test` columns** on this archive (verify against AUTO:SCHEMA) — the standard `deleted=FALSE AND is_test=FALSE` hygiene filter **cannot be applied here**; apply it on the joined `advertisers` / base table if you need it.
- **`datastream_metadata.source_timestamp` is ms CDC-capture, not business time.** The earliest backfilled versions share ONE `source_timestamp` — the Datastream onboarding snapshot (~2026-... e.g. acm_id 183 v1–v3 all stamped `1766088266942` = 2025-12-18). Never use it as event time; use `archive_time`/`create_time`.
- **`create_time` is the base-record birth (constant across versions)** — do NOT order versions by it; order by `archive_time` (or `version`).
- **`version` is monotonic-per-record HERE, but the `archives_*` family is not universally trustworthy** — `archives_audience_segment_archives.version` wraps/resets (data_knowledge §"version is NON-MONOTONIC"). When in doubt, `ORDER BY archive_time` rather than trusting `version`.
- **271 archived acm_ids have no live base row** (deleted) → LEFT JOIN to base, expect misses.
- **channel_id = 0** appears once (sentinel/default) — exclude it for clean CTV(8)/display(1) splits.

## Cost & partitioning notes
- **Unpartitioned base table** (verified: `timePartitioning None`), clustered by `advertiser_channel_margin_archive_id`. TTL none (archive retains history). Tiny table — ~1.29 MB backing storage (numBytes 1,287,930 = approx_logical_bytes).
- **Dry-run figures (labeled by column set):** `SELECT *` (all 14 cols) = **1,287,930 bytes (~1.29 MB)** = the whole table; `SELECT advertiser_id` (one INT64 col) = **78,232 bytes (~76 KB)**. No partition to prune, so **column pruning is the only lever** — `SELECT *` reads ~16× a single-column scan here.
- **The one filter to apply:** there's no partition; scope by `advertiser_channel_margin_id` (leverages clustering) or `advertiser_id`/`channel_id`. At ~1.3 MB a full scan is negligible regardless — just avoid `SELECT *` when you only need ids/timestamps (it drags in the sensitive NUMERIC columns too).

## Example queries
```sql
-- Latest margin snapshot per advertiser×channel (non-sensitive cols only), as-of history
SELECT advertiser_channel_margin_id, advertiser_id, channel_id, version, create_time, archive_time
FROM `dw-main-bronze.integrationprod.archives_advertiser_channel_margin_archives`
QUALIFY ROW_NUMBER() OVER (
          PARTITION BY advertiser_channel_margin_id
          ORDER BY archive_time DESC) = 1
```
