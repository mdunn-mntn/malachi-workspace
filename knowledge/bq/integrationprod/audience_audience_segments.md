# integrationprod.audience_audience_segments

## Purpose
Canonical Postgres dim (Datastream CDC) holding the **per-segment, compiled targeting expressions** that make up each live audience. Each audience (`audience_audiences`, one row per `audience_id`) fans out to ~10.8 rows here — one per targeting segment / campaign. This is the layer where the **Fangorn "audience overlay"** is written: the flip adds a `"data_source_id":46` reference to the segment `expression` here while the base `audience_audiences.expression` keeps DS13/DS19 (MM). Reach for this table to (a) read the actual compiled targeting/scoring/holdout expression a campaign runs, and (b) identify Fangorn-on advertisers from BigQuery when Postgres `tpa.fangorn_advertiser_inclusion` is unreachable.

## Grain & keys
- **Grain:** one row per `audience_segment_id` — a single compiled targeting-segment expression scoped to one `audience_id` and one `campaign_id`. Confirmed unique: 445,983 rows = 445,983 distinct `audience_segment_id` (2026-07-19).
- **Primary key:** `audience_segment_id` (surrogate; this table's own key — **NOT** an FK to the separate `audience_segments` table despite the name).
- **Parent FK:** `audience_id` → `audience_audiences.audience_id` (N:1; all 41,427 distinct values resolve). This is the real bridge key: **1 audience : ~10.8 segment rows**.
- **Other FKs:** `campaign_id` → `campaigns.campaign_id` (N:1); `expression_type_id` → `audience_expression_types` (N:1 lookup).
- **No `deleted` / `is_test` columns** — the standard `integrationprod` dim filter (`deleted=FALSE AND is_test=FALSE`) does **not** apply here (only 10 columns; see AUTO:SCHEMA). Every replicated row is "live."

## Column meanings (only the non-obvious ones)
- **audience_segment_id** — surrogate PK of this row (unique). Also the sole cluster key. Misleading name: it is **not** a foreign key into the `audience_segments` table.
- **audience_id** — FK → `audience_audiences.audience_id`. The audience this segment belongs to; N:1. Non-null; 100% resolve.
- **campaign_id** — FK → `campaigns.campaign_id`; the campaign this compiled segment serves. Not unique (322,651 distinct); a single audience's rows span multiple `campaign_id`s. Use `campaigns.funnel_level` for stage (not `objective_id`).
- **segment_id** — the targeting-segment identifier for this row. Repeats (351,372 distinct / 445,983 rows) and only **5.9% overlaps** `audience_segments.segment_id` (20,871/351,372) — treat as a within-table id, **not** a clean FK to `audience_segments`.
- **expression** — the targeting/scoring payload (STRING). Form depends on `expression_type_id`:
  - type 1 (`opm`): plaintext predicate, e.g. `UserCustomIdentifiers contains "ego_ads=1"`.
  - type 2 (`tpa`): compiled JSON v2, e.g. `{"version":"2","select":[{"count":{"name":"holdout","where":{"op":"bucket","value":{"md5":{"prefix":"<advertiser_id>:","num_buckets":1000,"bucket_beg":0,"bucket_end":99}}}}},{"score":...}]}`. Encodes the **10% holdout** (md5 prefix = `advertiser_id`, buckets 0–99), score types, and `"data_source_id":N` refs — **this is where DS46 (Fangorn) / DS13 / DS19 appear.** Largest column by bytes (~91% of table storage; measured).
- **expression_type_id** — FK → `audience_expression_types`. Domain seen here: **1=`opm`, 2=`tpa`** (lookup also defines 3=`sga`, unused in this table). Type 2 rows are the JSON `tpa` expressions the Fangorn/DS pattern parses.
- **is_targeted** — BOOL. `true` = segment used for positive targeting (285,652 rows, all type 2); `false` = not targeted (all 123,131 type-1/`opm` rows + 37,200 type-2). Filter `is_targeted=true` for active positive-targeting expressions.
- **create_time / update_time** — native `TIMESTAMP` (UTC), business insert / last-modify. Use these for recency. (UTC caveat: rows can show tomorrow's date relative to US-local.)
- **datastream_metadata.source_timestamp** — INT64 **milliseconds** epoch of the Datastream CDC capture (`= UNIX_MILLIS`; 13-digit; lands ~2s after `update_time`). CDC plumbing, **not** business time — prefer `create_time`/`update_time`.

## Joins & relationships
- **audience_id → `audience_audiences.audience_id`** — parent audience, **N:1**. `audience_audiences` is 1 row per `audience_id` (64,495 rows; PK). **Fan-out warning:** driving from `audience_audiences` INTO this table explodes **1 : ~10.8** (and only 41,427 of 64,495 audiences have segment rows).
- **campaign_id → `campaigns.campaign_id`** — **N:1** (many segment rows per campaign). Fan-out warning: joining `campaigns` → here multiplies campaign rows.
- **expression_type_id → `audience_expression_types`** — N:1 tiny lookup (`opm`/`tpa`/`sga`).
- **audience_id → `audience_audience_x_campaign_groups.audience_id`** — bridge to campaign_groups; used in the Fangorn advertiser-resolution pattern (see prose §data_catalog + Example queries below).
- **segment_id → `audience_segments.segment_id`** — **do NOT rely on this** (5.9% overlap; different id space). `audience_segments` is a separate advertiser-keyed table (PK `segment_id`, 112,836 rows, 1:1).
- **Fangorn model:** DS46 in a segment `expression` here = Fangorn scoring overlay on top of a DS13/DS19 MM base that still shows in `audience_audiences`. At segment level DS13 and DS46 **never co-occur** (flip swaps 13→46); DS19 survives the flip (TI-1037 / `reference_fangorn_audience_overlay`).

## Gotchas
- **No `deleted` / `is_test` columns** — cannot apply the standard bronze-dim live filter; do not add it. Lifecycle/version history lives in `archives_audience_segment_archives`.
- **`audience_segment_id` is this table's PK, not an FK** to `audience_segments` (name is misleading). And **`segment_id` mostly does not exist in `audience_segments`** (5.9% overlap) — don't join naively.
- **Fangorn overlay is written HERE, base stays in `audience_audiences`.** DS46-in-segments → Fangorn-on; DS13/DS19-in-segments → MM/non-Fangorn. The BQ DS46 advertiser count **lags** Postgres `tpa.fangorn_advertiser_inclusion` (authoritative) because freshly flipped advertisers may not yet have segments updated — cross-check before claiming exact tier identification.
- **`expression` (type 2) is a large JSON blob** — parse with `REGEXP_CONTAINS` / JSON functions; it dominates scan bytes.
- **`is_targeted=false`** mixes type-1 (`opm`) non-target rows with some type-2 rows — filter `is_targeted=true` for active positive targeting.
- **`source_timestamp` is CDC-capture ms**, ~2s after `update_time`; not business time. `create_time`/`update_time` are UTC.

## Cost & partitioning notes
BASE dim — **no partition, no TTL**. Clustered on `audience_segment_id`. `numBytes = 492,610,102` (~470 MiB) = the whole table (2026-07-19). The `expression` JSON column carries ~91% of bytes (measured, below), so cost is driven almost entirely by whether you SELECT it.

Measured dry-runs (2026-07-20, exact column sets):
- `SELECT *` (all 10 cols): **492,610,102 B (~470 MiB / 0.459 GB)** — equals numBytes.
- `SELECT expression` (the one big col): **447,489,557 B (~427 MiB / 0.417 GB)** — **~91% of the table**; the 9 other cols sum to 45,120,545 B (~9%).
- `SELECT audience_id, expression WHERE expression_type_id=2` (Fangorn set): **454,625,285 B (~434 MiB / 0.423 GB)** — the WHERE does **not** prune (no partition); this is `expression` + `audience_id` over all rows.
- `SELECT audience_segment_id` (one narrow col): **3,567,864 B (~3.4 MiB / 0.0033 GB)** — **138x cheaper than `SELECT *`**.

**Always-apply rule:** partitionless dim → project only the columns you need; never `SELECT *`, and pull `expression` only when you must parse it. Filtering `expression_type_id` / `is_targeted` does **not** reduce scanned bytes (no partition prune) — it's for correctness only.

## Example queries
```sql
-- Fangorn-on audience_ids from BigQuery (proxy for Postgres tpa.fangorn_advertiser_inclusion)
SELECT DISTINCT audience_id
FROM `dw-main-bronze.integrationprod.audience_audience_segments`
WHERE expression_type_id = 2                    -- tpa (JSON) expressions only
  AND REGEXP_CONTAINS(expression, r'"data_source_id":46');   -- DS46 overlay = Fangorn

-- Active positive-targeting expressions for one audience
SELECT audience_segment_id, campaign_id, expression
FROM `dw-main-bronze.integrationprod.audience_audience_segments`
WHERE audience_id = <audience_id> AND is_targeted = TRUE;
```
