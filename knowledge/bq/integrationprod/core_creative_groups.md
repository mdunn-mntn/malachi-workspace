# integrationprod.core_creative_groups

## Purpose
The MNTN **creative group** dimension — one row per named group of creatives plus its serving
configuration, attached to a campaign. A creative group bundles the creatives that rotate together, the
landing/click URL and URL prefix/suffix, frequency caps, rotation weight, control-holdout percentage, and
tracking-override flags. Reach for it to resolve a `group_id` (from the `core_creative_groups_x_creatives`
junction or logs) to its campaign, active state, and serving config. Base Postgres-CDC replica; exposed as
the `silver.core.creative_groups` VIEW.

This table is the **parent of three child tables**: the `core_creative_groups_x_creatives` junction (group
↔ creative) and the two per-group tracking-URL tables (`core_creative_groups_impression_tracking_urls`,
`core_creative_groups_visit_tracking_urls`). Note the child tables' FK is spelled `creative_group_id`
while the PK here is `group_id`.

## Grain & keys
- **Grain:** one row per **`group_id`** — verified 1:1 (rows 950,780 == COUNT(DISTINCT group_id), 2026-07-29).
- **Primary key:** `group_id` (INT64).
- **Foreign keys / join columns:**
  - `campaign_id` → `campaigns.campaign_id` — **N:1**, 0 NULL, 250,948 distinct campaigns (~3.8 groups/campaign).
  - `group_id` is the FK target for `core_creative_groups_x_creatives.group_id`,
    `core_creative_groups_impression_tracking_urls.creative_group_id`, and
    `core_creative_groups_visit_tracking_urls.creative_group_id`.
  - `parent_group_id` — self-reference to another `group_id` (group nesting/hierarchy); `user_id` → creating user.

## Column meanings (only the non-obvious ones)
- **`active`** (BOOL) — liveness flag; **73% TRUE** (697,160 / 950,780). Use this to filter to serviceable
  groups (there is no `deleted`/`is_test` column on this table).
- **`is_control`** (BOOL) / **`control_percentage`** (INT64) — holdout/control-group flag and its percentage.
  `is_control=TRUE` is **rare — 283 rows** (control creative groups, distinct from the platform-wide 10% IP
  holdout).
- **`weight`** (INT64) — creative-group rotation weight (relative serving share among sibling groups).
- **`imp_limit_day` / `imp_limit_user_day`** (INT64) — frequency caps: impressions/day for the group and
  impressions/day per user.
- **`delivery_mode_id`** (INT64) — serving-mode enum, **85% NULL**; populated values observed: 2 (93,039),
  1 (44,845), 3 (1,429). Small enum; no lookup table resolved here.
- **`escalation_type_id` / `escalating_order` / `escalation_limit`** — escalation config; `escalation_type_id`
  is **99.97% NULL** (only 259 rows =1, 50 rows =2). Rarely used.
- **`impression_tracking`** (STRING) / **`override_impression_tracking`**, **`override_visit_tracking`** (BOOL)
  — inline impression-tracking markup and the flags that say the group overrides campaign-level tracking with
  its own child `*_tracking_urls` rows.
- **`click_url` / `display_url` / `url_prefix` / `url_suffix`** — landing/click destination and the
  prefix/suffix wrapped around served click URLs.
- **`dpp_id` (STRING) / `dpp_filter` (STRING)** — dynamic-product-placement id/filter config.
- **`has_dynamic`** (BOOL) — **always FALSE** across all 950,780 rows (non-discriminating).
- **`mycreative_group_id` / `mycreative_video_group_id` / `template_group_id` / `ui_creative_group_id`** —
  cross-system linkage to the MyCreative builder and UI creative-group records (see `ui_ui_creative_groups`,
  `ui_mycreative_groups` siblings).
- **`snapshot` / `ui_creative_groups_version` / `ui_creative_group_schedule`** — opaque STRING config /
  serialized (JSON-like) blobs, not columnar fields.
- **`sequence_number` / `ordinal` / `parent_group_id`** — group ordering and nesting within a parent group.
- **`create_time` / `update_time`** — TIMESTAMP (application-layer), not epoch INT.
- **`datastream_metadata`** — Datastream CDC lineage RECORD; not business data.

## Joins & relationships
- **`campaign_id` → `campaigns`** (`campaign_id`): **N:1**; safe from this table (many groups per campaign),
  fans out the other way.
- **Group ↔ creative is many-to-many via `core_creative_groups_x_creatives`** (junction PK
  `group_id, creative_id`). There is **no `creative_id` column on this table** — go
  `core_creative_groups.group_id → core_creative_groups_x_creatives.group_id → .creative_id → creatives.creative_id`.
  In practice the junction is ~1:1 on the creative side (see that doc), but treat group→junction as a fan-out.
- **Child tracking URLs:** `core_creative_groups_impression_tracking_urls.creative_group_id` and
  `core_creative_groups_visit_tracking_urls.creative_group_id` both point at `group_id` — **1:N** (a group can
  have several tracking URLs). ~6,908 groups have no `x_creatives` link (943,872 groups appear in the junction
  vs 950,780 total).
- **`silver.core.creative_groups`** is a VIEW over this table (verified present 2026-07-29).

## Gotchas
- **Child FK name mismatch:** children use `creative_group_id`; the PK here is `group_id`. Join on
  `child.creative_group_id = core_creative_groups.group_id`.
- **No `deleted` / `is_test` columns** — filter liveness via `active` (73% TRUE), not the standard soft-delete
  dim filter.
- **`has_dynamic` is always FALSE**; **`escalation_type_id` and `delivery_mode_id` are mostly NULL** — guard
  for NULL rather than assuming population.
- **`snapshot` / `ui_*_version` / `ui_creative_group_schedule` are opaque serialized blobs** — do not treat as
  structured columns; parse only if you know the payload format.
- Not every group is linked to a creative (~6.9K groups absent from the junction).

## Cost & partitioning notes
- **No partition, no TTL** (base dim). ~950K rows / ~329 MB backing storage; clustered on `group_id` (helps
  point-lookups by group). The cost lever is **column pruning** — avoid `SELECT *` when you only need
  `group_id, campaign_id, active`; the STRING config blobs (`snapshot`, URLs, `impression_tracking`) are the
  bulk of the bytes.
- `require_partition_filter: false` — nothing to prune by date; filter by `campaign_id`/`group_id`.

## Example queries
```sql
-- Active creative groups for a campaign
SELECT group_id, name, weight, imp_limit_day, is_control, control_percentage
FROM `dw-main-bronze.integrationprod.core_creative_groups`
WHERE campaign_id = @campaign_id AND active = TRUE;

-- Group -> creatives (via junction), then to the creative dim
SELECT g.group_id, x.creative_id, cr.name
FROM `dw-main-bronze.integrationprod.core_creative_groups` g
JOIN `dw-main-bronze.integrationprod.core_creative_groups_x_creatives` x ON x.group_id = g.group_id
JOIN `dw-main-bronze.integrationprod.creatives` cr ON cr.creative_id = x.creative_id
WHERE g.group_id = @group_id;
```
