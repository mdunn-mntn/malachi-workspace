# integrationprod.ui_third_party_audiences

## Purpose
Registry/config of **third-party B2B custom audiences** created through MNTN's `b2beacon`
integration — primarily **Bombora** firmographic / demographic / ABM (account-based marketing)
segments built in the UI or via the public API. One row is written each time a user (or the API)
creates a third-party audience; the row carries the abstract targeting `criteria`, the provider it
was sent to, the provider's assigned segment IDs, and the request/response payloads.

**Net-new, pre-production table.** Created 2026-06-29; every one of the 11 rows present on
2026-07-20 is a smoke / debug / QA / E2E test row (names like "Codex Bombora smoke…",
"B2B Test Segment For QA Audience", "zz-abm-api-e2e-audience - safe to delete"). Do **not** treat
current contents as real production audiences. This is the delivery-side registry for the
AUDI Bombora B2B audience-design initiative (ElevenLabs et al.).

## Grain & keys
- **Grain:** one row per third-party audience.
- **Primary key:** `audience_id` (surrogate, also the cluster key). Auto-increment; the sequence
  starts at **2** in live data (0/1 not present).
- **No soft-delete columns.** This table has **no `deleted` / `is_test` columns**, so the standard
  `deleted=FALSE AND is_test=FALSE` integrationprod filter does **not** apply here.

## Column meanings (only the non-obvious ones)
- **`audience_id`** — surrogate PK / cluster key. Sequence starts at 2 in live data.
- **`category_id`** — the MNTN-side **category/segment slot** the audience is delivered into. It is
  echoed back as `request_metadata.categoryId`, as the provider's returned `externalId`, and (in the
  current test rows) as the provider `audienceId`. In this data it runs ~1:1 with `audience_id`
  (16→27), but it is a **distinct field**. **NOT a foreign key to `integrationprod.categories`** —
  values 16-27 only coincide with `categories` rows for an unrelated `data_source_id=16`; treat
  `category_id` as an internal b2beacon slot id, not a DDP-taxonomy category.
- **`data_source_id`** — DSxx data source of the provider. **51 = Bombora** (real `data_sources` row,
  `data_source_type_id=1`). **0 = placeholder** used only by the `mock` test provider (there is **no
  `data_sources` row for id 0**). Nominal FK to `data_sources.data_source_id`.
- **`provider`** — third-party vendor slug. Observed: **`bombora`** (live b2beacon integration) and
  **`mock`** (static test fixture, always paired with `data_source_id=0`).
- **`advertiser_id`** — advertiser the audience is built for; FK to `advertisers`. `32167` is the
  internal test advertiser (also the destination in Bombora `destinationConfig.advertiserId`); other
  values (`42001`, `987654321`, `99999901`) are fabricated test IDs.
- **`name` / `description`** — human labels; all test/debug strings currently.
- **`criteria`** — **MNTN's provider-agnostic audience-definition DSL** (the abstract targeting spec
  from the UI, before provider translation). Shape:
  `{"field","operator","type":"condition","value":{"type","value"|"values"}}`. Observed fields:
  `industry` (`equals`, string) and `domain` (`in`, `stringList` whose values look like
  `"accountList:<uuid>"` for ABM account-list targeting). Compound criteria use `and`/nested nodes.
- **`status`** — lifecycle enum. Observed: **`draft`**, **`created`**. (No active/expired values yet.)
- **`expiration_time`** — when the audience expires; nullable (often NULL or a far-future
  `2026-12-31` in test rows).
- **`request_metadata`** — JSON of the create-request payload: `categoryId`, provenance fields
  (`owner`/`testRun`/`runId`/`smoke`/`source`), and a **`segmentUsage`** object with the flags
  `usesAbmB2bInterestSegments` and `usesFirmographicDemographicSegments` describing which B2B segment
  families the audience draws on.
- **`response_metadata`** — JSON echo of the provider API response: `audienceId`, `categoryId`,
  `providerIdentifiers`, `providerMetadata`, `status`.
- **`provider_identifiers`** — provider-assigned IDs. Early rows: `{"categoryId":…}`. Bombora rows:
  `{"externalId","segmentId"}` where **`segmentId`** = the Bombora b2beacon audience-segment UUID and
  **`externalId`** = the numeric MNTN-side external id.
- **`provider_metadata`** — provider-specific detail (largest column). For Bombora it holds the full
  b2beacon **`audienceDefinition`** + **`audienceSegment`** objects: `targetingCriteria` in Bombora's
  *own* DSL (`{"a":<attr>,"eq"|"in":…}`), `tags` (`Firmographic` / `Demographic` / `Geographic` /
  `ABM`), `platform:"mntn"`, `status:"DRAFT"`, `destinationConfig{advertiserId,externalId}`,
  `expirationDate`, and `estimatedReach` (NULL in all test rows).
- **`create_time` / `update_time`** — Postgres row timestamps. **`update_time` is NULL on every
  row** (no row has been updated post-insert).
- **`datastream_metadata`** — Datastream CDC struct `{uuid, source_timestamp}`. `source_timestamp` =
  **milliseconds** CDC-capture epoch (`UNIX_MILLIS`), i.e. capture time not business time — but ≈
  `create_time` for inserts. Anchor: `1784558132598` ms → 2026-07-20 14:35:32 UTC = `create_time` of
  `audience_id=12`.

## Joins & relationships
- **`data_source_id` → `integrationprod.data_sources.data_source_id`** — N:1. `data_sources` is a
  small dim (1 row per source), no fan-out. Bombora = 51; `data_source_id=0` has no partner row
  (mock placeholder).
- **`advertiser_id` → `integrationprod.advertisers`** — N:1 to a per-advertiser dim, no fan-out.
- **`category_id`** — internal b2beacon slot id, **not** a join to `integrationprod.categories`
  (see Column meanings). Do not join it to the DDP category taxonomy.
- **No observed child table** materializing IPs/reach for these audiences yet (net-new, pre-prod).
  This table appears alongside the DDP/usage-reporting query family (AUDI-1089:
  `audience_uploads`, `categories`, `external.tpa__*` taxonomies, `coredw.usage_reporting_data`) but
  is not directly joined to them in those queries.

## Gotchas
- **Test data only (2026-07).** All 11 rows are smoke/debug/QA/E2E fixtures. Not production
  audiences; counts and reach are meaningless. Table went live 2026-06-29.
- **No `deleted`/`is_test` columns** → the standard integrationprod live-row filter is N/A here.
- **`update_time` is always NULL** — don't use it for freshness; use `create_time` (or
  `datastream_metadata.source_timestamp`, ms).
- **`category_id` is NOT a `categories` FK** — it's an internal delivery-slot id that happens to run
  ~1:1 with `audience_id` in the current rows.
- **`data_source_id=0` is a mock placeholder** with no `data_sources` row; only `provider='mock'`
  rows use it. Real Bombora audiences are `data_source_id=51`.
- **`audience_id` sequence starts at 2**, not 0/1.
- **`datastream_metadata.source_timestamp` is ms CDC-capture time**, not business time.

## Cost & partitioning notes
- **No partition** (`timePartitioning=null`), clustered by `audience_id`. Tiny dim — physical size
  **13,416 bytes** total (`bq show numBytes`), so there is no partition to filter and full scans are
  effectively free.
- Dry-run byte estimates (labeled by column set — same-column-set only comparisons):
  - `SELECT *` → **13,416 B** (whole table).
  - narrow `SELECT audience_id, provider, status` → **267 B**.
  - single JSON `SELECT provider_metadata` → **4,026 B** (the heavy JSON columns —
    `provider_metadata`, `response_metadata` — dominate storage).
- Only cost discipline: the table is negligible, but avoid `SELECT *` habitually — pull the JSON
  columns (`provider_metadata`/`response_metadata`) only when you actually need them.

## Example queries
```sql
-- All live third-party audiences (exclude mock fixtures), newest first
SELECT audience_id, provider, data_source_id, advertiser_id, status, name,
       JSON_VALUE(criteria, '$.field') AS criteria_field, create_time
FROM `dw-main-bronze.integrationprod.ui_third_party_audiences`
WHERE provider != 'mock'          -- drop mock/test fixtures (data_source_id=0)
ORDER BY create_time DESC;

-- Bombora segment IDs + targeting tags
SELECT audience_id, advertiser_id,
       JSON_VALUE(provider_identifiers, '$.segmentId')  AS bombora_segment_id,
       JSON_VALUE(provider_identifiers, '$.externalId') AS external_id,
       JSON_QUERY(provider_metadata, '$.audienceDefinition.tags') AS tags
FROM `dw-main-bronze.integrationprod.ui_third_party_audiences`
WHERE data_source_id = 51;        -- Bombora
```
