# integrationprod.core_icloud_blacklist

## Purpose
Tiny per-advertiser control table for **Apple iCloud Private Relay** handling. Apple Private Relay masks
the client IP, which degrades IP-based verified visits, audience targeting, and conversion attribution.
This table names the advertisers flagged for special iCloud treatment and carries a boolean per pipeline
(`verified_visits`, `audience_targeting`, `conversion_attribution`) indicating whether that pipeline is
affected/excluded for the advertiser. Reach for it only to check whether a specific advertiser is on the
iCloud list. `silver.core.icloud_blacklist` is a plain `SELECT *` view over this base table.

## Grain & keys
- **Grain:** one row per advertiser. **2 rows** live (advertiser_id 22955, 22607).
- **Primary key:** `advertiser_id` (also the sole cluster key).
- **FK:** `advertiser_id` → `advertisers.id`.

## Column meanings (only the non-obvious ones)
- **advertiser_id** — the advertiser this iCloud rule applies to (PK). Only 2 advertisers are listed.
- **verified_visits / audience_targeting / conversion_attribution** — three independent BOOL flags, one
  per downstream pipeline, marking whether iCloud Private Relay handling applies to that pipeline for the
  advertiser. **Both live rows have all three `TRUE`.** The exact polarity (TRUE = "exclude/blacklist
  from" vs "apply special handling in") is not decodable from the 2 source rows — treat as an
  advertiser-level iCloud flag per pipeline; confirm intended semantics with the owning team before
  wiring it into logic.
- **create_time / update_time** — business TIMESTAMP (UTC). Both rows created 2022-10-01; one has a later
  `update_time`, the other NULL (never edited).
- **datastream_metadata.source_timestamp** — INT64 **milliseconds** CDC-capture epoch
  (`TIMESTAMP_MILLIS`), not business time.

## Joins & relationships
- **`advertisers`** (dim, 1:1): `advertiser_id` → `advertisers.id`. Lookup-only; joining onto this 2-row
  table never fans out the advertiser side.
- **`silver.core.icloud_blacklist`** is a `SELECT *` view over this base table;
  **`silver.core.v_icloud_blacklist`** is a variant view (projection may differ).

## Gotchas
- **Only 2 rows.** This is effectively an allow/deny exception list, not a broad dimension.
- **All three flags are TRUE on both live rows** — you cannot infer per-flag polarity or independence
  from the current data.
- **No `deleted` / `is_test` columns** — the dataset-wide hygiene filter does not apply here.
- **`update_time` NULL on an un-edited row** — not a reliable recency signal.
- **`source_timestamp` is ms CDC-capture, not business time** — use `create_time`/`update_time` for age.

## Cost & partitioning notes
- **BASE TABLE, physical `self`**, no partition, cluster=[advertiser_id], no TTL. `bq show`: numRows=2,
  numBytes=138. Whole table is well under the 10 MB billing floor. `SELECT *` freely.
