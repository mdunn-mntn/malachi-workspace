# integrationprod.core_segmentation_defaults

## Purpose
Tiny bronze CDC replica dimension holding MNTN's **default audience-segmentation rules** — one row per
packaged targeting expression written in the segment DSL (`UserLastVisitTime`, `UserNumPageViews`,
`UserCartQuantity`, `UserCustomIdentifiers contains …`, etc.). Reach for it to read the actual rule text
behind a segment type (e.g. what "Cart" or "High Intent C" evaluates to), or to see which rule is
auto-appended. This is the physical Postgres-CDC table behind the thin silver view
`dw-main-silver.core.segmentation_defaults` (`SELECT * FROM dw-main-bronze.integrationprod.core_segmentation_defaults`)
— no SQLMesh, no transform. As of 2026-07-29 the domain is exactly 7 rows, ids contiguous 1-7 (verified live):

| id | section | name | auto_append | expression (live, abridged) |
|---|---|---|---|---|
| 1 | 1 | Auto Default | true | `(UserLastVisitTime >= 30,day AND UserNumPageViews >= 2)` |
| 2 | 1 | Cart | false | `UserLastVisitTime >= 30,day AND (UserCartQuantity/Value >= 1 OR UserPageViews/CustomIdentifiers contains "cart"/"checkout")` |
| 3 | 1 | 5+ PV | false | `(UserLastVisitTime >= 30,day AND UserNumPageViews >= 5)` |
| 4 | 1 | High Intent C | false | `UserLastVisitTime >= 30,day and UserNumVisits >= 1 and (contains "/cart"/"/signup"/"/checkout"/"cart")` |
| 5 | 2 | Ego | false | `UserCustomIdentifiers contains "ego_ads=1"` |
| 6 | 1 | 1+ PV | false | `(UserLastVisitTime >= 30,day AND UserNumPageViews >= 1)` |
| 7 | 1 | 1+ Conversion | false | `(UserNumConversions >= 1 AND UserNumPageViews >= 1)` |

## Grain & keys
- **Grain:** one row per default segmentation rule. Static lookup — 7 rows total (verified live 2026-07-29).
- **Primary key:** `segmentation_default_id` (INT64, unique; the physical is clustered on it).
- **Referenced by:** `core_segment_types.segmentation_default_id` (this dim is the 1 side).
- **No `deleted` / `is_test` columns** — the usual live-row filter does not apply; all 7 rows are always live.

## Column meanings (only the non-obvious ones)
- **`segmentation_default_id`** — enum PK, sole cluster key. Domain = contiguous {1..7}. This is the value stored in `core_segment_types.segmentation_default_id`.
- **`expression`** — the targeting rule in MNTN's audience segment DSL (a free-text predicate string, not SQL). Operators seen live: `UserLastVisitTime >= 30,day`, `UserNumPageViews >= N`, `UserNumVisits`, `UserNumConversions`, `UserCartQuantity/UserCartValue >= 1`, `UserPageViews contains "…"`, `UserCustomIdentifiers contains "…"`, combined with `AND`/`OR`. Parse/interpret, don't join on it.
- **`segmentation_section_id`** — groups rules into sections; live values are 1 (page-view / visit / cart / conversion retargeting rules, 6 of 7) and 2 (Ego). No section-name lookup table is dereferenced here.
- **`auto_append`** — BOOL; only `Auto Default` (id 1) is `true` — that rule is auto-appended by default. All other rules are opt-in (`false`).
- **`created_at`** — Postgres row-creation TIMESTAMP (2018-02-21 → 2022-01-21). Business time.
- **`datastream_metadata`** — STRUCT<uuid STRING, source_timestamp INT64>; `source_timestamp` = millisecond CDC-capture epoch (not business time — use `created_at`). `uuid` = CDC event id.

## Joins & relationships
- **`core_segment_types.segmentation_default_id` → this.`segmentation_default_id`** — N:1 (many segment types point at one default; 6 of 13 segment types have a NULL default, so use a LEFT join from segment_types). This dim is the 1 side; no fan-out when joined from segment_types.
- No further FK is dereferenced here (`segmentation_section_id` has no resolved lookup table in this catalog).

## Gotchas
- **`expression` is a DSL string, not SQL** — it encodes the audience rule but cannot be executed as SQL directly; don't try to `WHERE`-filter with it.
- **No soft-delete columns.** No `deleted`/`is_test` — do not add those predicates (they will error). All 7 rows are live.
- **`auto_append` is true for exactly one row** (Auto Default) — that's the only rule appended by default.
- **Static lookup** — treat as frozen; a net-new rule would appear as an 8th row (last verified 7 rows on 2026-07-29).

## Example queries
```sql
-- read the default rule behind each segment type (prefer silver views)
SELECT st.segment_type_id, st.name AS segment_type, sd.name AS default_name,
       sd.auto_append, sd.expression
FROM `dw-main-silver.core.segment_types` st
LEFT JOIN `dw-main-silver.core.segmentation_defaults` sd USING (segmentation_default_id)
ORDER BY st.segment_type_id;
```
