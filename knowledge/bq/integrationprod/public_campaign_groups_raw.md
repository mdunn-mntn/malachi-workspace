# integrationprod.public_campaign_groups_raw

## Purpose
Datastream CDC **landing table** — the closest BigQuery replica of coredb's Postgres `public.campaign_groups`. This is the campaign-group dimension (the flight/line-item-parent = "client campaign" unit and primary budget-allocation entity). It is one of **four BQ variants** of the same Postgres source, all of which agree exactly on `product_id`:

| Table | What it is | Use when |
|---|---|---|
| **`public_campaign_groups_raw`** (this doc) | CDC landing table, closest to source. Has `datastream_metadata`, declared PK, clustered. | Pipelines / Spark / Databricks; incremental reads via `datastream_metadata.source_timestamp`. |
| `public_campaign_groups` | SQLMesh versioned view over this raw table. | Raw-equivalent with SQLMesh applied. |
| `campaign_groups` | SQLMesh analytical table — enriched/cleaned columns (`update_time_raw`, `has_audience_raw`, denormalized `campaign_group_status` name, budget/flight joined in). | Day-to-day analytics. |
| `campaign_groups_raw` | SQLMesh staging intermediate. | Rarely queried directly. |

Reach for this table when you want the source-of-truth `product_id` (Select vs PTV) in a pipeline, or a near-real-time CDC snapshot for incremental processing.

## Grain & keys
- **Grain:** exactly **one row per `campaign_group_id`** — current-state upsert snapshot (verified 2026-07-19: n_rows = n_distinct campaign_group_id = 129,390). **Not versioned** — for as-of history use `archives_campaign_group_archives`.
- **Primary key:** `campaign_group_id` (declared `tableConstraints.primaryKey`; also the sole cluster key).
- **Key FKs:** `advertiser_id` → advertisers; `parent_campaign_group_id` → self (nested groups); `user_id` → owning user; `product_id`/`objective_id`/`goal_type_id`/`campaign_group_status_id`/`pacing_type_id`/`delivery_mode_id`/`publisher_type_id`/`platform_id` → `core_*` lookups.

## Column meanings (only the non-obvious ones)
- **`product_id`** — MNTN product line. Domain (verified 2026-07-19): `1`=PTV (128,797 rows), `2`=Select (593). `3`=QuickFrame exists in `core_products` but no groups carry it. **Source of truth** for Select vs PTV (flows to reporting + invoices); **immutable** — verified across 735K archive versions, never changes after creation. All four table variants agree exactly. Select began 2025-07-31 (zero rows before).
- **`objective_id`** — group-level marketing objective. Domain (verified): `1` (78,134), `5` (29,026), `4` (20,698), `3` (1,499), NULL (33). **UNRELIABLE for funnel stage** — use `campaigns.funnel_level` (authoritative) for prospecting/retargeting classification; this column is on the *group*, not the *campaign*.
- **`goal_type_id` / `goal_type_name`** — optimization goal. Domain (verified): `13`=CostPerVisit (dominant), `14`=CostPerCompletedView, `1`=ROAS, `16`=CPA, plus `0`/`9` (often unlabeled). `goal_type_name` is denormalized and **occasionally NULL or mismatched** against `goal_type_id` (e.g. id `0`/`9` rows appear both with a name and NULL) — treat the id as canonical.
- **`goal_value`** — NUMERIC(12,2) target value for the chosen `goal_type` (e.g. the CPV/CPA target).
- **`campaign_group_status_id`** — status enum. Domain (verified): `8` (48,027), `1` (32,691), `3` (15,487), `9` (14,859), `4` (10,164), `5` (8,101), NULL (61). Name lives in a `core_*` lookup — **this raw table does NOT carry the denormalized `campaign_group_status` name** (that is added on the analytical `campaign_groups` table).
- **`pacing_type_id`** (`1`=91,492 / `2`=32,932 / `0`=4,966), **`delivery_mode_id`** (`2`=113,130 dominant / `1`=16,175 / `3`=85), **`publisher_type_id`** (`1`=129,363 / `2`=27), **`platform_id`** (`1`=124,071 / `2`=5,319) — config enums; resolve names via `core_*` lookups.
- **`parent_campaign_group_id`** — self-FK for nested/child campaign groups. Populated for ~29K rows (~22%); NULL = top-level group. Used for parent/child resolution in Fangorn/audience joins (match on `campaign_group_id` OR `parent_campaign_group_id`).
- **`cgid_link_id`** — near-always NULL (only 10 populated rows table-wide); ignore unless specifically needed.
- **`click_conversion_window` / `view_conversion_window` / `frequency_cap_duration`** — INTERVAL (Postgres interval durations), not integers. `frequency_cap_impressions` is the paired INT cap count.
- **`extension_budget_split`** — NUMERIC(12,2) split fraction for extension budget.
- **`create_time` vs `first_launch_time`** — row-creation timestamp vs the timestamp the group first went live.
- **`datastream_metadata`** — CDC struct `{uuid, source_timestamp}`. `source_timestamp` = **milliseconds** CDC-capture epoch (verified 2026-07-19: MAX = 1784562229584 ≈ UNIX_MILLIS(MAX update_time) = 1784562229583). It is replication-capture time, **not** business time; use it for incremental reads. Near-real-time (matched wall clock to the ms).
- Boolean flags: `deleted`, `is_test`, `is_click_opt`, `budget_lock`, `restricted_edits`, `network_creative_approval`, `fb_dynamic`, `has_audience`.

## Joins & relationships
- **→ `campaigns` (1:N, fan-out):** `campaigns.campaign_group_id = campaign_group_id`. One group → many child campaigns (line items / funnel stages). **`product_id` is only on the group**, so to classify Select campaigns you must join campaign → group (see Example queries). Filter `deleted=FALSE AND is_test=FALSE` on **both** sides.
- **→ `advertisers` / `public_advertisers` (N:1):** `advertiser_id`; many groups per advertiser. For advertiser names join `advertisers.company_name` — `fpa_advertiser_verticals.advertiser_name` is empty since 2025-12.
- **→ self (parent/child):** `parent_campaign_group_id → campaign_group_id`. Nested groups; used in the Fangorn/MM overlay pattern.
- **→ `audience_audience_x_campaign_groups` (1:N junction) → audiences:** join on `campaign_group_id` (or `parent_campaign_group_id`) to reach audience expressions (DS13/DS19/DS46 detection).
- **→ flights (`core_flights` / `ui_flights`) for budget & schedule:** **this raw table has NO `budget`, `budget_type_id`, `active_flight_id`, `start_time`, or `end_time` columns** — those live in the flights tables and are joined in only on the analytical `campaign_groups` view. For flight window/budget, join flights by `campaign_group_id` (do NOT rely on `active_flight_id`, which is stale even where it exists).
- **→ `core_products` / `core_*` lookups (N:1):** resolve `product_id`, `objective_id`, `goal_type_id`, `campaign_group_status_id`, `pacing_type_id`, `delivery_mode_id`, `publisher_type_id`, `platform_id` to names.
- **→ `archives_campaign_group_archives` (1:N history, ~7 versions/group):** version snapshots of each group for as-of reconstruction.

## Gotchas
- **Current-state snapshot, not versioned.** Exactly one row per `campaign_group_id`; upserted in place by CDC. Any as-of / historical-state question needs `archives_campaign_group_archives` (order by `create_time`/`update_time`; use `MAX(version)` per group for the effective version).
- **Test + soft-deleted rows are material.** `is_test=TRUE` on 17,566 rows (~13.6%) and `deleted=TRUE` on 1,993 rows. Always filter **`deleted=FALSE AND is_test=FALSE`** for live analysis. Caveat: some QA groups have `is_test` unset (e.g. 8 Select QA groups), so `is_test` alone does not catch all test junk — also screen suspicious advertiser IDs/names.
- **No budget/flight columns here** (see Joins). Don't expect `budget`, `active_flight_id`, `start_time`, or `end_time` on this table — they are not replicated onto the raw campaign-group mirror.
- **`update_time` is a single computed column.** Per Victor Savitskiy (via prose oracle, not re-verified this pass): the Postgres `public.campaign_groups` source is a view whose `update_time = GREATEST(ui_flights.update_time, cg_raw.update_time)`, so this mirror's `update_time` is flight-aware. There is **no separate `update_time_raw`** column here — that cg-only/flight-aware split exists only on the analytical `campaign_groups` table.
- **`goal_type_name` can lag/mismatch `goal_type_id`** — trust the id.
- **`product_id` has only 1 and 2** (no QuickFrame groups); it is immutable — never infer product changes over time.
- **`source_timestamp` is ms and is capture-time**, not business time; do not treat it as a launch/change timestamp.

## Cost & partitioning notes
- **No partition** (verified: `timePartitioning`/`rangePartitioning` both null; `requirePartitionFilter` null). This is a tiny dim — a full scan is cheap and there is nothing to prune. The "always filter the partition column" advice does **not** apply; the meaningful always-on filter is **`deleted=FALSE AND is_test=FALSE`** (row filter, not a byte-saver).
- **Byte figures (dry-run, 2026-07-19):** `SELECT *` = **40,070,903 B (~40.07 MB)** — the whole table (matches `numBytes`). `SELECT campaign_group_id, advertiser_id, product_id, name` = **6,829,166 B (~6.83 MB)**. Column pruning is the only real lever (~6x here); select only what you need.
- Clustered by `campaign_group_id` — point/range lookups on the group id benefit from clustering, but on a 40 MB table the practical win is negligible.

## Example queries
```sql
-- MNTN Select groups (CDC source of truth):
SELECT campaign_group_id, advertiser_id, name
FROM `dw-main-bronze.integrationprod.public_campaign_groups_raw`
WHERE product_id = 2 AND deleted = FALSE AND is_test = FALSE;

-- Select campaigns (line items) — product_id is on the GROUP, join down:
SELECT c.*
FROM `dw-main-bronze.integrationprod.campaigns` c
JOIN `dw-main-bronze.integrationprod.public_campaign_groups_raw` cg
  ON c.campaign_group_id = cg.campaign_group_id
WHERE cg.product_id = 2
  AND c.deleted = FALSE AND cg.deleted = FALSE
  AND c.is_test = FALSE AND cg.is_test = FALSE;

-- Incremental read via CDC capture timestamp (ms epoch):
SELECT campaign_group_id, product_id, update_time
FROM `dw-main-bronze.integrationprod.public_campaign_groups_raw`
WHERE datastream_metadata.source_timestamp > UNIX_MILLIS(TIMESTAMP '2026-07-19 00:00:00');
```
