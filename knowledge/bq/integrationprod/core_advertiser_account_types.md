# integrationprod.core_advertiser_account_types

## Purpose
Sparse override x-ref that tags an advertiser with an `account_type_id` (e.g. B2B, Mobile). Postgres
CDC dim landed via Datastream. **Only 16 advertisers have a row** — this is a manual/exception
assignment table, not a complete advertiser-type map; the vast majority of advertisers have no row
here at all. Exposed as the `silver.core.advertiser_account_types` view (`SELECT * FROM` this table,
verified 2026-07-29). Reach for it only to read the account-type tag on the handful of advertisers
that carry one.

## Grain & keys
- **Grain:** one row per advertiser with an explicit account-type assignment. 16 rows, 16 distinct
  advertisers → `advertiser_id` is unique here (verified 2026-07-29).
- **Primary/natural key:** `advertiser_id` (unique). Cluster key is the pair `(account_type_id, advertiser_id)`.
- **Foreign keys:** `advertiser_id` → `advertisers.advertiser_id`; `account_type_id` →
  `core_account_types.account_type_id`.

## Column meanings (only the non-obvious ones)
- **`account_type_id`** — FK to `core_account_types`. Full decode (from `core_account_types`, 8 rows,
  verified 2026-07-29): 1=Ecommerce, 2=B2B, 3=Mobile, 4=Gaming, 5=Transparent Pricing, 6=Agency,
  7=Local, 8=Mobile With Conversions. **Only 3 values are actually present in this x-ref**: 2 B2B (5
  advertisers), 3 Mobile (9), 8 Mobile With Conversions (2).
- **`create_time`** — TIMESTAMP the assignment row was written in source Postgres (CDC). Not an
  advertiser lifecycle date.
- **`datastream_metadata`** — Datastream CDC lineage RECORD (`uuid`, `source_timestamp`); not business
  data.

## Joins & relationships
- **`advertiser_id` → `advertisers.advertiser_id`** — N:1 into this table, but since `advertiser_id`
  is unique here it acts as a **1:0-or-1 optional lookup** (most advertisers have no row). LEFT JOIN;
  expect NULL account_type for nearly every advertiser.
- **`account_type_id` → `core_account_types.account_type_id`** — N:1 decode lookup; cannot fan out.
- `silver.core.advertiser_account_types` is a `SELECT *` view over this table (content-identical).

## Gotchas
- **Coverage is tiny (16 rows).** Do not treat this as the authoritative account-type of every
  advertiser — it is an override/exception set. A missing advertiser means "no explicit tag," not a
  default type.
- **No `deleted`/`is_test` columns** — the standard bronze soft-delete filter
  (`deleted=FALSE AND is_test=FALSE`) does not apply; read all rows.
- **`create_time` is CDC write time**, not a business event time.

## Cost & partitioning notes
- **Non-partitioned static dim: 16 rows / ~1.1 KB.** No partition, no TTL, no `require_partition_filter`.
  Clustered on `(account_type_id, advertiser_id)` — a no-op at this size.
- Full `SELECT *` bills the tier-1 10 MB minimum (0 real bytes). Broadcast-join it freely.

## Example queries
```sql
-- Read the account-type tag for advertisers that carry one
SELECT a.advertiser_id, t.name AS account_type
FROM `dw-main-bronze.integrationprod.core_advertiser_account_types` a
LEFT JOIN `dw-main-bronze.integrationprod.core_account_types` t USING (account_type_id)
ORDER BY t.name;
```
