# integrationprod.core_advertisers_impression_tracking_urls

## Purpose
Stores the third-party **impression** tracking URLs (pixels/postbacks) configured for an advertiser —
fired to log/verify impressions with an external partner (e.g. Freshpaint). Postgres CDC dim landed
via Datastream. Reach for it to see which impression trackers an advertiser has configured and whether
they fire server-side or as a POST. Exposed as the `silver.core.advertisers_impression_tracking_urls`
view (`SELECT * FROM` this table, verified 2026-07-29).

## Grain & keys
- **Grain:** one row per impression tracking URL. 428 rows, 350 distinct advertisers (an advertiser can
  have multiple URLs; `impression_tracking_url_id` unique, verified 2026-07-29).
- **Primary key:** `impression_tracking_url_id` (sole cluster key).
- **Foreign keys:** `advertiser_id` → `advertisers.advertiser_id`; `user_id` → the internal user who
  added it.

## Column meanings (only the non-obvious ones)
- **`impression_tracking_url`** — the tracking endpoint fired on an impression; often a partner pixel
  (sampled rows are `https://freshpaint-impression.com/pixel.png?env_id=...`).
- **`server_side`** — TRUE = fired from MNTN servers (server-to-server) rather than the client. **All
  428 sampled rows are TRUE.**
- **`is_post`** — TRUE = HTTP POST (uses `request_body`); FALSE = GET. **All 428 rows FALSE** (all GET
  in current data).
- **`request_body`** — payload template for POST-style trackers (only relevant when `is_post` is TRUE).
- **`create_time`** — CDC write timestamp in source Postgres.
- **`datastream_metadata`** — Datastream CDC lineage RECORD; not business data.

## Joins & relationships
- **`advertiser_id` → `advertisers.advertiser_id`** — N:1 into this table. Joining advertisers to this
  table **fans out** (up to several URLs per advertiser). Aggregate or filter to one URL to keep grain.
- `silver.core.advertisers_impression_tracking_urls` is a `SELECT *` view over this table.
- Sibling table: `core_advertisers_visit_tracking_urls` (same shape, for visit rather than impression
  tracking).

## Gotchas
- **Fan-out on advertiser joins** — one advertiser can have many tracking URLs.
- **`request_body` only matters when `is_post` = TRUE** (currently no POST rows).
- **No `deleted`/`is_test` columns** — standard bronze soft-delete filter does not apply.

## Cost & partitioning notes
- **Non-partitioned dim: 428 rows / ~117 KB.** No partition, no TTL, no `require_partition_filter`.
  Clustered on `impression_tracking_url_id`. Full `SELECT *` bills the tier-1 10 MB minimum.

## Example queries
```sql
-- Impression trackers configured for an advertiser
SELECT impression_tracking_url_id, impression_tracking_url, server_side, is_post
FROM `dw-main-bronze.integrationprod.core_advertisers_impression_tracking_urls`
WHERE advertiser_id = @advertiser_id;
```
