# integrationprod.core_advertisers_x_hotels

## Purpose
The advertiser ↔ "hotel" membership x-ref. A **hotel** is a portfolio/holding grouping of advertisers
("hoteling" — grouping advertiser IDs, e.g. franchise/parent-child brand structures, under one root).
Postgres CDC dim landed via Datastream. Reach for it to map an advertiser to its hotel (portfolio) or
to expand a hotel into its member advertisers; `hotel_id` decodes via `core_hotels`. Exposed as the
`silver.core.advertisers_x_hotels` view (`SELECT * FROM` this table, verified 2026-07-29).

> Related concept: `fpa.mm_domain_map` performs domain-based "hoteling" (advertisers sharing a domain →
> a single root/parent advertiser) — see `data_knowledge.md`. This table is the structured
> advertiser↔hotel membership; the two are distinct mechanisms for the same portfolio idea.

## Grain & keys
- **Grain:** one row per `(advertiser_id, hotel_id)` membership. ~41,999 rows, 39,008 advertisers,
  36,031 hotels; `(advertiser_id, hotel_id)` is unique (41,999 pairs, verified 2026-07-29). Most
  advertisers map to exactly one hotel (~1.08 rows/advertiser).
- **Primary/natural key:** `(advertiser_id, hotel_id)`. Cluster key is `(hotel_id, advertiser_id)` —
  leading key `hotel_id` (optimized for hotel→members expansion).
- **Foreign keys:** `advertiser_id` → `advertisers.advertiser_id`; `hotel_id` → `core_hotels.hotel_id`
  (distinct namespace — `hotel_id` is never equal to `advertiser_id`, verified 0 self-refs);
  `user_id` → the internal user who created the membership.

## Column meanings (only the non-obvious ones)
- **`hotel_id`** — FK to `core_hotels` (~36K-row hotel dim). A hotel is a portfolio group, **not** an
  advertiser (separate id space).
- **`portfolio_role`** — the advertiser's role inside the hotel's hierarchy. Values (verified
  2026-07-29): empty string `""` on 41,912 rows (the overwhelming majority — no explicit role),
  `"child"` on 79 rows, `"parent"` on 8 rows. Treat empty as "member, role unspecified."
- **`datastream_metadata`** — Datastream CDC lineage RECORD; not business data.
- **Note:** this table has **no `create_time` / `update_time` columns** (unlike the other core_
  advertiser dims) — only `user_id` and `portfolio_role` beyond the two ids.

## Joins & relationships
- **`advertiser_id` → `advertisers.advertiser_id`** — near 1:1 (avg ~1.08 hotels per advertiser); a few
  advertisers belong to multiple hotels. LEFT JOIN when decorating advertisers with a hotel.
- **`hotel_id` → `core_hotels.hotel_id`** — N:1 decode. Expanding a hotel into members fans out to its
  member advertisers (the clustering leads with `hotel_id` to make this efficient).
- `silver.core.advertisers_x_hotels` is a `SELECT *` view over this table.

## Gotchas
- **`portfolio_role` is almost always empty** — do not rely on parent/child being populated (only 87 of
  ~42K rows carry a non-empty role). Empty ≠ "no relationship," it means role unspecified.
- **`hotel_id` and `advertiser_id` are different id spaces** — never join `hotel_id` to advertiser
  tables; decode it through `core_hotels`.
- **No `create_time`/`update_time`** — cannot date a membership from this table.
- **No `deleted`/`is_test` columns** — standard bronze soft-delete filter does not apply.

## Cost & partitioning notes
- **Non-partitioned dim: ~42K rows / ~2.8 MB.** No partition, no TTL, no `require_partition_filter`.
  Clustered on `(hotel_id, advertiser_id)` — filtering `hotel_id` prunes blocks (helps hotel→members).
- Full scan is tiny (~2.8 MB → tier-1 minimum). Broadcast-join freely.

## Example queries
```sql
-- Hotel (portfolio) an advertiser belongs to
SELECT xh.advertiser_id, xh.hotel_id, xh.portfolio_role, h.name AS hotel
FROM `dw-main-bronze.integrationprod.core_advertisers_x_hotels` xh
LEFT JOIN `dw-main-bronze.integrationprod.core_hotels` h USING (hotel_id)
WHERE xh.advertiser_id = @advertiser_id;

-- All member advertisers of a hotel (hotel_id is the leading cluster key)
SELECT advertiser_id, portfolio_role
FROM `dw-main-bronze.integrationprod.core_advertisers_x_hotels`
WHERE hotel_id = @hotel_id;
```
