# integrationprod.dso_configuration_service_campaign_presets

## Purpose
Per-campaign optimization **preset overrides** written by the DSO (demand-side optimization) configuration service. One row per campaign holds a manually- or programmatically-set override for the DSO knobs — frequency cap, pacing behaviour/multiplier, budget pace, and the CTV score/CPM/performance thresholds — that otherwise default from campaign-group/DSO config. Reach for it to see whether a specific campaign has a bespoke DSO preset (e.g. a hand-tuned frequency cap or a "pace ahead" instruction) and why it was set (the `reason` audit trail). It is a Postgres replica landed via Datastream CDC (`datastream_metadata` present). This is the **preset/override** table in the DSO family — distinct from the operative DSO **budget** tables (`dso_campaign_*_budgets`, `dso_campaign_group_*_budgets`) that hold the resolved live budget.

## Grain & keys
- **Grain:** one row per campaign. `campaign_id` is unique — verified live: 16,830 rows = 16,830 distinct `campaign_id`, 0 NULL PK. This is **current-state** (CDC upsert on PK), **not** a change-history table — unlike the versioned `dso_*` budget tables that keep a row per change.
- **Primary/natural key:** `campaign_id`.
- **Foreign keys / join columns:** `campaign_id` → `campaigns.campaign_id` (N:1, this side is the "1" — one preset row per campaign). Only a subset of all campaigns have a preset row (16,830 here vs ~548K campaigns), so this is a **left-join lookup**, not a spine.

## Column meanings (only the non-obvious ones)
- **`campaign_id`** — the campaign this preset applies to; PK and clustering key. Joins to `campaigns.campaign_id`.
- **`frequency_cap_cap_preset` / `frequency_cap_duration_preset`** — override frequency-cap "N impressions per duration" pair (cap count + duration). Most-populated presets (484 non-null rows). `secondary_frequency_cap_cap_preset` / `secondary_frequency_cap_duration_preset` = a second (secondary) cap tier, sparser still.
- **`pace_multiplier_preset` / `pacing_multiplier`** — NUMERIC(16,2) pacing multipliers (both extremely sparse: ~7 non-null). Two similarly-named columns coexist — `pace_multiplier_preset` is the older preset field; `pacing_multiplier` pairs with the newer `pacing_behavior` string set.
- **`pacing_behavior`** — STRING pacing directive. Live domain: `NULL` (16,824) and `"ahead"` (6). Effectively unused today; only value observed is `"ahead"` (spend ahead of even pacing).
- **`pacing_catchup_behavior`** — STRING; **100% NULL** in current data (no non-null rows).
- **`budget_pace_preset`** — NUMERIC(10,2) budget-pace override (22 non-null rows).
- **`recency_score_threshold_preset` / `viewability_score_threshold_preset` / `household_score_threshold_preset`** — INT overrides for the CTV bid-eligibility score gates (recency/viewability/household score thresholds), the DSO counterpart of `dso.household_score_thresholds` and the recency/viewability score models. Sparse.
- **`publisher_performance_threshold_preset` / `network_performance_threshold_preset`** — INT publisher/network performance-floor overrides.
- **`cpm_threshold_preset`** — CPM ceiling override stored as **STRING** (not numeric); **100% NULL** in current data.
- **`pmp_nullification_preset`** — BOOL, PMP (private-marketplace) nullification flag; **100% NULL** in current data.
- **`reason`** — free-text **append-only audit trail** of why the preset was set/changed. Each edit appends a token joined by `" | "`, so a value looks like `"PER-0123 | PER-0123 | PACE-6897"`. Tokens are internal ticket/reason codes (`PER-####`, `PACE-####`) or free text (`"SF Setup"`, `"EOM Help"`). The repeated-token count roughly tracks how many times the preset was touched — it is a log, not a single reason.
- **`create_time` / `update_time`** — CDC row timestamps (TIMESTAMP, UTC). Range observed: `create_time` 2024-06-25 → `update_time` 2026-07-29 (actively written). Use `update_time` for "when the preset last changed".
- **`datastream_metadata`** — Datastream CDC envelope. `uuid` = change event id; `source_timestamp` = source commit time as an **epoch in milliseconds** (INT64, e.g. `1785346297597`). Use `TIMESTAMP_MILLIS(datastream_metadata.source_timestamp)` to convert.

## Joins & relationships
- **`campaign_id` → `campaigns.campaign_id`** — N:1, this table is the "1" side (one preset row per campaign). Joining `campaigns` → this table is a safe **left-join lookup** that never fans out; only ~16.8K of ~548K campaigns have a preset row, so expect mostly NULL matches.
- Sits in the `dso_*` family. **Do not confuse with the DSO budget tables** (`dso_campaign_group_daily_budgets`, `dso_campaign_group_flight_budgets`, `dso_campaign_budgets`, …) which hold the *operative* budget and are versioned by `update_time`. This presets table is current-state per campaign and carries the optimization knobs, not the resolved budget.

## Gotchas
- **Most columns are almost entirely NULL.** Presets are exception overrides, not defaults. Live non-null counts: `frequency_cap_cap_preset` 484, `budget_pace_preset` 22, `pace_multiplier_preset` 7, `pacing_behavior` 6; `cpm_threshold_preset`, `pmp_nullification_preset`, and `pacing_catchup_behavior` are **100% NULL**. Never assume a preset is set — a NULL means "use the group/DSO default", not zero.
- **Current-state, not history.** `campaign_id` is unique (upsert). To reconstruct change history you only have `reason` (the appended token log) and `update_time`/`source_timestamp` — there is no prior-value row.
- **`reason` is a concatenated log, not a code.** Do not `GROUP BY reason` expecting clean buckets; split on `" | "` or take the last token if you need the most-recent reason.
- **Two pacing-multiplier columns** (`pace_multiplier_preset` vs `pacing_multiplier`) and two threshold naming styles coexist from schema evolution — check which one your consumer reads.
- **CDC replica:** rows appear/refresh via Datastream; no soft-delete column is present here, so a deleted-in-Postgres preset may simply vanish rather than flag.

## Cost & partitioning notes
- **BASE TABLE (Postgres/Datastream CDC replica), NOT partitioned, clustered on `campaign_id`, no TTL** — confirmed via `bq show` (timePartitioning None, clustering fields `[campaign_id]`). Tiny: **16,830 rows / ~2.15 MB** (`numBytes` 2,151,489). There is no partition column and no cost trap — even a full `SELECT *` scan is ~0.002 GB. Filtering/joining on `campaign_id` prunes via the clustering key.
- No date filter is required (this is a small dimension, not a log table). The one useful filter is `campaign_id` (clustered) or `<col> IS NOT NULL` to find campaigns that actually have a given preset set.

## Example queries
```sql
-- Campaigns with a bespoke frequency-cap preset, most-recently touched first
SELECT campaign_id,
       frequency_cap_cap_preset, frequency_cap_duration_preset,
       reason, update_time
FROM `dw-main-bronze.integrationprod.dso_configuration_service_campaign_presets`
WHERE frequency_cap_cap_preset IS NOT NULL
ORDER BY update_time DESC
```
