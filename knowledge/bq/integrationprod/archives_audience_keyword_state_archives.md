# integrationprod.archives_audience_keyword_state_archives

## Purpose
Datastream (Postgres CDC) audit trail / version history of `ui.audience_keyword_state` (CoreDB) — the parent/child keyword associations that define each audience's DS19 (MM Core / MNTN-Matched) targeting. Reach for it to reconstruct **which keywords an audience targeted as-of a historical date** (e.g. what the DS19 expression was during an analysis window), or to detect when keywords were added / removed / toggled `selected`. Live current state is `dw-main-silver.ui.audience_keyword_state`; this archive is the only place with the historical snapshots. (See `data_catalog.md` → `ui.audience_keyword_state` for the parent/child + is_magic semantics this inherits.)

## Grain & keys
- **Grain:** one row per archived version of an `audience_keyword_state` row.
- **Primary key:** `audience_keyword_state_archives_id` — unique (4,905,105 distinct = row count).
- **`id`** = the live `ui.audience_keyword_state` PK. Near-unique here (4,881,717 distinct → ~1.005 versions/id avg, **max 3**); natural key ≈ (`id`, `archive_time`). Version history is **shallow** — 99.5% of ids have exactly one archived row.
- **`audience_id`** = FK to `audiences` (18,201 distinct). One audience → many keyword rows (both PARENT and CHILD). No `advertiser_id` column.

## Column meanings (only the non-obvious ones)
- **`keyword_type`** — domain is exactly two values: `PARENT` (customer seed terms shown in the UI audience builder, ~20/audience; `data_source_id` NULL) vs `CHILD` (MNTN-Matched embedding-expanded keywords that actually target under DS19; `data_source_id`=19). 3.93M CHILD / 0.97M PARENT.
- **`selected`** (BOOL) — CHILD rows with `selected=true` are the keywords included in the DS19 audience-expression JSON blob. ~60% of rows selected. **Real targeting set = `selected=true AND keyword_type='CHILD' AND is_magic=false`.**
- **`is_magic`** (BOOL, ~8%) — UI-construction keywords that appear in the expression but are **UNTARGETABLE** (they exist so the displayed audience size updates when the customer edits). Do NOT count as real targeting.
- **`is_custom`** (BOOL, ~3.6%) — customer-entered vs system-generated keyword.
- **`is_hidden`** (BOOL, ~16%) — UI hidden flag.
- **`data_source_id`** — 19 (DS19 = MM Core / MNTN-Matched) for CHILD; NULL for PARENT. No other values in the table.
- **`data_source_category_id`** — the DS19 interest-category the CHILD keyword maps to (observed range ~900146–977554); NULL for PARENT.
- **`expanded_from`** (JSON, ~80% populated) — the PARENT seed keyword(s) this CHILD was embedding-expanded from.
- **`create_time`** — business time the underlying keyword row was created (min 2024-08-13); can **predate** archiving.
- **`archive_time`** — when the CDC archive snapshot row was written (min 2025-03-05 = archiving started ~Mar 2025). **This is the ordering column** — there is NO `version` column on this table (unlike other `archives_*`).
- **`datastream_metadata.source_timestamp`** — INT64 = **UNIX_MILLIS** of CDC capture (verified: `TIMESTAMP_MILLIS(source_timestamp)` == `archive_time` to the second). `datastream_metadata.uuid` = CDC event id. This is CDC-capture time, not business time.
- **`model_version`** — LLM/expansion model version; populated on only ~0.18% of rows (mostly NULL).
- **`description`, `feedback`** — present in schema but **100% NULL** (newly added, not yet populated). Do not rely on them.

## Joins & relationships
- **`audience_id` → `audiences` / `audience_segments`** — N:1 from this table's rows (many keyword rows per audience; the fan-out is intentional). To reach an advertiser: `audience_id` → `audiences` → advertiser (no `advertiser_id` here).
- **Live current-state sibling: `dw-main-silver.ui.audience_keyword_state`** — same business columns minus the archive PK/`archive_time`. 1:1 on `id` with the *latest* archived version.
- **`data_source_id` → `data_sources`** (=19 MM Core, 1:1 lookup). **`data_source_category_id` → the DS19 interest-category dim** (N:1; each CHILD keyword sits in one category).

## Gotchas
- **NO `version` column** (unlike `archives_campaign_group_archives`). Order history by `archive_time` (or `datastream_metadata.source_timestamp` / `create_time`), never by version.
- **Shallow history:** 99.5% of live keyword `id`s have exactly one archived row; max version depth = 3. Closer to a near-current snapshot than a deep audit trail.
- **Reconstruction floor ~2025-03-05:** `archive_time` starts then even though `create_time` goes back to 2024-08 → you cannot reconstruct audience-keyword state before ~March 2025.
- **`description` + `feedback` are 100% NULL.**
- **`is_magic` keywords are untargetable** — exclude them when counting real targeting.
- **No `deleted` / `is_test` / `update_time` columns** → the standard bronze `deleted=FALSE AND is_test=FALSE` filter does NOT apply here.

## Cost & partitioning notes
- **Genuinely unpartitioned** (bq show: `timePartitioning` null, `rangePartitioning` null); clustered on `audience_keyword_state_archives_id` only. 4,905,105 rows / 875 MB logical (bq show `numBytes`). No TTL — the archive grows.
- **The one lever to always apply: project only the columns you need.** There is no partition to filter, and `audience_id` is not the cluster key, so filtering by audience does NOT prune the scan.
- Dry-run (2026-07-19): `SELECT *` (all 18 cols) = **875 MB**; `(audience_id, keyword, selected)` = **143 MB**; `(audience_id)` alone = **39 MB**. `SELECT *` costs ~6x a 3-col read, ~22x a 1-col read. Only same-column-set figures are comparable.

## Example queries
```sql
-- Latest archived keyword state for one audience's DS19 targeting set (real targetable children only)
WITH ranked AS (
  SELECT id, keyword, data_source_category_id, selected, is_magic,
         ROW_NUMBER() OVER (PARTITION BY id ORDER BY archive_time DESC) AS rn
  FROM `dw-main-bronze.integrationprod.archives_audience_keyword_state_archives`
  WHERE audience_id = @audience_id AND keyword_type = 'CHILD'
)
SELECT keyword, data_source_category_id
FROM ranked
WHERE rn = 1 AND selected = TRUE AND is_magic = FALSE
```
