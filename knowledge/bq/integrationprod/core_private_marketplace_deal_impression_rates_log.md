# integrationprod.core_private_marketplace_deal_impression_rates_log

## Purpose
Append-only history of per-PMP-deal impression-availability metrics — for each private-marketplace deal,
a periodic (~daily) snapshot of its win rate, average daily impression rate, distinct IPs, and prior-day
inventory. Reach for it to see how a deal's inventory/availability trends over time, or to get the latest
availability per deal. **~13.9K rows, growing ~daily.** Exposed as the
`silver.core.private_marketplace_deal_impression_rates_log` view; a curated cut feeds the
`silver.aggregates.pmp_impression_rates` view (partner_deal_id, days_with_data, distinct_ips,
avg_daily_impression_rate, yesterdays_inventory).

## Grain & keys
- **Grain:** one snapshot row per PMP deal per logging run (~daily). 13,850 rows across 125 distinct
  `partner_deal_id` and 317 distinct `DATE(log_time)` (2025-08-18 → 2026-07-29). Most deal-days have
  exactly 1 row (12,630), but some runs re-log a deal within a day (up to 4 rows/deal/day). So it is NOT
  strictly one-per-deal-per-day — dedup by `log_time` if you need the latest.
- **Primary key:** `private_marketplace_deal_impression_rate_id` (INT, incrementing). Unique
  (13,850 distinct = row count). Cluster key #1.
- **Foreign key:** `partner_deal_id` (STRING) → `private_marketplace_deals.partner_deal_id` (exchange-side
  deal id). Cluster is `[private_marketplace_deal_impression_rate_id, log_time]` — `log_time` is cluster #2.

## Column meanings (only the non-obvious ones)
- **`private_marketplace_deal_impression_rate_id`** — incrementing surrogate PK / cluster key #1; one per
  logged snapshot (not per deal).
- **`partner_deal_id`** — the exchange-side deal identifier (STRING). Free-form: named deals
  (e.g. `MGN-MNTN-Philo-PauseAds`), UUIDs, and exchange ids (e.g. `IX761695528793873574`) all appear.
  Join to `private_marketplace_deals.partner_deal_id`.
- **`log_time`** — TIMESTAMP of the snapshot run; cluster key #2. Use it to order/dedup to the latest per deal.
- **`days_with_data`** — number of days the rate is computed over (a trailing window; e.g. 7).
- **`win_rate`** — bid win rate for the deal, **stored as a decimal STRING** (e.g. `"0.1324"`), not a
  FLOAT — `SAFE_CAST(win_rate AS FLOAT64)` to do math.
- **`avg_daily_impression_rate`** — average daily impression availability rate, **decimal STRING**.
- **`adj_avg_daily_impression_rate`** — adjusted average daily impression rate, **decimal STRING**.
- **`distinct_ips`** — distinct IPs seen for the deal in the window (INT).
- **`yesterdays_inventory`** — prior-day available inventory count for the deal (INT).
- **`datastream_metadata`** — Datastream CDC lineage RECORD; not business data.

## Joins & relationships
- **`partner_deal_id` → `private_marketplace_deals.partner_deal_id`** — links each snapshot to its deal
  config (floor_price, partner_id, advertiser/campaign_group, active). The log is the **many-side**
  (many snapshots per deal over time), so joining it to `private_marketplace_deals` fans out per deal.
- **`silver.aggregates.pmp_impression_rates`** and **`silver.core.private_marketplace_deal_impression_rates_log`**
  are VIEWs downstream of this table.

## Gotchas
- **Rate columns are STRINGs** (`win_rate`, `avg_daily_impression_rate`, `adj_avg_daily_impression_rate`) —
  always `SAFE_CAST(... AS FLOAT64)` before comparing/aggregating; string ordering is not numeric ordering.
- **Not strictly one row per deal per day** — some deals are re-logged multiple times within a day. To get
  "current availability" per deal, take the row with `MAX(log_time)` per `partner_deal_id` (or per
  `private_marketplace_deal_impression_rate_id` order).
- **Append-only log, non-partitioned** — history begins 2025-08-18. There is **no partition column and no
  `require_partition_filter`**; the whole (~1.76 MB) table scans on any query. Filter on `log_time` for
  time slices even though it does not prune to partitions (it's a cluster key, so it prunes blocks).
- **No `deleted`/`is_test`** columns — standard integrationprod soft-delete dim filter does not apply.

## Cost & partitioning notes
- **Non-partitioned append-only log: 13,850 rows / ~1.76 MB.** No partition, no TTL, no
  `require_partition_filter`. Clustered `[private_marketplace_deal_impression_rate_id, log_time]` — filtering
  `log_time` (or the id) prunes blocks within the single table.
- Full `SELECT *` bills roughly the tier-1 10 MB minimum (table is ~1.76 MB). Cheap; still prefer selecting
  the columns you need and casting rate STRINGs.

## Example queries
```sql
-- Latest impression-rate snapshot per PMP deal (dedup the intra-day re-logs)
SELECT partner_deal_id, log_time,
       SAFE_CAST(win_rate AS FLOAT64) AS win_rate,
       SAFE_CAST(avg_daily_impression_rate AS FLOAT64) AS avg_daily_impression_rate,
       distinct_ips, yesterdays_inventory
FROM (
  SELECT *, ROW_NUMBER() OVER (PARTITION BY partner_deal_id ORDER BY log_time DESC) AS rn
  FROM `dw-main-bronze.integrationprod.core_private_marketplace_deal_impression_rates_log`
)
WHERE rn = 1
ORDER BY distinct_ips DESC;

-- One deal's availability trend over time
SELECT DATE(log_time) AS d, SAFE_CAST(avg_daily_impression_rate AS FLOAT64) AS rate, distinct_ips
FROM `dw-main-bronze.integrationprod.core_private_marketplace_deal_impression_rates_log`
WHERE partner_deal_id = @partner_deal_id
ORDER BY d;
```
