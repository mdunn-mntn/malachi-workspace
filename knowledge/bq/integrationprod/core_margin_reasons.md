# integrationprod.core_margin_reasons

## Purpose
Tiny bronze CDC replica dimension that decodes a **margin-adjustment reason** — the categorical why
behind a non-standard margin applied to an account, campaign group, or global setting. Reach for it to
turn a `margin_reason_id` into a human label and to know whether that reason is surfaced in the UI
(`ui_exposed`) vs. used only for internal system adjustments. As of 2026-07-29 the domain is exactly 10
rows: a sentinel `-1 = Unknown` plus ids 1-9 (verified via full dump). No `silver.core.margin_reasons`
view exists (checked 2026-07-29) — query the bronze physical table directly.

## Grain & keys
- **Grain:** one row per margin-adjustment reason. Static enum, 10 rows (verified live 2026-07-29).
- **Primary key:** `margin_reason_id` (INT64, unique, no NULLs; the sole cluster key). Includes the
  sentinel value **`-1` (Unknown)** — ids are NOT all positive.
- **Join column:** `margin_reason_id` — FK target for margin records that carry an adjustment reason.
  This table is always the **1-side** of any join.
- **No `deleted` / `is_test` columns** — the standard live-row dim filter does not apply; all 10 rows are
  always live. `create_time`/`update_time` ARE present (unlike most bronze enum dims).

## Column meanings (only the non-obvious ones)
- **`margin_reason_id`** — enum PK, sole cluster key. Domain = {-1, 1-9} (verified live 2026-07-29).
  **`-1` is the `Unknown` sentinel** — treat as "no/unspecified reason", not a real adjustment. Join this
  dim or hard-code the map below.
- **`name`** — free-text label of the reason (`Unknown`, `MNTN AID adjustment`, `Advanced Pricing`,
  `Customer Incentive Program`, …). Match on `margin_reason_id`, not the free-text `name`.
- **`ui_exposed`** — BOOL. `true` = reason is customer/account-facing and selectable in the UI
  (ids 4-9); `false` = internal/system-only reason not shown in the UI (the `-1 Unknown` sentinel and the
  three `MNTN … adjustment` reasons, ids 1-3). Use it to filter to user-selectable reasons.
- **`create_time` / `update_time`** — TIMESTAMP (UTC) of the source-row insert/last-change in the
  operational DB. Current snapshot: rows created 2026-07-21; the UI-exposed rows (4-9) were last updated
  2026-07-21 22:07:51, the internal rows (-1, 1-3) unchanged since create. These are seed/config times,
  not business event times.
- **`datastream_metadata`** — Datastream CDC lineage RECORD (`uuid`, `source_timestamp`).
  `source_timestamp` is a **millisecond** epoch (CDC-capture time), not business time. Ignore for decode.

## Joins & relationships
- **`<margin record>.margin_reason_id` → `core_margin_reasons.margin_reason_id`** — **N:1** decode lookup
  (this dim is the one-side; the margin-carrying record is the many-side). It **cannot fan out** the table
  it joins to (1 row per id).
- **No silver view** — unlike sibling enums (e.g. `silver.core.price_models`), there is no
  `silver.core.margin_reasons` view (checked 2026-07-29). Reference the bronze physical table directly.
- The reverse direction is **1:N** — never join outward from this dim to aggregate margin facts without
  expecting full cardinality.

## Gotchas
- **`-1` sentinel** — the PK domain is not all-positive; `-1 = Unknown` means "no reason specified". Don't
  assume `margin_reason_id >= 1` in filters/joins.
- **`ui_exposed` splits internal vs customer-facing** — ids 1-3 (`MNTN … adjustment`) and `-1` are
  system/internal (`false`); ids 4-9 are the user-selectable business reasons (`true`).
- **No soft-delete columns.** No `deleted`/`is_test` — do not add those predicates (they'll error).
- **Static enum** — treat the code→name map as frozen; a net-new reason would appear as an 11th row (last
  verified 10 rows on 2026-07-29).
- **`create_time`/`update_time` are config seed times**, not business event times; don't use them as a
  fact timeline.
