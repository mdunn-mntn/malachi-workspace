# integrationprod.core_mobile_apps

## Purpose
Datastream-CDC mirror of the **mobile-app registry**: each row registers one mobile app (by its
app-store identifier) against an advertiser and an integration `partner_id`, with an `active` flag. Reach
for it to enumerate the mobile apps tied to an advertiser or to resolve a `mobile_app_id`.
`silver.core.mobile_apps` is a view over this base table.

## Grain & keys
- **Grain:** one row per registered mobile app. **125 rows.**
- **Primary key:** `mobile_app_id` (surrogate INT, also the sole cluster key).
- **FKs:** `advertiser_id` → `advertisers.id`; `partner_id` → integration/data-partner id.

## Column meanings (only the non-obvious ones)
- **mobile_app_id** — surrogate PK (clustered).
- **advertiser_id** — the owning advertiser → `advertisers.id`. An advertiser can register several apps
  (multiple rows).
- **partner_id** — integration/data-partner id. Observed domain: `{7, 14, 15, 78}` (partner 7 is the
  bulk: 80 of 125 rows). No partner-lookup table is joined here; the per-code meaning is not decoded from
  source — treat it as an opaque partner id.
- **app_id** — the app-store identifier as a STRING, in one of two observed forms: an **Android package
  name** (`com.pof.android`, `com.thirdrock.fivemiles`) or an **iOS App Store id** (`id917554930`,
  `id435588892`). The platform is inferable from the format (`id` + digits = iOS; reverse-DNS = Android).
- **active** — TRUE = active registration; FALSE = inactive (30 of 125 rows are inactive).
- **datastream_metadata.source_timestamp** — INT64 **milliseconds** CDC-capture epoch (`TIMESTAMP_MILLIS`),
  not business time. This table has no `create_time`/`update_time`.

## Joins & relationships
- **`advertisers`** (dim, N:1): `advertiser_id` → `advertisers.id`. Multiple apps per advertiser →
  fan-out N:1 the safe direction; `DISTINCT advertiser_id` when counting advertisers with apps.
- **`silver.core.mobile_apps`** is a VIEW over this base table (same 125 rows).

## Gotchas
- **`app_id` mixes platforms in one column** — iOS (`id<digits>`) and Android (reverse-DNS package) live
  together; branch on the format if you need the platform, there is no separate platform column.
- **`partner_id` has no lookup dim here** — observed values {7,14,15,78}; meanings undocumented in source.
- **No `create_time` / `update_time`** — only the CDC `source_timestamp` (ms) is available for timing.
- **No `deleted` / `is_test` columns** — the dataset-wide hygiene filter does not apply; use `active` to
  filter live registrations.

## Cost & partitioning notes
- **BASE TABLE, physical `self`**, no partition, cluster=[mobile_app_id], no TTL. `bq show`: numRows=125,
  numBytes=11,120. Trivially below the billing floor — `SELECT *` freely.

## Example queries
```sql
-- Active app registrations for an advertiser
SELECT mobile_app_id, partner_id, app_id, active
FROM `dw-main-bronze.integrationprod.core_mobile_apps`
WHERE advertiser_id = 32030 AND active
ORDER BY mobile_app_id;
```
