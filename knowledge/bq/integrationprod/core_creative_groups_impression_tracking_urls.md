# integrationprod.core_creative_groups_impression_tracking_urls

## Purpose
Third-party **impression-tracking URLs (pixels)** attached to a creative group — one row per configured
tracking URL. When an advertiser/agency wants a 3P vendor pixel to fire on each impression served by a
creative group, it is stored here. Child of `core_creative_groups`; exposed as the
`silver.core.creative_groups_impression_tracking_urls` VIEW. Sibling of the visit-tracking table
(`core_creative_groups_visit_tracking_urls`).

## Grain & keys
- **Grain:** one row per **`impression_tracking_url_id`** — PK (rows 83,572 == distinct id, 2026-07-29).
- **Primary key:** `impression_tracking_url_id` (INT64); sole cluster key.
- **Foreign key:** `creative_group_id` → `core_creative_groups.group_id` — **N:1** (75,007 distinct groups →
  ~1.1 tracking URLs per group; a group can have several). Note the FK is named `creative_group_id` while the
  parent PK is `group_id`.

## Column meanings (only the non-obvious ones)
- **`impression_tracking_url`** (STRING) — the tracking URL/pixel that fires on impression (usually a 3P
  vendor endpoint with macros).
- **`server_side`** (BOOL) — whether the pixel fires server-side vs client-side. **86% TRUE** (71,956 / 83,572).
- **`is_post`** (BOOL) — HTTP method is POST (vs GET). **`request_body`** (STRING) — the POST body sent when
  `is_post=TRUE`.
- **`creative_group_id`** — FK to the parent group's `group_id` (name mismatch — see keys).
- **`create_time`** — TIMESTAMP the URL was configured; there is **no `update_time`** here.
- **`user_id`** — user who added the tracking URL.
- **`datastream_metadata`** — Datastream CDC lineage RECORD; not business data.

## Joins & relationships
- **`creative_group_id` → `core_creative_groups.group_id`**: **N:1** — a creative group can have multiple
  impression-tracking URLs (1:N from the group's perspective). Aggregate this side before joining a group to
  avoid fan-out.
- The parent group's `override_impression_tracking` (BOOL) flag indicates the group uses its own tracking
  URLs (these rows) instead of campaign-level tracking.
- **`silver.core.creative_groups_impression_tracking_urls`** is a VIEW over this table (verified 2026-07-29).

## Gotchas
- **FK name mismatch:** join `creative_group_id` (here) to `group_id` (parent), not to a `creative_group_id`
  column on the parent (which does not exist).
- **1:N fan-out:** joining a creative group to this table multiplies group rows by its tracking-URL count —
  pre-aggregate (e.g. `ARRAY_AGG`/`COUNT`) if you need one row per group.
- **No `update_time`** — only `create_time`; use `datastream_metadata.source_timestamp` for later changes.
- **No `deleted`/`is_test`** — no soft-delete filter applies.

## Cost & partitioning notes
- **No partition, no TTL** (child dim). ~83.6K rows / ~23 MB; clustered on `impression_tracking_url_id`.
  Small; the STRING `impression_tracking_url` / `request_body` are the bulk of the bytes — prune them if you
  only need counts by group. `require_partition_filter: false`.

## Example queries
```sql
-- Impression-tracking URLs for a creative group
SELECT impression_tracking_url_id, impression_tracking_url, server_side, is_post
FROM `dw-main-bronze.integrationprod.core_creative_groups_impression_tracking_urls`
WHERE creative_group_id = @group_id;

-- Count of tracking URLs per group (pre-aggregate to avoid fan-out)
SELECT creative_group_id, COUNT(*) AS n_urls
FROM `dw-main-bronze.integrationprod.core_creative_groups_impression_tracking_urls`
GROUP BY creative_group_id;
```
