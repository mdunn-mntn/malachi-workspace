# integrationprod.core_audience_types

## Purpose
Tiny bronze CDC replica dimension that decodes an audience's **type**. Reach for it to turn
`core_audiences.audience_type_id` into a human label. As of 2026-07-29 the domain is exactly 4 rows,
ids contiguous 1-4 (verified via full dump):

| audience_type_id | name | create_time (dim-seed) |
|---|---|---|
| 1 | First Party Audience | 2019-07-26 |
| 2 | Third Party Audience | 2019-07-26 |
| 3 | Control Group Audience | 2020-11-19 |
| 4 | Extension Audience | 2021-03-04 |

**No silver view exists** for this enum (unlike most `core_*` dims): `silver.core.audience_types` is
absent (verified 2026-07-29). Query the bronze physical table directly, or decode inline from the map
above.

## Grain & keys
- **Grain:** one row per audience type. Static enum, 4 rows (verified live 2026-07-29).
- **Primary key:** `audience_type_id` (INT64, unique, no NULLs; the sole cluster key).
- **Join column:** `audience_type_id` — FK target for `core_audiences.audience_type_id`. This table is
  always the **1-side** of any join.
- **No `deleted` / `is_test` columns** — the standard live-row dim filter does not apply; all 4 rows are
  always live.

## Column meanings (only the non-obvious ones)
- **`audience_type_id`** — enum PK, sole cluster key. Domain = contiguous {1..4} (see Purpose table).
  Join this dim (or hard-code the 4-value map); values verified live 2026-07-29.
- **`name`** — human label for the audience type. Exact live spellings carry the trailing word
  "Audience" (e.g. `First Party Audience`). Match on `audience_type_id`, not the free-text `name`.
- **`create_time`** — TIMESTAMP the enum ROW was seeded in source Postgres (dim-management metadata),
  **not** any audience's creation time. ids 1-2 seeded 2019-07-26; id 3 2020-11-19; id 4 2021-03-04.
- **`datastream_metadata`** — Datastream CDC lineage RECORD (`uuid`, `source_timestamp`).
  `source_timestamp` is a **millisecond** epoch (CDC-capture time), not business time:
  `TIMESTAMP_MILLIS(...)` resolves to a sane datetime. Not business data; ignore for decode.

## Joins & relationships
- **`core_audiences.audience_type_id` → `core_audience_types.audience_type_id`** — **N:1** (`core_audiences`
  is the many-side; this dim is the one-side). Used as a decode lookup it **cannot fan out** (1 row per id).
- The reverse direction (`core_audience_types → core_audiences`) is **1:N** — never join outward from this
  dim to aggregate audience facts without expecting full audience cardinality.
