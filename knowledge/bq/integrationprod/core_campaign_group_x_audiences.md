# integrationprod.core_campaign_group_x_audiences

## Purpose
Junction / bridge table (bronze Postgres-CDC replica) recording which `audience` a `campaign_group` was associated with. Reach for it to answer "which audience(s) did this campaign group carry?" or the reverse. The thin silver view `silver.core.campaign_group_x_audiences` is a `SELECT *` over this table.

**Legacy / frozen — read before using.** Business writes stopped in Dec 2023 (per the silver-sibling analysis; same freeze as `core_campaign_x_audiences`). For **current** campaign-group ↔ audience membership use `integrationprod.audience_audience_x_campaign_groups` (the table the Fangorn / DS46 detection SQL joins). Treat this table as a historical record for campaign groups configured on or before Dec 2023 — do not use it for current targeting.

## Grain & keys
- **Grain:** one row per `campaign_group_x_audience_id` (surrogate PK). Verified 2026-07-29: 27,966 rows = 27,966 distinct PKs; natural key `(campaign_group_id, audience_id)` also unique.
- **Primary key:** `campaign_group_x_audience_id` (surrogate; also the cluster key). Sparse — deletes upstream are hard deletes, so the surrogate sequence has gaps.
- **Foreign keys:** `campaign_group_id` → `campaign_groups` (1:N — some cgs carry >1 audience); `audience_id` → `audience_audiences` / `core.audiences` (N:1 from bridge); `segment_id` → targeting-segment id (nullable).

## Column meanings (only the non-obvious ones)
- **campaign_group_x_audience_id** — surrogate PK; also the cluster key. Unique per row.
- **campaign_group_id** — FK → `campaign_groups.campaign_group_id`. 27,577 distinct across 27,966 rows (2026-07-29) → ~389 cgs carry more than one audience row. 1:N from campaign group to bridge.
- **audience_id** — FK → `audience_audiences.audience_id` (silver `core.audiences`). 14,662 distinct → audiences are reused across many campaign groups. N:1 from bridge to audience.
- **segment_id** — nullable pointer to the compiled targeting segment for the association; presence is era-dependent (early rows sparsely populated). Not a reliable universal key.
- **user_id** — column present but **unused in this replica** (NULL throughout on the silver sibling; treat as unusable for who-created attribution).
- **create_time** — native `TIMESTAMP`, business creation time of the association (there is **no `update_time`** on this table). Frozen after 2023-12-15. Use this for business time.
- **datastream_metadata.source_timestamp** — CDC-capture epoch in **MILLISECONDS**; a single uniform bulk-snapshot value across rows (family-wide convention) — carries no business signal, never use it as an "updated" proxy. `.uuid` = the CDC row id.

## Joins & relationships
- **`audience_id` → `audience_audiences` (silver `core.audiences`)** — partner grain 1 row per audience → bridge→audiences is **N:1, no fan-out** (safe). Reverse (audience→bridge) is 1:N — an audience appears on many campaign-group rows.
- **`campaign_group_id` → `campaign_groups` / `public_campaign_groups`** — partner grain 1 row per campaign group. Bridge is the **N** side: joining a campaign-group table to this bridge fans out for the ~389 cgs with >1 audience — dedupe/aggregate if you need one row per cg. Filter `deleted=FALSE AND is_test=FALSE` on the `campaign_groups` side.
- **`segment_id`** — points at the compiled targeting segment (same id space as `audience.audience_segments.segment_id`); nullable and era-dependent, not a safe join key for older rows.
- **Superseded by** `integrationprod.audience_audience_x_campaign_groups` — the current bridge the Fangorn/DS46 detection queries use. Cross-check any membership conclusion there before treating it as current.

## Gotchas
- **Frozen since 2023-12-15** — no new associations after that date. Never use for "current" targeting; it silently misses every association created in 2024+.
- **No `deleted` / `is_test` columns** — the standard dimension soft-delete/test filter does NOT apply here (columns absent). Deletes are hard deletes → the surrogate PK sequence has gaps.
- **No `update_time`** — only `create_time`; no in-table signal for later edits to an association.
- **`user_id` unusable and `segment_id` frequently NULL** — neither is a safe universal key.
- **`datastream_metadata.source_timestamp` is a single uniform snapshot value**, not per-row CDC time — meaningless as a change/recency signal.

## Cost & partitioning notes
- **Genuine BASE TABLE**, unpartitioned, clustered on `campaign_group_x_audience_id`, no TTL — `bq show`: 27,966 rows / 2,315,804 bytes (~2.21 MB). No partition column to filter; `require_partition_filter=false`.
- The only cost lever is **column pruning** (avoid `SELECT *`, which drags in `datastream_metadata`). At ~2.2 MB a full scan is cheap regardless. Clustering on the PK helps point-lookups by `campaign_group_x_audience_id` only.

## Example queries
```sql
-- Historical audiences a campaign group carried (<= 2023), with audience names
SELECT b.campaign_group_id, b.audience_id, a.name, b.segment_id, b.create_time
FROM `dw-main-bronze.integrationprod.core_campaign_group_x_audiences` b
JOIN `dw-main-silver.core.audiences` a USING (audience_id)
WHERE b.campaign_group_id = @cg_id
ORDER BY b.create_time DESC;
```
