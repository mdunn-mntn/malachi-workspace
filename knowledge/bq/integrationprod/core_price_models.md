# integrationprod.core_price_models

## Purpose
Tiny bronze CDC replica dimension that decodes a **billing price model** — the rule by which a campaign's
spend is turned into billable revenue. Reach for it to turn a `price_model_id` into a human label
(CPM / CPC / Click CPA / View Revenue Share / Media / Platform Fee …) or to read the underlying
`FormulaPriceModel` calculation template. As of 2026-07-29 the domain is exactly 18 rows, ids contiguous
1-18 (verified via full dump). Exposed as the `silver.core.price_models` view (a plain `SELECT * FROM`
this bronze table). Prefer the silver view in queries; this doc records the physical source.

## Grain & keys
- **Grain:** one row per price model. Static enum, 18 rows (verified live 2026-07-29).
- **Primary key:** `price_model_id` (INT64, unique, no NULLs; the sole cluster key).
- **Join column:** `price_model_id` — FK target for campaign/campaign-group records that carry a pricing
  model. This table is always the **1-side** of any join.
- **No `deleted` / `is_test` columns** and **no `create_time` / `update_time`** — the standard live-row
  dim filter does not apply; all 18 rows are always live.

## Column meanings (only the non-obvious ones)
- **`price_model_id`** — enum PK, sole cluster key. Domain = contiguous {1-18} (verified live 2026-07-29).
  Join this dim or hard-code the map below.
- **`name`** — free-text label of the pricing model (`CPM`, `CPC`, `Fixed Monthly`, `Click CPA`,
  `View CPA`, `View Revenue Share`, `Media`, `Platform Fee - Cost Plus Model`, …). Match on
  `price_model_id`, not the free-text `name`.
- **`calculator_name`** — the calculator class that evaluates the model. **All 18 rows are
  `FormulaPriceModel`** (verified live 2026-07-29) — i.e. the billed amount is computed from the
  `calculator_options` formula string. Not currently a discriminating column.
- **`calculator_options`** — the **formula template** the calculator evaluates, an `=`-prefixed
  expression over a stats source with `%PLACEHOLDER%` slots filled per-campaign at billing time.
  Placeholders seen: `%PRICE%` (the negotiated rate), `%DISCOUNT%`, `%TOTAL%`. Stats sources referenced:
  `SteelHouseStatistics` (native MNTN/legacy), `TradeDeskStatistics`, `FacebookStatistics`,
  `TwitterStatistics` / `TwitterCampaignStatistics`. A comma separates two formulas (standard vs control
  impressions) for CPM (1) and Platform Agreement (9). Example: CPM =
  `=SteelHouseStatistics.StandardImpressions / 1000.0 * %PRICE%`.
- **`keys`** — comma-list of the stats **group-by columns** the formula aggregates over
  (e.g. `SteelHouseStatistics.Hour,…AdvertiserId,…CampaignId,…CreativeGroupId,…CreativeId`;
  TradeDesk rows add geo/PMP keys). Describes the grain at which the price model is computed.
- **`filter`** — the WHERE predicate template applied to the stats source, e.g.
  `SteelHouseStatistics.CampaignID=?` (the `?` bound to the campaign at eval time).
- **`datastream_metadata`** — Datastream CDC lineage RECORD (`uuid`, `source_timestamp`).
  `source_timestamp` is a **millisecond** epoch (CDC-capture time, ~2025-12-19 for the current snapshot),
  not business time. Ignore for decode.

### Value set (verified live 2026-07-29, all calculator_name = FormulaPriceModel)
| id | name | calculator_options (formula) |
|---|---|---|
| 1 | CPM | `=SteelHouseStatistics.StandardImpressions / 1000.0 * %PRICE%` (+ ControlImpressions variant) |
| 2 | CPC | `=SteelHouseStatistics.Clicks * %PRICE%` |
| 3 | Fixed Monthly | `=%PRICE%` |
| 4 | Click CPA | `=SteelHouseStatistics.ClickConversions * %PRICE%` |
| 5 | View CPA | `=SteelHouseStatistics.ViewConversions * %PRICE% * (1 - %DISCOUNT%)` |
| 6 | Click Revenue Share | `=SteelHouseStatistics.ClickTotalOrderValue * %PRICE%` |
| 7 | View Revenue Share | `=SteelHouseStatistics.ViewTotalOrderValue * %PRICE% * (1 - %DISCOUNT%)` |
| 8 | Discount | `=- (%TOTAL% * %PRICE%)` |
| 9 | Platform Agreement | `=SteelHouseStatistics.StandardImpressions / 1000.0 * %PRICE%` (+ ControlImpressions variant) |
| 10 | Media | `=TradeDeskStatistics.MediaAndFeeWithMarginCost` |
| 11 | FB Direct Cost Plus | `=TradeDeskStatistics.MediaCost / 0.85` |
| 12 | Twitter Media | `=TwitterCampaignStatistics.MediaSpend` |
| 13 | Twitter Platform Agreement | `=TwitterCampaignStatistics.Impressions / 1000.0 * %PRICE%` |
| 14 | Platform Fee - Cost Plus Model | `=(TradeDeskStatistics.MediaAndFeeWithMarginCost / %PRICE%) - TradeDeskStatistics.MediaAndFeeWithMarginCost` |
| 15 | FB Direct Cost Plus V2 | `=FacebookStatistics.MediaCost * 0.17` |
| 16 | TradeDesk Data | `=(TradeDeskStatistics.DataCost/(1-TradeDeskStatistics.PlatformMargin)) / .45` |
| 17 | Oracle Data | `=TradeDeskStatistics.Impressions / 1000.0 * 0.0` |

## Joins & relationships
- **`<campaign / campaign-group>.price_model_id` → `core_price_models.price_model_id`** — **N:1** decode
  lookup (this dim is the one-side; the priced record is the many-side). It **cannot fan out** the table
  it joins to (1 row per id).
- **`silver.core.price_models`** is a VIEW = `SELECT * FROM dw-main-bronze.integrationprod.core_price_models`
  (verified 2026-07-29). Content-identical; use whichever project you're already in.
- The reverse direction is **1:N** — never join outward from this dim to aggregate spend/billing facts
  without expecting full cardinality.

## Gotchas
- **No soft-delete columns.** No `deleted`/`is_test` — do not add those predicates (they'll error).
  Also no `create_time`/`update_time` on this table (unlike its sibling `core_margin_reasons`).
- **Static enum** — treat the code→name map as frozen; a net-new pricing model would appear as a 19th row
  (last verified 18 rows, ids 1-18, on 2026-07-29).
- **`calculator_name` is non-discriminating** — all 18 rows are `FormulaPriceModel`; the real logic lives
  in `calculator_options`. Don't branch on `calculator_name`.
- **`calculator_options` is a template, not a computed value** — `%PRICE%`/`%DISCOUNT%`/`%TOTAL%` are
  substituted per campaign at billing time; the string here is the formula, not a rate.
- **`SteelHouseStatistics` is the legacy/native MNTN stats source** (SteelHouse = MNTN's former name);
  TradeDesk/Facebook/Twitter rows target the respective integration stats.

## Cost & partitioning notes
