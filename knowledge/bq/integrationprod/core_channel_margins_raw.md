# integrationprod.core_channel_margins_raw

## Purpose
Raw **per-channel margin configuration** — one row per `channel_margin_id`, keyed on a
(`channel_id`, `partner_id`) combination, holding the margin / padding / partner-margin / data-margin rate
config for that channel-partner. This is the **base ("raw") layer** in the channel-margin family; the
resolved/materialized siblings (`core_channel_margins`, the view `core_channel_margins_raw_vw`,
`core_v_channel_margins`) and the finer-grained override layers (`core_advertiser_channel_margins`,
`core_campaign_group_channel_margins`) build on top of it. Base Postgres-CDC replica. **No `silver.core`
view exists** for this table (confirmed absent 2026-07-29). Actively maintained (recent `update_time` in
2026-07).

## Grain & keys
- **Grain:** one row per **`channel_margin_id`** (PK) — a distinct channel-partner margin config. 9 rows,
  full dump 2026-07-29. **Sparse ids:** 1–5 (legacy, partner 2), then 100–103 (partners 8/79).
- **Primary key:** `channel_margin_id` (INT64); sole cluster key.
- **Foreign keys / join columns:**
  - `channel_id` → `channels.channel_id` (values seen: 1,3,4,7,8; per convention 1≈display, 8≈CTV).
  - `partner_id` → partner/DSP dim (values seen: 2, 8, 79).
  - `margin_reason_id` → `core_margin_reasons.margin_reason_id` (all NULL in current rows).
  - `user_id` → creating user (all NULL in current rows).

## Column meanings (only the non-obvious ones)
- **`budget_margin`, `budget_padding`, `partner_margin`, `data_margin`** — rate values **stored as STRING**
  (e.g. "0.3400", "1.0600", "0.1100", "0.0000") — must be `CAST(... AS NUMERIC/FLOAT64)` before arithmetic.
  They are fractional rates (margin/padding multipliers); `budget_padding` is around 1.0x (a padding
  multiplier), the margins are fractions <1. Formatting is inconsistent across rows (some "0.5", some
  "0.5000", some "1") — normalize on read.
- **`platform_fee`, `target_cpm`** (NUMERIC) — present in schema but **NULL for all 9 current rows**.
- **`margin_reason_id`** (INT64) — FK to `core_margin_reasons`; **NULL for all current rows**.
- **`channel_id`** — the channel this margin applies to (join `channels`); a given `channel_id` can appear
  in multiple rows across different partners (e.g. channel 8 appears for partners 2, 8, 79).
- **`create_time` / `update_time`** — TIMESTAMP; `update_time` shows active maintenance (rows updated 2026-03
  / 2026-07). Legacy rows 1–5 were seeded 2020-03.
- **`user_id`** — creating user; NULL for all current rows.
- **`datastream_metadata`** — Datastream CDC lineage RECORD; not business data.

## Joins & relationships
- **`channel_id` → `channels.channel_id`**: N:1 decode of the channel.
- **`margin_reason_id` → `core_margin_reasons.margin_reason_id`**: N:1 (currently unused — all NULL).
- **Family context (all in `integrationprod`, verified via `bq ls` 2026-07-29):** `core_channel_margins`
  (resolved/current), `core_channel_margins_raw_vw` (view over this raw table),
  `core_channel_margin_archives_raw` + `archives_*_channel_margin_archives` (history), and the override
  layers `core_advertiser_channel_margins` / `core_campaign_group_channel_margins` (advertiser- and
  campaign-group-level margins that override the channel default). Prefer the resolved
  `core_channel_margins` / `core_v_channel_margins` for effective rates; use THIS table for the raw
  per-channel base config.
- **No `silver.core.channel_margins_raw` view** — query the bronze table directly.

## Gotchas
- **Margin/padding rates are STRING, not numeric** — always `CAST` before math, and normalize inconsistent
  formatting ("0.5" vs "0.5000" vs "1").
- **`platform_fee`, `target_cpm`, `margin_reason_id`, `user_id` are all NULL** in the current 9 rows — do
  not rely on them being populated.
- **This is the RAW base layer** — effective billed margins may be overridden at the advertiser or
  campaign-group level (see the sibling tables). Do not treat a raw channel margin as the final applied rate.
- **Sparse ids** (1–5, 100–103) — decode on the literal id, do not generate a range.
- **No `deleted`/`is_test`** — no soft-delete filter applies; read all rows.

## Cost & partitioning notes
- **Non-partitioned static config: 9 rows / ~1 KB.** No partition, no TTL, no `require_partition_filter`.
  Clustered on `channel_margin_id` (no-op at this size). `SELECT *` bills the tier-1 10 MB minimum; broadcast
  freely.

## Example queries
```sql
-- Full raw channel-margin config (tiny)
SELECT channel_margin_id, channel_id, partner_id,
       CAST(budget_margin AS FLOAT64)  AS budget_margin,
       CAST(budget_padding AS FLOAT64) AS budget_padding,
       CAST(partner_margin AS FLOAT64) AS partner_margin,
       CAST(data_margin AS FLOAT64)    AS data_margin,
       update_time
FROM `dw-main-bronze.integrationprod.core_channel_margins_raw`
ORDER BY channel_margin_id;
```
