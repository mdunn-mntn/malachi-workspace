# integrationprod.core_beta_advertisers

## Purpose
Bronze CDC replica table listing advertisers flagged as **beta** (one enrollment row per advertiser).
Reach for it to test whether an `advertiser_id` is in the beta set and when it was added. It is a thin
membership/flag table — a surrogate `id`, the `advertiser_id`, and a `create_time`; no other attributes.
Exposed as the `silver.core.beta_advertisers` view (a plain `SELECT * FROM` this bronze table). As of
2026-07-29 it holds 35,146 rows — `advertiser_id` is **unique** (1:1 with rows), and rows accrue over
time (newest `create_time` values are current-day), so treat it as an append-driven membership list, not
a static enum.

## Grain & keys
- **Grain:** one row per beta-flagged advertiser (verified: 35,146 rows = 35,146 distinct `id` = 35,146
  distinct `advertiser_id`, 2026-07-29).
- **Primary key:** `id` (INT64, surrogate autoincrement, unique; the sole cluster key).
- **Natural key:** `advertiser_id` — **unique** here (one beta row per advertiser); safe to join on.
- **Foreign key:** `advertiser_id` → `advertisers.advertiser_id` (and the `public_advertisers` /
  `core.advertisers` equivalents).
- **No `deleted` / `is_test` columns** — no soft-delete on this table; presence of a row = the flag.

## Column meanings (only the non-obvious ones)
- **`id`** — surrogate PK / cluster key (autoincrement enrollment id). Ordering by `id` tracks enrollment
  order. Not the advertiser id.
- **`advertiser_id`** — the flagged advertiser; unique across the table. This is the join/lookup key, not
  `id`.
- **`create_time`** — TIMESTAMP the advertiser was added to the beta set (enrollment time). Populated;
  newest rows are current-day, confirming this table grows over time.
- **`datastream_metadata`** — Datastream CDC lineage RECORD (`uuid`, `source_timestamp`).
  `source_timestamp` is a **millisecond** epoch (CDC-capture time), not business time. There is no
  `update_time` — membership is add-only in the observed schema.

## Joins & relationships
- **`core_beta_advertisers.advertiser_id` → `advertisers.advertiser_id`** — **N:1** into the advertiser
  dim (this table is the many-side only in the sense of listing a subset; each advertiser appears once).
  Used as an existence/flag test (`WHERE advertiser_id IN (SELECT advertiser_id FROM ...)` or a LEFT
  JOIN + `IS NOT NULL`), it **cannot fan out** the advertiser side, since `advertiser_id` is unique here.
- **`silver.core.beta_advertisers`** is a VIEW = `SELECT * FROM dw-main-bronze.integrationprod.core_beta_advertisers`
  (verified 2026-07-29). Content-identical.

## Gotchas
- **What "beta" designates is not encoded in this table.** The table carries only membership + enrollment
  time; the business meaning of the beta flag (which program/feature) is not derivable from its columns —
  confirm with the product/eng owner before attributing behavior to it.
- **No soft-delete / `update_time`.** Presence of a row is the flag; there is no observed mechanism here
  to mark an advertiser as removed from beta. Do not assume a missing advertiser was "un-flagged".
- **Join on `advertiser_id`, not `id`.** `id` is an internal surrogate; `advertiser_id` is the business
  key and is unique.
- **Row count is large (~35K).** Despite the name, a large share of advertisers carry a row — do not
  treat "has a beta row" as a small/exclusive cohort without checking against the live advertiser count.

## Cost & partitioning notes
- **BASE TABLE, physical `self`** (the silver `core.beta_advertisers` view reads it directly). `bq show`:
  `type=TABLE`, `numRows=35146`, `numBytes≈2.46 MB`, `timePartitioning=None`, `clustering.fields=[id]`,
  no `expirationTime` (no TTL).
- **Partition: none.** `require_partition_filter=false`. Nothing to prune; a full scan is ~2.5 MB
  (tier-1 floor). Read freely.
- Clustered on `id` — only helps point lookups by surrogate id, which you rarely need. Filter/join on
  `advertiser_id` for the common case.

## Example queries
```sql
-- is an advertiser flagged beta? (existence test, no fan-out) — prefer the silver view
SELECT a.advertiser_id, (b.advertiser_id IS NOT NULL) AS is_beta, b.create_time AS beta_since
FROM `dw-main-silver.core.advertisers` a
LEFT JOIN `dw-main-silver.core.beta_advertisers` b USING (advertiser_id)
LIMIT 100;

-- the beta set with enrollment dates (whole table, cheap)
SELECT advertiser_id, create_time
FROM `dw-main-bronze.integrationprod.core_beta_advertisers`
ORDER BY create_time DESC;
```
