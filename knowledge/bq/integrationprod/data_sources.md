# integrationprod.data_sources

## Purpose
The **authoritative `data_source_id` (DS) → name registry** — the master dimension that decodes every DS leaf
that appears in audience-segment expressions, `ipdsc__v1`, the usage/billing meters, and conversion logs.
Reach for it whenever you have a bare `data_source_id` (or `conversion_source_id`) and need the canonical
name, whether a DS is a shared/platform source vs a per-advertiser container, or which conversion-type
sentinel a pixel source defaults to. This is a Postgres dimension mirrored into BQ via Datastream CDC.

## Grain & keys
- **Grain:** one row per `data_source_id` (a registered data source). 86,729 rows.
- **Primary key:** `data_source_id` — 86,729 distinct = row count, unique.
- **Secondary unique key:** `data_source_key` — 86,729 distinct, zero NULL (one anomaly: DS61 = literal `'false'`).
- **Two sub-populations by `data_source_type_id`:**
  - **type 1 = 72 shared/platform DSes** — the canonical DSxx taxonomy (IDs `-1..64` + mobile-partner `328493–328497` + `355420` + `3986845`). This is the map everyone means by "the DSes".
  - **type 2 = 86,657 per-advertiser container DSes** — IDs ≥ 1072, all `visible=false`, names like `"{AID} - First Party Audience"` / `"… - Third Party Audience"` / `"… - Control Group Audience"` / `"… - Extension Audience"` / `"… - Prospecting Campaign"` / `"… - Retargeting Campaign"`.

## Column meanings (only the non-obvious ones)
- **`data_source_type_id`** — only two values live. `1` = shared/platform DS (the DSxx taxonomy, 72 rows); `2` = per-advertiser container (86,657 rows, IDs ≥ 1072, all `visible=false`). Filter `=1` to get the canonical map; join on it (not an ID range) when deciding whether an expression leaf is a platform DS or an advertiser's own container.
- **`data_source_null_key_id`** — populated on only **12 rows**, and each value is the **default/"unnamed" conversion-type sentinel** emitted when a conversion arrives from that source with no explicit `type`. Values run `-100 … -111` and map 1:1 to the sentinels in `core_advertiser_conversion_types`: `-1→-100`(MNTN Pixel), `23→-101`(guid_log), `31→-102`(CRM Upload), `32→-103`(CDK), `37→-104`(CallRail), `328494→-105`(AppsFlyer), `328496→-106`(Kochava), `328497→-107`(Singular), `41→-108`(Freshpaint), `61→-109`(AppsFlyer v2), `57→-110`(Ours Privacy), `64→-111`(Quorum). This dim is the authoritative **source → sentinel** registry — it extends the 6-sentinel list in `data_knowledge.md` to the full 12.
- **`is_mobile`** — TRUE only for mobile-MMP conversion sources (AppsFlyer 61/328494, Kochava 328496, Singular 328497, Quorum 64) and `35` LiveRamp IP. Flags mobile-partner sources, not "mobile audience."
- **`visible`** — whether the DS surfaces in the client UI. Most platform DSes are internal (`visible=false`); only a handful are `true` (MNTN Pixel, Oracle, CRM, LiveRamp, ShareThis, Dstillery, OnAudience, Experian, shopify, CRM Inclusions, MNTN Audience API, …). **This is a visibility flag, not a soft-delete** — there is no `deleted` column (see Gotchas).
- **`display_name`** — client-facing name; usually NULL → fall back to `name`. Set on a few (`-1`/`23`="MNTN Pixel", `61`/`328494`="AppsFlyer", `328496`="Kochava", `328497`="Singular", `64`="Quorum", `57`="OursPrivacy Event").
- **`conversion_type_display_name`** — the label conversions from this source render under (e.g. "Website Event", "Mobile Event", "Offline Event", "HubSpot", "Tealium", "Bombora"). Populated only for conversion/pixel/integration sources; NULL for pure audience DSes.
- **`data_source_key`** — external/API delivery key, unique + non-null in this table. **Anomaly:** DS61 (AppsFlyer v2) stores the literal string `'false'`.
- **`category_id_maps_to`** — **100% NULL across all 86,729 rows; vestigial/unused.** Do not rely on it.
- **`create_time` / `update_time`** — native `TIMESTAMP` (no epoch decode; `time_unit: timestamp`). **`create_time` is FLOORED at the CDC-mirror initialization `2024-07-09`** for every row that predated Datastream — IDs `1–19,21` all read `2024-07-09`, which is NOT their true creation. Only DSes created after that carry real dates (DS20 `2024-07-16`, DS22 Experian `2024-09-24`, DS23 guid_log `2024-10-04`, …). `update_time` for the legacy rows clusters at a single `2025-03-03` bulk touch.

## Joins & relationships
`data_source_id` is the dim/**"1" side** of every relationship below → **no fan-out originates from this table** (PK is unique); fan-out risk is always on the fact side, dedup there.
- **`summarydata.conversions.conversion_source_id` → data_sources.data_source_id** (N:1). Decodes the conversion pixel source; `-1`/`23` both display as "MNTN Pixel", `21`="MNTN Conversion".
- **`coredw.usage_reporting_data.data_source_id` / `usage_reporting_audits.data_source_id` → data_sources** (N:1). ⚠️ this table's `data_source_id` is **INT64**; `tpa.direct_data_partners.data_source_id` is **STRING** — cast one side when bridging the billing meter to the partner registry.
- **`external.ipdsc__v1.data_source_id` → data_sources** (N:1). The IP→DS membership feed; DS13/19/35/17/18 leaves decode here.
- **`categories` / `keyword_categories` WHERE data_source_id = N** (1:N — data_sources is the 1). Per-DS category catalogs: DS13 verticals, DS16 funnel tags, DS38 keyword strings. NOTE DS19 category names are NOT in `categories` (they live in `external.tpa__mntn_matched_taxonomy__v2`).
- **Audience-segment expression JSON** references `data_source_id` leaves (both type-1 platform DSes and type-2 per-advertiser containers — see Gotchas).
- **Sibling `integrationprod.audience_data_sources`** = the audience-service's near-duplicate registry. It carries a `datastream_metadata` RECORD and the duplicate-`data_source_key` anomaly (AUD-5368); **this `data_sources` table has neither** (no RECORD column; all keys distinct).

## Gotchas
- **No `deleted` / `is_test` columns** — the standard integrationprod live-row filter does NOT apply here; every row is live. Use `visible` for UI-surfacing, never as a soft-delete proxy.
- **`create_time` is a CDC floor (`2024-07-09`), not a true birthdate** — don't date old DSes from it. For a real "first seen" of a conversion source, use `core_advertiser_conversion_types.create_time` or registry evidence.
- **Two names per DS** (code/canonical `name` vs product/war-room label): DS13 "MNTN Vertical Categorization" = "Peak Performance"/PP v1; DS19 "MNTN Matched" = "MM"/"MM Core"/Bryce's "Keywords"; DS46 = "Peak Performance v2" (Fangorn/RTC); DS2 "MNTN First Party" = OPM, **not** "MM" (Bryce's mapping was wrong). Always cite the canonical `name` from this table; never trust a tribal DS id.
- **Type-2 per-advertiser containers DO appear in audience expressions** (not only IDs 1–99) — e.g. AID 36678 references its own `… - Prospecting Campaign` DS. Detect audience buckets by joining to this table and filtering `data_source_type_id` / name pattern, not by ID range.
- **`category_id_maps_to` is always NULL** — never join or filter on it.
- **Don't cross-apply the `audience_data_sources` duplicate-key anomaly here** — in this table all 86,729 `data_source_key`s are unique (only oddity: DS61 = `'false'`).
- **DS19/DS13 category ids don't resolve in `categories` under data_source_id=19/13 as expected** — this dim only holds the DS-level id→name, not category-level names.

## Cost & partitioning notes
- Base TABLE — **no partition, no cluster, no TTL**, ~5.9 MB (`numBytes` 6,173,933). Cheap; column projection is the only cost lever (no partition to prune).
- **The one filter to always apply:** `WHERE data_source_type_id = 1` — returns the 72-row canonical taxonomy instead of 86K per-advertiser container rows (cuts noise, not bytes, since unpartitioned).
- Dry-run byte figures (2026-07-19), labeled by column set:
  - `SELECT *` (all 13 cols): **6,173,933 bytes** (~5.9 MB — the whole table).
  - `SELECT data_source_id, name WHERE data_source_type_id=1` (2 cols): **3,988,326 bytes** (~3.8 MB — the long `name` column dominates; the `WHERE` does NOT reduce bytes because the table is unpartitioned).

## Example queries
```sql
-- Canonical DSxx taxonomy (the 72 platform data sources)
SELECT data_source_id, name, display_name, visible, is_mobile, conversion_type_display_name
FROM `dw-main-bronze.integrationprod.data_sources`
WHERE data_source_type_id = 1
ORDER BY data_source_id;

-- Decode a single DS id (or conversion_source_id)
SELECT data_source_id, name, data_source_null_key_id
FROM `dw-main-bronze.integrationprod.data_sources`
WHERE data_source_id = 19;
```
