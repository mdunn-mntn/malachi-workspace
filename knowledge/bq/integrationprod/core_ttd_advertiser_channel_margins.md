# integrationprod.core_ttd_advertiser_channel_margins

## Purpose
Bronze CDC replica dimension holding **per-advertiser, per-channel TTD (The Trade Desk) budget margins**.
Each row sets a `budget_margin` for one `(advertiser_id, channel_id)` pair. Reach for it to find an
advertiser's TTD budget margin on a given channel. This is the physical Postgres-CDC table behind the thin
silver view `dw-main-silver.core.ttd_advertiser_channel_margins`
(`SELECT * FROM dw-main-bronze.integrationprod.core_ttd_advertiser_channel_margins`). As of 2026-07-29:
**71 rows, 58 distinct advertisers, 2 distinct channels** — `channel_id=1` (Multi-Touch, 58 rows) and
`channel_id=8` (Television, 13 rows); `budget_margin` ranges 0.0375 → 1.0.

## Grain & keys
- **Grain:** one row per `(advertiser_id, channel_id)` TTD budget-margin setting. 71 rows / 71 distinct pairs (verified unique 2026-07-29).
- **Primary key:** `advertiser_channel_margin_id` (INT64, surrogate; the physical is clustered on it).
- **Natural key:** `(advertiser_id, channel_id)` — unique (71 rows = 71 distinct pairs).
- **Foreign keys:** `advertiser_id` → `integrationprod.advertisers.advertiser_id`; `channel_id` → `integrationprod.channels.channel_id` (1=Multi-Touch, 8=Television, verified live).
- **No `deleted` / `is_test` columns** — no live-row hygiene filter applies here.

## Column meanings (only the non-obvious ones)
- **`advertiser_channel_margin_id`** — surrogate PK, sole cluster key.
- **`advertiser_id`** — FK to `advertisers`; 58 distinct across 71 rows (some advertisers have both a Multi-Touch and a Television row).
- **`channel_id`** — FK to `channels`; live values `1`=Multi-Touch (58 rows) and `8`=Television (13 rows). Not the CTV/display encoding used in log tables — resolve via `integrationprod.channels`.
- **`budget_margin`** — NUMERIC budget-margin rate as a fraction (observed 0.0375 → 1.0). Fraction/rate, not a dollar amount.
- **`create_time` / `update_time`** — Postgres business timestamps (earliest create 2020-03-03).
- **`datastream_metadata`** — STRUCT<uuid STRING, source_timestamp INT64>; `source_timestamp` = millisecond CDC-capture epoch (not business time).

## Joins & relationships
- **`advertiser_id` → `integrationprod.advertisers.advertiser_id`** — N:1 (apply `deleted=FALSE AND is_test=FALSE` on the advertiser side). An advertiser can have up to 2 rows here (one per channel), so joining advertiser → this table fans out up to 2x.
- **`channel_id` → `integrationprod.channels.channel_id`** — N:1 (1=Multi-Touch, 8=Television).
- **History:** `integrationprod.archives_advertiser_channel_margin_archives` holds change history for these margins.

## Gotchas
- **Sparse coverage** — only 58 advertisers have any row; most advertisers are absent (no TTD channel-margin override).
- **`channel_id` here uses the `channels` dim encoding (1=Multi-Touch, 8=Television)**, not the log-table CTV/display convention. Always resolve via `integrationprod.channels`.
- **Rates are fractions, not dollars** — `budget_margin` is a NUMERIC fraction; one row is 1.0 (100%).
- **No soft-delete columns.** No `deleted`/`is_test` — do not add those predicates (they will error).
- **`datastream_metadata.source_timestamp` is CDC-capture time in ms**, not business time.

## Cost & partitioning notes
- **BASE TABLE, physical `self`** (silver `core.ttd_advertiser_channel_margins` reads it directly). `bq show`: `type=TABLE`, `numRows=71`, `numBytes=7242`, `timePartitioning=None`, `clustering.fields=[advertiser_channel_margin_id]`, no TTL.

## Example queries
```sql
-- per-advertiser TTD budget margin by channel (prefer silver views)
SELECT a.company_name, c.name AS channel, m.budget_margin
FROM `dw-main-silver.core.ttd_advertiser_channel_margins` m
JOIN `dw-main-silver.core.advertisers` a
  ON a.advertiser_id = m.advertiser_id AND a.deleted = FALSE AND a.is_test = FALSE
LEFT JOIN `dw-main-bronze.integrationprod.channels` c USING (channel_id)
ORDER BY a.company_name, c.name;
```
