# integrationprod.core_features

## Purpose
Registry of **product feature flags** — one row per feature toggle, giving its name, description, default
on/off value, and the flag system it originates from. Reach for it to resolve a `feature_id` to a flag name,
read a flag's default, or enumerate the known feature toggles. This is the flag **definition** table (not
per-entity enablement state). Datastream-CDC replica of Postgres `core.features`.

## Grain & keys
- **Grain:** one row per feature flag. 90 rows (2026-07-29).
- **Primary key:** `feature_id` (INT, sole cluster key).
- **Join column:** `feature_id` — the 1-side for any feature-flag decode / enablement join.

## Column meanings (only the non-obvious ones)
- **`name`** — the flag identifier, human-readable (e.g. `MULTI_TOUCH_ENABLED`, `EGO_CAMPAIGNS_DISABLED`,
  `CAMPAIGN_GROUP_FREQUENCY_CAPS_ENABLED`, `AUDIENCE_SIZE_WARNING_DISABLED`). Note many names encode polarity
  (`*_ENABLED` vs `*_DISABLED`), so a `default_value=false` on a `*_DISABLED` flag means the feature is on.
- **`default_value`** — BOOLEAN default state of the flag when no per-entity override exists.
- **`source`** — the originating flag system. Live distribution (2026-07-29): `harness` = 50, empty/`''` = 35,
  `tag` = 3, `internal` = 2.
- **`create_time`** — TIMESTAMP the flag row was inserted in source Postgres (flag age), not an enablement
  time.
- **`datastream_metadata.source_timestamp`** — INT64 **milliseconds** CDC-capture epoch, not business time.

## Joins & relationships
- **1-side of a decode.** Join per-entity feature-enablement tables onto this registry on `feature_id` to
  attach the flag name/default — this table cannot fan out (one row per flag). Per-advertiser/campaign flag
  STATE is not here; it lives in separate join tables.

## Gotchas
- **Polarity is in the name** — `default_value=false` on a `*_DISABLED` flag means the capability is ON.
  Read the name suffix before interpreting the boolean.
- **`source` is often empty** (35 of 90 blank) — do not assume every flag names a system.
- **No `deleted`/`is_test` columns** — the soft-delete dim filter does not apply; read all 90 rows. This is
  the flag definition table, not per-entity state.

## Cost & partitioning notes
- **Non-partitioned static dim: 90 rows / ~12 KB.** No partition, no TTL, `require_partition_filter=false`.
  Clustered on `feature_id` (a no-op at this size). `SELECT *` bills the 10 MB tier-1 minimum.

## Example queries
```sql
-- Decode / enumerate feature flags
SELECT feature_id, name, default_value, source, description
FROM `dw-main-bronze.integrationprod.core_features`
ORDER BY feature_id;

-- Flags defaulting ON
SELECT feature_id, name FROM `dw-main-bronze.integrationprod.core_features`
WHERE default_value = TRUE;
```
