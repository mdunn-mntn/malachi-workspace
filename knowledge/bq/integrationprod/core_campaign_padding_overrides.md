# integrationprod.core_campaign_padding_overrides

## Purpose
Small **exception / override table** (bronze Postgres-CDC dim via Datastream): stores a `padding` multiplier for the handful of campaigns that need a non-default value. `padding` is a decimal stored as a STRING (`"1.4"` = a +40% uplift, `"1.05"` = +5%); no row = default (no padding). Reach for it to know whether a given campaign has an operator-set padding override and what it is (with `notes` usually pointing at the Jira ticket that requested it). The **campaign-grain twin** of `core_campaign_group_padding_overrides` (campaign-group grain) and `core_advertiser_padding_overrides` (advertiser grain). The thin silver view `silver.core.campaign_padding_overrides` is a `SELECT *` over this table.

## Grain & keys
- **Grain:** one row per campaign that has a padding override. `campaign_id` is unique (physical clustered on it). Override-only table, not a per-campaign dimension — the vast majority of campaigns have **no** row. Observed live 2026-07-29: exactly **2 rows** (campaign 531697 padding `"1.4"`; campaign 219898 padding `"1.05"`).
- **Key(s) / join columns:** `campaign_id` (PK) → `campaigns.campaign_id`.

## Column meanings (only the non-obvious ones)
- **padding** — decimal multiplier stored as a **STRING**, not a number. `"1.4"` = +40%, `"1.05"` = +5%; `"1.0"` / no row = default. `CAST(padding AS NUMERIC)` before any arithmetic. Only campaigns needing a non-default override are stored. The exact quantity the factor multiplies (pacing/delivery buffer vs billing/spend) is set by the consuming service, not determinable from this dim alone.
- **notes** — free-text operator note; in practice a Jira ticket reference explaining the override (observed `"PER-5842"`, `"PER-2694"`). Not a structured field.
- **create_time / update_time** — native `TIMESTAMP` of the Postgres source row (business create / last-modify). NOT the replication time. Observed: campaign 219898 created 2024-04-29, campaign 531697 created 2026-02-12.
- **datastream_metadata.source_timestamp** — Datastream CDC-capture epoch in **MILLISECONDS** (family-wide convention). CDC / backfill event time, **not** the business `create_time` — do not conflate. `datastream_metadata.uuid` = the change-event id.

## Joins & relationships
- **`campaign_id` → `dw-main-bronze.integrationprod.campaigns.campaign_id`** (PK `campaign_id`, ~548.7K rows). **1:1** — each override references exactly one campaign; the campaign is the parent → lookup with **no fan-out**. `campaigns` is where you get `name`, the authoritative `funnel_level`, and the `deleted`/`is_test` hygiene flags.
- **Sibling override family:** `core_campaign_group_padding_overrides` (campaign-group grain), `core_advertiser_padding_overrides` (advertiser grain) — identical schema/mechanism at other grains.

## Gotchas
- **Override-only table.** Absence of a row = default (no padding). Never assume a campaign is present — `LEFT JOIN` and `COALESCE(CAST(padding AS NUMERIC), 1.0)`. Currently only 2 rows exist.
- **`padding` is a STRING.** Cast to NUMERIC before math; a raw string compare/sum is a bug.
- **No `deleted` / `is_test` columns.** Cannot filter test / soft-deleted rows here — apply that hygiene by joining to `campaigns` (`deleted=FALSE AND is_test=FALSE`).
- **Two different time meanings:** `create_time`/`update_time` = Postgres business timestamps; `datastream_metadata.source_timestamp` = CDC replication time (ms epoch). In the 219898 row they differ by ~20 months.

## Cost & partitioning notes
- **Genuine BASE TABLE**, no partition, no TTL, clustered on `campaign_id` — confirmed `bq show` (2 rows, 171 bytes). At this size clustering is immaterial and there is no partition filter to apply; `SELECT *` is trivially cheap (bills the 10 MB tier-1 minimum). Any real cost in a join comes from the `campaigns` side (~548.7K rows), not this table.

## Example queries
```sql
-- Resolve a campaign's effective padding (default 1.0 when no override row), with hygiene filter
SELECT c.campaign_id, c.name,
       COALESCE(CAST(p.padding AS NUMERIC), 1.0) AS effective_padding, p.notes
FROM `dw-main-bronze.integrationprod.campaigns` c
LEFT JOIN `dw-main-bronze.integrationprod.core_campaign_padding_overrides` p
  ON p.campaign_id = c.campaign_id
WHERE c.deleted = FALSE AND c.is_test = FALSE
  AND p.campaign_id IS NOT NULL;
```
