# integrationprod.core_ui_flight_x_media_plan

## Purpose
Bronze CDC replica **junction table** linking a **UI flight** to a **media plan**. Each row assigns one
`ui_flight_id` to one `media_plan_id`. Reach for it to find which media plan a flight belongs to, or to
list the flights inside a media plan. This is the physical Postgres-CDC table behind the thin silver view
`dw-main-silver.core.ui_flight_x_media_plan`
(`SELECT * FROM dw-main-bronze.integrationprod.core_ui_flight_x_media_plan`). As of 2026-07-29: **1,004
rows, 1,004 distinct ui_flight_id (every flight appears exactly once), 565 distinct media_plan_id** — so
each flight belongs to exactly one plan and a plan can hold up to ~18 flights.

## Grain & keys
- **Grain:** one row per `ui_flight_id`. `ui_flight_id` is **unique** here (1,004 rows = 1,004 distinct flights, verified live) — despite the `_x_` bridge name, a flight maps to exactly one media plan.
- **Natural / effective PK:** `ui_flight_id`. The declared composite `(media_plan_id, ui_flight_id)` is also unique (it's the cluster key and the source-Postgres key), but `ui_flight_id` alone already is.
- **Foreign keys:** `ui_flight_id` → `integrationprod.ui_ui_flights.flight_id` (100% resolve, verified); `media_plan_id` → `integrationprod.core_media_plan.media_plan_id` (100% resolve, verified).
- **No `deleted` / `is_test` columns** — no live-row hygiene filter applies here.

## Column meanings (only the non-obvious ones)
- **`ui_flight_id`** — the flight being assigned. **Joins to `ui_ui_flights.flight_id`** (note the name mismatch: this column is `ui_flight_id`, the target PK is `flight_id`). Unique in this table — one row per flight.
- **`media_plan_id`** — the media plan the flight belongs to. Leading cluster key. FK to `core_media_plan.media_plan_id`. Repeats — up to ~18 flights per plan.
- **`create_time` / `update_time`** — Postgres business timestamps of the assignment (freshly written; the latest sample rows are 2026-07-29).
- **`datastream_metadata`** — STRUCT<uuid STRING, source_timestamp INT64>; `source_timestamp` = millisecond CDC-capture epoch (not business time).

## Joins & relationships
- **`ui_flight_id` → `integrationprod.ui_ui_flights.flight_id`** — N:1 from this junction to the flight dim; but since `ui_flight_id` is unique here, the junction↔flight relationship is effectively **1:1** (safe to enrich flights with their media plan without fan-out).
- **`media_plan_id` → `integrationprod.core_media_plan.media_plan_id`** — N:1 to the media-plan dim. This is the **many** side: joining `core_media_plan → this table` fans out up to ~18x (flights per plan).
- **Use this as the bridge** to attach a media plan to any flight-grain fact, or to roll flights up to plan grain.

## Gotchas
- **Bridge name is misleading** — despite `_x_`, it is **not** a many-to-many at flight grain: `ui_flight_id` is unique, so each flight belongs to exactly one media plan. The many-to-one is plan→flights (a plan holds many flights).
- **Join-key name mismatch** — `ui_flight_id` here joins to `ui_ui_flights.flight_id` (not a same-named `ui_flight_id`).
- **Actively written** — rows are created continuously (latest at query time were same-day), so this table grows; treat row count as a snapshot.
- **No soft-delete columns.** No `deleted`/`is_test` — do not add those predicates (they will error).
- **`datastream_metadata.source_timestamp` is CDC-capture time in ms**, not business time.

## Cost & partitioning notes
- **BASE TABLE, physical `self`** (silver `core.ui_flight_x_media_plan` reads it directly). `bq show`: `type=TABLE`, `numRows=1004`, `numBytes=78312`, `timePartitioning=None`, `clustering.fields=[media_plan_id, ui_flight_id]`, no TTL.
- **Partition: none.** `require_partition_filter=false`. Clustered on `(media_plan_id, ui_flight_id)` — filtering `media_plan_id` first prunes best, though at 1,004 rows it hardly matters.
- **Cost:** whole-table `SELECT *` dry-runs at ~0 GB (10 MB billed floor). Read freely.

## Example queries
```sql
-- flights in each media plan (prefer silver views)
SELECT j.media_plan_id, j.ui_flight_id, f.campaign_group_id, f.start_time, f.end_time
FROM `dw-main-silver.core.ui_flight_x_media_plan` j
LEFT JOIN `dw-main-bronze.integrationprod.ui_ui_flights` f ON f.flight_id = j.ui_flight_id
ORDER BY j.media_plan_id, j.ui_flight_id;
```
