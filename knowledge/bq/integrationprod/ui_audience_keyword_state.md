# integrationprod.ui_audience_keyword_state

## Purpose
The CoreDB (Postgres → Datastream CDC) **current-state** record of which keywords are attached to each audience. This is the preferred source for "what keywords does audience X target" — an alternative to parsing the JSON expression blob in `audience.audiences`. Each audience holds ~20 **PARENT** seed terms (what the customer sees/edits in the UI audience builder) plus the system's **CHILD** expansions of those seeds; the CHILD rows with `selected=true` (minus the `is_magic` ones) are the real **DS19 / MNTN-Matched** targeting set.

Reach for this **base table** (not the `audience_keyword_state_history` view) whenever you need `is_magic`, `model_version`, `description`, `feedback`, or `datastream_metadata` — the history view drops all five, so it is the *only* place you can separate real DS19 targeting from untargetable "magic" keywords. Use the history view instead only when you need superseded/archived versions (as-of-date reconstruction). This is the **live** half that `summarydata.audience_keyword_state_history` UNIONs with `archives.audience_keyword_state_archives`.

## Grain & keys
- **Grain:** one row per **audience ↔ keyword association**, current state only. There is no `archive_time` / `update_time` / `deleted` column here — every row is the live version; edit history lives in `archives.audience_keyword_state_archives` (surfaced via the history view).
- **Primary key:** `id` (INT64) — **strictly unique** (5,022,391 rows = 5,022,391 distinct ids, verified live). Unlike the history view (where `id` is only near-unique), `id` is a safe join/dedupe key here.
- **Join columns:** `audience_id` (→ audiences / audience_segments), `data_source_id` (=19 for CHILD/DS19 rows; NULL for PARENT seeds), `data_source_category_id` (the specific DS19 keyword-segment id).

## Column meanings (only the non-obvious ones)
- **`keyword_type`** — enum `{PARENT, CHILD}` only (verified live; no other values). **PARENT** (970,259 rows) = the ~20 customer-visible seed terms shown in the UI audience builder. **CHILD** (4,052,132 rows) = the system/LLM-embedding expansions grouped under a parent. UI shows only PARENTs; the DS19 expression is built from **selected CHILDren**.
- **`selected`** — BOOL; `true` = keyword is included in the audience expression. `selected=true AND keyword_type='CHILD' AND is_magic=false` ≈ the real DS19 targeting set (2,797,890 rows live). `selected=true` overall = 3,911,323.
- **`is_custom`** — customer-entered vs system-generated. **PARENT-only** (73,939 custom PARENTs; 0 custom CHILDren, verified) — customers seed parents, the system expands children. Filtering `is_custom=true` implicitly restricts to PARENTs.
- **`is_hidden`** — **CHILD-only** (582,875 hidden CHILDren; 0 hidden PARENTs). PARENT seeds are never hidden.
- **`is_magic`** — **CHILD-only** (478,984 magic CHILDren; 0 magic PARENTs). ⚠ **`is_magic=true` keywords are UNTARGETABLE** — a UI construction whose only job is to make the displayed audience size change when the customer edits, not to bid on anyone. 410,099 of them are `selected` (they appear in the DS19 expression yet target no one). **Do not count magic keywords as off-target targeting.** The real targetable DS19 set = `selected AND keyword_type='CHILD' AND is_magic=false`. **This column exists only here — the history view drops it.**
- **`data_source_id`** — `19` (DS19 / MNTN-Matched) for CHILD rows (4,051,129); **NULL for PARENT seeds** (parents carry no data source — they are customer input, not a data-source category). ~1,003 CHILD rows are also NULL. So do **not** filter `data_source_id=19` if you want the PARENT seeds.
- **`data_source_category_id`** — high-cardinality INT: the specific keyword-segment/category id within DS19. Not a small enum — do not treat as a type code.
- **`create_time`** — native **TIMESTAMP** (not an epoch int) of business creation. Range 2024-07-25 → present (live). Use this for business time.
- **`datastream_metadata`** — STRUCT `<uuid STRING, source_timestamp INT64>` from Datastream CDC. **`source_timestamp` = milliseconds** (UNIX_MILLIS): `TIMESTAMP_MILLIS(1784561834562)` = 2026-07-20 15:37:14, matching that row's `create_time`. ⚠ It is the **CDC-capture time, NOT business time** — its min is 2026-05-06 (Datastream backfill window) while `create_time` goes back to 2024-07-25. Use `create_time` for when a keyword was created; use `source_timestamp` only for CDC/replication debugging.
- **`expanded_from`** — JSON **array** of the PARENT seed(s) a CHILD was embedding-expanded from, e.g. `["Garden Tools"]`. Populated for CHILDren (4,051,591 rows), NULL/empty for PARENTs. Extract with `JSON_VALUE`/`JSON_QUERY`; sometimes the child text equals the seed.
- **`model_version`** — **sparse: 99.9% NULL** (only ~5,352 of 5.02M rows stamped). When set, it is the expansion model version, either a composite `level:advertiser|als:<n>|llm:<hash>|kmeans:<hash>` string or `autopilot:1`. Do not rely on it being present.
- **`description`** — **100% NULL/empty** across the table (verified) — currently unused. Do not build logic on it.
- **`feedback`** — **100% NULL** across the table (verified) — currently unused. Do not build logic on it.

## Joins & relationships
- **`audience_id` → `audience.audiences` / `ui.audience_segments`** — partner grain is **1 row per audience** (dim). This table is **N:1** into audiences (avg ~5 keyword rows per audience; large audiences have hundreds–thousands of keyword rows). Joining audiences → this table **fans out**; aggregate or filter to the keyword subset you need (e.g. `keyword_type='CHILD' AND selected`) before joining back to a per-audience metric. (Partner tables are CoreDB dims; verify grain 1-per-audience before a raw join.)
- **`data_source_id = 19`** ties CHILD rows to the DS19 / MNTN-Matched targeting path; the selected non-magic CHILDren here are the source-of-truth DS19 expression (preferred over parsing the JSON blob in `audience.audiences`).
- **`data_source_category_id`** → the DS19 keyword-segment category id (high cardinality); resolve names via the DS19 category/`tpa.categories` path if needed — not a code to interpret inline.
- **Live half of `summarydata.audience_keyword_state_history`** — that view is `UNION ALL` of this table (rows with `archive_time` NULL) + `archives.audience_keyword_state_archives` (superseded versions). Same `id` space; join on `id`.
- **No direct join to impression/bid logs** — this is a config/dimension, not an event log. Connect keywords to delivery via audience → campaign → bid/impression, not from here directly.

## Gotchas
- **is_magic keywords are UNTARGETABLE and live only here.** 410K selected-magic CHILDren appear in the DS19 expression but target no one; the history view drops `is_magic` so you cannot filter them out there. Real DS19 set = `selected AND keyword_type='CHILD' AND is_magic=false`. (TI-1026 / Alex Knorr 2026-06-17.)
- **PARENT seeds have NULL `data_source_id`.** Filtering `data_source_id=19` silently drops all ~970K PARENT rows. Filter on `keyword_type` for PARENT/CHILD splits, not `data_source_id`.
- **`feedback` and `description` are entirely NULL; `model_version` is 99.9% NULL.** Treat all three as effectively unpopulated — no analysis should depend on them.
- **`datastream_metadata.source_timestamp` is CDC-capture ms, not business time** — min 2026-05-06 reflects a Datastream backfill, not when keywords were created. Use `create_time` (native TIMESTAMP, back to 2024-07-25) for business time.
- **Current state only — no history, no soft-delete flags.** There is no `archive_time`, `update_time`, `deleted`, or `is_test` column. A keyword removed from an audience simply disappears from this table (its prior version survives in `archives.audience_keyword_state_archives`). For an audit trail / as-of-date, use `summarydata.audience_keyword_state_history`.
- **`id` is a strict unique PK here** (unlike the near-unique `id` in the history view) — safe to dedupe/join on directly.
- **UI ≠ expression.** The audience builder shows only PARENT seeds; the actual DS19 targeting is the selected non-magic CHILDren, which are not individually searchable in the UI.

## Cost & partitioning notes
- **Physical BASE TABLE — unpartitioned, clustered on `id`.** `timePartitioning = None`, `require_partition_filter = false`, no TTL. There is **no date partition to filter** — the only cost lever is **column projection**.
- **Dry-run figures (2026-07-20, labeled by column set):** `SELECT *` (all 16 cols) = **793.6 MB** (= full `numBytes`); `SELECT keyword_type` (one narrow STRING col) = **36.1 MB**; a 6-column aggregate (keyword_type, is_custom, is_hidden, is_magic, selected, data_source_id) = **88.1 MB**. ~22x spread between `SELECT *` and one narrow column — never `SELECT *` for exploration.
- **Clustering:** a filter on **`id`** prunes at runtime (dry-run estimates do not reflect cluster pruning); a filter on `audience_id` prunes nothing.
- **Backing storage (real):** 793.6 MB / 5,022,391 rows (`bq show` numBytes; = approx_logical_bytes). No partition expiration — full current-state retained.
- Always project only the columns you need and (typically) filter `audience_id = @id` for single-audience lookups.

## Example queries
```sql
-- Real DS19 / MNTN-Matched targeting set for one audience (magic excluded)
SELECT keyword, data_source_category_id
FROM `dw-main-bronze.integrationprod.ui_audience_keyword_state`
WHERE audience_id = @audience_id
  AND keyword_type = 'CHILD'
  AND selected = TRUE
  AND is_magic = FALSE;

-- The ~20 customer-visible seed terms (UI audience builder view)
SELECT keyword, is_custom
FROM `dw-main-bronze.integrationprod.ui_audience_keyword_state`
WHERE audience_id = @audience_id
  AND keyword_type = 'PARENT';
```
> Need superseded/archived versions or as-of-date reconstruction? This table is current-state only — use `summarydata.audience_keyword_state_history` (but note it drops is_magic/model_version).
