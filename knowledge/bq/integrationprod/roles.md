# integrationprod.roles

## Purpose
The RBAC role dimension for the MNTN platform's user-permission system. 13 canonical roles
(Super Admin, Performance Analyst, Advertiser Admin, Campaign Manager, …). Reach for it to turn a
`role_id` / `user_role_id` integer FK found on a user or user×advertiser junction row into a
human-readable role name plus its scope and default/superuser flags. It is a small static seed/lookup
dim — join it, don't scan it. Note there is an identical sibling `ui_roles` (same 13 rows / same id
space) that is the live Datastream-CDC mirror; this `roles` copy adds the `assignable_to` column but
carries no `datastream_metadata`.

## Grain & keys
- **Grain:** one row per platform RBAC role. 13 live rows.
- **Primary key:** `roles_id` (non-contiguous — ids 11, 12, 13 are absent; the live set is
  1-10, 14, 15, 16).
- **Consumed as a FK target** by `role_id` / `user_role_id` columns on the user and junction tables
  (see Joins). No `deleted` / `is_test` columns exist, so the standard
  `deleted=FALSE AND is_test=FALSE` live-row filter does not apply here — all 13 rows are live.

## Column meanings (only the non-obvious ones)
- **roles_id** — PK. Non-contiguous; gaps at 11/12/13 are historically deleted roles. Consuming
  tables still carry orphan/sentinel FK values (`11`, `99`, `-1`, `NULL`) that will NOT resolve here.
- **hotel_id** — vestigial legacy multi-tenant column. **100% NULL across all 13 rows.** "hotel" is
  boilerplate terminology inherited from the source app's starter schema; MNTN roles are global, not
  per-tenant. Never a usable join key.
- **sort_order** — integer UI display-ordering hint for role pickers (lower sorts higher). Not unique,
  arbitrary gaps (10 … 10000); `Restricted` = 10000 sorts last. No business meaning beyond ordering.
- **default_role** — BOOL. Marks the role auto-assigned to a new customer user. Exactly one TRUE:
  `Portfolio Admin` (id 2). Renders as string `"true"`/`"false"` in prettyjson.
- **unlimited_power** — BOOL superuser-bypass flag. TRUE only for `Super Admin` (id 1); grants all
  permissions regardless of scope. Renders as string `"true"`/`"false"` in prettyjson.
- **scope** — which audience the role belongs to. Full domain (all 13 rows) = **{mntn, customer,
  reviewer}**. `mntn` = internal MNTN staff roles (Super Admin, Sales, Performance Analyst,
  Account/Onboarding/Growth Manager, Restricted); `customer` = external client-side roles (Portfolio
  Admin, User, Advertiser Admin, Campaign Manager, Reporting Only); `reviewer` = Guest Reviewer.
- **assignable_to** — template-placeholder string for the entity level a role attaches to. Full domain
  = **{NULL, '{advertiser}', '{hotel}'}**. `{advertiser}` for advertiser-level customer roles (User,
  Advertiser Admin, Campaign Manager, Reporting Only); `{hotel}` for Portfolio Admin (legacy "hotel"
  == portfolio/customer); NULL for mntn- and reviewer-scope roles that aren't advertiser-assignable.
  This column exists ONLY on `roles`, not on the `ui_roles` mirror.

## Joins & relationships
`roles.roles_id` is a **1:N FK target** (this dim is the "1" side). Sentinel/orphan FK values
(`11`, `99`, `-1`, `NULL`) won't resolve — always LEFT JOIN and expect misses.

- **core_r2_roles_x_advertisers.role_id → roles.roles_id** — R2 / RBAC-v2 auth role×advertiser
  junction. **Heavy fan-out (~38K rows per role_id; ~230K total).** Observed role_id domain there =
  {1, 9, 10, 11, 14, 15}; `11` is an orphan (absent from this dim). Aggregate/DISTINCT before joining.
- **ui_users.user_role_id → roles.roles_id** — the internal MNTN platform user table; one role per
  user (N users : 1 role). Dominated by role 6 (Performance Analyst, ~43K) and role 1 (Super Admin,
  ~6K). Contains sentinels `-1`, `99` and ~1.3K NULLs that won't join.
- **ui_users_x_advertisers.role_id → roles.roles_id** — user×advertiser junction; **currently 100%
  NULL** (role is instead encoded in that table's `permissions` column). **core_users_x_hotels.role_id**
  is the legacy user×hotel equivalent.
- **Sibling `ui_roles`** — identical 13-row dim sharing the exact same `roles_id` space; either table
  resolves the same FK. Use `ui_roles` when you need `datastream_metadata` / CDC timing; use `roles`
  when you need `assignable_to`.

## Gotchas
- **Not a live CDC mirror.** `roles` has no `datastream_metadata` and no create/update time — it is a
  static seed dim. There is no business-time column, so `time_unit = none`. The Datastream-CDC copy is
  the sibling `ui_roles`.
- **No `deleted` / `is_test` columns** — the standard `deleted=FALSE AND is_test=FALSE` filter does not
  apply (columns absent); all 13 rows are live.
- **Non-contiguous PK + orphan FKs.** `roles_id` skips 11/12/13. Consuming tables reference deleted
  role 11 plus sentinels 99 / -1 / NULL that won't join — never assume every `role_id` resolves.
- **hotel_id is 100% NULL and vestigial** — not a join key.
- **BOOL columns render as string** `"true"`/`"false"` in prettyjson output.

## Cost & partitioning notes
- Physical BASE TABLE (not a view): unpartitioned, unclustered, 13 rows / 598 bytes. No partition
  filter is needed or possible — scan freely; it's a broadcast/lookup dim, not a scan-cost concern.
- **Full `SELECT *` (all 8 columns) = 598 bytes** (measured via `--dry_run`, 2026-07-19). Effectively
  free; do not bother pruning columns on this table.

## Example queries
```sql
-- Label internal MNTN platform users with their role name/scope
SELECT u.user_id, u.email_addr, r.name AS role_name, r.scope
FROM `dw-main-bronze.integrationprod.ui_users` u
LEFT JOIN `dw-main-bronze.integrationprod.roles` r   -- LEFT: sentinels -1/99/NULL won't resolve
  ON u.user_role_id = r.roles_id

-- The role dimension itself (whole table, ~free)
SELECT roles_id, name, scope, assignable_to, default_role, unlimited_power
FROM `dw-main-bronze.integrationprod.roles`
ORDER BY sort_order
```
