# integrationprod.core_device_type_groups

## Purpose
Static reference enum that groups device types into 5 broad device families and carries the **default
optimization budget ratio** per family. Reach for it to decode a `device_type_group_id` into a family label
(MOBILE / COMPUTER / CONNECTED_TV / TABLET / UNKNOWN) or to read the per-family default budget-allocation
ratio. It is the parent of `core_device_types` (which references `device_type_group_id`).

## Grain & keys
- **Grain:** one row per device-type group. Static enum, 5 rows (full dump verified 2026-07-29).
- **Primary key:** `device_type_group_id` (INT, sole cluster key). Includes the sentinel `-1` (UNKNOWN).
- **Children:** `core_device_types.device_type_group_id` → this table (1:N).

## Column meanings (only the non-obvious ones)
- **`device_type_group_id`** — enum code, PK, cluster key. Full live domain (2026-07-29):

  | device_type_group_id | device_type_group_name | optimization_default_ratio |
  |---|---|---|
  | -1 | UNKNOWN | 0 |
  | 1 | MOBILE | 0.15 |
  | 2 | COMPUTER | 0.05 |
  | 3 | CONNECTED_TV | 0.70 |
  | 4 | TABLET | 0.10 |

- **`optimization_default_ratio`** — NUMERIC(3,2) default share of budget/optimization weight for the family
  (CONNECTED_TV highest at 0.70; UNKNOWN 0). Non-null on all 5 rows.
- **`budget_floor`** / **`budget_ceiling`** — NUMERIC(4,3) per-group budget bounds; **NULL on all 5 rows**
  in the live table (defined in schema, unpopulated).
- **`datastream_metadata.source_timestamp`** — INT64 **milliseconds** CDC-capture epoch, not business time.

## Joins & relationships
- **Parent of `core_device_types`:** `core_device_types.device_type_group_id` → `device_type_group_id`
  (1:N). This table is always the 1-side; the decode cannot fan out.
- Distinct from `integrationprod.device_type` (the flat 8-row INT→name ENUM used on `bronze.raw` bidder
  event tables) — that lookup has no group concept.

## Gotchas
- **Sentinel `-1` = UNKNOWN** (ratio 0) — filter it out when enumerating real device families.
- **`budget_floor`/`budget_ceiling` are all-NULL** in the live table — do not rely on them.
- **No `deleted`/`is_test` columns** — the soft-delete dim filter does not apply; read all 5 rows.

## Cost & partitioning notes
- **Non-partitioned static dim: 5 rows / ~399 bytes.** No partition, no TTL, `require_partition_filter=false`.
  Clustered on `device_type_group_id` (a no-op at this size). `SELECT *` bills the 10 MB tier-1 minimum.

## Example queries
```sql
-- Decode a device-type group + its default optimization ratio
SELECT device_type_group_id, device_type_group_name, optimization_default_ratio
FROM `dw-main-bronze.integrationprod.core_device_type_groups`
ORDER BY device_type_group_id;

-- Roll device types up to their family
SELECT g.device_type_group_name, dt.device_type_name
FROM `dw-main-bronze.integrationprod.core_device_types` dt
JOIN `dw-main-bronze.integrationprod.core_device_type_groups` g USING (device_type_group_id);
```
