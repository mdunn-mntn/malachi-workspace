# integrationprod.archives_integration_margin_archives

## Purpose
Append-only **version history** of `core_integration_margins`. `core_integration_margins`
holds the margin MNTN applies to a *data-source integration* (a data provider such as Oracle,
or the internal MNTN Pixel). Every time one of those live margin rows is created or edited, a
snapshot of it is written here with an incrementing `version`, so you can reconstruct what the
margin for a given integration was on any past date. The live parent keeps only current rows
(1 observed) — the historical trail lives here.
**SENSITIVE:** this is a `*margin*` table; `data_margin` carries the actual rate. Document
schema/grain only — never surface rate values in shared docs.

## Grain & keys
- **Grain:** one row per `(integration_margin_id, version)` — an archived snapshot of a
  `core_integration_margins` row.
- **PK / cluster:** `integration_margin_archive_id` — surrogate, table-wide monotonic (1..N),
  sole cluster key.
- **Natural key:** `(integration_margin_id, version)`.
- **FKs:** `integration_margin_id → core_integration_margins.integration_margin_id`;
  `data_source_id → data_sources.data_source_id`.

## Column meanings (only the non-obvious ones)
- **integration_margin_archive_id** — surrogate PK of the archive row and sole cluster key.
  Monotonic across the whole table, NOT per `integration_margin_id`.
- **integration_margin_id** — FK to the live `core_integration_margins` row this snapshots.
  Repeats across the row's versions.
- **data_source_id** — FK to `data_sources`; identifies the data provider / integration the
  margin applies to. This is the **integrations/margin data-source dim**, NOT the audience DSxx
  taxonomy (DS19 MM Core, DS13 PP v1, …) — different namespace. Observed values: `1`=Oracle,
  `-1`=MNTN Pixel, `-2`=unmapped (no matching `data_sources` row). Negative sentinels are normal
  here.
- **create_time** — business timestamp copied from the parent: the parent margin row's original
  creation. Constant across a row's versions.
- **update_time** — business timestamp of the parent's last edit at snapshot time; advances
  across versions for the same `integration_margin_id`.
- **data_margin** — NUMERIC(5,4) margin rate. **SENSITIVE — value omitted.**
- **version** — snapshot sequence for a given `integration_margin_id`, starting at 1. Observed
  monotonic (1, 2) but the `archives_*` family convention warns version can be non-monotonic —
  do not assume `MAX(version)` = latest; order by `archive_time`.
- **archive_time** — when THIS snapshot was written to the archive (the archival event time).
  This is the column that changes across versions and orders the history.
- **datastream_metadata.source_timestamp** — INT64 **milliseconds** epoch of the Datastream CDC
  capture (`TIMESTAMP_MILLIS(...)`; confirmed: 13-digit value → 2026-05-18, matching the row's
  business timestamps; MICROS/SECONDS would be wildly off). CDC-capture time, not business time —
  lands minutes-to-hours after `archive_time`. `.uuid` = CDC row uuid.

## Joins & relationships
- **core_integration_margins** (parent, **1:N** — one live margin → many archive snapshots) on
  `integration_margin_id`. Parent is tiny (1 row observed); the archive holds pruned history.
  Fan-out: joining archive→parent is N:1 (safe); parent→archive is 1:N (expected, that's the
  history). Note `core_integration_margins` is a bronze CDC dim (not SQLMesh); reported
  `numRows` may lag.
- **data_sources** (N:1 — many archive rows → one data_source) on `data_source_id`. Small dim,
  no fan-out. Negative/unmapped sentinels (`-2`) will NOT join — use a LEFT JOIN if you need all
  rows.
- Neither this table nor its parent has `deleted` / `is_test` columns, so the
  `deleted=FALSE AND is_test=FALSE` convention does **not** apply.

## Gotchas
- Tiny table (5 rows / 590 bytes). It exists so vendor/integration margin history survives after
  the live `core_integration_margins` prunes to current rows.
- `version` is per-`integration_margin_id` and not globally unique — key on
  `(integration_margin_id, version)` or the surrogate `integration_margin_archive_id`.
- Do not assume `MAX(version)` = latest snapshot; order by `archive_time` (dataset-wide
  `archives_*` non-monotonic-version warning).
- `data_source_id` is the integrations/margin dim (Oracle, MNTN Pixel, sentinels), **not** the
  audience DSxx taxonomy. Do not join it to audience `data_source` logic.
- Negative sentinel `data_source_id`s present: `-1` (MNTN Pixel) resolves in `data_sources`,
  `-2` does not.
- `datastream_metadata.source_timestamp` is ms CDC-capture time, ~minutes/hours after
  `archive_time`; never use it as business time.
- **SENSITIVE margin table** — never surface `data_margin` rate values in shared docs.

## Cost & partitioning notes
- **No partition**; single cluster key `integration_margin_archive_id`. Whole table is 590 bytes.
- `SELECT *` full-table dry-run = **590 bytes** (all 9 columns, all 5 rows) — a full scan is
  trivially cheap; no date/partition filter is needed. To isolate one vendor's history, filter
  by `integration_margin_id` or `data_source_id`.

## Example queries
```sql
-- Latest snapshot per integration margin (order by archive_time, not version)
SELECT integration_margin_id, data_source_id, version, archive_time
FROM `dw-main-bronze.integrationprod.archives_integration_margin_archives`
QUALIFY ROW_NUMBER() OVER (
  PARTITION BY integration_margin_id ORDER BY archive_time DESC
) = 1
ORDER BY integration_margin_id
```
