# integrationprod.core_media_plan

## Purpose
Datastream-CDC mirror of MNTN's **media plan** header: one generated CTV media plan per advertiser +
campaign group. Each plan proposes a set of streaming publishers/networks with a budget split; the
publisher lines are duplicated into the child `core_media_plan_publishers`, and a denormalized copy of
the same recommendations (with per-publisher LLM `rationale` text) is embedded in the
`original_recommendations` JSON here. Reach for it to get the plan header (owner, campaign group, status,
deliverability grade, manual-vs-generated). `silver.core.media_plan` is a view over this base table.

## Grain & keys
- **Grain:** one row per media plan. 2,376 rows; `media_plan_id` is unique.
- **Primary key:** `media_plan_id` (surrogate INT, also the sole cluster key).
- **FKs:** `advertiser_id` → `advertisers.id` (206 distinct); `campaign_group_id` → `campaign_groups.id`
  (654 distinct, **never NULL** — a plan is always scoped to a campaign group).

## Column meanings (only the non-obvious ones)
- **media_plan_id** — surrogate PK (clustered).
- **media_plan_status_id** — plan lifecycle status. **Observed domain `{1, 3, 8}`** (1=68 rows, 3=563,
  8=1,743). There is **no `core_media_plan_statuses` lookup table in bronze** — the status labels are not
  decodable from source; do not hard-code a meaning.
- **original_recommendations** — JSON array of the plan's originally-recommended publishers; each element
  has `name`, `rank`, `is_manual`, `rationale` (LLM-generated free text), `badge_state`, `publisher_id`,
  `budget_percentage`. This is the denormalized snapshot; the normalized per-line form is
  `core_media_plan_publishers`.
- **deliverability_classification** — plan-level deliverability grade. Domain: `NULL` / `low` / `medium` /
  `high` (mostly populated only for `media_plan_status_id = 3`).
- **is_manual** — TRUE = human-built/edited plan; FALSE = system-generated.
- **regeneration_run_id** — opaque STRING id tying the plan to a (re)generation run/batch of the planner.
- **create_time / update_time** — business TIMESTAMP (UTC).
- **datastream_metadata.source_timestamp** — INT64 **milliseconds** CDC-capture epoch (`TIMESTAMP_MILLIS`),
  not business time.

## Joins & relationships
- **`core_media_plan_publishers`** (child, 1:N): `media_plan.media_plan_id` = `publishers.media_plan_id`,
  ~15 publisher rows per plan → **fan-out**; aggregate the child when joining plan→publishers.
- **`advertisers`** / **`campaign_groups`** (dims, N:1): safe lookups on `advertiser_id` /
  `campaign_group_id`.
- **`silver.core.ui_flight_x_media_plan`** — bridges media plans to UI flights.
- **`silver.core.media_plan`** is a VIEW over this base table.

## Gotchas
- **`media_plan_status_id` has no lookup dim** — observed values 1/3/8 only; meanings undocumented in
  source. Don't invent status labels.
- **`original_recommendations` (JSON) is wide** — it dominates scan bytes; project it out unless you need
  the embedded rationale/budget snapshot (the normalized child is usually cheaper to read).
- **No `deleted` / `is_test` columns** — the dataset-wide hygiene filter does not apply here.
- **`deliverability_classification` is often NULL** (populated mainly at status 3) — not a reliable filter
  for all plans.
- **`source_timestamp` is ms CDC-capture, not business time** — use `create_time`/`update_time` for age.

## Cost & partitioning notes
- **BASE TABLE, physical `self`**, no partition, cluster=[media_plan_id], no TTL. `bq show`: numRows=2,376,
  numBytes=12,860,628 (~12.3 MiB) — the `original_recommendations` JSON is the bulk. `require_partition_filter:
  false`; there is nothing to prune. Avoid `SELECT *`; project the header columns and skip the JSON.

## Example queries
```sql
-- Plan headers for one advertiser (skip the heavy JSON)
SELECT media_plan_id, campaign_group_id, media_plan_status_id,
       deliverability_classification, is_manual, create_time
FROM `dw-main-bronze.integrationprod.core_media_plan`
WHERE advertiser_id = 68784
ORDER BY media_plan_id DESC;

-- Plan header + its recommended publisher lines (child fan-out)
SELECT p.media_plan_id, p.campaign_group_id, pub.rank, pub.name, pub.percentage
FROM `dw-main-bronze.integrationprod.core_media_plan` p
JOIN `dw-main-bronze.integrationprod.core_media_plan_publishers` pub
  ON pub.media_plan_id = p.media_plan_id
WHERE p.media_plan_id = 2517
ORDER BY pub.rank;
```
