# integrationprod.archives_campaign_group_archives

## Purpose
Versioned edit history (Postgres CDC archive via Datastream) of the live `campaign_groups` dimension. Every time a campaign_group (a client "media plan" / campaign group) is created or edited, a full snapshot of the row is written here with a monotonic `version`. Reach for it to reconstruct campaign_group state **as-of any historical point in time** — e.g. "what was this cg's budget / status / goal on day D?", status-flip detection, or historical simulation of advertiser-scoring filters. The live table `campaign_groups` holds only the current state; this archive holds the full trail back to 2012.

## Grain & keys
- **Grain:** one row per **(campaign_group_id, version)** — a single point-in-time snapshot of one campaign_group. Verified: 853,619 rows = 853,619 distinct `campaign_group_archive_id` = 853,619 distinct `(campaign_group_id, version)` pairs.
- **Surrogate PK:** `campaign_group_archive_id` (unique per snapshot; the sole cluster key).
- **Natural key:** `(campaign_group_id, version)`.
- **Coverage:** 126,648 distinct campaign_groups → ~6.7 versions per cg on average. History spans `update_time` 2012-06-14 → present (no TTL).
- **Foreign keys:** `campaign_group_id` → `campaign_groups`; `advertiser_id` → `advertisers`; plus the usual cg lookups (`objective_id`→`objectives`, `budget_type_id`→`core_budget_types`, `goal_type_id`→`core_goal_types`, `product_id` 1=PTV/2=Select/3=QF, `parent_campaign_group_id` self-ref).

## Column meanings (only the non-obvious ones)
> Same column set as live `campaign_groups` plus `version`. Only the archive-specific / trap columns are called out.
- `campaign_group_archive_id` — surrogate PK of the *archive snapshot* (unique per row, cluster key). NOT the cg id; never join on this.
- `campaign_group_id` — FK to the base record in `campaign_groups`; the same value repeats across every version. Half of the natural key. A campaign_group is a client "media plan" / campaign group; `campaigns` sit under it.
- `version` — per-`campaign_group_id` revision counter, increments on each edit/re-archive. **Use `MAX(version)` (or `MAX(update_time)`) ≤ as-of moment to pick the effective version.** There is **no `archive_time` column** on this table (unlike the margin archives) — `update_time` is the as-of ordering field.
- `update_time` — the base row's last-modified time captured in this snapshot; advances across versions. The de-facto as-of key here. Verified range 2012-06-14 → present.
- `create_time` — the base cg's creation timestamp; typically constant across a cg's versions (birth of the record, not the snapshot write time). Do not order versions by it.
- `campaign_group_status_id` — cg lifecycle status (decode via the cg status dim). Track flips across versions for status-change detection.
- `objective_id` — funnel objective; per the stack's standard, `objective_id` is UNRELIABLE for stage inference in log data (prefer `funnel_level` there), but on the cg record it is the configured objective (1=Prospecting/4=Retargeting/5=MT-S2/6=MT-S3/7=Ego).
- `budget` / `daily_budget` / `goal_value` / `extension_budget_split` — NUMERIC(12,2) money. For as-of budget resolution prefer flight-level tables first (`core_flights` / DSO flight budget); this archive's `budget` is the cg-level fallback (see data_catalog "Budget-resolution order").
- `goal_type_id` / `goal_type_name` — goal type (CPA, ROAS, etc.); decode via `core_goal_types`. For authoritative as-of-day goal prefer the `v_daily_goal_by_campaign_group` view.
- `product_id` — 1=PTV / 2=Select / 3=QF.
- `parent_campaign_group_id` — self-referential parent (cg hierarchy); NULL for top-level.
- `click_conversion_window` / `view_conversion_window` / `frequency_cap_duration` — INTERVAL types (attribution windows / freq-cap span).
- `datastream_metadata` — Datastream CDC metadata STRUCT. `.source_timestamp` = CDC-capture epoch in **MILLISECONDS** (not business time); `.uuid` = CDC event id. Earliest backfilled versions share one onboarding-snapshot `source_timestamp`. Use `update_time`, never this, for event/as-of ordering.
- `deleted` / `is_test` — standard hygiene flags; apply `deleted = FALSE AND is_test = FALSE` when reconstructing real cg state.

## Joins & relationships
- **→ `campaign_groups`** on `campaign_group_id`: base = 1 row per cg (current state), archive = **N:1** (N versions per cg). **Fan-out warning:** joining base→archive explodes to every version — dedupe to the effective version with `QUALIFY ROW_NUMBER() OVER (PARTITION BY campaign_group_id ORDER BY version DESC) = 1` (optionally bounded by `update_time <= as_of`). Some archived cg_ids may no longer exist live → use LEFT JOIN when you want full history.
- **→ `advertisers`** on `advertiser_id` (many archive rows : 1 advertiser). Get the name from `advertisers.company_name` (advertiser_name fields are unreliable elsewhere in the stack).
- **→ `campaigns`** on `campaign_group_id` (a cg fans out to many campaigns).
- **Sibling archives:** `archives_ui_flight_archives` = flight-level version history; `archives_campaign_group_channel_margin_archives` = cg×channel margin history. **No `archives_advertisers_*` exists in bronze.integrationprod** — advertiser version history lives in `archives.advertiser_archives` (coreDB) only.

## Gotchas
- **No `archive_time` column** — unlike the `archives_*margin*` family, order versions by `update_time` (or `version`), not by a snapshot-write timestamp.
- **`datastream_metadata.source_timestamp` is ms CDC-capture, not business time.** Earliest backfilled versions share one onboarding-snapshot value. Never use it as event time; use `update_time`.
- **Fan-out on join to `campaign_groups`** — always dedupe to the effective version (QUALIFY ROW_NUMBER) or you multiply the base row by its full version count (~6.7×).
- **Apply `deleted = FALSE AND is_test = FALSE`** when reconstructing live-comparable cg state (standard dim hygiene).
- **`version` is monotonic-per-cg here**, but the `archives_*` family is not universally trustworthy (e.g. `archives_audience_segment_archives.version` wraps/resets). When in doubt, `ORDER BY update_time` rather than trusting `version`.
- **Full history back to 2012** (no TTL, no partition) — an unbounded `SELECT *` reads the whole 274 MB table; scope by `campaign_group_id`/`advertiser_id`/`update_time` and prune columns.

## Cost & partitioning notes
- **Unpartitioned BASE table** (verified: `timePartitioning: null`, `requirePartitionFilter: null`), clustered by `campaign_group_archive_id`. TTL none (archive retains full history). Backing storage ≈ 274 MB (`numBytes` 274,036,479), 853,623 rows.
- **No partition to prune** → the two levers are (1) **column pruning** — avoid `SELECT *` (54 columns, many money/STRING) when you only need ids/status/timestamps; a 3-INT-column grain scan billed ~26 MB vs ~274 MB for the full table; and (2) **clustering** — filter/scope by `campaign_group_archive_id` (the cluster key) or `campaign_group_id` to reduce blocks read.
- At ~274 MB a full scan is cheap regardless; the wins are avoiding wide `SELECT *` on repeated as-of queries.

## Example queries
```sql
-- The campaign_group state effective as-of a given day (one row per cg)
SELECT *
FROM `dw-main-bronze.integrationprod.archives_campaign_group_archives`
WHERE update_time <= TIMESTAMP('2026-06-01')
  AND deleted = FALSE AND is_test = FALSE
QUALIFY ROW_NUMBER() OVER (
          PARTITION BY campaign_group_id
          ORDER BY version DESC) = 1
```
```sql
-- Any cg modified within [D-1d, D] (rule-coverage / status-flip style filtering)
SELECT advertiser_id, ANY_VALUE(campaign_group_id) AS cg_id
FROM `dw-main-bronze.integrationprod.archives_campaign_group_archives`
WHERE update_time BETWEEN TIMESTAMP_SUB(TIMESTAMP('2026-06-01'), INTERVAL 24 HOUR)
                      AND TIMESTAMP('2026-06-01')
GROUP BY advertiser_id
```
