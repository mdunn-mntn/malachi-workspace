# integrationprod.ctv_ctv_sites

## Purpose
Manually-curated CTV/supply-quality **site list** — each row classifies one piece of inventory (`site`)
by publisher type and flags whether MNTN blocks it. It is both a **classification** table (which
`publisher_type_id` a site is) and a **blocklist/allowlist**: type 1 = *CTV – Living Room Quality (LRQ)*
sites are approved (all `block=FALSE`); types 2/3/4 and untyped rows are all `block=TRUE`. Rows are
curated by ~30 named human operators (`user_name`). Datastream CDC mirror of the Postgres `ctv.ctv_sites`
table. Reach for it to answer "is this CTV site premium/LRQ or blocked?" or to build a supply
allow/deny map keyed on the raw bidstream `site` string.

## Grain & keys
- **Grain:** one row per inventory **site** string. `site` is **globally unique** (1,193,783 distinct =
  1,193,783 rows), so `site` alone is the natural key; the Postgres/clustered composite key is
  `(publisher_id, site)`.
- **Key(s) / join columns:** `site` (natural key, the raw bidstream inventory string) · `publisher_id` →
  `public_publishers.publisher_id` (99.996% valid FK) · `publisher_type_id` → `public_publisher_types`.
- **Not a key:** `ctv_site_id` is NULL for ~92% of rows (99,753 distinct non-null of 1,193,783) — a
  sparse surrogate, do **not** treat it as the PK. `datastream_metadata.uuid` is also non-unique
  (403,755 distinct across 1.19M rows, 0 NULL) — not a row key either.

## Column meanings (only the non-obvious ones)
- **site** — the raw bidstream inventory identifier (STRING up to 100000 chars, the fat column). Values are
  CTV app-bundle/channel strings, often composite, e.g. `g15147002586.all3mediafifthgear`,
  `46041.sling.colors_tamil`, `b00odc5n80.c15 studio` (app-store bundle id + network/channel). This is the
  natural key and the join surface against a bidstream `site`/app field.
- **domain** — web domain; **NULL for ~94% of rows** (only 74,591 non-null). Sparsely populated, and mostly
  on `publisher_type_id=3` (Display) rows — CTV apps generally have no domain.
- **publisher_type_id** — supply/format class; FK to `public_publisher_types`. Observed domain here:
  `1`=CTV – Living Room Quality (LRQ), `2`=CTV – Other, `3`=Display, `4`=Encrypted, plus a NULL bucket
  (`6`=Mobile Tablet PC exists in the dim but is absent from this table). **Fully correlated with `block`**
  in current data (see below).
- **block** — BOOL; TRUE = MNTN blocks this site. TRUE for ~88% of rows. In the current snapshot it is
  perfectly determined by `publisher_type_id`: type 1 (LRQ) → all `block=FALSE` (allowed); types 2/3/4 and
  NULL → all `block=TRUE`. So the table doubles as an LRQ allowlist (type 1) + a deny list (everything else).
- **ctv_site_id** — sparse INT surrogate; **NULL for ~92% of rows**. Not the primary key; do not rely on it.
- **deal_id** — PMP/deal identifier string; can be a **comma-separated list of multiple deals** (e.g.
  `WUR-WUR-00044,WUR-WUR-00138`). NULL for ~38% of rows. Split on `,` before matching a single deal.
- **user_name** — free-text name of the human operator who curated the row (30 distinct); `user_id` is the
  matching numeric operator id. Evidence this is a hand-maintained list, not a machine feed.
- **create_time / update_time** — native TIMESTAMP business/CDC times (UTC); `update_time >= create_time`
  always. Many `create_time` values land on round hours (e.g. `01:00:00`), consistent with batch loads.
- **datastream_metadata.source_timestamp** — **milliseconds** CDC-capture epoch
  (`= UNIX_MILLIS(capture_time)`; `TIMESTAMP_MILLIS(1784553409333)` = 2026-07-20). This is capture time,
  **not business time** — use `create_time`/`update_time` for business logic. `.uuid` is the CDC event id
  (non-unique across rows here).

## Joins & relationships
- **→ `public_publishers`** on `publisher_id` — partner grain **1 row per publisher** (PK `publisher_id`).
  Direction sites→publishers is **N:1, no fan-out** (219,864 of 219,873 distinct `publisher_id` match,
  99.996% valid FK). Joining the other way (publishers→sites) fans out ~5 sites/publisher on average.
- **→ `public_publisher_types`** on `publisher_type_id` — partner grain **1 row per type** (PK), a tiny
  dim (5 rows). N:1, no fan-out; use it to label the LRQ/Other/Display/Encrypted class.
- **→ bidstream / auction inventory** on `site` — join MNTN bidstream `site`/app-bundle strings to this
  table to tag each impression's supply class or block status. 1:1 on `site` (globally unique here);
  many bidstream rows map to one site row.
- **Sibling `integrationprod.ctv_sites`** — a near-duplicate copy (1,193,676 rows, ~147 MB, **same columns
  minus `datastream_metadata`, unclustered**). `ctv_ctv_sites` (this table) is the Datastream CDC mirror of
  Postgres schema `ctv` table `ctv_sites` (hence the doubled name), carries CDC metadata, and is clustered
  on `(publisher_id, site)` — prefer it over the bare `ctv_sites`.

## Gotchas
- **No `deleted`/`is_test` columns** — the standard `deleted=FALSE AND is_test=FALSE` live-row filter does
  **not** apply here (those columns don't exist). Row liveness is expressed via `block` and the
  presence/absence of a row, not a soft-delete flag.
- **`block` is not free-standing signal today** — it is fully explained by `publisher_type_id` (type 1 =
  allow, others = block). Do not assume a nuanced per-site block decision; it currently tracks the type.
- **`site` can contain spaces and mixed case** (e.g. `b00odc5n80.c15 studio`, `dark matter tv italy`) —
  normalize case/whitespace before matching against bidstream strings.
- **`deal_id` is multi-valued** (comma-joined) — a naive `deal_id = 'X'` misses rows where X is one of
  several; use `deal_id LIKE '%X%'` or `SPLIT(deal_id, ',')` + UNNEST.
- **`ctv_site_id` and `datastream_metadata.uuid` are not unique** — never dedup or join on them; dedup on
  `site`.
- **`source_timestamp` is capture time, not business time** — milliseconds; earliest capture 2026-01-09
  equals the table's Datastream (re)creation, so it reflects backfill timing, not when a site was added.

## Cost & partitioning notes
- **No partition** (`partition_by: none`, `require_partition_filter: false`) — small dim, whole-table scan
  is cheap (~184 MB). The pruning levers are **column projection** and the **cluster keys** `(publisher_id,
  site)`.
- Dry-run byte estimates (labeled by exact column set, no filter, full table):
  - `SELECT *` → **193,238,910 B (~184 MiB)** = full table (matches `approx_logical_bytes`).
  - `SELECT site, block, publisher_type_id` → **61,371,036 B (~58.5 MiB)** — a 3-col projection is ~3× cheaper.
  - `SELECT site` → **50,635,685 B (~48.3 MiB)** — `site` alone is the fat column; most of the table's bytes.
- **Cluster filters do NOT lower the dry-run upper bound**: `WHERE publisher_id = 263764 SELECT *` still
  estimates 193,238,910 B. Clustering on `(publisher_id, site)` prunes **at execution**, so actual bytes
  scanned when filtering those columns are lower than the dry-run estimate — but you can't see it in a
  dry-run. Always project only needed columns; avoid `SELECT *`.

## Example queries
```sql
-- Supply class + block status for a set of bidstream site strings (project narrow, cluster-friendly)
SELECT s.site, s.publisher_id, t.name AS publisher_type, s.block, s.deal_id
FROM `dw-main-bronze.integrationprod.ctv_ctv_sites` s
LEFT JOIN `dw-main-bronze.integrationprod.public_publisher_types` t
  USING (publisher_type_id)
WHERE s.publisher_id = 263764;   -- cluster key #1 prunes at runtime

-- LRQ allowlist (approved premium CTV inventory)
SELECT site, publisher_id, deal_id
FROM `dw-main-bronze.integrationprod.ctv_ctv_sites`
WHERE publisher_type_id = 1 AND block = FALSE;
```
