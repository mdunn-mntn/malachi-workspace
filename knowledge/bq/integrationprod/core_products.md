# integrationprod.core_products

## Purpose
The canonical **MNTN product dimension** — 3 rows, one per product line: `1=PTV` (Performance TV), `2=Select` (MNTN Select), `3=QuickFrame`. Reach for it to turn a `product_id` integer FK found on campaign-group / order / offering rows into a product name. A static seed/lookup dim — join it, don't scan it. (This matches the platform-wide convention `product_id 1=PTV / 2=Select / 3=QF`.)

## Grain & keys
- **Grain:** one row per MNTN product. 3 rows (ids 1, 2, 3).
- **Primary/natural key:** `product_id` (PK, cluster key). `name` also unique.
- **Consumed as a FK target** by `product_id` columns elsewhere on the platform (campaign groups, MNTN Select offerings/orders, etc.).

## Column meanings (only the non-obvious ones)
- **product_id** — PK, cluster key. Full domain = {1, 2, 3}.
- **name** — product label: `1=PTV` (Performance TV), `2=Select` (MNTN Select), `3=QuickFrame`.
- **create_time / update_time** — native TIMESTAMP (UTC); all three rows seeded 2025-03-18.
- **datastream_metadata.source_timestamp** — Datastream CDC snapshot epoch in **milliseconds** (replication time). `.uuid` = CDC event id.

## Joins & relationships
- 1:N FK target for `product_id` across the platform (this dim is the "1" side). LEFT JOIN — sentinel/NULL `product_id` values on consuming tables won't resolve.
- Corroborates the standing platform mapping (`data_knowledge.md`): PTV / Select / QuickFrame = 1 / 2 / 3.

## Gotchas
- **No `deleted` / `is_test` columns** — the standard live-row filter does not apply; all 3 rows are live.
- Only 3 products exist — a `product_id` outside {1,2,3} is a sentinel/orphan and won't join.
- `datastream_metadata.source_timestamp` is ms and reflects CDC replication, not the business `update_time`.

## Cost & partitioning notes
- **BASE TABLE**, no partition, no TTL; clustered on `product_id` (numRows 3, numBytes 235 via `bq show`). A broadcast/lookup dim — scan freely.
- **No partition column to filter.** Whole table <300 B — effectively free.
