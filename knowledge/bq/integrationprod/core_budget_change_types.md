# integrationprod.core_budget_change_types

## Purpose
Minimal bronze CDC replica dimension that decodes the **direction of a budget change**. Reach for it to
turn a `budget_change_type_id` into a label. As of 2026-07-29 the domain is exactly 2 rows (verified via
full dump):

| budget_change_type_id | name |
|---|---|
| 1 | increase |
| 2 | decrease |

**No silver view exists** for this enum: `silver.core.budget_change_types` is absent (verified
2026-07-29). Query the bronze physical table directly, or decode inline from the 2-value map above.

## Grain & keys
- **Grain:** one row per budget-change direction. Static enum, 2 rows (verified live 2026-07-29).
- **Primary key:** `budget_change_type_id` (INT64, unique, no NULLs; the sole cluster key).
- **Join column:** `budget_change_type_id` — FK target for budget-change/audit log rows that record
  whether a budget was raised or lowered. This table is always the **1-side** of any join.
- **No `deleted` / `is_test` columns** — the standard live-row dim filter does not apply; both rows are
  always live.

## Column meanings (only the non-obvious ones)
- **`budget_change_type_id`** — enum PK, sole cluster key. Domain = {1 increase, 2 decrease} (verified
  live 2026-07-29). Join this dim or hard-code the 2-value map.
- **`name`** — lower-case label (`increase` / `decrease`). Match on `budget_change_type_id`, not the
  free-text `name`.
- **`datastream_metadata`** — Datastream CDC lineage RECORD (`uuid`, `source_timestamp`).
  `source_timestamp` is a **millisecond** epoch (CDC-capture time), not business time. Ignore for decode.
  This table has no `create_time`/`update_time`.

## Joins & relationships
- **`<budget_change_log>.budget_change_type_id` → `core_budget_change_types.budget_change_type_id`** —
  **N:1** decode lookup (this dim is the one-side; the change-log/audit rows are the many-side). It
  **cannot fan out** the table it joins to (1 row per id).
- The reverse direction is **1:N** — never join outward from this dim to aggregate change-log facts
  without expecting full log cardinality.
