# integrationprod.audience_audience_x_campaign_groups

## Purpose
Junction (bridge) table that maps each **campaign group** to the single **audience** assigned to it (its targeting audience). Reach for it when you need to go from a campaign group → its audience (and thus its targeting expression / data-source overlay), or from an audience → the campaign groups that use it. Canonical use: identifying Fangorn / Mountain-Matched advertisers from BigQuery by joining DS-tagged audiences (DS13/DS19/DS46) through this bridge to campaign groups and on to advertisers (see the pattern in `data_catalog.md` → `audience_audience_segments`). Postgres-CDC-replicated (Datastream) mirror of the `audience.audience_x_campaign_groups` source table.

## Grain & keys
- **Grain:** one row per `campaign_group_id`. Re-verified 2026-07-29: `COUNT(*) = COUNT(DISTINCT campaign_group_id) = 61,421` (was 60,547 on 2026-07-19), so `campaign_group_id` is **unique** and is the effective primary key. It is current-state (one active assignment per campaign group), not an append-only history.
- **Key(s) / join columns:** `campaign_group_id` (unique, cluster key, FK → `campaign_groups`) + `audience_id` (FK → `audience_audiences`). The pair is also unique, but the cg column alone already is.

## Column meanings (only the non-obvious ones)
- **campaign_group_id** — FK → `campaign_groups.campaign_group_id`. Unique in this table. **Almost always a top-level / parent campaign group** (parent_campaign_group_id IS NULL): verified 2026-07-19, 60,537 of 60,547 rows match a cg that is top-level. Child campaign groups do **not** get their own row here — they inherit the audience through their `parent_campaign_group_id`. This is why the standard join is `cg.campaign_group_id = axcg.campaign_group_id OR cg.parent_campaign_group_id = axcg.campaign_group_id`.
- **audience_id** — FK → `audience_audiences.audience_id`. 100% of rows resolve (0 NULL, re-verified 2026-07-29). N:1 — an audience is shared across multiple campaign groups (avg 1.44, p50 1, p99 7, max 99 cgs per audience). The DS taxonomy (DS13/DS19/DS46, Fangorn/MM) lives in `audience_audiences.expression` and `audience_audience_segments`, **not here** — this table only carries the audience_id link.
- **user_id** — the user who created/assigned the mapping. **~52% NULL** (32,175 of 61,421, re-verified 2026-07-29) — system/automated assignments carry no user. Do not use for attribution; not a reliable join key.
- **create_time / update_time** — TIMESTAMP of assignment creation / last modification (UTC). `update_time` equals the CDC capture time (see below). Min create_time 2023-03-09; table stays current (max update_time = "now").
- **datastream_metadata.source_timestamp** — INT64 **milliseconds** since epoch = the Datastream CDC capture time, i.e. `UNIX_MILLIS(update_time)`. Verified 2026-07-19: `TIMESTAMP_MILLIS(source_timestamp) = update_time` exactly (0-second diff), 13-digit values. This is CDC-capture metadata, **not** a business event time. `datastream_metadata.uuid` = the CDC event id.

## Joins & relationships
- **audience_id → `audience_audiences`** (partner grain: one row per audience_id). This side is **N:1** — many bridge rows share one audience. Fanning **out from an audience** through this bridge multiplies up to ~99 campaign groups (typically 1). Complete coverage (100% resolve).
- **campaign_group_id → `campaign_groups` / `public_campaign_groups`** (partner grain: one row per campaign_group_id). 1:1 on the cg key itself, but to capture every campaign group affected by an audience you must **OR-join child cgs via `parent_campaign_group_id`** (children inherit the parent's audience). Filter `deleted=FALSE AND is_test=FALSE` on `campaign_groups` (this bridge table has no such columns).
- **Onward to advertiser:** `campaign_groups → campaigns` (on campaign_group_id) → `advertiser_id`. Standard path to attribute an audience/DS overlay to an advertiser.

## Gotchas
- **No `deleted` / `is_test` columns** — you cannot filter live rows on this table. It holds current-state assignments (one per cg; reassignment replaces the source row and CDC reflects the current value). Apply liveness filters on the joined `campaign_groups`, not here.
- **campaign_group_id is the PARENT cg, not the child** — child campaign groups are absent. Always OR-join on `parent_campaign_group_id` (as the Fangorn/DS46 pattern in `data_catalog.md` does) or you will drop every child campaign group.
- **9 rows (0.015%)** reference a `campaign_group_id` not present in `campaign_groups` (deleted/timing skew). Inner-joining to `campaign_groups` silently drops them.
- **`user_id` ~53% NULL** — automated assignments have no user; do not rely on it.
- **DS/Fangorn/MM tags are not in this table.** To know whether an audience is DS19 (MM Core) / DS13 (PP v1) / DS46 (PP v2, Fangorn), join `audience_id` to `audience_audiences.expression` or go through `audience_audience_segments`. This bridge is pure structure.

## Cost & partitioning notes
- **No partition** (small current-state dim, ~4.95 MB / ~60.5K rows). `require_partition_filter=false`. Clustered on `campaign_group_id`, which helps point-lookups (`WHERE campaign_group_id = X`) at runtime but does **not** lower a dry-run estimate (clustering pruning shows only in actual bytes billed).
- **The one lever that matters here is column projection, not a filter** — the wide `datastream_metadata` STRUCT + two timestamps dominate the bytes:
  - `SELECT *` (all 6 cols): 4,949,634 bytes (~4.95 MB) — dry-run 2026-07-19.
  - `SELECT campaign_group_id, audience_id` (2 cols): 968,752 bytes (~0.97 MB) — dry-run 2026-07-19, ~5x cheaper.
  - `SELECT audience_id WHERE campaign_group_id = X` (2 cols read, cluster-pruned): 968,752 bytes upper-bound — same dry-run estimate as unfiltered 2-col (cluster prune only reduces runtime bytes billed).
- Whole-table scans are cheap regardless; still prefer the smallest column set (skip `datastream_metadata`/`user_id` unless needed).

## Example queries
```sql
-- audience assigned to a campaign group (parent) and all its child cgs
SELECT cg.campaign_group_id, axcg.audience_id
FROM `dw-main-bronze.integrationprod.campaign_groups` cg
JOIN `dw-main-bronze.integrationprod.audience_audience_x_campaign_groups` axcg
  ON cg.campaign_group_id = axcg.campaign_group_id
  OR cg.parent_campaign_group_id = axcg.campaign_group_id
WHERE cg.deleted = FALSE AND cg.is_test = FALSE
  AND cg.advertiser_id = <advertiser_id>
```
