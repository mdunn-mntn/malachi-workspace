# integrationprod.core_budget_types

## Purpose
Tiny bronze CDC replica dimension that decodes a budget's **cadence / pacing type**. Reach for it to
turn a `budget_type_id` into a human label (Monthly / Daily / Flighted). As of 2026-07-29 the domain is
exactly 3 rows, ids contiguous 1-3 (verified via full dump):

| budget_type_id | name |
|---|---|
| 1 | Monthly |
| 2 | Daily |
| 3 | Flighted |

Exposed as the `silver.core.budget_types` view (a plain `SELECT * FROM` this bronze table). Prefer the
silver view in queries; this doc records the physical source.

## Grain & keys
- **Grain:** one row per budget cadence type. Static enum, 3 rows (verified live 2026-07-29).
- **Primary key:** `budget_type_id` (INT64, unique, no NULLs; the sole cluster key).
- **Join column:** `budget_type_id` — FK target for budget/campaign-group records that carry a budget
  cadence. This table is always the **1-side** of any join.
- **No `deleted` / `is_test` columns** — the standard live-row dim filter does not apply; all 3 rows are
  always live.

## Column meanings (only the non-obvious ones)
- **`budget_type_id`** — enum PK, sole cluster key. Domain = contiguous {1 Monthly, 2 Daily, 3 Flighted}
  (verified live 2026-07-29). Join this dim or hard-code the 3-value map.
- **`name`** — title-case label (`Monthly` / `Daily` / `Flighted`). `Flighted` = a fixed-window flight
  budget. Match on `budget_type_id`, not the free-text `name`.
- **`datastream_metadata`** — Datastream CDC lineage RECORD (`uuid`, `source_timestamp`).
  `source_timestamp` is a **millisecond** epoch (CDC-capture time), not business time. Ignore for decode.
  This table has no `create_time`/`update_time`.

## Joins & relationships
- **`<budget/campaign-group>.budget_type_id` → `core_budget_types.budget_type_id`** — **N:1** decode
  lookup (this dim is the one-side; the budget-carrying record is the many-side). It **cannot fan out**
  the table it joins to (1 row per id).
- **`silver.core.budget_types`** is a VIEW = `SELECT * FROM dw-main-bronze.integrationprod.core_budget_types`
  (verified 2026-07-29). Content-identical; use whichever project you're already in.
- The reverse direction is **1:N** — never join outward from this dim to aggregate budget facts without
  expecting full cardinality.

## Gotchas
- **No soft-delete columns.** No `deleted`/`is_test` — do not add those predicates (they'll error).
- **Static enum** — treat the code→name map as frozen; a net-new cadence would appear as a 4th row (last
  verified 3 rows on 2026-07-29).
- **`Flighted` (3) implies a start/end window** — the flight dates live on the budget-carrying record,
  not on this label dim.

## Cost & partitioning notes
- **BASE TABLE, physical `self`** (the silver `core.budget_types` view reads it directly). `bq show`:
  `type=TABLE`, `numRows=3`, `numBytes=188`, `timePartitioning=None`,
  `clustering.fields=[budget_type_id]`, no `expirationTime` (no TTL).
- **Partition: none.** `require_partition_filter=false`. Nothing to filter.
- **Cost:** a full `SELECT *` bills the tier-1 10 MB floor (~0 real bytes). Read freely or hard-code the
  3-value map and skip the join entirely.
