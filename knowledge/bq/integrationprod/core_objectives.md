# integrationprod.core_objectives

## Purpose
Static reference enum that maps `objective_id` → human label (`name`) for a campaign's marketing
objective (strategy). Reach for it to decode `campaigns.objective_id` (and any log/dim row that carries
`objective_id`) into a readable strategy name. **7 rows, never grows in normal ops.** Exposed as the
`silver.core.objectives` view. This is the CDC sibling of `integrationprod.objectives` — **content-identical**
(same 7 rows, names, descriptions; FULL JOIN diff = 0, per objectives.md 2026-07-19), the only difference
being this table carries a `datastream_metadata` CDC RECORD and clusters on `objective_id`.

**Do NOT use `objective_id` to determine funnel stage** — it is unreliable for that (see Gotchas).
`campaigns.funnel_level` is the authoritative stage indicator.

## Grain & keys
- **Grain:** one row per marketing objective. Static enum, 7 rows (verified 2026-07-29).
- **Primary key:** `objective_id` (INT, 1–7). Unique, no NULLs. Also the sole cluster key.
- **Join column:** `objective_id` — FK target for `campaigns.objective_id` and `campaign_groups.objective_id`.
  This table is always the **1-side** of any join.

## Column meanings (only the non-obvious ones)
- **`objective_id`** — the enum code, PK, and cluster key. Live domain (full dump `ORDER BY objective_id`,
  2026-07-29):

  | objective_id | name | description (as stored) | business meaning |
  |---|---|---|---|
  | 1 | Prospecting | `CTV Prospecting` | Prospecting (CTV). Prospecting filter. NOT a stage — spans funnel_level 1/2/3 (holds mislabeled S2/S3 campaigns; see Gotchas). |
  | 2 | Onsite | `` (empty) | Onsite (ads on the customer's own website). Rare. |
  | 3 | Prospecting | `CTV Prospecting` | Duplicate of 1, largely unused legacy. |
  | 4 | Retargeting | `Retargeting` | Retargeting. Spans funnel_level 1/2/3; absent at 4 (Ego). |
  | 5 | Multi-Touch | `Multi-Touch` | Multi-Touch (S2 prospecting, newer naming). Prospecting filter. |
  | 6 | Multi-Touch Full Funnel | `Multi-Touch Full Funnel` | MT+ = Stage-3 prospecting (newer naming). Prospecting filter. |
  | 7 | Ego | `Retargeting` | Ego = employee/self targeting. **`description` is STALE here — says "Retargeting" but `name`=Ego is correct.** |

- **`name`** — the clean, authoritative enum label. **Two ids share "Prospecting" (1 and 3)** — `name`
  alone is not unique; only `objective_id` is. Prefer `name` over `description`.
- **`description`** — free-text, **unreliable**: empty for id 2; a redundant "CTV Prospecting" for ids 1 & 3;
  and **wrong for id 7** (stores "Retargeting" while the objective is Ego). Decode on the numeric `objective_id`.
- **`datastream_metadata`** — Datastream CDC lineage RECORD (`uuid`, `source_timestamp`) stamped by the
  bronze CDC pipeline. Not business data; ignore for decode. (This is the only column the plain
  `integrationprod.objectives` copy lacks.)

## Joins & relationships
- **`campaigns.objective_id` → `core_objectives.objective_id`** — **N:1** (`campaigns` is the many-side;
  this table is the one-side). Used as a decode lookup it **cannot fan out** (1 row per id). Same for
  `campaign_groups.objective_id`.
- **`silver.core.objectives`** is a VIEW over this table.
- **Sibling `integrationprod.objectives`** (documented separately, `coverage_state: verified`) is
  content-identical — same 7 rows/names/descriptions — but has ONLY `objective_id, name, description`
  (no `datastream_metadata`, no cluster). Use whichever you're already near; use this `core_objectives`
  copy if you also want CDC lineage.

## Gotchas
- **`objective_id` is UNRELIABLE as a stage indicator (Ray, 2026-03-11).** During the "TV Only" UI
  migration the UI team stopped setting `objective_id` correctly and pivoted to `funnel_level`. Many
  S3/MT+ campaigns carry `objective_id=1` instead of 6. **`campaigns.funnel_level` (1=S1, 2=S2, 3=S3,
  4=Ego) is the authoritative stage indicator, not this enum.**
- **Prospecting filter:** `objective_id IN (1,5,6)` (per Ray) or `objective_id NOT IN (4,7)` (safer).
- **`name` is not unique** (ids 1 & 3 both = "Prospecting"); **`description` is stale/empty** in places.
- **No soft-delete columns.** This table has `objective_id, name, description, datastream_metadata` only —
  no `deleted`/`is_test`. The standard integrationprod dim filter does not apply; read all 7 rows.
- **Static enum** — no late-arriving data, no partitions. Treat as constant.

## Cost & partitioning notes
- **Non-partitioned static dim: 7 rows / ~566 bytes backing storage.** No partition, no TTL, no
  `require_partition_filter`. Clustered on `objective_id` (a no-op at this size).
- Full `SELECT *` bills only the tier-1 10 MB minimum (~0 real bytes). Broadcast-join it freely.
- Prefer selecting `objective_id, name` (skip the unreliable `description` and CDC RECORD).

## Example queries
```sql
-- Decode campaign objectives (N:1 lookup; core_objectives never fans out)
SELECT c.campaign_id, c.objective_id, o.name AS objective, c.funnel_level
FROM `dw-main-bronze.integrationprod.campaigns` c
LEFT JOIN `dw-main-bronze.integrationprod.core_objectives` o USING (objective_id)
WHERE c.objective_id IS NOT NULL;

-- Prospecting campaigns only (objective_id is NOT the stage; funnel_level is)
SELECT campaign_id FROM `dw-main-bronze.integrationprod.campaigns`
WHERE objective_id IN (1, 5, 6);
```
