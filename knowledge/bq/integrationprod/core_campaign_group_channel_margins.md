# integrationprod.core_campaign_group_channel_margins

## Purpose
Bronze CDC replica holding **per-campaign-group, per-channel margin and pricing overrides**. Each row
sets the margin/fee/CPM parameters MNTN applies when buying media for a specific campaign group on a
specific channel: `budget_margin`, `platform_fee`, `data_margin`, `target_cpm`, `ad_buying_cpm`. Reach
for it to know the effective margin/CPM configuration for a campaign group on a channel. Exposed as the
`silver.core.campaign_group_channel_margins` view (a plain `SELECT * FROM` this bronze table). Small
config table — 624 rows as of 2026-07-29. Related to `core_advertiser_channel_margins`
(advertiser-level) and `archives_campaign_group_channel_margin_archives` (history of prior values).

## Grain & keys
- **Grain:** one row per **(campaign_group_id, channel_id)** margin config (verified: 624 rows = 624
  distinct `campaign_group_id|channel_id` pairs; 612 distinct campaign groups → a few groups configure 2
  channels, 2026-07-29).
- **Primary key:** `campaign_group_channel_margin_id` (INT64, surrogate, unique; the sole cluster key).
- **Foreign keys:** `campaign_group_id` → `campaign_groups`; `channel_id` → `core.channels`
  (e.g. 8 = CTV); `advertiser_id` → `advertisers` (denormalized owner); `margin_source_id`,
  `margin_reason_id` → their reference dims; `user_id` → the user who set it.
- **No `deleted` / `is_test` columns** — presence of a row = the active margin config for that
  (campaign_group, channel); superseded values move to the `_archives` table.

## Column meanings (only the non-obvious ones)
- **`campaign_group_channel_margin_id`** — surrogate PK / cluster key. Join on the (campaign_group_id,
  channel_id) pair for the business grain, not on this id.
- **`campaign_group_id` + `channel_id`** — the composite business key (unique together). `channel_id`
  follows the standard channel dim (8 = CTV in the sample; see `core.channels`).
- **`budget_margin` / `platform_fee` / `data_margin`** — NUMERIC(5,4) **fractional** margin/fee rates
  (scale 4 → up to 9.9999; e.g. `1` = 1.0000). `platform_fee` and `data_margin` are frequently NULL in
  the sample (only `budget_margin` populated). Interpret as fractions/multipliers, not currency.
- **`target_cpm` / `ad_buying_cpm`** — NUMERIC(7,4) **CPM dollar amounts** (e.g. `target_cpm`=53,
  `ad_buying_cpm`=40). `target_cpm` = the CPM targeted for the campaign group on this channel;
  `ad_buying_cpm` = the buy-side CPM. These are money values, not fractions.
- **`margin_source_id` / `margin_reason_id`** — FKs classifying where the margin came from / why it was
  set (reference dims; sample values margin_source_id=2, margin_reason_id=3). Confirm the target dims
  before attributing specific semantics.
- **`advertiser_id`** — denormalized owner of the campaign group (redundant with `campaign_groups`).
- **`create_time` / `update_time`** — business timestamps of when this margin config was set / last
  edited in source Postgres.
- **`datastream_metadata`** — Datastream CDC lineage RECORD (`uuid`, `source_timestamp`).
  `source_timestamp` is a **millisecond** epoch (CDC-capture time), not business time.

## Joins & relationships
- **`core_campaign_group_channel_margins.campaign_group_id` → `campaign_groups.campaign_group_id`** —
  **N:1** on the campaign-group side, but note a campaign group can have **up to one row per channel**
  (mostly 1, a few 2). Joining campaign_groups → this table is **1:N over channels** — expect one row per
  configured channel, and aggregate/pivot by `channel_id` if you need one row per group.
- **`channel_id` → `core.channels`** — **N:1** channel decode.
- **`silver.core.campaign_group_channel_margins`** is a VIEW =
  `SELECT * FROM dw-main-bronze.integrationprod.core_campaign_group_channel_margins` (verified 2026-07-29).
- **History:** superseded margin values live in
  `archives_campaign_group_channel_margin_archives` — this table holds only the current config.
  For advertiser-level (not campaign-group-level) margins, see `core_advertiser_channel_margins`.

## Gotchas
- **Grain is (campaign_group, channel), not campaign_group.** A group with margins on 2 channels has 2
  rows — do not assume one row per campaign group (612 groups → 624 rows). Aggregate/pivot by channel.
- **Fractions vs dollars.** `budget_margin`/`platform_fee`/`data_margin` are NUMERIC(5,4) fractional
  rates; `target_cpm`/`ad_buying_cpm` are NUMERIC(7,4) dollar CPMs. Do not mix the two scales.
- **NULL margin components are common** — `platform_fee`, `data_margin` often NULL (only `budget_margin`
  set). A NULL means "not overridden here", not zero.
- **No soft-delete** — this table is the current state; use the `_archives` table for prior values.
- **`datastream_metadata.source_timestamp` is ms CDC-capture time** — use `create_time`/`update_time`
  for business timing.

## Cost & partitioning notes
- **BASE TABLE, physical `self`** (the silver `core.campaign_group_channel_margins` view reads it
  directly). `bq show`: `type=TABLE`, `numRows=624`, `numBytes≈92.9 KB`, `timePartitioning=None`,
  `clustering.fields=[campaign_group_channel_margin_id]`, no `expirationTime` (no TTL).
- **Partition: none** (`require_partition_filter=false`). Tiny config table (~93 KB) — a full `SELECT *`
  bills the tier-1 10 MB floor. Read freely; clustering on the surrogate id is a no-op at 624 rows.

## Example queries
```sql
-- current margin/CPM config for a campaign group, per channel (prefer the silver view)
SELECT campaign_group_id, channel_id, budget_margin, platform_fee, data_margin,
       target_cpm, ad_buying_cpm, margin_source_id, margin_reason_id, update_time
FROM `dw-main-silver.core.campaign_group_channel_margins`
WHERE campaign_group_id = 131942
ORDER BY channel_id;

-- whole config table (tiny, cheap)
SELECT * EXCEPT(datastream_metadata)
FROM `dw-main-bronze.integrationprod.core_campaign_group_channel_margins`
ORDER BY campaign_group_channel_margin_id DESC
LIMIT 100;
```
