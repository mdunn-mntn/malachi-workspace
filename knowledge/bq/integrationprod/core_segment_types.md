# integrationprod.core_segment_types

## Purpose
Tiny bronze CDC replica dimension that decodes an **audience segment type**. Reach for it to turn a
`segment_type_id` into a human label (OPM, FPA, Cart, Ego, …) and to reach that type's **default
segmentation expression** via `segmentation_default_id`. This is the physical Postgres-CDC table that the
thin silver view `dw-main-silver.core.segment_types` (`SELECT * FROM dw-main-bronze.integrationprod.core_segment_types`)
sits directly on top of — no SQLMesh, no transform. Prefer the silver view in queries; this doc records
the physical source. As of 2026-07-29 the domain is exactly 13 rows, ids contiguous 1-13 (verified live):

| segment_type_id | name | segmentation_default_id |
|---|---|---|
| 1 | OPM | _(null)_ |
| 2 | FPA | _(null)_ |
| 3 | Auto Default | 1 |
| 4 | 5+ PV | 3 |
| 5 | Cart | 2 |
| 6 | High Intent C | 4 |
| 7 | Ego | 5 |
| 8 | EXT | _(null)_ |
| 9 | High Intent B | _(null)_ |
| 10 | 1+ PV | 6 |
| 11 | 1+ Conversion | 7 |
| 12 | Control Group Audience | _(null)_ |
| 13 | Ego Campaign Audience | _(null)_ |

## Grain & keys
- **Grain:** one row per audience segment type. Static enum — 13 rows total (verified live 2026-07-29).
- **Primary key:** `segment_type_id` (INT64, unique; the physical is clustered on it).
- **Foreign key:** `segmentation_default_id` → `core_segmentation_defaults.segmentation_default_id` (nullable — 6 of 13 rows are NULL, i.e. no default expression attached).
- **No `deleted` / `is_test` columns** on this table — the usual `deleted=FALSE AND is_test=FALSE` live-row filter does not apply; all 13 rows are always live.

## Column meanings (only the non-obvious ones)
- **`segment_type_id`** — enum PK, sole cluster key. Domain = contiguous {1..13}. Join this dim; do not hard-code the map in application logic (values verified live 2026-07-29).
- **`name`** — human label for the segment type. Exact live spellings above (e.g. `5+ PV`, `1+ Conversion`, `High Intent C`). Match on `segment_type_id`, not the free-text `name`.
- **`segmentation_default_id`** — nullable FK to `core_segmentation_defaults`; identifies the default targeting expression for that type. NULL for OPM, FPA, EXT, High Intent B, Control Group Audience, Ego Campaign Audience (types that carry no packaged default rule).
- **`create_time`** — Postgres row-creation TIMESTAMP (2021-09-13 → 2023-01-13 across the 13 rows). Business time, unlike the CDC metadata timestamp.
- **`datastream_metadata`** — STRUCT<uuid STRING, source_timestamp INT64> stamped by the Datastream CDC pipeline. `source_timestamp` is a **millisecond** epoch (CDC-capture time), NOT business time; use `create_time` for business time. `datastream_metadata.uuid` is the CDC event id.

## Joins & relationships
- **`core_segment_types.segmentation_default_id` → `core_segmentation_defaults.segmentation_default_id`** — N:1 to the default-expression dim (7 rows). No fan-out (default id is unique on the parent). NULL on 6 rows means no default.
- **This dim is the 1 side** of `segment_type_id`. Audience-segment / targeting tables that carry a `segment_type_id` join in N:1 (many segments per type). Joining outward from this dim is 1:N — expect full child cardinality.

## Gotchas
- **No soft-delete columns.** No `deleted`/`is_test` — do not add those predicates (they will error). All 13 rows are live.
- **6 of 13 rows have a NULL `segmentation_default_id`** — a LEFT (not INNER) join to `core_segmentation_defaults` is required to keep OPM/FPA/EXT/etc.
- **Static enum** — treat the code→name map as effectively frozen; a net-new type would appear as a 14th row (last verified 13 rows on 2026-07-29).
- **`datastream_metadata.source_timestamp` is CDC-capture time in ms, not business time** — use `create_time` for business time.

## Cost & partitioning notes
- **BASE TABLE, physical `self`** (silver `core.segment_types` reads it directly). `bq show`: `type=TABLE`, `numRows=13`, `numBytes=1008`, `timePartitioning=None`, `clustering.fields=[segment_type_id]`, no TTL.
- **Partition: none.** `require_partition_filter=false`. No partition column to filter, no cost trap.
- **Cost:** a `SELECT *` of the whole dim dry-runs at ~0 GB (10 MB billed floor). Read the whole table freely.

## Example queries
```sql
-- decode a segment type + its default expression (prefer the silver view)
SELECT st.segment_type_id, st.name, sd.name AS default_name, sd.expression
FROM `dw-main-silver.core.segment_types` st
LEFT JOIN `dw-main-silver.core.segmentation_defaults` sd USING (segmentation_default_id)
ORDER BY st.segment_type_id;
```
