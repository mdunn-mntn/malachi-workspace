# integrationprod.objectives

## Purpose
Static reference enum that maps `objective_id` → human label (`name`) for a campaign's marketing
objective (strategy). Reach for it to decode `campaigns.objective_id` (and any log/dim row that carries
`objective_id`) into a readable strategy name. **7 rows, never grows in normal ops.**

**Do NOT use `objective_id` to determine funnel stage** — it is unreliable for that (see Gotchas).
`campaigns.funnel_level` is the authoritative stage indicator. This table only tells you the strategy
*label*, and even that is partly stale in the `description` column.

## Grain & keys
- **Grain:** one row per marketing objective. Static enum, 7 rows (verified 2026-07-19).
- **Primary key:** `objective_id` (INT, 1–7). Unique, no NULLs.
- **Join column:** `objective_id` — the FK target for `campaigns.objective_id` (and the live
  `campaign_groups.objective_id`). This table is always the **1-side** of any join.

## Column meanings (only the non-obvious ones)
- **`objective_id`** — the enum code and PK. Live domain (verified `SELECT * ... ORDER BY objective_id`,
  2026-07-19):

  | objective_id | name | description (as stored) | business meaning |
  |---|---|---|---|
  | 1 | Prospecting | `CTV Prospecting` | Prospecting (CTV). Prospecting filter. NOT a stage — spans funnel_level 1/2/3 (holds the mislabeled S2/S3 campaigns; see Gotchas). |
  | 2 | Onsite | `NULL` | Onsite (ads on the customer's own website). Rare (33 campaigns). |
  | 3 | Prospecting | `CTV Prospecting` | Duplicate of 1, largely unused legacy (still tagged on 7,900 campaigns). |
  | 4 | Retargeting | `Retargeting` | Retargeting. Spans funnel_level 1/2/3; absent at 4 (Ego). |
  | 5 | Multi-Touch | `Multi-Touch` | Multi-Touch (S2 prospecting, newer naming). Prospecting filter. |
  | 6 | Multi-Touch Full Funnel | `Multi-Touch Full Funnel` | MT+ = Stage-3 prospecting (newer naming). Prospecting filter. |
  | 7 | Ego | `Retargeting` | Ego = employee/self targeting. **`description` is STALE here — says "Retargeting" but `name`=Ego is correct.** |

- **`name`** — the clean, authoritative enum label. Note **two ids share the label "Prospecting" (1 and 3)** —
  `name` alone is not unique; only `objective_id` is. Prefer `name` over `description`.
- **`description`** — free-text, **unreliable**: NULL for id 2; a redundant "CTV Prospecting" for ids 1 & 3;
  and outright **wrong for id 7** (stores "Retargeting" while the objective is Ego). Never key logic on it —
  use `name` (or better, the `objective_id` code directly).

## Joins & relationships
- **`campaigns.objective_id` → `objectives.objective_id`** — **N:1** (`campaigns` is the many-side; this
  table is the one-side). Verified referential integrity 2026-07-19: no orphans — every non-NULL
  `campaigns.objective_id` resolves; **217 campaigns carry a NULL `objective_id`** (drop or COALESCE them).
  Joining `objectives` in as a lookup **cannot fan out** `campaigns` (1 row per id).
- **`campaign_groups.objective_id`** — the same enum also lives on `campaign_groups` as a **live,
  actively-maintained** INT64 column (NOT deprecated). Verified 2026-07-20: 129,334 of 129,367 rows
  carry a non-NULL `objective_id` (99.97%; 107,203 after `deleted=FALSE AND is_test=FALSE`), 0 orphans
  against `objectives`, and `MAX(update_time)` = 2026-07-20 (rows still updated today). Same N:1 lookup
  semantics as `campaigns.objective_id`.
- **Sibling `integrationprod.core_objectives`** (exposed as the `silver.core.objectives` view) is
  **content-identical** to this table — same 7 rows, same names + descriptions (FULL JOIN diff = 0 rows,
  2026-07-19). The only schema difference: `core_objectives` carries a `datastream_metadata` CDC RECORD
  (uuid, source_timestamp) that this `objectives` copy does **not** have. Either works as the decode
  lookup; use `core_objectives`/`silver.core.objectives` if you also need CDC lineage.

## Gotchas
- **`objective_id` is UNRELIABLE as a stage indicator (Ray, 2026-03-11).** During the "TV Only" UI
  migration the UI team stopped setting `objective_id` correctly and pivoted to `funnel_level`. Result:
  ~48,934 "Beeswax Television Multi-Touch Plus" (S3/MT+) campaigns carry `objective_id=1` instead of 6
  (point-in-time count as of 2026-03-11; the drift has since grown — as of 2026-07-20, `objective_id=1`
  sits on funnel_level 2 & 3 at 58,748 / 58,724 campaigns, so ~58,724 S3 campaigns now hang off id 1).
  **`campaigns.funnel_level` (1=S1, 2=S2, 3=S3, 4=Ego) is the authoritative stage indicator, not this enum.**
- **Prospecting filter:** `objective_id IN (1,5,6)` (per Ray) or `objective_id NOT IN (4,7)` (safer) — both
  work because the mislabeled MT+ campaigns land on `objective_id=1` (included either way). Excludes
  Retargeting (4) and Ego (7); `IN (1,5,6)` additionally excludes Onsite (2) and the unused dup (3).
- **`funnel_level` ≠ prospecting.** Retargeting (`objective_id=4`) campaigns span funnel_level 1/2/3
  (absent at 4=Ego) — they are not stage-bound (verified 2026-07-20).
- **No soft-delete columns.** This table has ONLY `objective_id, name, description` — there is **no
  `deleted`, `is_test`, `create_time`, `update_time`, or `datastream_metadata` column.** The standard
  integrationprod `deleted=FALSE AND is_test=FALSE` dim filter **does not apply and will error here**
  (columns don't exist). Nothing to filter — read all 7 rows.
- **`name` is not unique** (ids 1 & 3 both = "Prospecting"); **`description` is stale/NULL** in places
  (see Column meanings). Decode on the numeric `objective_id`, not on text.
- **Static enum** — no late-arriving data, no partitions, no timezone traps. Treat as constant.

## Cost & partitioning notes
- **Non-partitioned static dim: 7 rows / ~244 bytes backing storage.** No partition, no cluster, no TTL —
  there is nothing to filter and no partition pruning to do.
- Full `SELECT *` dry-run processed **0 bytes** (7 rows / 244 B; the "0.01 GB billed" is the tier-1
  10 MB minimum, not a real scan). Cost is negligible; broadcast-join it freely against any fact/dim.
- Prefer selecting `objective_id, name` (skip the unreliable `description`).

## Example queries
```sql
-- Decode campaign objectives (N:1 lookup; objectives never fans out)
SELECT c.campaign_id, c.objective_id, o.name AS objective, c.funnel_level
FROM `dw-main-bronze.integrationprod.campaigns` c
LEFT JOIN `dw-main-bronze.integrationprod.objectives` o USING (objective_id)
WHERE c.objective_id IS NOT NULL;

-- Prospecting campaigns only (objective_id is NOT the stage; funnel_level is)
SELECT campaign_id FROM `dw-main-bronze.integrationprod.campaigns`
WHERE objective_id IN (1, 5, 6);
```
