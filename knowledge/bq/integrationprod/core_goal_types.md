# integrationprod.core_goal_types

## Purpose
Tiny bronze CDC replica dimension that decodes a campaign group's **optimization goal**. Reach for it to
turn `campaign_groups.goal_type_id` into a human label + a plain-English definition of the goal metric.
This is the **physical Postgres-CDC table** that the thin silver view
`dw-main-silver.core.goal_types` (`SELECT * FROM dw-main-bronze.integrationprod.core_goal_types`) sits
directly on top of — no SQLMesh, no transform. Prefer the silver view in queries; this doc records the
physical source. As of 2026-07-29 the domain is exactly 16 rows, ids contiguous 1-16 (verified live):

| goal_type_id | name | description (live) |
|---|---|---|
| 1 | ROAS | desired gross revenue return for every $1 spent |
| 2 | Click ROAS | desired gross revenue return per click for every $1 spent |
| 3 | eCPA | target cost per desired action |
| 4 | Click CPA | target cost per click |
| 5 | ROI | desired gross percentage return for every $1 spent |
| 6 | Click ROI | desired gross percentage return per click for every $1 spent |
| 7 | A/S | desired gross percentage return per acquisition cost |
| 8 | Click A/S | desired gross percentage click return per acquisition cost |
| 9 | Efficiency | reach as many high-intent customers as possible |
| 10 | CTR | drive the highest possible volume of click-throughs back to site |
| 11 | Average Daily Spend | spend an average amount each day over the month |
| 12 | Visits | drive as many site visits to high-intent customers as possible |
| 13 | CostPerVisit | cost per Verified Visit |
| 14 | CostPerCompletedView | ratio of total spend over completed views |
| 15 | VisitRate | percentage of impressions that resulted in a Verified Visit |
| 16 | CPA | cost per Verified Conversion |

## Grain & keys
- **Grain:** one row per goal type. Static enum — 16 rows total (verified live 2026-07-29).
- **Primary key:** `goal_type_id` (INT64, unique; the physical is clustered on it).
- **Join column:** `goal_type_id` — referenced by `campaign_groups.goal_type_id` (and its raw / public /
  archive / dso_valid_* equivalents; see Joins). This is the only join key.
- **No `deleted` / `is_test` columns** on this table (many small enum dims lack them) — so the usual
  `deleted=FALSE AND is_test=FALSE` live-row filter does not apply here; all 16 rows are always live.

## Column meanings (only the non-obvious ones)
- **`goal_type_id`** — enum PK, sole cluster key. Domain = contiguous {1..16} (see Purpose table). Do
  not hard-code the code→name map in application logic; join this dim (values verified live 2026-07-29).
- **`name`** — human label for the optimization goal. Exact live spellings are camelCase for the newer
  visit/view metrics — `CostPerVisit`, `CostPerCompletedView`, `VisitRate` (no spaces) — versus the
  space-separated legacy `Average Daily Spend`, `Click ROAS`, etc. Match on `goal_type_id`, not the
  free-text `name`.
- **`description`** — plain-English definition of the goal metric (e.g. id 15 VisitRate = "The
  Percentage of Impressions that resulted in a Verified Visit"). Useful for surfacing goal semantics in
  UI/reporting; not a join key.
- **`datastream_metadata`** — STRUCT<uuid STRING, source_timestamp INT64> stamped by the Datastream CDC
  pipeline. `source_timestamp` is a **millisecond** epoch (CDC-capture time), NOT business time:
  `TIMESTAMP_MILLIS(datastream_metadata.source_timestamp)` resolves to a 2026 datetime, whereas
  `TIMESTAMP_MICROS(...)` yields a 1970 nonsense value. All 16 rows carry the identical `source_timestamp`
  (a single bulk backfill snapshot), so this field cannot order rows or infer per-row edit time.
  `datastream_metadata.uuid` is the Datastream event id. There is no `create_time`/`update_time` on this
  dim.

## Joins & relationships
- **`campaign_groups.goal_type_id` → `core_goal_types.goal_type_id`** — the canonical join. The goal is
  set at the **campaign-group** level (not per campaign). `campaign_groups` is the **N side** (one goal
  type maps to many campaign groups); this dim is the **1 side** (lookup). Enriching campaign groups with
  the label is a safe **N:1** left join — **no fan-out**, since `goal_type_id` is unique here.
- **Often unnecessary:** `campaign_groups` already carries a **denormalized `goal_type_name`** column, so
  the label is usually available without joining this dim; join it when you also need the `description`,
  or to validate the denormalized name.
- **Reverse direction fans out:** `core_goal_types → campaign_groups` is **1:N** (many campaign groups
  per goal type). Never join outward from this dim to aggregate campaign-group facts without expecting
  full campaign-group cardinality.
- **Other carriers of `goal_type_id`** (all denormalize `goal_type_name` too): `campaign_groups_raw`,
  `public_campaign_groups`(`_raw`), `archives_campaign_group_archives`, `dso_valid_campaign_groups`,
  `dso_valid_campaigns`, `valid_campaigns`. All reference the same enum; none change the fan-out story
  (this dim is always the 1 side).

## Gotchas
- **No soft-delete columns.** Unlike most `core_*` dims, this table has no `deleted`/`is_test` — do not
  add those predicates (they'll error). All 16 rows are live.
- **Goal is a campaign-GROUP attribute, not a campaign attribute.** `goal_type_id` lives on
  `campaign_groups`; individual `campaigns` inherit it via their group. Don't look for it on `campaigns`.
- **Comparison direction depends on goal_type** when scoring "hit goal" (see the Mode
  "Campaign Groups Hitting Goal Percentage" logic): revenue/return goals hit if actual **>=** goal
  (e.g. id 1 ROAS = order_value/spend); cost goals hit if actual **<=** goal (id 13 CostPerVisit =
  spend/visits, id 16 CPA = spend/conversions). **id 14 CostPerCompletedView is hard-coded hit=1
  (always passes)** in that report, which inflates any headline attainment rate (it is ~25% of
  campaign-groups-with-a-goal). Strip or properly score it for a true rate.
- **`datastream_metadata.source_timestamp` is CDC-capture time in ms, not business time**, and is
  identical across all rows (single bulk backfill). It is useless for ordering or change detection here.
- **Static enum** — treat the code→name map as effectively frozen; a net-new goal would appear as a
  17th row (last verified 16 rows on 2026-07-29).

## Cost & partitioning notes
- **BASE TABLE, physical `self`** (the silver `core.goal_types` view reads it directly). `bq show`:
  `type=TABLE`, `numRows=16`, `numBytes=1996`, `timePartitioning=None`, `clustering.fields=[goal_type_id]`,
  no `expirationTime` (no TTL).
- **Partition: none.** `require_partition_filter=false`. There is no partition column to filter and no
  cost trap.
- **Cost:** a `SELECT *` of the whole dim dry-runs at ~0 GB (10 MB billed floor, tier 1). Read the whole
  table freely; clustering on `goal_type_id` only helps point lookups you rarely need at 16 rows. You can
  also hard-code the map above in application code and skip the join entirely.

## Example queries
```sql
-- decode a campaign group's optimization goal (N:1, no fan-out) — prefer the silver view
SELECT cg.campaign_group_id, cg.goal_type_id, gt.name, gt.description
FROM `dw-main-silver.core.campaign_groups` cg
LEFT JOIN `dw-main-silver.core.goal_types` gt USING (goal_type_id)
WHERE cg.deleted = FALSE AND cg.is_test = FALSE
LIMIT 100;

-- the full enum straight from the physical dim (whole table, cheap)
SELECT goal_type_id, name, description
FROM `dw-main-bronze.integrationprod.core_goal_types`
ORDER BY goal_type_id;
```
