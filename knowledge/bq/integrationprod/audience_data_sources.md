# integrationprod.audience_data_sources

## Purpose
The authoritative **`data_source_id` → name registry** for the audience/targeting graph. Decode the `data_source_id` (DS) leaves in audience expressions and segments (`audience_segments.data_source_id`), and the conversion-pixel `conversion_source_id` in summarydata. This is the audience-service dimension (supersedes the frozen `core.audiences`/`data_sources` variants).

Two logical layers live in one table (split by `data_source_type_id`):
- **`data_source_type_id = 1` — the GLOBAL DSxx taxonomy (72 rows).** The well-known canonical sources every analysis references: `-1`=MNTN Pixel, `4`=CRM, `19`=MNTN Matched (MM), `13`=MNTN Vertical Categorization (PP anchor), `46`=ML Audience Intent Scoring Model (PP v2 / RTC), the DDP vendors (17=ShareThis, 18=Dstillery, 28=33Across, 29=deepsync, 36=Cybba, 39=Klickly, …), etc. **This is the subset the prose "DS registry" describes.**
- **`data_source_type_id = 2` — per-advertiser instances (86,639 rows).** Auto-created, named `<advertiser_id> - <object kind>` (e.g. `34678 - Control Group Audience`). **SIX kinds live (verified 2026-07-19):** four `… Audience` kinds — `First Party` / `Third Party` / `Control Group` / `Extension` — at 15,210 rows each, PLUS `Prospecting Campaign` and `Retargeting Campaign` at 12,899 each (so ~30% of type_id=2 rows are Campaign objects, NOT audiences), + 1 stray `MNTN Taxonomy` row (id 81174, no leading integer). **~5.7 rows per advertiser** (86,639 / 15,210 distinct advertisers), not ~4. The leading integer in `name` is the `advertiser_id` (holds across all kinds). These are NOT taxonomy codes — they are individual audience/campaign objects that inherit a taxonomy meaning.

## Grain & keys
- **Grain:** one row per **`data_source_id`** — PK, verified unique (86,711 rows = 86,711 distinct `data_source_id` = 86,711 distinct `data_source_key`).
- **Key(s):** `data_source_id` (INT64 PK; range `-1` … `4,019,959`). `data_source_key` (opaque 10-char string, also unique) is an alternate key.
- **Referenced by:** `audience_segments.data_source_id` (the DS leaf on a targeting segment). Segments can reference **either** a low taxonomy id (DS19/DS13/DS46/DS4…) **or** a high per-advertiser instance id (type_id=2) — do not assume every referenced id is ≤100.

## Column meanings (only the non-obvious ones)
- **`data_source_id`** — INT64 PK. Range is not contiguous and does NOT cleanly split the two layers: 65 of the 72 global taxonomy rows have ids `≤100`, but **7 taxonomy (type_id=1) rows carry high ids** (328493 Adjust, 328494 AppsFlyer, 328495 Branch, 328496 Kochava, 328497 Singular, 355420 MNTN PageView, 3986845 MNTN Audience API); per-advertiser (type_id=2) instances start at 1072. **Split the layers on `data_source_type_id`, never on an id threshold** — `id<=100` returns 65 rows and silently drops those 7 global sources (incl. the AppsFlyer/Kochava/Singular conversion sources carrying the `-105`/`-106`/`-107` sentinels).
- **`data_source_type_id`** — the split above: **`1`** = global taxonomy source (72 rows, ids `-1`…`3,986,845` but 65 concentrated in `-1`…`64`, the other 7 at ids ≥328,493); **`2`** = per-advertiser audience/campaign instance (86,639 rows, ids ≥1072). Only these two values exist live.
- **`name`** — internal source name. For type_id=1 = the canonical DS name (`MNTN Matched`, `CRM`, `ShareThis`…). For type_id=2 = `"<advertiser_id> - <object kind>"` (six kinds — 4 `… Audience` + `Prospecting`/`Retargeting Campaign`; see Purpose). **Use `name` for decoding** — `display_name` is almost always NULL.
- **`display_name`** — UI label; **NON-NULL for only 8 rows** (e.g. DS-1 `MNTN Pixel`, DS23 `MNTN Pixel`, AppsFlyer, Quorum, OursPrivacy). Fall back to `name` when NULL.
- **`visible`** — UI-surfaced / self-serve flag, **NOT a soft-delete**. Only **13 rows** are `TRUE` (the audience sources selectable in the builder: MNTN Pixel, Oracle, CRM, Oracle Custom Audience, LiveRamp, ShareThis, Dstillery, OnAudience, Experian, shopify, CRM Inclusions, …). The other 86,698 rows are `FALSE` but fully live. **There is no `deleted`/`is_test` column on this table** — do not apply the usual integrationprod live-row filter.
- **`is_mobile`** — mobile-app source flag; `TRUE` for only 5 rows (AppsFlyer v2, Quorum, …).
- **`conversion_type_display_name`** — the label shown for conversions emitted by this source (`Website Event`, `Offline Event`, `CDK Event`, `HubSpot`, `Bombora`…). NON-NULL for **23 rows** (the conversion/pixel-emitting sources); NULL for pure audience/interest sources.
- **`data_source_null_key_id`** — the "unnamed/null conversion" sentinel for pixel/conversion-type sources; populated for exactly **12 rows spanning `-100`…`-111`**: DS-1 MNTN Pixel `-100`, DS23 guid_log `-101`, DS31 CRM Upload `-102`, DS32 CDK `-103`, DS37 CallRail `-104`, AppsFlyer(328494) `-105`, Kochava(328496) `-106`, Singular(328497) `-107`, DS41 Freshpaint `-108`, DS61 AppsFlyer v2 `-109`, DS57 Ours Privacy `-110`, DS64 Quorum `-111`. Six of these (`-100`/`-101`/`-102`/`-105`/`-106`/`-107`) are the sentinel conversion codes in `core_advertiser_conversion_types` / `ui_conversions`.
- **`data_source_key`** — opaque 10-char random string, unique per source; alternate join key (rarely used vs `data_source_id`).
- **`description`** — STRING(1000) but **empty for 100% of rows live** (column defined, never populated). Do not rely on it.
- **`category_id_maps_to`** — STRING(100), **NULL/empty for 100% of rows live**. Do not rely on it.
- **`create_time` / `update_time`** — TIMESTAMP business times (source registration / last edit). Prefer these for "when was this source added/changed."
- **`datastream_metadata.source_timestamp`** — **MILLIS** CDC-capture epoch (Datastream), NOT business time and **NOT** a copy of `update_time`. Unit verified: `TIMESTAMP_MILLIS(1784523021059) → 2026-07-20 04:50:21 UTC` (`TIMESTAMP_MICROS` of the same value lands in 1970 — confirms milliseconds). It is the CDC capture time: only **5,617 distinct values** across 86,711 rows (= capture batches, not per-row edits), and **52,074 rows have `update_time` NULL while `source_timestamp` is populated** — so it coincides with `update_time` only by accident, never as a tz-shifted copy. Anchor: `source_timestamp = UNIX_MILLIS(cdc_capture_time)`. Use `create_time`/`update_time` for business time, not this.

## Joins & relationships
- **`audience_segments.data_source_id` → `audience_data_sources.data_source_id`** (**N:1**; many segments per source). Decode the DS leaf on a targeting segment. Fan-out risk: joining FROM segments is safe (dim on the 1-side); joining FROM this dim TO segments fans out massively (a single DS-19 row maps to millions of segment rows) — never do that without an aggregate.
- **`summarydata` `conversion_source_id` → `data_source_id`** (**N:1**) — decode the source behind a conversion (e.g. `23`=guid_log/Website Event, `-1`=MNTN Pixel, `21`=MNTN Conversion).
- **`data_source_null_key_id` ↔ `core_advertiser_conversion_types` sentinel codes** — the 12 populated values span `-100`…`-111`; six of them (`-100`/`-101`/`-102`/`-105`/`-106`/`-107`) are the "unnamed conversion" pseudo-type sentinels documented in `core_advertiser_conversion_types`.
- **`name` leading integer (type_id=2) = `advertisers.advertiser_id`** — extract with `SPLIT(name,' - ')[OFFSET(0)]` to attribute a per-advertiser instance to its advertiser.
- **`coredw.usage_reporting_*` `data_source_id`** → this registry for the DDP billing meter's source names (their `data_source_id` is joined back here / to `tpa.direct_data_partners`).

## Gotchas
- **NOT a ~50-row registry — 86,711 rows.** The famous DSxx codes are the 72-row `data_source_type_id=1` subset; the other **86,639** rows are per-advertiser `type_id=2` instances. **Filter `data_source_type_id = 1`** when you want the canonical taxonomy — NOT `data_source_id <= 100`, which returns only 65 rows and drops 7 high-id global sources (Adjust/AppsFlyer/Branch/Kochava/Singular/MNTN PageView/MNTN Audience API).
- **No `deleted` / `is_test` columns.** The standard `WHERE deleted=FALSE AND is_test=FALSE` integrationprod filter does not apply here (columns don't exist). `visible` is a UI-surfacing flag (only 13 TRUE), **not** a liveness/soft-delete flag — filtering `visible=TRUE` would drop MM/PP/most DDP taxonomy rows.
- **`display_name`, `description`, `category_id_maps_to` are essentially empty** (8 / 0 / 0 populated) — decode from `name`, never `display_name`/`description`.
- **DS46 never co-occurs with DS13 at segment level** (the `onFangorn` flip swaps 13→46); DS19 survives. "MM = has DS19" undercounts the MM-scored layer by ~7.6% of prospecting spend. (Belongs to `audience_segments`, but relevant when decoding DS leaves.)
- **`datastream_metadata` is a RECORD** — breaks CSV export (`bq --format=csv`); select scalar columns explicitly.
- **`is_mobile`/`visible` are BOOL** — 5 and 13 TRUE respectively; don't infer significance from a FALSE.

## Cost & partitioning notes
- **Tiny dimension — no partition, no cost trap.** `SELECT *` full scan = **10,161,415 bytes ≈ 9.7 MB** (dry-run, all 14 columns; equals `approx_logical_bytes`). Filtered/narrow reads bill the 10 MB minimum tier. Safe to scan whole; no date/partition filter needed.
- **The one filter to always apply is semantic, not for cost:** `WHERE data_source_type_id = 1` to get the canonical DSxx taxonomy (72 rows) instead of 86,639 per-advertiser instances. Do NOT use `data_source_id <= 100` as a proxy — it returns 65 rows and drops the 7 high-id global sources.
- Clustered on `data_source_id`; at this size clustering/pruning is irrelevant.

## Example queries
```sql
-- Canonical DSxx taxonomy (the "DS registry")
SELECT data_source_id, name, conversion_type_display_name, visible
FROM `dw-main-bronze.integrationprod.audience_data_sources`
WHERE data_source_type_id = 1
ORDER BY data_source_id;

-- Decode a per-advertiser instance to its advertiser
-- SAFE_CAST: one stray type_id=2 row (id 81174, name 'MNTN Taxonomy') has a
-- non-integer leading token, so a plain CAST would error mid-scan.
SELECT data_source_id, name,
       SAFE_CAST(SPLIT(name, ' - ')[OFFSET(0)] AS INT64) AS advertiser_id
FROM `dw-main-bronze.integrationprod.audience_data_sources`
WHERE data_source_type_id = 2
LIMIT 100;
```
