# integrationprod.public_campaigns

## Purpose
The campaign (a.k.a. **line item**) configuration dim — the level *below* `campaign_groups`. Reach for it to
resolve a `campaign_id` to its **stage** (`funnel_level`), **channel** (CTV vs display, `channel_id`),
**objective** (`objective_id`), owning **campaign_group** / **advertiser**, status, flight window, and
budget-pacing/frequency config. This is the **raw Datastream CDC landing table** — a near-verbatim mirror of
the coredb Postgres `public.campaigns` table (`max_staleness=15min`), analogous to `public_campaign_groups_raw`
for groups. There is **no `public_campaigns_raw`**; `public_campaigns` *is* the raw base table here. Its SQLMesh
analytical sibling is `integrationprod.campaigns` (see Joins). Canonical use: join `campaign_id →` here to get
`objective_id` / `funnel_level` when scoping prospecting vs retargeting (e.g. the CHAPI "Performance Report" lens).

## Grain & keys
- **Grain:** one row per **`campaign_id`** — a single line item. Verified 548,767 rows = 548,767 distinct
  `campaign_id` (no dupes; PK holds). This is the current-state snapshot, **not** version history (for history use
  `archives_campaign_archives`).
- **Primary key:** `campaign_id` (declared `PRIMARY KEY … NOT ENFORCED` in DDL).
- **Foreign keys / join columns:** `campaign_group_id` → campaign_groups (1:N, ~129k groups own ~548k campaigns),
  `advertiser_id` → advertisers, `campaign_status_id` → core_campaign_statuses, `objective_id` → core_objectives,
  `channel_id` → channels, `partner_id` → core_partners.

## Column meanings (only the non-obvious ones)
All counts below are on **live** rows (`deleted=FALSE AND is_test=FALSE` = 474,109 of 548,767).

- **`funnel_level`** — the **authoritative stage indicator** (more reliable than `objective_id`): 1=S1 Prospecting,
  2=S2 Multi-Touch, 3=S3 MT-Plus, 4=Ego. **~8.5% NULL** on live rows (40,536) — handle NULL when bucketing by stage.
- **`objective_id`** → core_objectives. Live domain: 1=Prospecting (169k), 4=Retargeting (94k), 5=Multi-Touch (75k),
  6=Multi-Touch Full Funnel (74k), 7=Ego (57k), 3=Prospecting (5.2k — a second "Prospecting" code), 2=Onsite (27).
  **Prospecting scope convention = `objective_id IN (1,5,6)`** (CHAPI collapses 5/6/7→1); retargeting = `objective_id=4`.
  Treated as **unreliable for stage** in prior work — prefer `funnel_level`, but note funnel_level's NULLs.
- **`channel_id`** → channels. **Authoritative for CTV vs display:** 8=Television/CTV (264k), 1=Multi-Touch/display
  (199k), 7=Social (10k), 4=Mobile Web, 3=In-App, 10=Onsite; ~213 NULL.
- **`campaign_status_id`** → core_campaign_statuses: 1=Ready, 3=Live, 4=Pause By Advertisers, 5=Pause By MNTN,
  7=Inactive, 8=Deleted, 9=Legacy Archived. **⚠ status_id=8 ("Deleted") is NOT the same as the `deleted` BOOL** —
  70,268 live rows (`deleted=FALSE`) carry status "Deleted". Use the `deleted` BOOL for the soft-delete filter, not status.
- **`deleted` / `is_test`** — soft-delete + test-row flags; **always filter `deleted=FALSE AND is_test=FALSE`** for
  live campaigns (this is the "always apply" filter — there is no partition to filter on).
- **`control_percentage`** — legacy per-campaign holdout %; **≈0 for 99.99% of live rows** (only ~68 non-zero, values
  1–52). This is NOT the standard 10% MD5(`AID:IP`) holdout (that's applied downstream, not stored here).
- **`budget_floor` / `budget_ceiling`** — `NUMERIC(4,3)` **fractional pacing bounds, NOT dollar budgets** (observed
  range 0.0–1.1; ~all populated). The real $ budget lives on `campaign_groups.budget` / the `dso_*` budget tables.
- **`clickpass_click_ttl`** — INTERVAL override for the clickpass click-attribution window; **NULL for ~all rows**
  (falls back to default) — only 18 live rows set it (observed value `180 days`).
- **`frequency_cap_type_id`** — 2 (default, 421k) or 1 (53k). **`dso_manage_budget`** BOOL flags whether DSO
  auto-manages this campaign's budget (use the `dso_*` tables for the operative budget when TRUE).
- **`audience_type_id` / `audience_source_id`** — sparse legacy targeting-config enums, **mostly NULL** (audience_type
  1 on 177k else NULL; audience_source 1/2/3 on ~132k else NULL). The real targeting expression lives in the
  `audience_*` / `audience_audience_segments` tables, not here.
- **`partner_channel_objective_id`** — FK to the partner_channel_objectives config (wide domain 20–62); pipeline-internal.
- **`datastream_metadata`** — STRUCT<uuid, source_timestamp>. **`source_timestamp` = milliseconds** (13-digit UNIX_MILLIS)
  of **CDC capture**, NOT business time — max value trails `CURRENT_TIMESTAMP` by ≤15 min (the max_staleness). Its floor
  (~2026-04, well after most campaigns' `create_time`) reflects the last Datastream re-snapshot, not campaign age.
- **`start_time` / `end_time` / `create_time` / `update_time`** — TIMESTAMP business times (campaign flight window +
  audit stamps); these are the columns to reason about for campaign age, not `datastream_metadata.source_timestamp`.

## Joins & relationships
- **→ `campaign_groups` / `public_campaign_groups(_raw)`** on `campaign_group_id` — **N:1** (many campaigns per group;
  ~548k campaigns → ~129k groups). Product line (PTV/Select), flight, and the operative budget live on the **group**,
  not here. Joining group→campaigns **fans out ~4x** — dedup/aggregate to group grain when rolling up.
- **→ `advertisers`** on `advertiser_id` — **N:1**. Use `advertisers.company_name` for advertiser labels.
- **`integrationprod.campaigns` (SQLMesh analytical sibling)** — same grain (campaign_id PK), **80 fewer rows**
  (548,687 vs 548,767 here) after SQLMesh filtering. Prefer the analytical `campaigns` for day-to-day analytics;
  use `public_campaigns` (this table) when you need the closest-to-source CDC row or CDC-incremental reads via
  `datastream_metadata.source_timestamp`. Both are 1:1 on `campaign_id`.
- **Reference dims (all N:1, small):** `objective_id`→core_objectives, `channel_id`→channels,
  `campaign_status_id`→core_campaign_statuses, `partner_id`→core_partners.
- **History:** `archives_campaign_archives` holds one row per version of each campaign (order by `create_time` /
  version; version may be non-monotonic across Datastream) — use for as-of-date reconstruction.
- **Downstream config keyed on `campaign_id`:** `dso_household_score_thresholds` (HHST gate), `dso_campaign_*`
  budgets/caps, `beeswax_campaign_*` mappings, `audience_audience_segments` (targeting expression). All **N:1 back
  to this table** (this is the parent dim) but each can hold **multiple rows per campaign** (versioned/CDC) — dedup
  before joining to avoid fan-out.

## Gotchas
- **Two different "deleted".** `deleted` (BOOL) is the soft-delete flag to filter on; `campaign_status_id=8`
  ("Deleted" status) is a UI status that coexists with `deleted=FALSE` on 70k+ live rows. Don't conflate them.
- **`funnel_level` is ~8.5% NULL** on live rows — stage buckets must handle NULL (and NULL ≠ stage 0).
- **PK is `campaign_id`, NOT `id`.** There is no `id` column and no `silver.core.campaigns` view.
- **`budget_floor`/`budget_ceiling` are NOT dollars** — NUMERIC(4,3) fractional pacing bounds (0–1.1). The dollar
  budget is on `campaign_groups` / `dso_*` tables.
- **`datastream_metadata.source_timestamp` is CDC-capture time (ms), not business time**, and its history floor
  (~2026-04) is a re-snapshot artifact — never use it to reason about how old a campaign is; use `create_time`.
- **This is current-state, single-version** (no `version` column). For "what did this campaign look like on day D"
  go to `archives_campaign_archives`.
- **`public_campaigns` (this, raw CDC) has 80 more rows than the analytical `campaigns`** — pick deliberately; results
  can differ slightly at the margins.
- **`objective_id` is a weak stage separator** (some `objective_id=4` retargeting rows are `funnel_level=1`); use
  `funnel_level` for stage, but use `objective_id IN (1,5,6)` when reproducing CHAPI's prospecting scope.
- Small dim, `max_staleness=15min` — reads can lag the source by up to 15 minutes.

## Cost & partitioning notes
- **No partition** (base table, no `PARTITION BY`); clustered by `campaign_id`. **The always-apply filter is
  `deleted=FALSE AND is_test=FALSE`** (there is no time partition to filter). It's a tiny dim (~130 MiB) so cost is
  negligible, but the levers, all from `bash .claude/scripts/bq_run.sh --dry_run`:
  - `SELECT *` full table = **136,149,944 B (~130 MiB)** — the whole table.
  - `SELECT campaign_id, objective_id, funnel_level` full = **12,773,096 B (~12 MiB)** — same rows, **~10.7× cheaper**;
    **column selection is the real prune lever** — avoid `SELECT *`.
  - `SELECT * WHERE campaign_id = 259556` = **136,149,944 B** (same as full in the *estimate*) — clustering prunes
    only at **runtime**, so the dry-run upper bound never reflects the `campaign_id` filter. Still, filter/order by
    `campaign_id` for cheaper actual execution.
- `approx_logical_bytes` = 136,149,944 (bq show `numBytes`, the physical backing store).

## Example queries
```sql
-- Live campaigns for an advertiser with stage + channel (pick specific columns, not SELECT *)
SELECT campaign_id, campaign_group_id, funnel_level, objective_id, channel_id, campaign_status_id
FROM `dw-main-bronze.integrationprod.public_campaigns`
WHERE advertiser_id = 31921 AND deleted = FALSE AND is_test = FALSE;

-- Prospecting-scope campaigns (CHAPI lens): objective_id IN (1,5,6)
SELECT campaign_id, funnel_level
FROM `dw-main-bronze.integrationprod.public_campaigns`
WHERE objective_id IN (1,5,6) AND deleted = FALSE AND is_test = FALSE;
```
