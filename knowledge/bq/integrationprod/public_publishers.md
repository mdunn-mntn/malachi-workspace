# integrationprod.public_publishers

## Purpose
Datastream CDC **landing mirror** of coredb's Postgres `public.publishers`. This is MNTN's **CTV / streaming publisher (network / channel) dimension** — the human-readable catalog of the networks and channels that CTV inventory belongs to (ESPN2, The CW, Peacock, Paramount, Adult Swim, etc.). Reach for it to resolve a `publisher_id` to a network name, to enumerate premium "Living Room Quality" networks (`is_lrq`), or as the parent dim for `ctv_ctv_sites` (network → sites/apps). It is `public_*`-prefixed, so it is the closest-to-source raw mirror (carries `datastream_metadata`); use it for pipeline / incremental reads.

Note: `mntnselect_publishers` is a **different** table (the MNTN Select self-serve platform's publisher accounts) — do not confuse the two despite the shared `publisher_id` column name.

## Grain & keys
- **Grain:** exactly **one row per `publisher_id`** — current-state upsert snapshot (verified 2026-07-20: n_rows = n_distinct publisher_id = 262,631; 0 NULL ids). **Not versioned** — CDC upserts in place; there is no as-of history here.
- **Primary key:** `publisher_id` (declared table PK; also the sole cluster key). IDs are **sparse** — max id 263,791 > row count 262,631, so deletes leave gaps; do not assume dense/contiguous ids.
- **`name` is NOT a key** — 232,984 distinct names across 262,631 rows (~30K duplicate names), largely from LRQ/non-LRQ splits (see Gotchas).

## Column meanings (only the non-obvious ones)
- **`name`** — network / channel display name (e.g. `"ESPN2"`, `"The CW"`, `"Peacock (Non-LRQ)"`, `"Paramount"`). **Not unique.** Carries inline **curation annotations** in the string itself: `"- DO NOT USE"` (retired/blocked) and `"(Non-LRQ)"` / `"(non LRQ)"` (the non-premium variant of a named network). LRQ and non-LRQ versions of the same network are stored as **separate `publisher_id` rows**.
- **`is_lrq`** — BOOL **"Living Room Quality"** flag: TRUE = premium CTV inventory (big-screen / living-room device). Name derived from the `public_publisher_types` lookup value `1 = "CTV - Living Room Quality (LRQ)"`. Distribution (verified 2026-07-20): **210 TRUE, 262,421 FALSE, 0 NULL**. This boolean — **not** `publisher_type_id` — is where the LRQ signal actually lives in this table.
- **`logo`** — relative storage path to the network's logo asset (e.g. `"/storage/publisherlogos/ESPN2.png"`, occasionally `.svg`). Only **233 non-NULL** (the branded/curated networks); NULL for the ~262K programmatically-added rows.
- **`create_time` / `update_time`** — TIMESTAMP row lifecycle (UTC; no tz offset stored). Range: min `create_time` 2020-04-20, max `create_time` 2026-06-11, max `update_time` 2026-07-16 — the dim is **actively maintained**.
- **`budget_cap`** — NUMERIC(3,2). **Entirely NULL** (0 non-NULL table-wide, verified 2026-07-20) — an unused column replicated from the Postgres source. Do not filter/aggregate on it.
- **`user_id`** — INT, would FK to a users table. **Entirely NULL** (0 non-NULL) — no owning-user is populated; unused schema artifact.
- **`publisher_type_id`** — INT, FK → `public_publisher_types.publisher_type_id`. **Entirely NULL in this table** (0 non-NULL), so the join yields nothing here — use `is_lrq` for the premium/non-premium split. The lookup's authoritative domain (from `public_publisher_types`, verified 2026-07-20): `1`=CTV - Living Room Quality (LRQ), `2`=CTV - Other, `3`=Display, `4`=Encrypted, `6`=Mobile Tablet PC (**no `5`**). NOTE this differs from the `cost_impression_log` prose gloss in `data_catalog.md` ("1=CTV/OTT, 2=premium, 3=web/display"); the `public_publisher_types` values above are the source-of-truth enum.
- **`datastream_metadata`** — CDC struct `{uuid, source_timestamp}`. `source_timestamp` = **milliseconds** CDC-capture epoch (13 digits; verified 2026-07-20: sample `1784234453044` = UNIX_MILLIS ≈ 2026-07-16, matching that row's `update_time` 2026-07-16 20:40:53). Replication-capture time, **not** business time; use it for incremental reads.

## Joins & relationships
- **→ `ctv_ctv_sites` (1:N, fan-out ~5.4x):** `ctv_ctv_sites.publisher_id = publisher_id`. Maps a publisher (network) to its many sites/apps. Verified 2026-07-20: `ctv_ctv_sites` = 1,193,783 rows across 219,873 distinct publisher_id, only **11 orphan** publisher_ids not present in this dim → `publisher_id` is a clean FK. Joining this dim to `ctv_ctv_sites` fans out to ~1.19M rows (~5.4 sites per publisher on average).
- **→ `public_publisher_types` (N:1, but inert here):** `publisher_type_id → public_publisher_types.publisher_type_id`. Because `publisher_type_id` is 100% NULL in this table, this join returns no type name for any row; the types lookup is consumed by other tables, not by this dim.
- **CTV reporting joins by NAME, not id:** the CTV network reporting tables key on the human network-name string, not `publisher_id`. `summarydata.sum_by_ctv_network_by_day.domain` and `silver.core.media_plan_publishers.name` are the same "CBS / NBC / HBO Max"-style names (cross-validated TI-748) that appear in this table's `name`. **Fan-out caveat:** `name` is non-unique here (LRQ/non-LRQ splits, dup names), so name-keyed joins to this dim can multiply rows — prefer the `publisher_id` FK wherever the partner table carries it (e.g. `ctv_ctv_sites`).
- **→ users (N:1, never populated):** `user_id` would reference the owning user, but it is entirely NULL — the join is not usable.

## Gotchas
- **No `deleted` / `is_test` columns.** The standard `deleted=FALSE AND is_test=FALSE` live-row filter **does not apply** — those columns do not exist on this table. Curation status is instead encoded **inside the `name` string** (`"- DO NOT USE"`, `"(Non-LRQ)"`). Screen the name text, not a boolean flag.
- **Three columns are entirely NULL:** `budget_cap`, `user_id`, `publisher_type_id` — all 0 non-NULL table-wide. Don't join, filter, or aggregate on them expecting data. In particular, use `is_lrq` (not `publisher_type_id`) for the premium/non-premium CTV split.
- **`name` is not unique (~30K dup names).** Name-keyed joins to reporting tables can fan out, and counting "distinct networks" by name is noisy because a single network appears as multiple rows — its LRQ variant and its `"(Non-LRQ)"` variant have **separate `publisher_id`s**.
- **Sparse ids.** Max `publisher_id` (263,791) exceeds row count (262,631); deleted rows leave gaps. Do not assume contiguous ids or use `MAX(publisher_id)` as a count.
- **Current-state snapshot, not versioned.** CDC upserts each `publisher_id` in place — there is no version history in this table for as-of reconstruction.
- **`source_timestamp` is ms capture time, not business time** — do not treat it as a creation/launch timestamp; use `create_time`/`update_time` for business lifecycle.

## Cost & partitioning notes
- **No partition** (verified: base table, `timePartitioning` null, clustered only). This is a tiny dim (~24 MB) — a full scan is cheap and there is nothing to prune by date; the "always filter the partition column" advice **does not apply**. There is also no meaningful row filter to always apply (no `deleted`/`is_test`) beyond screening the `name` annotations if you want live/usable networks only.
- **Byte figures (dry-run, 2026-07-20):** `SELECT *` = **24,403,420 B (~24.4 MB)** — the whole table (matches `numBytes`). `SELECT publisher_id, name` = **8,333,726 B (~8.33 MB)**. Column pruning (~3x here) is the only lever; avoid pulling the `datastream_metadata` struct unless doing an incremental read.
- Clustered by `publisher_id` — point/range lookups on the id benefit marginally, but on a 24 MB table the practical win is negligible.

## Example queries
```sql
-- Premium "Living Room Quality" CTV networks:
SELECT publisher_id, name
FROM `dw-main-bronze.integrationprod.public_publishers`
WHERE is_lrq = TRUE
ORDER BY publisher_id;

-- Resolve a network to its many sites/apps (1:N via ctv_ctv_sites):
SELECT p.publisher_id, p.name, s.site
FROM `dw-main-bronze.integrationprod.public_publishers` p
JOIN `dw-main-bronze.integrationprod.ctv_ctv_sites` s
  ON s.publisher_id = p.publisher_id
WHERE p.name = 'ESPN2';

-- Incremental read via CDC capture timestamp (ms epoch):
SELECT publisher_id, name, update_time
FROM `dw-main-bronze.integrationprod.public_publishers`
WHERE datastream_metadata.source_timestamp > UNIX_MILLIS(TIMESTAMP '2026-07-19 00:00:00');
```
