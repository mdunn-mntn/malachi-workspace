# core.advertisers_impression_tracking_urls

## Purpose
Configuration dimension: the set of **third-party impression-tracking URLs** an advertiser has registered so an external vendor (e.g. iSpot.tv `pi.ispot.tv`, DoubleVerify, freshpaint, generic CloudFront/`zprk.io` pixels) can independently count/verify impressions MNTN serves on their behalf. At serve time MNTN fires these URLs (currently every row is `server_side=TRUE`), substituting macros embedded in the string (`${aid}`, `${random}`, `add_gdpr_macro`, `consent`, etc.). Reach for it to answer "which advertisers have 3P impression trackers attached, and to which vendor," or to audit tracker configuration. Tiny lookup dim (428 rows) — never a fact/event table.

## Grain & keys
- **Grain:** one row per `impression_tracking_url_id` — a single registered impression tracker. Verified unique: 428 rows / 428 distinct ids (1:1).
- **Primary key:** `impression_tracking_url_id` (also the physical cluster key).
- **Foreign key:** `advertiser_id` → `bronze.integrationprod.advertisers` (PK `advertiser_id`). An advertiser may register many trackers (350 distinct advertisers across 428 rows → **1:N** advertiser→trackers). `user_id` → internal MNTN user/operator who created the row (0 = system/unattributed).

## Column meanings (only the non-obvious ones)
- **`impression_tracking_url`** — the 3P tracker URL as configured, macro-templated (macros like `${aid}`, `${random}`, `add_gdpr_macro`, `consent` are substituted at serve time). Free-text; may contain malformed entries (e.g. `https:example1.com`, `https://example.com` test rows). Not a MNTN-owned endpoint.
- **`server_side`** (BOOL) — TRUE = MNTN fires the tracker server-side (S2S) rather than embedding it client-side. **Empirically all 428 rows are TRUE** — every currently-registered tracker is server-side.
- **`is_post`** (BOOL) — HTTP method for the fire: TRUE = POST (uses `request_body`), FALSE = GET. **Empirically all 428 rows are FALSE** (all GET) — the POST path is a schema capability that is currently unused.
- **`request_body`** (STRING) — POST payload used only when `is_post=TRUE`. **Empirically NULL/empty for all rows** (consistent with `is_post` all FALSE).
- **`user_id`** (INT64) — internal user/operator who created the tracker. `0` = system/unattributed; non-zero = a MNTN user id (not an advertiser id). One row has NULL user_id.
- **`create_time`** (TIMESTAMP) — native UTC business creation time of the row (2023-07-25 → present). This is the authoritative "when was this tracker added" timestamp.
- **`datastream_metadata`** (STRUCT) — Datastream/CDC replication metadata. `.uuid` = per-change event id; `.source_timestamp` (INT64) = **UNIX MILLISECONDS** of the CDC capture, i.e. `= UNIX_MILLIS(cdc_capture_time)` → decode with `TIMESTAMP_MILLIS(datastream_metadata.source_timestamp)`. This is the **replication/backfill time, NOT `create_time`**: for a recent live edit it aligns with `create_time` to the second, but backfilled 2023-era rows show ~2.4-year divergence (max ~75.8M s). Use `create_time` for business timing; use `source_timestamp` only for CDC/freshness debugging.

## Joins & relationships
- **`advertiser_id` → `bronze.integrationprod.advertisers`** (silver: no `core.advertisers` view exists — the advertiser dim is the un-prefixed `integrationprod.advertisers`, PK `advertiser_id`, ~38.8K distinct rows scanned). Join to `advertisers.company_name` for the authoritative advertiser name (the advertiser dim's own name columns can be stale; `company_name` is the current source of truth).
- **`user_id` → internal user dimension** (MNTN operator, not an advertiser). Left as directional — user dim not resolved this pass; `0` is a sentinel, filter it out before joining.
- No event/fact table joins on `impression_tracking_url_id` were confirmed here; this is a config dim consumed by the ad-serving/bidder path, not something you fan a fact table across.

## Gotchas
- **No `deleted` / `is_test` columns.** Unlike most `core.*` dims, this table has NO soft-delete or test flags — the standard `deleted=FALSE AND is_test=FALSE` dim filter does **not** apply and would error. This is a CDC snapshot of current state: all 428 rows are live. (Test/junk rows do slip in via the URL text itself, e.g. `example1.com` — filter on `impression_tracking_url` content, not a flag.)
- **`source_timestamp` ≠ `create_time`.** See column note — it is the Datastream capture time. Do not use it as the creation date; backfilled rows are off by years.
- **`is_post`/`request_body` are dormant.** Every row is GET with an empty body today; do not assume POST trackers exist.
- **`server_side` is uniformly TRUE today** — do not treat it as a discriminator in current data (all trackers are S2S).
- **Free-text URLs** — expect malformed/test URLs and unsubstituted macros in the raw string.

## Example queries
```sql
-- Trackers per advertiser, with authoritative advertiser name
SELECT u.advertiser_id, a.company_name, COUNT(*) AS n_trackers
FROM `dw-main-silver.core.advertisers_impression_tracking_urls` u
JOIN `dw-main-bronze.integrationprod.advertisers` a USING (advertiser_id)
GROUP BY 1, 2
ORDER BY n_trackers DESC;

-- Decode the CDC capture time (milliseconds)
SELECT impression_tracking_url_id, create_time,
       TIMESTAMP_MILLIS(datastream_metadata.source_timestamp) AS cdc_capture_time
FROM `dw-main-silver.core.advertisers_impression_tracking_urls`
ORDER BY create_time DESC
LIMIT 20;
```
