# core.attribution_models

## Purpose
Config/enum dimension that names every attribution model MNTN runs. Each row is one attribution
"recipe": a rule for how a conversion or visit gets credited back to an ad exposure. Reach for it to
translate an `attribution_model_id` (carried on conversion/attribution fact rows) into a human-readable
model, and to tell **standard** (MNTN) models apart from **competing** (industry-standard comparison)
models and **display last-touch** from **CTV/TV last-touch**. Static lookup — 30 rows, grows only when
engineering adds a new model.

## Grain & keys
- **Grain:** one row per attribution model. 30 rows live (as of 2026-07-19). IDs run 1-20 and 25-34
  (21-24 are unused gaps, not deletes).
- **Primary key:** `attribution_model_id`.
- **Self-reference key:** `counterpart_attribution_model_id` → `attribution_model_id` (bidirectional 1:1).
- **No soft-delete / no test columns.** This table has NO `deleted` and NO `is_test` column, so the
  standard `deleted=FALSE AND is_test=FALSE` core-dim filter does **not** apply here — all 30 rows are live.

## Column meanings (only the non-obvious ones)
- **`name`** — free-text model label. Encodes two things worth parsing:
  1. Channel/touch axis: `"Last Touch ..."` = credits the last touch across any impression;
     `"Last TV Touch ..."` = credits only the last TV/CTV touch.
  2. Identity-key variant used to match conversion→exposure, given as the suffix:
     `guid`, `ip`, `ga_client_id`, `household id`, `IFA-IP winlogs`, `Offline Attribution`,
     `Impression`, and Freshpaint variants (`Freshpaint (Imp Attr)`, `Freshpaint (Visit Attr)`,
     `Competing Visit - Freshpaint`).
- **`attribution_model_type_id`** — 4-value enum (live `SELECT DISTINCT`, no lookup dim exists for it in
  bronze/silver — meaning is inferred from the model names it groups). The two axes are
  {standard vs competing} x {last-touch vs last-TV-touch}:
  | type_id | meaning | competing? | channel |
  |---------|---------|-----------|---------|
  | 1 | Last Touch | no (standard/MNTN) | any/display |
  | 2 | Last TV Touch | no (standard/MNTN) | TV/CTV only |
  | 3 | Last Touch Competing | yes (industry-standard comparison) | any/display |
  | 4 | Last TV Touch Competing | yes (industry-standard comparison) | TV/CTV only |
  "Competing" models power the `competing_*` / industry-standard (last-touch) reporting lens (see
  `reference_chapi_ui.md`: industry_standard = last-touch + competing_*).
- **`counterpart_attribution_model_id`** — points to this model's **display↔CTV mirror** — the otherwise-
  identical model on the other channel axis (type 1↔2, or type 3↔4), NOT the competing counterpart.
  E.g. 1 (`Last Touch - guid`) ↔ 4 (`Last TV Touch - guid`); 9 (`Last Touch Competing - guid`) ↔
  12 (`Last TV Touch Competing - guid`). Relationship is symmetric (a.counterpart=b ⟺ b.counterpart=a).
- **`create_time`** — native TIMESTAMP (UTC) of when the model row was inserted. Not an epoch INT; no unit
  conversion needed. Useful as a rough "when did this model ship" marker (e.g. household-id models 31-34
  created 2026-06-01; Freshpaint visit-attr 29/30 created 2025-11-23).

## Joins & relationships
- **Consumed by conversion/attribution fact tables** via `attribution_model_id` (fact side carries the
  FK). Fact→dim is **N:1** (safe, no fan-out): many conversion/visit rows point at one model. The reverse
  (dim→fact) fans out massively — never start a scan from this 30-row dim expecting to bound the fact side.
- **Self-join on counterpart:** `attribution_models a JOIN attribution_models b
  ON a.counterpart_attribution_model_id = b.attribution_model_id` is **1:1** (every model has exactly one
  counterpart). Use it to line up the display vs CTV pair of the same variant.
- **No dedicated `attribution_model_types` lookup** exists in bronze/silver (confirmed absent 2026-07-19);
  the type domain is documented inline above.

## Gotchas
- **Standard core-dim filter is N/A.** No `deleted`/`is_test` columns exist — do not add that filter
  (it would error). All rows are live.
- **`counterpart` ≠ competing pair.** Prose long described it as "linked competing model ID"; empirically
  it is the display↔CTV mirror (type 1↔2 / 3↔4). Competing-vs-standard is captured by
  `attribution_model_type_id` (3/4 = competing) and the `Competing` substring in `name`, not by counterpart.
- **No "probabilistic" model.** Older prose implied type distinguishes "last-touch vs probabilistic" —
  all 30 rows are last-touch variants; there is no probabilistic model in the table.
- **Bronze `datastream_metadata` RECORD is dropped by the silver view.** The physical bronze table also
  has a `datastream_metadata` STRUCT (`uuid`, `source_timestamp` epoch INT) from Datastream CDC, but the
  sqlmesh projecting view exposes only the 5 columns above — so there is no CDC version/watermark column
  in silver.
- **ID gap 21-24** is intentional (never assigned), not soft-deleted rows.

## Example queries
```sql
-- decode a fact row's attribution model + its standard/competing + channel flags
SELECT attribution_model_id, name, attribution_model_type_id,
       attribution_model_type_id IN (3,4) AS is_competing,
       attribution_model_type_id IN (2,4) AS is_tv_only
FROM `dw-main-silver.core.attribution_models`
ORDER BY attribution_model_id;

-- pair each display model with its CTV counterpart
SELECT a.attribution_model_id AS display_id, a.name AS display_name,
       b.attribution_model_id AS ctv_id, b.name AS ctv_name
FROM `dw-main-silver.core.attribution_models` a
JOIN `dw-main-silver.core.attribution_models` b
  ON a.counterpart_attribution_model_id = b.attribution_model_id
WHERE a.attribution_model_type_id IN (1,3);  -- display side only, avoid dupes
```
