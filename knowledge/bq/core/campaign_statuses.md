# core.campaign_statuses

## Purpose
The enum-decode dimension for a campaign's lifecycle status. Reach for it to translate the integer
`campaigns.campaign_status_id` into a human name (Live, Paused, Inactive, …) and — critically — to
find **currently-delivering** campaigns (`campaign_status_id = 3` = "Live"). Seven fixed rows; it is a
static reference lookup, not an event/fact table.

## Grain & keys
- **Grain:** one row per campaign-status enum value (7 rows total).
- **Primary key:** `campaign_status_id` (INT64) — unique, also the physical cluster key.
- **Join column:** `campaign_status_id` ← `campaigns.campaign_status_id` (and likely `core_flights.status_id`; see Joins).

## Column meanings (only the non-obvious ones)
- **campaign_status_id** — the enum PK. Live domain (verified 2026-07-19, `SELECT DISTINCT … ORDER BY`):

  | id | name | Delivering? |
  |---|---|---|
  | 1 | Ready | no — set up, not started |
  | 3 | **Live** | **yes — actively delivering** |
  | 4 | Pause By Advertisers | no — paused by advertiser/agency |
  | 5 | Pause By MNTN | no — paused by MNTN ops |
  | 7 | Inactive | no — ended / off |
  | 8 | Deleted | no |
  | 9 | Legacy Archived | no |

  **IDs 2 and 6 do not exist** — the enum is sparse (gaps), so never assume a contiguous range.
- **created_at** — TIMESTAMP the enum row was first inserted in the source Postgres (2018 for the
  original six, 2020 for "Legacy Archived"). This is business/row-creation time, not CDC-capture time.
- **datastream_metadata.source_timestamp** — CDC (Datastream) capture epoch in **MILLISECONDS**
  (anchor: `source_timestamp = UNIX_MILLIS(capture_time)`; `TIMESTAMP_MILLIS(1768409922474)` =
  2026-01-14 16:58:42 UTC, whereas `TIMESTAMP_MICROS` yields 1970 — confirms ms). **All 7 rows carry the
  identical value** — a single snapshot capture of this static dim. It is NOT business/change time; use
  `created_at` for row age, and do not treat `source_timestamp` as a per-row modification timestamp.
- **datastream_metadata.uuid** — Datastream change-record id (opaque); no analytical use.

## Joins & relationships
- **`campaigns.campaign_status_id` → this.campaign_status_id** — partner grain: `campaigns` is
  1 row per campaign (many campaigns per status). Direction is **N:1** (many campaigns → one status row),
  so joining `campaigns` to this dim **cannot fan out** — it is a safe enrichment lookup. This is the
  primary use (decode a campaign's live/paused state).
- **`core_flights.status_id`** — the flights dim carries a `status_id` with observed values 3 and 8
  (= Live / Deleted per this enum), very likely the same status vocabulary; treat as a probable shared
  enum but the documented, verified FK is `campaigns.campaign_status_id`. (Not live-verified here.)

## Gotchas
- **"Live" ≠ `deleted=FALSE`.** To find an advertiser's currently-delivering campaigns filter
  `campaign_status_id = 3` (Live), NOT merely non-deleted campaigns — Paused (4/5) and Inactive (7) rows
  are also non-deleted. Optionally cross-check with recent impressions (e.g. `all_facts` / CIL) for
  true delivery.
- **No `deleted` / `is_test` columns on this dim.** The usual `deleted=FALSE AND is_test=FALSE` live-row
  filter for `core.*` dims does not apply here — those columns don't exist. All 7 rows are always valid
  reference rows. "Deleted" (id 8) is a *campaign* state value, not a soft-delete flag on this table.
- **Sparse enum:** ids 2 and 6 are absent. Never hard-code a `BETWEEN 1 AND 9` assumption.
- **`source_timestamp` is a single capture instant for every row** — do not use it to order or date rows.

## Cost & partitioning notes
- **The one filter to always apply: none needed.** This is a 7-row / 520-byte static lookup with no time
  partition and no date column to bound — `SELECT *` is safe and effectively free.
- Physical `dw-main-bronze.integrationprod.core_campaign_statuses`: **no time partitioning**, clustered by
  `campaign_status_id`, no TTL. `numRows` = 7, `numBytes` = 520 (real backing storage).
- Dry-run of `SELECT campaign_status_id, name, created_at, datastream_metadata.source_timestamp`
  (four columns) billed the 10 MB minimum (0.01 GB) — the table is far below any billing floor; column
  selection is irrelevant to cost at this size.

## Example queries
```sql
-- Decode a campaign's status (safe N:1 lookup, no fan-out)
SELECT c.campaign_id, c.name AS campaign_name, s.name AS status
FROM `dw-main-silver.core.campaigns` c            -- or bronze.integrationprod.core_campaigns
JOIN `dw-main-silver.core.campaign_statuses` s USING (campaign_status_id)
WHERE c.deleted = FALSE AND c.is_test = FALSE;

-- Currently-delivering campaigns for one advertiser
SELECT campaign_id, name
FROM `dw-main-silver.core.campaigns`
WHERE advertiser_id = @aid
  AND campaign_status_id = 3      -- 3 = Live
  AND deleted = FALSE AND is_test = FALSE;
```
