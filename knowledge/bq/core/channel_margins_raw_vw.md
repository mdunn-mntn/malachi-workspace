# core.channel_margins_raw_vw

## Purpose
A very small reference/config dimension holding MNTN's channel-level margin and fee
configuration — the rate components used to derive take/margin in pricing and billing.
Each row bundles a set of NUMERIC rate knobs (budget margin, budget padding, partner
margin, data margin, platform fee, target CPM) for a given channel × partner combination.
Reach for it when you need to know which margin/fee parameters apply to a
(channel, partner) pairing. **SENSITIVE:** margin/rate values are private (take rates) —
document and join on keys, but do not print or share the NUMERIC rate columns' values.

## Grain & keys
- **Grain:** one row per `channel_margin_id` (surrogate PK). Currently **8 rows** total.
- **Key(s) / join columns:** `channel_margin_id` PK (8 distinct = 8 rows, 1:1 confirmed).
  Natural key `(channel_id, partner_id)` is also unique (8 combos over 8 rows), so each
  row is exactly one channel×partner config. FKs: `partner_id` → `core.partners`,
  `channel_id` = channel/media-type identifier (see Joins).

## Column meanings (only the non-obvious ones)
- **channel_margin_id** — surrogate PK. Also the clustering key on the physical table.
- **channel_id** — channel / media-type identifier for the config. There is **no
  `core_channels` dimension table** to join to (it does not exist); interpret via the
  channel enum used elsewhere (e.g. log tables use `channel_id` 1=display, 8=CTV). 5
  distinct values across the 8 rows.
- **partner_id** — FK to `core.partners` (supply/demand partner). Non-null in all rows;
  3 distinct values across the 8 rows.
- **budget_margin, budget_padding, partner_margin, data_margin** — NUMERIC rate
  components (**SENSITIVE**). In the SQLMesh view these four are wrapped in
  `SAFE_CAST(... AS NUMERIC)` — the underlying raw column stores a looser type and a
  malformed value would coerce to **NULL** rather than error. `platform_fee` and
  `target_cpm` are already NUMERIC in the raw table (no SAFE_CAST).
- **platform_fee, target_cpm** — NUMERIC fee / target-CPM knobs (**SENSITIVE**).
- **create_time / update_time** — business-time TIMESTAMPs (not epoch integers; no unit
  resolution needed). Both non-null in all 8 rows. Use `update_time` for latest-config
  recency.

## Joins & relationships
- **`partner_id` → `core.partners.partner_id`** — partners is the parent (PK `partner_id`,
  one row per partner). This table is the *many* side, so the join is **N:1 (safe, no
  fan-out)**. `core.partners` also carries `partner_type_id` → `core.partner_types`.
- **`channel_id`** — **no partner dimension table** (`core_channels` not found). Treat as
  an enum identifier; resolve meaning from the channel enum used across log/summary tables.
- **`channel_margin_id`** — surrogate PK; expected to be referenced by downstream
  pricing/billing/margin computations, but no confirmed child table within `core` in this
  pass. Because this is an 8-row dimension, any join *from* a fact table is N:1 (safe).
- **Sibling `core.channel_margins` (non-`_raw`)** — a *separate* object: a `sqlmesh__core`
  model (`core__channel_margins`), not the integrationprod passthrough. It exposes the
  **identical 11-column set**. `_raw_vw` here is the direct integrationprod CDC passthrough;
  prefer it when you want the untransformed source rows.

## Gotchas
- **Tiny reference table (8 rows, 927 bytes).** No partition, no cost trap; no aggregation
  or date filter needed.
- **NO `deleted` / `is_test` columns.** Unlike most `core.*` CDC dimensions, this table has
  neither, so the standard `deleted=FALSE AND is_test=FALSE` live-row filter does **not
  apply** (and cannot) — every row is a live config.
- **SENSITIVE margins.** `budget_margin`, `budget_padding`, `partner_margin`, `data_margin`,
  `platform_fee`, `target_cpm` are private take-rate components — do not print or share
  their values.
- **SAFE_CAST null-out.** The four `budget_margin`/`budget_padding`/`partner_margin`/
  `data_margin` columns are `SAFE_CAST`-coerced to NUMERIC in the view; a malformed raw
  value surfaces as NULL, not an error.
- **Two variants exist** (`channel_margins_raw_vw` vs `channel_margins`) with the same
  columns but different lineage — be explicit about which one a query/model references.
