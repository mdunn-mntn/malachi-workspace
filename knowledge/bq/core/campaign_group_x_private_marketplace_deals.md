# core.campaign_group_x_private_marketplace_deals

## Purpose
Thin silver view over the `bronze.integrationprod.core_campaign_group_x_private_marketplace_deals` CDC
dimension. It is the canonical mapping that records **which private-marketplace (PMP) deal-group a
campaign group buys inventory from**. Reach for it to tell whether a campaign group runs on PMP
inventory at all, and which deal-group — the mechanism behind **MNTN Select** delivery and the PTV
**Pause Ads** feature (both consume PMP inventory). Rows begin 2025-07-31 (the MNTN Select launch /
`product_id` immutability date), so this table has no pre-Select history.

## Grain & keys
- **Grain:** exactly one row per `campaign_group_id`. Verified: 608 rows = 608 distinct
  `campaign_group_id` = 608 distinct (cg, deal-group) pairs. `campaign_group_id` is the effective
  primary key — a group attaches to **at most one** PMP deal-group.
- **Foreign keys:**
  - `campaign_group_id` → `campaign_groups.campaign_group_id` (1:1).
  - `private_marketplace_deal_group_id` → `private_marketplace_groups.private_marketplace_group_id`
    (N:1 — 608 campaign groups fan into only **82** distinct deal-groups).

## Column meanings (only the non-obvious ones)
- **`private_marketplace_deal_group_id`** — despite the table name saying "…private_marketplace_deals",
  this column points at a PMP **deal-GROUP** (`core_private_marketplace_groups.private_marketplace_group_id`),
  i.e. a named bundle/level of deals, **not** an individual deal in `core_private_marketplace_deals`.
  Do not join it to `private_marketplace_deals` — you'll get zero matches.
- **`create_time` / `update_time`** — TIMESTAMP (UTC) of when the mapping row was created / last changed
  in the source Postgres. `create_time` earliest is 2025-07-31.
- **`datastream_metadata.source_timestamp`** — CDC-capture epoch in **milliseconds**
  (`= UNIX_MILLIS(update_time)`; anchor: `TIMESTAMP_MILLIS(1784223511059)` = `2026-07-16 17:38:31` =
  that row's `update_time` exactly). This is Datastream capture time, **not** business time — use
  `create_time` / `update_time` for anything analytical.
- **`datastream_metadata.uuid`** — CDC change-event id; not a business key.

## Joins & relationships
- **→ `campaign_groups`** on `campaign_group_id` (partner grain: **1 row per campaign group**, so 1:1;
  no fan-out). The silver `campaign_groups` view carries `product_id` (1=PTV, 2=Select, 3=QuickFrame),
  budget, and status — join here to classify what kind of group owns the PMP attachment.
- **→ `private_marketplace_groups`** on `private_marketplace_deal_group_id =
  private_marketplace_group_id` (partner grain: **1 row per deal-group**; this bridge is the **N** side,
  N:1 — many campaign groups share one deal-group, so joining FROM the bridge never fans out, but
  joining FROM `private_marketplace_groups` INTO the bridge fans out ~7x on average). 605/608 bridge
  rows match a live PMP group; 3 are orphans (referenced group hard-deleted upstream).
- Individual deals live in `private_marketplace_groups`'s children (`core_private_marketplace_deals`,
  `core_private_marketplace_families`); reach them via the deal-group, not directly from this bridge.

## Gotchas
- **No `deleted` / `is_test` columns** — the standard `deleted=FALSE AND is_test=FALSE` live-row filter
  cannot be applied here (columns don't exist). Treat every row as the current CDC state; if you need
  "live" semantics, filter on the joined `campaign_groups` / `private_marketplace_groups` instead.
- **Naming trap:** table/column say "deal" but the FK targets a deal-**group** (see Column meanings).
- **Do NOT use PMP attachment as an MNTN-Select proxy.** 28 PTV (`product_id=1`) groups also attach a
  PMP deal-group — all are **Pause Ads** campaigns (a separate PTV feature that consumes PMP inventory,
  not Select). Filtering "has a PMP attachment" alone over-counts Select by ~10%. To isolate Select,
  join `campaign_groups` and filter `product_id=2` (and exclude test-account advertisers, since the
  group `is_test` flag is unset on some of these).
- **3 orphan rows** point at a `private_marketplace_deal_group_id` with no live `private_marketplace_groups`
  match — use a LEFT JOIN if you need all bridge rows.
- **No history before 2025-07-31** — this is a Select-era table; earlier campaign groups simply have no
  row here.

## Cost & partitioning notes
- **Tiny, non-partitioned CDC dim:** 608 rows, 47,424 bytes physical (`bq show` numBytes). No time
  partition; **clustered by `campaign_group_id`**. There is no partition filter to apply — the whole
  table is a single micro-scan.
- `SELECT *` full scan = **47,424 bytes** (dry-run, all 5 columns) — the entire table; billed at the
  tier-1 minimum (~0.01–0.02 GB). No cost trap. When pulling a single group, filter on the clustered
  `campaign_group_id`.

## Example queries
```sql
-- All campaign groups on PMP inventory, classified by product line
SELECT b.campaign_group_id,
       b.private_marketplace_deal_group_id,
       cg.product_id,          -- 1=PTV(Pause Ads), 2=MNTN Select, 3=QuickFrame
       g.name AS deal_group_name
FROM `core.campaign_group_x_private_marketplace_deals` b
LEFT JOIN `core.private_marketplace_groups` g
       ON g.private_marketplace_group_id = b.private_marketplace_deal_group_id
LEFT JOIN `core.campaign_groups` cg          -- silver campaign_groups view
       ON cg.campaign_group_id = b.campaign_group_id
```
