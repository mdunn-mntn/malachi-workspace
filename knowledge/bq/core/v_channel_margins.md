# core.v_channel_margins

## Purpose
Holds the **global, platform-wide default margin/fee configuration keyed by (ad channel × DSP/bidding partner)** — budget margin, budget padding, partner margin, data margin, platform fee, and target CPM. It is the **top (coarsest) tier of the margin-layering hierarchy**: `v_channel_margins` / `channel_margins` (global per channel×partner) → `advertiser_channel_margins` (per advertiser×channel) → `campaign_group_channel_margins` (per campaign-group override). This `v_`-prefixed object is the **CDC-replicated mirror of a source-Postgres view** and is the **SAFE_CAST variant** of `channel_margins` — it exposes the identical 11 columns over the identical 9-row physical, differing only in lineage (see Gotchas). Reach for it (or its equivalent `channel_margins` / `channel_margins_raw_vw`) when you need the **platform default** margins before any advertiser or campaign-group override. **SENSITIVE: margins/take rates are private — never surface the rate columns in shareable output.**

## Grain & keys
- **Grain:** one row per **(channel_id, partner_id)** pair. Verified live 2026-07-29: **9 rows** total, 9 distinct `channel_margin_id`, 9 distinct (channel_id, partner_id) — all three counts equal, so the natural key is unique and there are no duplicates. This is a **tiny global lookup**, NOT keyed by advertiser or campaign (no `advertiser_id` column).
- **Primary key:** `channel_margin_id` (surrogate; the sole cluster key on the physical).
- **Natural key:** (`channel_id`, `partner_id`) — confirmed unique across all 9 rows.
- **Foreign keys:** `channel_id` → channel enum (no core dim table); `partner_id` → `core.partners.partner_id`.

## Column meanings (only the non-obvious ones)
- `channel_margin_id` — surrogate PK; also the cluster key on the physical `core_channel_margins_raw`.
- `channel_id` — the ad channel this default applies to. **Observed domain (all 9 rows): {1, 3, 4, 7, 8}.** 1 = display, 8 = CTV (workspace-wide channel enum); 3/4/7 are additional/legacy channel ids that survive only in these global defaults. There is **no `core_channels` dimension** to join to — resolve the meaning from the channel enum used across log/summary tables.
- `partner_id` — the **DSP / bidding partner** the default applies to. FK → `core.partners`. **Observed domain: 2 = Trade Desk, 8 = Beeswax, 79 = MNTN Bidder.** The partner axis is load-bearing: the same channel has different margin rows per DSP. Observed pairings (2026-07-29): display (1) on partners {2, 8, 79}; CTV (8) on partners {2, 8, 79}; legacy channels 3/4/7 only on partner 2 (the original Trade Desk defaults). The 9th row (added since 2026-07-19) is display (1) × MNTN Bidder (79).
- `create_time` / `update_time` — TIMESTAMP (UTC) of source-row creation / last change, replicated from the source Postgres row. Use `update_time` for latest-config recency; the partner-2 (Trade Desk) rows are stale originals while the CTV/Beeswax/MNTN-Bidder rows carry the actively maintained config.
- `budget_margin`, `budget_padding`, `partner_margin`, `data_margin` — NUMERIC **rate fractions**. **Stored as a looser type in the raw physical and `SAFE_CAST(... AS NUMERIC)` in the lineage** (see Gotchas) — a malformed raw value coerces to **NULL** rather than erroring. **SENSITIVE — actual values not documented.**
- `platform_fee`, `target_cpm` — `platform_fee` = NUMERIC rate; `target_cpm` = NUMERIC CPM dollar rate. Both are native NUMERIC in the raw physical (no cast). **SENSITIVE — actual values not documented.**

## Joins & relationships
- `partner_id` → **`core.partners`** (dim, PK `partner_id`, 1 row per partner). N:1 — the ≤9 margin rows map to 1 partner each. No fan-out risk (tiny table). `core.partners` further carries `partner_type_id` → `core.partner_types`.
- `channel_id` → channel enum (1 = display, 8 = CTV; also 3/4/7 legacy). No dedicated core dim — use the literal enum.
- **This is a global default, NOT the final applied rate.** When layering margins for a serve it is the platform baseline that is broadcast and then **overridden** by `advertiser_channel_margins` (per advertiser×channel) and `campaign_group_channel_margins` (per campaign group). Do not treat this table's rows as the effective rate — it is the coarsest tier only.
- **Any join *from* a fact table into this 8-row dim is N:1 (safe, no fan-out).**
- Sibling margin objects (same 9-row physical, same 11 columns): **`channel_margins`** (silver — plain `CAST` via a `sqlmesh__core` model) and **`channel_margins_raw_vw`** (silver — `SAFE_CAST`, one hop shorter than this view). Broader margin family: `advertiser_channel_margins`, `campaign_group_channel_margins`, `select_advertiser_margins`, `select_margins`, `ttd_advertiser_channel_margins`, `advertiser_padding_overrides`, `campaign_padding_overrides`, `margin_sources`.

## Gotchas
- **Same physical as `channel_margins`; differs only in lineage/cast.** `v_channel_margins` resolves (see View definition) to the **identical 9-row backing table** `dw-main-bronze.integrationprod.core_channel_margins_raw` as `channel_margins`, but reaches it through the integrationprod `..._raw_vw` chain that applies **`SAFE_CAST`** to the four STRING rate columns, whereas `core.channel_margins` uses a `sqlmesh__core` model with a plain **`CAST`**. Output rows/columns are otherwise identical. Be explicit about which object a query/model references.
- **`SAFE_CAST` null-out.** `budget_margin`, `budget_padding`, `partner_margin`, `data_margin` are STRING in the raw table and `SAFE_CAST`-coerced to NUMERIC — a malformed raw value surfaces as **NULL**, not an error (the `CAST`-based `channel_margins` would instead error).
- **No `datastream_metadata` in this view.** The CDC envelope (`.uuid`, `.source_timestamp`) on the raw physical is projected away by every hop of the chain, so there is **no INT-epoch column here**. The only time columns are the TIMESTAMP `create_time`/`update_time`; front-matter `time_unit: timestamp`.
- **No `deleted` / `is_test` columns** — the standard integrationprod-dimension filter (`deleted=FALSE AND is_test=FALSE`) does **NOT** apply (adding those predicates errors / returns zero). This is a Datastream current-state snapshot; every row is a live config.
- **9 rows — a global default, not per advertiser.** Do not confuse with `advertiser_channel_margins` (5,866 rows, keyed by advertiser×channel). No `advertiser_id` here.
- **Partner axis is load-bearing.** The same channel has different margin rows per DSP; a stale partner-2 (Trade Desk) row and an active partner-79 (MNTN Bidder) row can co-exist for the same channel. Filter/pick by the partner that actually served.
- **SENSITIVE:** the six rate columns (`budget_margin`, `budget_padding`, `partner_margin`, `data_margin`, `platform_fee`, `target_cpm`) are private take-rate data. Never print, sample, or export their values into shareable artifacts.

## Cost & partitioning notes
- **Unpartitioned, tiny global lookup.** Physical backing storage = **1,040 bytes, 9 rows** (`bq show numBytes` on `dw-main-bronze.integrationprod.core_channel_margins_raw`, 2026-07-29; single physical, no UNION). Clustered on `channel_margin_id` (PK point-lookups only).
- **No partition column to filter** — a full scan is negligible; `require_partition_filter=false`, nothing to prune. Non-rate grain columns (`channel_margin_id, channel_id, partner_id, create_time, update_time`) dry-run = **320 bytes upper bound** (2026-07-19). Even so, any read bills the ~10 MB tier-1 minimum.
- When selecting, prefer naming the non-rate columns over `SELECT *` purely to keep the SENSITIVE rate columns out of logs/outputs, not for cost.
