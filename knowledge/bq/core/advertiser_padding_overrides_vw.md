# core.advertiser_padding_overrides_vw

## Purpose
Config/exception table that overrides the default **delivery-pacing padding multiplier** for
specific advertisers. Padding is the pacing headroom factor applied when pacing an advertiser's
delivery (e.g. `1.05` = pace ~5% above the nominal target to absorb win-rate/discrepancy shrinkage).
This view exposes **only the advertisers that need a non-default padding** — everyone not listed
runs on the system default. Reach for it when explaining why one advertiser paces hotter/cooler
than others, or when auditing manual pacing overrides. Currently a single row (advertiser 31966,
padding `1.05`, note `PER-4384`, set 2025-05-09) — an operational one-off, not a bulk table.

The sibling `core.campaign_padding_overrides` does the same at the campaign grain.

## Grain & keys
- **Grain:** one row per `advertiser_id` that has an explicit padding override (sparse/exception table — absence = system default, **not** zero).
- **Primary key:** `advertiser_id` (also the cluster key on the physical). No surrogate id column.
- **Foreign key:** `advertiser_id` → `core.advertisers.id` (1:1).

## Column meanings (only the non-obvious ones)
- **padding** — the pacing padding **multiplier**, a decimal factor (observed `1.05` ≈ +5% pacing headroom; default is applied when an advertiser is absent from this table). Stored as **STRING** in the CDC source and `SAFE_CAST(... AS NUMERIC)` in the view chain, so a non-numeric source value surfaces as **NULL** rather than erroring. Not a margin/take-rate — safe to inspect.
- **notes** — free-text operator annotation; observed value is a ticket reference (`PER-4384`) documenting why the override was set. No schema meaning; audit trail only.
- **create_time / update_time** — native `TIMESTAMP` (UTC), not epoch integers. Equal on insert; `update_time` advances when the override is edited. No epoch-unit ambiguity here (the physical CDC table carries an INT `datastream_metadata.source_timestamp`, but the view does **not** expose it).

## Joins & relationships
- **`advertiser_id` → `core.advertisers.id`** — partner grain is **1 row per advertiser** (1:1). This override table is sparse, so join it as a **LEFT JOIN from advertisers** and `COALESCE(padding, <default>)`; an INNER JOIN silently drops every advertiser without an override (currently all but one). No fan-out risk in either direction (both sides unique on `advertiser_id`).
- **Sibling:** `core.campaign_padding_overrides` (same concept, campaign grain) — do not confuse advertiser-level vs campaign-level overrides.

## Gotchas
- **Not a soft-delete dimension.** This table has **no `deleted` / `is_test` columns** (see AUTO:SCHEMA), so the standard `deleted=FALSE AND is_test=FALSE` core-dim filter does **not** apply — every row is a live override. A removed override is hard-deleted at the Datastream physical (it just vanishes), not flag-toggled.
- **Sparse / exception semantics.** Absence of an advertiser means "use the system default padding," **not** padding = 0. Never treat a missing row as a zero multiplier.
- **`padding` is STRING → NUMERIC via SAFE_CAST.** A malformed source string yields `NULL` in the view (silent), not a query error.
- **Datastream CDC source.** The physical `core_advertiser_padding_overrides` is a Datastream-replicated table (`datastream_metadata` RECORD present on the physical, hidden by the view); rows reflect the current Postgres state, no CDC history retained here.
- **Tiny/volatile row count.** Currently 1 row. Do not build logic assuming a populated table; guard for the empty/near-empty case.

## Cost & partitioning notes
- **Unpartitioned**, clustered by `advertiser_id`; no TTL (config dim). There is nothing to date-filter — the whole table is trivially small.
- `SELECT *` full-view scan dry-run = **40 bytes** (all 5 columns; measured 2026-07-19). Backing physical `core_advertiser_padding_overrides` = **86 bytes / 1 row** (`bq show` numBytes). Any query here bills at the 10 MB minimum — cost is a non-issue; filter on `advertiser_id` only to hit the cluster key when joining large tables.

## Example queries
```sql
-- Attach the padding override to advertisers, defaulting missing ones to 1.0
SELECT a.id AS advertiser_id,
       COALESCE(p.padding, 1.0) AS padding_multiplier,
       p.notes, p.update_time
FROM `dw-main-silver.core.advertisers` a
LEFT JOIN `dw-main-silver.core.advertiser_padding_overrides_vw` p
  ON p.advertiser_id = a.id
WHERE a.id = 31966;
```
