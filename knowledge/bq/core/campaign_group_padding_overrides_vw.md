# core.campaign_group_padding_overrides_vw

## Purpose
Config/exception table that overrides the default **delivery-pacing padding** for specific
**campaign groups** (the primary budget-allocation unit / "flight" equivalent). Padding is the
pacing headroom factor the pacer applies to a campaign group's delivery (e.g. a `1.05` multiplier
= pace ~5% above the nominal target to absorb win-rate/discrepancy shrinkage). This view exposes
**only the campaign groups that need a non-default padding** — every campaign group not listed runs
on the system default. Reach for it when explaining why one campaign group paces hotter/cooler than
others, or when auditing manual pacing overrides. Currently 31 rows, each annotated with a `PER-…`
ticket reference (operational one-offs, not a bulk table).

This is the **campaign-group-grain sibling** of `core.advertiser_padding_overrides_vw` (advertiser
grain) and `core.campaign_padding_overrides` (campaign grain) — same override-exception pattern,
different level of the advertiser → campaign_group → campaign hierarchy.

## Grain & keys
- **Grain:** one row per `campaign_group_id` that has an explicit padding override (sparse/exception table — absence = system default, **not** zero). Verified unique: 31 rows / 31 distinct `campaign_group_id` / 0 NULLs (2026-07-19).
- **Primary key:** `campaign_group_id` (also the cluster key on the physical). No surrogate id column.
- **Foreign key:** `campaign_group_id` → `bronze.integrationprod.campaign_groups.campaign_group_id` (1:1).

## Column meanings (only the non-obvious ones)
- **padding** — the pacing padding **factor**. Stored as **free-text STRING** in the CDC source and `SAFE_CAST(... AS NUMERIC)` in the sqlmesh view chain, so a non-numeric source value would surface as **NULL** rather than erroring (observed: all 31 cast cleanly, 0 NULLs). Observed value set is a **mix of two conventions**: decimal multipliers near 1.0 (`1.01`×8, `1.05`×9, `1.1`×3 — consistent with the advertiser sibling's "1.05 = +5% headroom" convention) **and** bare integers (`1`×1, `5`×10). Do **not** assume every value is a ~1.0 multiplier — the numeric meaning of the integer entries (`1`, `5`) is **not determinable from this table alone**; the pacing consumer defines the unit. Not a margin/take-rate — safe to inspect.
- **notes** — free-text operator annotation; every observed value is a `PER-…` ticket reference (e.g. `PER-2399`, `PER-5959`, and one multi-ticket concatenation `PER-6038 | PER-6070 | …`). No schema meaning; audit trail only. All rows populated (0 NULL).
- **create_time / update_time** — native `TIMESTAMP` (UTC), **not** epoch integers. Equal on insert; `update_time` advances when the override is edited (observed: cg 114732 and the `PER-5959` batch have `update_time > create_time`). No epoch-unit ambiguity here — the view exposes no INT time columns.

## Joins & relationships
- **`campaign_group_id` → `bronze.integrationprod.campaign_groups.campaign_group_id`** — partner grain is **1 row per campaign group** (PK is literally `campaign_group_id`, not `id`, so join on same-named columns). This override table is sparse, so join it as a **LEFT JOIN from `campaign_groups`** and `COALESCE(padding, <default>)`; an INNER JOIN silently drops every campaign group without an override (currently all but 31). No fan-out risk in either direction (both sides unique on `campaign_group_id`). Note the partner `campaign_groups` **does** carry `deleted`/`is_test` — apply `deleted=FALSE AND is_test=FALSE` on that side.
- **Siblings:** `core.advertiser_padding_overrides_vw` (advertiser grain) and `core.campaign_padding_overrides` (campaign grain) — same override concept at different hierarchy levels; do not confuse them.

## Gotchas
- **Padding is STRING-in-source with mixed unit conventions.** The `padding` column holds free-text strings cast to NUMERIC; observed values mix near-1.0 decimals (`1.01`/`1.05`/`1.1`) with bare integers (`1`, `5`). A `5` is **not** obviously "5×" — the pacing consumer, not this table, defines the interpretation. Never treat this column as a guaranteed 1.0-centered multiplier.
- **Not a soft-delete dimension.** This table has **no `deleted` / `is_test` columns** (see AUTO:SCHEMA — only 5 columns), so the standard `deleted=FALSE AND is_test=FALSE` core-dim filter does **not** apply *here*. Every row is a live override; a removed override is hard-deleted at the Datastream physical (it vanishes), not flag-toggled. (The **partner** `campaign_groups` does have those flags — filter there.)
- **Sparse / exception semantics.** Absence of a campaign group means "use the system default padding," **not** padding = 0. Never treat a missing row as a zero factor.
- **`padding` STRING → NUMERIC via SAFE_CAST.** A malformed source string would yield `NULL` in the view (silent), not a query error. Currently none are malformed.
- **Datastream CDC source, metadata hidden by the view.** The physical `core_campaign_group_padding_overrides` is a Datastream-replicated table carrying a `datastream_metadata` RECORD `{uuid, source_timestamp}`; the sqlmesh view **drops** it, exposing only the 5 business columns. `source_timestamp` is CDC-capture epoch (not business time) and is **not** reachable through this view — use `create_time`/`update_time` for timing. Rows reflect current Postgres state; no CDC history retained here.
- **Tiny/volatile row count.** Currently 31 rows. Do not build logic assuming a large populated table; guard for near-empty joins.

## Cost & partitioning notes
- **Unpartitioned** (physical `timePartitioning: None`), clustered by `campaign_group_id`, **no TTL** (config dim). There is nothing to date-filter — the whole table is trivially small.
- `SELECT *` full-view dry-run = **1318 bytes** (all 5 columns; measured 2026-07-19). Backing physical `core_campaign_group_padding_overrides` = **2744 bytes / 31 rows** (`bq show` numBytes). Any query here bills at the 10 MB minimum — cost is a non-issue; filter/join on `campaign_group_id` only to hit the cluster key when joining large tables.

## Example queries
```sql
-- Attach the padding override to campaign groups, defaulting missing ones to 1.0
SELECT cg.campaign_group_id,
       cg.name,
       COALESCE(p.padding, 1.0) AS padding_factor,
       p.notes, p.update_time
FROM `dw-main-bronze.integrationprod.campaign_groups` cg
LEFT JOIN `dw-main-silver.core.campaign_group_padding_overrides_vw` p
  ON p.campaign_group_id = cg.campaign_group_id
WHERE cg.deleted = FALSE AND cg.is_test = FALSE
  AND cg.campaign_group_id = 114732;
```
