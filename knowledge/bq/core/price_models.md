# core.price_models

## Purpose
Lookup dimension of the billing/pricing **model templates** the (legacy SteelHouse) billing
engine uses to turn platform statistics into a dollar charge (or discount) for a campaign.
Each row is a named calculator + formula (e.g. CPM, CPC, Click/View CPA, Revenue Share,
Discount, Platform Agreement, Media pass-through). Reach for it to decode what a campaign's
`price_model_id` means, or to enumerate the supported billing methods. It is a small, static
enum — 18 rows — not an event or fact table.

## Grain & keys
- **Grain:** one row per billing-model template. 18 rows today (`price_model_id` 1–18).
- **Primary key:** `price_model_id` (INT, also the physical cluster key). `name` is effectively distinct.
- **Foreign keys:** none. This dim carries no FK to other tables.

## Column meanings (only the non-obvious ones)
- **price_model_id** — stable integer enum + PK (also the cluster key). Referenced by the
  billing engine / campaign billing config to pick a formula. 1–18 are populated.
- **name** — human display/selection label (CPM, CPC, Fixed Monthly, Click CPA, View CPA,
  Click/View Revenue Share, Discount, Platform Agreement, Media, FB Direct Cost Plus, TradeDesk
  Data, Oracle Data, Facebook Media, …). Effectively unique but not a hard key.
- **calculator_name** — the calculator class the engine instantiates. **Single-valued today:
  all 18 rows = `FormulaPriceModel`** (a spreadsheet-style formula evaluator). Do not assume it varies.
- **calculator_options** — the `=`-prefixed formula(s) the calculator evaluates over
  statistics-feed fields, with runtime placeholders `%PRICE%`, `%DISCOUNT%`, `%TOTAL%`
  substituted from the campaign's billing config (the actual rate is **injected at `%PRICE%`,
  not stored here**). A comma separates multiple outputs (e.g. CPM emits a standard- and a
  control-impression charge). References stat namespaces: `SteelHouseStatistics` (MNTN native),
  `TradeDeskStatistics`, `FacebookStatistics`, `TwitterStatistics`/`TwitterCampaignStatistics`.
  A few rows bake in hard-coded constants (part of the model definition, not a private rate).
  Free text for the engine's evaluator — not SQL; do not parse placeholders as literals.
- **keys** — comma-separated list of the statistics-feed group-by columns the calculator
  aggregates over (Hour, AdvertiserId, CampaignId, CreativeGroupId, CreativeId, plus geo/PMP
  columns for the `Media` model). Defines the roll-up grain of the computed charge.
- **filter** — the predicate template scoping a run to one campaign, e.g.
  `SteelHouseStatistics.CampaignID=?` (`?` bound at runtime). Template, not evaluated SQL.
- **datastream_metadata** — Datastream CDC envelope. `uuid` = per-change id; `source_timestamp`
  = CDC-capture epoch in **MILLISECONDS** (`TIMESTAMP_MILLIS` → 2025-12-19; `TIMESTAMP_MICROS`
  gives 1970, so it is definitively ms). **Not business time** — all 18 rows share
  `1766121478902` (the 2025-12-19 backfill snapshot).

## Joins & relationships
- **No in-warehouse FK.** A scan of `integrationprod.INFORMATION_SCHEMA.COLUMNS` shows
  `price_model_id` exists on **`core_price_models` only** — no other `core_*` CDC dim carries it.
  The campaign→price-model linkage lives in the application/billing layer, not in these silver dims.
- The `keys`/`filter` strings bind the calculator to **external legacy billing statistics feeds**
  (`SteelHouseStatistics`, `TradeDeskStatistics`, `FacebookStatistics`, `TwitterStatistics`).
  Treat these as documentation of the calculator's inputs — they are **not** joinable BQ log tables.
- Because there is no FK partner in-warehouse, this dim carries **no fan-out risk**.

## Gotchas
- **No `deleted` / `is_test` / `create_time` / `update_time` columns** — the standard
  `deleted=FALSE AND is_test=FALSE` dim filter **does not apply** (columns absent). All 18 rows are live.
- **Static seed dim, no business time.** Every row shares `source_timestamp` = 2025-12-19
  (Datastream backfill). You cannot tell when a model was actually created or last changed from this table.
- **`calculator_options` / `filter` are engine formula/predicate strings, not SQL.**
  `%PRICE%`/`%DISCOUNT%`/`%TOTAL%` are runtime placeholders.
- **Row 11 (`FB Direct Cost Plus`) is inconsistent** — `calculator_options` references
  `TradeDeskStatistics.MediaCost` while `filter` references `FacebookStatistics.CampaignId`.
  Apparent legacy artifact; verify against billing before relying on it.
- **These are model TEMPLATES, not private per-advertiser take rates.** Actual advertiser
  margins/rates live in the `*_margins` dims; the `%PRICE%` rate is injected per campaign elsewhere.

- **No partition filter to apply.** Full scan of `SELECT *` = **6,860 bytes** (dry-run,
