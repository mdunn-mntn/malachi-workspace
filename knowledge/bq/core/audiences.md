# core.audiences

## Purpose
Named-audience dimension from the **legacy monolithic `core` Greenplum schema** — one row per configured audience object (its name, owning advertiser, type, and top-level targeting `expression`). A thin silver view over the bronze CDC replica `dw-main-bronze.integrationprod.core_audiences`.

**⚠️ This table is FROZEN.** The latest `update_time` is **2023-12-15** — updates stopped when the standalone audience service (Greenplum `audience` schema) took over. For any current-state audience analysis, use the **live successor `bronze.integrationprod.audience_audiences`** (updated to today) or the segment-level `audience_audience_segments` / `audience_segments`. Reach for `core.audiences` only for pre-2024 historical audience attributes (audience_type, segment_type, geo_segment, opportunity linkage) that the successor table does not carry, and even then cross-check against the live table on shared `audience_id`.

## Grain & keys
- **Grain:** one row per `audience_id` (verified: 79,874 rows = 79,874 distinct `audience_id` — a true unique PK, no dedup needed).
- **Primary key:** `audience_id` (also the physical **cluster key**).
- **Foreign keys:** `advertiser_id` → `advertisers.advertiser_id` (5,176 distinct); `user_id` → `integrationprod.users` (creator); `audience_type_id` → `core_audience_types`; `segment_type_id` → `core_segment_types`; `segmentation_default_id` → `core_segmentation_defaults`; `geo_segment_id` → geo segment dim; `opportunity_id` → sales/CRM opportunity.
- **Shared namespace:** `audience_id` is the same key space as the live `audience_audiences` (both start `create_time` 2011-07-11); 59,240 ids appear in both tables.

## Column meanings (only the non-obvious ones)
- **`audience_type_id`** — FK → `core_audience_types`. Domain (live-decoded): `1`=First Party Audience (47,518), `2`=Third Party Audience (16,719), `3`=Control Group Audience (3), `4`=Extension Audience (15,634).
- **`segment_type_id`** — FK → `core_segment_types` (retargeting/segment preset). 13-value enum: `1`=OPM, `2`=FPA, `3`=Auto Default, `4`=5+ PV, `5`=Cart, `6`=High Intent C, `7`=Ego, `8`=EXT, `9`=High Intent B, `10`=1+ PV, `11`=1+ Conversion, `12`=Control Group Audience, `13`=Ego Campaign Audience. NULL on 12 rows.
- **`segmentation_default_id`** — FK → `core_segmentation_defaults`. `1`=Auto Default, `2`=Cart, `3`=5+ PV, `4`=High Intent C, `5`=Ego, `6`=1+ PV, `7`=1+ Conversion. **NULL on 63,987 of 79,874 rows** — only populated on the retargeting-preset audiences (rows carrying the corresponding non-base `segment_type_id`).
- **`expression`** — STRING targeting definition (JSON leaf-DS blob for prospecting, or OPM text like `UserNumPageViews <= 22` for retargeting). **NULL on 2,231 rows** (audiences with no stored expression). Note: unlike the live `audience_audiences`, this table has **no `expression_type_id`** column to disambiguate OPM vs TPA form.
- **`external_audience_id`** — STRING, **populated on all 79,874 rows** (never NULL). External/DSP-side audience identifier.
- **`opportunity_id`** — sales/CRM opportunity link; populated on 24,214 rows, NULL otherwise.
- **`geo_segment_id`** — geo segment reference; populated on 9,106 rows, NULL otherwise.
- **`auto_append`** — BOOL; TRUE on 2,697 rows (audience auto-appends newly-matching members).
- **`is_test`** — BOOL; TRUE on 847 rows. **The only soft-filter flag — there is NO `deleted` column** on this table (see Gotchas).
- **`create_time` / `update_time`** — business timestamps. `create_time` spans 2011-07-11 onward; **`update_time` maxes at 2023-12-15** (the freeze point).
- **`datastream_metadata`** — STRUCT<uuid STRING, source_timestamp INT64>. `source_timestamp` is the **Datastream CDC-capture epoch in MILLISECONDS** (`TIMESTAMP_MILLIS(source_timestamp)` ≈ 2025-12-19; `TIMESTAMP_MICROS` gives a bogus 1970 → confirms ms). The value is **uniform across every row** (one-time bulk backfill snapshot), so it is NOT a per-row business time — always use `create_time`/`update_time` for event timing.

## Joins & relationships
- **`audience_audiences` (live successor)** on `audience_id` — **1:1** on shared ids (both PK'd on `audience_id`; 59,240 overlap). The successor drops ~20K pre-2024 rows this table still has, and adds 5,254 audiences created after the freeze plus the `expression_type_id` and `is_hidden` columns. Prefer the successor for anything current; use this table for legacy-only attributes.
- **`advertisers`** on `advertiser_id` — **N:1** (many audiences per advertiser). Filter `advertisers.deleted=FALSE AND advertisers.is_test=FALSE` for live advertisers.
- **`core_audience_types`** on `audience_type_id` — **N:1** enum decode (see Column meanings).
- **`core_segment_types`** on `segment_type_id` — **N:1** enum decode.
- **`core_segmentation_defaults`** on `segmentation_default_id` — **N:1** enum decode (only for non-NULL rows).
- **`integrationprod.users`** on `user_id` — **N:1** (audience creator).
- **Fan-out note:** all documented joins are lookup-dim decodes (N:1 into this table's PK or into small enum tables) — no fan-out risk from this table's side. Joining *out* to campaign/segment tables (e.g. `audience_segments`, `campaign_x_audiences`) is 1:N and can fan out; those live-targeting tables — not this frozen one — are the correct source for "which audience was actually targeted" (see data_catalog § "audience.audiences vs audience_segments").

## Gotchas
- **FROZEN table — the #1 gotcha.** No row has `update_time` after **2023-12-15**; the CDC snapshot froze when the audience service split out of the `core` schema. Any analysis that needs 2024+ audiences will silently miss them here. Use `bronze.integrationprod.audience_audiences` (live, updated daily) or `audience_audiences` / `audience_segments` at segment grain.
- **NO `deleted` column.** The standard dimension filter `deleted=FALSE AND is_test=FALSE` cannot be fully applied — only `is_test` exists. Filter `is_test=FALSE` (drops 847 rows); there is no soft-delete flag to exclude, so "live" cannot be inferred from this table alone.
- **Template ≠ what was targeted.** Like the live `audience_audiences`, this is an audience *template/definition* table. `expression` is the buyer's configured selection, not the bidder-evaluated expression; it omits holdout/DS14/retargeting wrapping. Never size funnels or infer actual targeting off this table — use the segment-level tables. (Corollary of data_catalog § "`audience.audiences` is just a template wrapper — don't query it directly for analysis.")
- **No `expression_type_id` here.** The live successor uses `expression_type_id` (1=OPM source, 2=TPA/targeted) to distinguish representations; this frozen table lacks it, so OPM-text vs JSON-TPA expressions can only be told apart by parsing `expression` itself.
- **`datastream_metadata.source_timestamp` is not business time** — it is a uniform millisecond CDC-capture instant (~2025-12-19) from the one-time backfill; use `create_time`/`update_time`.
- **`segmentation_default_id` is mostly NULL** (80% of rows) — treat NULL as "not a retargeting preset," not as missing data.

## Cost & partitioning notes
- **Physical:** `dw-main-bronze.integrationprod.core_audiences` — **unpartitioned** (`timePartitioning: None`), **clustered by `audience_id`**, no TTL. 79,874 rows, **40,931,433 bytes (~39 MB) backing storage** (`bq show` numBytes). This is a small lookup dim — no partition cost trap.
- **The one filter to always apply:** `is_test = FALSE` (there is no `deleted` column). For point lookups, filter/join on `audience_id` to exploit the cluster key.
- **Cost (dry-run measured, labeled by column set):** an 11-aggregate scan over `audience_id, is_test, expression, external_audience_id, opportunity_id, geo_segment_id, auto_append, advertiser_id, create_time, update_time` billed **0.031 GB**. A `COUNT(*)` / single-column scan billed **0.01 GB** (minimum tier). A full `SELECT *` reads ≤ ~39 MB total — cost is negligible regardless.

## Example queries
```sql
-- Legacy audience attributes for a set of audiences (decode the type enums)
SELECT ca.audience_id, ca.advertiser_id, ca.name,
       at.name  AS audience_type,
       st.name  AS segment_type,
       ca.auto_append, ca.create_time, ca.update_time
FROM `dw-main-bronze.integrationprod.core_audiences` ca
LEFT JOIN `dw-main-bronze.integrationprod.core_audience_types` at USING (audience_type_id)
LEFT JOIN `dw-main-bronze.integrationprod.core_segment_types`   st USING (segment_type_id)
WHERE ca.is_test = FALSE
  AND ca.audience_id IN (/* ids */);

-- Which legacy audiences are gone from the live table (frozen after 2023-12-15)
SELECT ca.audience_id, ca.name, ca.update_time
FROM `dw-main-bronze.integrationprod.core_audiences` ca
WHERE ca.is_test = FALSE
  AND NOT EXISTS (
    SELECT 1 FROM `dw-main-bronze.integrationprod.audience_audiences` aa
    WHERE aa.audience_id = ca.audience_id);
```
