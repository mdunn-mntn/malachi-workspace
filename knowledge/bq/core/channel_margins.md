# core.channel_margins

## Purpose
Holds the **global, platform-wide default margin/pricing configuration keyed by (ad channel × DSP/bidding partner)** — the budget margin, budget padding, partner margin, data margin, platform fee, and target CPM that apply as the baseline for a given channel on a given bidding partner. It is the **top of the margin-layering hierarchy** and the coarsest member of the core margin family: `channel_margins` (this — global per channel×partner) → `advertiser_channel_margins` (per advertiser×channel) → `campaign_group_channel_margins` (per campaign-group override). Product/partner-specific variants: `select_advertiser_margins` / `select_margins` (MNTN Select), `ttd_advertiser_channel_margins` (Trade Desk). Reach for it when you need the **platform default** margins before any advertiser or campaign-group override. **SENSITIVE: margins/take rates are private — never surface the rate columns in shareable output.**

## Grain & keys
- **Grain:** one row per **(channel_id, partner_id)** pair. Verified live: 8 rows total, all 8 (channel_id, partner_id) combinations distinct = 8 distinct `channel_margin_id`. This is a **tiny global lookup**, NOT keyed by advertiser or campaign.
- **Primary key:** `channel_margin_id` (surrogate; the sole cluster key).
- **Natural key:** (`channel_id`, `partner_id`) — confirmed unique across all 8 rows.
- **Foreign keys:** `channel_id` → channel enum; `partner_id` → `core.partners.partner_id`.

## Column meanings (only the non-obvious ones)
- `channel_id` — the ad channel this default applies to. **Observed domain (all 8 rows): {1, 3, 4, 7, 8}.** 1 = display, 8 = CTV (workspace-wide channel enum); 3/4/7 are additional/legacy channel ids that survive only in these global defaults (no per-advertiser rows use them today).
- `partner_id` — the **DSP / bidding partner** the default applies to. FK → `core.partners`. **Observed domain: 2 = Trade Desk, 8 = Beeswax, 79 = MNTN Bidder.** The partner axis matters: margins differ by which bidding platform served the impression. Partner-2 (Trade Desk) rows are the original 2020 defaults; partner-8 (Beeswax) and partner-79 (MNTN Bidder, added 2025-12-10) carry the active recent config.
- `create_time` / `update_time` — TIMESTAMP (UTC) of source-row creation / last change, replicated from the source Postgres row. Several rows are stale (partner-2 Trade Desk rows unchanged since 2020); the actively maintained rows are the recent CTV/Beeswax and MNTN-Bidder rows (e.g. one CTV row last updated 2026-07-10).
- `budget_margin`, `budget_padding`, `partner_margin`, `data_margin` — NUMERIC **rate fractions**. **Stored as STRING in the raw physical and CAST to NUMERIC by the silver/SQLMesh view** (see Gotchas). **SENSITIVE — actual values not documented.**
- `platform_fee`, `target_cpm` — `platform_fee` = NUMERIC rate; `target_cpm` = NUMERIC CPM dollar rate. Both are native NUMERIC in the raw physical (not CAST). **SENSITIVE — actual values not documented.**

## Joins & relationships
- `partner_id` → **`core.partners`** (dim, PK `partner_id`, 1 row per partner). N:1 — the ≤8 channel-margin rows map to 1 partner each. No fan-out risk (tiny table).
- `channel_id` → channel enum (1 = display, 8 = CTV; also 3/4/7 legacy); no dedicated core dim needed — use the literal enum.
- **This is a global default, NOT keyed by advertiser.** When layering margins for a serve, it is the platform baseline that is broadcast/cross-joined and then **overridden** by `advertiser_channel_margins` (per advertiser×channel) and `campaign_group_channel_margins` (per campaign group). Do **not** treat this table as the final applied rate — it is the coarsest tier only.
- Sibling margin tables (same `core.*` family): `advertiser_channel_margins`, `campaign_group_channel_margins`, `select_advertiser_margins`, `select_margins`, `ttd_advertiser_channel_margins`, `advertiser_padding_overrides`, `campaign_padding_overrides`, `margin_sources`, and the view variants `v_channel_margins` / `v_advertiser_channel_margins` / `v_campaign_group_channel_margins`. A closely related raw-view sibling `channel_margins_raw_vw` reads the same `core_channel_margins_raw` physical.

## Gotchas
- **NOT a thin passthrough view.** Unlike the advertiser sibling (which is `SELECT * FROM bronze.integrationprod.core_advertiser_channel_margins`), `core.channel_margins` resolves through a **SQLMesh view** (`sqlmesh__core.core__channel_margins__1235741753`) that (a) **CASTs 4 STRING columns to NUMERIC** — `budget_margin`, `budget_padding`, `partner_margin`, `data_margin` are `STRING` in the raw physical `dw-main-bronze.integrationprod.core_channel_margins_raw`; and (b) **drops `datastream_metadata`**. See View definition for the full chain.
- **No `datastream_metadata` in this view** — the CDC envelope (`.uuid`, `.source_timestamp`) exists on the raw physical but is projected away by the SQLMesh view. There is therefore **no INT-epoch column here** (contrast `advertiser_channel_margins`, whose view keeps `datastream_metadata.source_timestamp` in MILLISECONDS). The only time columns are the TIMESTAMP `create_time`/`update_time`; front-matter `time_unit: timestamp`.
- **No `deleted` / `is_test` columns** — the standard integrationprod-dimension filter (`deleted=FALSE AND is_test=FALSE`) does **NOT** apply. This is a Datastream current-state snapshot (each PK appears once; no soft-delete flag). Adding those predicates errors / returns zero rows.
- **8 rows — a global default, not per advertiser.** Do not confuse with `advertiser_channel_margins` (5,866 rows, keyed by advertiser×channel). This table has no `advertiser_id`.
- **Partner axis is load-bearing.** The same channel has different margin rows per DSP; a stale partner-2 (Trade Desk) row and an active partner-79 (MNTN Bidder) row can both exist for the same channel. Filter/pick by the partner that actually served.
- **SENSITIVE:** the six rate columns (`budget_margin`, `budget_padding`, `partner_margin`, `data_margin`, `platform_fee`, `target_cpm`) are private take-rate data. Never print, sample, or export their values into shareable artifacts.

## Cost & partitioning notes
- **Unpartitioned, tiny global lookup.** Physical backing storage = **927 bytes, 8 rows** (`bq show numBytes` on `dw-main-bronze.integrationprod.core_channel_margins_raw`; single physical, no UNION). Clustered on `channel_margin_id` (helps PK point-lookups only).
- **No partition column to filter** — a full scan is negligible. Observed: the 5-non-rate-column grain query (channel_margin_id, channel_id, partner_id, create_time, update_time) billed **0.01 GB** (the 10 MB tier-1 minimum; 0 GB actually processed). Nothing to prune; `require_partition_filter=false`.
- When selecting, prefer naming columns over `SELECT *` purely to keep the SENSITIVE rate columns out of logs/outputs, not for cost.

## Example queries

```sql
WHERE channel_id = 8   -- 8=CTV, 1=display
  AND partner_id = 79  -- 2=Trade Desk, 8=Beeswax, 79=MNTN Bidder
```
