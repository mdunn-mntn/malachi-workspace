# core.currency_codes

## Purpose
Static ISO 4217 currency reference dimension: given a 3-letter currency code, look up its human-readable name and its per-currency billing threshold. Reach for it to decode/label the `currency` (and `display_currency`) codes carried on `advertisers` and the `invoice_*` billing tables. It is a small, unpartitioned lookup dim — not an event or fact table. In practice MNTN bills almost entirely in USD, so this is a labeling/reference table rather than a hot join.

## Grain & keys
- **Grain:** one row per ISO 4217 currency code (167 rows, all distinct — no duplicates).
- **Primary key:** `currency` (STRING, maxLength 3 — e.g. `USD`, `EUR`, `JPY`). Also the sole cluster key.
- **No `deleted` / `is_test` columns** on this dim — the standard `deleted=FALSE AND is_test=FALSE` live-row filter does **not** apply here (nothing to filter; every row is live). Do not add it.

## Column meanings (only the non-obvious ones)
- **`currency`** — ISO 4217 alpha-3 code (schema maxLength 3). The PK / join key. Includes standard fiat codes plus a few non-ISO extras (e.g. `BTC`).
- **`currency_name`** — human-readable ISO 4217 name (`US Dollar`, `Yen`, `Pound Sterling`). **NULL for 6 rows** — newer / crypto / placeholder codes that lack a populated name (e.g. `BTC`, `BYN`). Never rely on it as a key; use `currency`.
- **`billing_threshold`** — a per-currency integer billing threshold **stored as STRING** despite being purely numeric (0 of 167 rows are non-numeric; never NULL). Ad-server billing-config field — the minimum charge/billing amount expressed in that currency's own scale. Sample values: `USD`=5000, `EUR`=4000, `GBP`=4000, `JPY`=557000, `BTC`=2. Values track rough cross-currency equivalence (high-denomination currencies like JPY carry larger integers). **`SAFE_CAST(billing_threshold AS INT64)` before any arithmetic** — it will not compare/aggregate correctly as text.
- **`datastream_metadata`** — STRUCT<`uuid` STRING, `source_timestamp` INT64> stamped by Datastream CDC, **not business time**.
  - `source_timestamp` is **milliseconds** since Unix epoch. Anchor: `TIMESTAMP_MILLIS(1766121518314) = 2025-12-19 05:18:38 UTC` (the same value micro-decoded lands at 1970, confirming ms). **All 167 rows share one identical `source_timestamp`** — a single bulk CDC snapshot, so it is a batch-load marker, *not* a per-row last-updated field. Do not use it to detect which currency changed.
  - `uuid` = Datastream change-event id.

## Joins & relationships
- **`advertisers.currency` / `advertisers.display_currency` = `currency_codes.currency`** — the primary use. `advertisers` grain is one row per advertiser (N advertisers), so joining from the advertiser side is **N advertisers : 1 dim row** (safe lookup, no fan-out). Joining *from* this dim to `advertisers` fans out 1→N.
- **`invoice_*.currency = currency_codes.currency`** — billing/revenue tables carry the same code: `invoice_invoices`, `invoice_campaign_group_revenue`, `invoice_lds_flight_revenue_log`, `invoice_raw_invoices`, `payment_management_vw_qfai_paid_invoices`. All are the many side (many invoice/revenue rows : 1 dim row) — safe as a labeling lookup.
- Any other STRING column holding a 3-letter code (`attr_ga4_properties.currency_code`, `public_advertisers.currency`, `archives_advertiser_archives.currency`) can be decoded against this dim. Cardinality is always many-fact : 1-dim.

## Gotchas
- **`billing_threshold` is STRING, not INT** — cast before math (see Column meanings).
- **`currency_name` is NULL for 6 codes** — coalesce or fall back to `currency` when displaying.
- **`datastream_metadata.source_timestamp` is CDC capture time in ms, uniform across all rows** — never a business/updated timestamp and never per-row; there is no create/update column on this dim at all.
- **No soft-delete / test columns** — do not apply the `deleted=FALSE AND is_test=FALSE` filter; those columns don't exist here.
- Physical is a real base TABLE (not itself a view), unpartitioned — no date filter is possible or needed.

## Cost & partitioning notes
- **Unpartitioned**, clustered on `currency`. Physical `dw-main-bronze.integrationprod.core_currency_codes` — 167 rows, `numBytes` = 11,994 (real backing storage). There is no partition column to filter and none is needed; a full `SELECT * ` reads the whole ~12 KB table.
- Dry-run reference (`SELECT *` full table): **0.01 GB billed (tier-1 minimum, 10 MB floor)** — the table is far below any meaningful scan cost. Filter on `currency` to leverage the cluster key when pulling a single code, but cost is negligible either way.
- Since it's a bronze base table (no SQLMesh), the silver view `core.currency_codes` = `SELECT * FROM dw-main-bronze.integrationprod.core_currency_codes` with no rewrite hash.

## Example queries
```sql
-- Decode a single code (cluster-key filter)
SELECT currency, currency_name, SAFE_CAST(billing_threshold AS INT64) AS billing_threshold
FROM `dw-main-silver.core.currency_codes`
WHERE currency = 'USD';

-- Label advertiser billing currency (fact-side join, no fan-out)
SELECT a.id, a.currency, c.currency_name
FROM `dw-main-silver.core.advertisers` a
LEFT JOIN `dw-main-silver.core.currency_codes` c ON a.currency = c.currency;
```
