# core.advertiser_channel_margins

## Purpose
Holds each advertiser's **default per-channel margin/pricing configuration** — the budget margin, platform fee, data margin, and target/ad-buying CPM applied to that advertiser on a given channel (display vs CTV). It is the advertiser×channel row in the core margin family (siblings: `channel_margins` = global-per-channel defaults, `campaign_group_channel_margins` = the finer campaign-group override, `select_advertiser_margins`/`select_margins`/`ttd_advertiser_channel_margins` = product/partner-specific variants). Reach for it when you need the advertiser-level margin baseline before campaign-group overrides. **SENSITIVE: margins/take rates are private — never surface the rate columns in shareable output.**

## Grain & keys
- **Grain:** one row per **(advertiser_id, channel_id)** pair. Verified live: 5,866 rows = 5,866 distinct `advertiser_channel_margin_id` = 5,866 distinct (advertiser_id, channel_id); 3,170 distinct advertisers (so most advertisers carry a row for one or both channels).
- **Primary key:** `advertiser_channel_margin_id` (surrogate; the sole cluster key).
- **Natural key:** (`advertiser_id`, `channel_id`) — confirmed unique.
- **Foreign keys:** `advertiser_id` → `core.advertisers.advertiser_id`; `channel_id` → channel enum.

## Column meanings (only the non-obvious ones)
- `channel_id` — the ad channel this margin row applies to. **Observed domain: only 1 (display, 2,697 rows) and 8 (CTV, 3,169 rows)** — matches the workspace-wide channel enum (1=display, 8=CTV). An advertiser is not guaranteed to have both channels.
- `create_time` / `update_time` — TIMESTAMP (UTC) of source-row creation / last change, replicated from the source Postgres row. `update_time` is the last-modified time of the config, not the CDC replication time.
- `budget_margin`, `platform_fee`, `data_margin` — NUMERIC(5,4) **rate fractions** (structural cap 9.9999). **SENSITIVE — actual values not documented.**
- `target_cpm`, `ad_buying_cpm` — NUMERIC(7,4) **CPM dollar rates** (structural cap 999.9999). **SENSITIVE — actual values not documented.**
- `datastream_metadata` — Datastream CDC envelope. `.uuid` = the change-event UUID; `.source_timestamp` = INT64 source commit time in **MILLISECONDS** (anchor: `source_timestamp` ≈ `UNIX_MILLIS(update_time)`, verified — e.g. 1784344159541 vs UNIX_MILLIS 1784344159526). Note the unit differs from the TIMESTAMP `create_time`/`update_time`.

## Joins & relationships
- `advertiser_id` → **`core.advertisers`** (dim, PK `advertiser_id`, 1 row per advertiser). This table is **1:N off advertisers** — up to 2 rows per advertiser (one per channel), so `advertisers ⋈ advertiser_channel_margins` **fans out up to 2×**. To keep it 1:1, filter `channel_id = <1 or 8>`.
- `channel_id` → channel enum (display / CTV); no dedicated core dim needed, use the literal enum.
- Sibling margin tables (same `core.*` family, join on `advertiser_id`/`channel_id`): `channel_margins`, `campaign_group_channel_margins`, `select_advertiser_margins`, `select_margins`, `ttd_advertiser_channel_margins`, `margin_sources`, and the view variants `v_advertiser_channel_margins` / `v_channel_margins` / `v_campaign_group_channel_margins`. Effective margin at serve time is layered (advertiser default here → campaign-group override) — do not treat this table as the final applied rate.

## Gotchas
- **No `deleted` / `is_test` columns** — the standard integrationprod-dimension filter (`deleted=FALSE AND is_test=FALSE`) does **NOT** apply here. This is a Datastream-replicated **current-state snapshot** (each PK appears exactly once; no soft-delete flag, no append-only CDC history). Do not add those predicates or a query returns zero rows / errors.
- **SENSITIVE:** the five rate columns (`budget_margin`, `platform_fee`, `data_margin`, `target_cpm`, `ad_buying_cpm`) are private take-rate data. Never print, sample, or export their values into shareable artifacts.
- **Not every advertiser has both channels** (3,170 advertisers → 5,866 rows). Do not assume a display and a CTV row exist for a given advertiser.
- `datastream_metadata.source_timestamp` is MILLISECONDS (INT64), unlike the TIMESTAMP time columns — convert with `TIMESTAMP_MILLIS()`, not `TIMESTAMP_MICROS()`.
- This is only the advertiser-level default margin; the applied rate can be overridden downstream (campaign-group margins) — see Joins.

## Cost & partitioning notes
- **Unpartitioned, tiny lookup dim.** Physical backing storage = 616,092 bytes (~0.6 MB), 5,866 rows (`bq show numBytes`). Clustered on `advertiser_channel_margin_id` (helps PK point-lookups only).
- **No partition column to filter** — a full scan is negligible. Observed: the 4-non-margin-column grain query billed 0.01 GB (the 10 MB tier-1 minimum; 0 GB actually processed). Nothing to prune; `require_partition_filter=false`.
- When selecting, prefer naming columns over `SELECT *` purely to avoid pulling the SENSITIVE rate columns into logs/outputs, not for cost.

## Example queries
```sql
-- advertiser margin config for one channel (keeps join 1:1); rate cols omitted deliberately
SELECT advertiser_channel_margin_id, advertiser_id, channel_id, update_time
FROM `dw-main-silver.core.advertiser_channel_margins`
WHERE channel_id = 8   -- 8=CTV, 1=display
  AND advertiser_id = @advertiser_id
```
