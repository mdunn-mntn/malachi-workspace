# core.private_marketplace_deal_impression_rates_log

## Purpose
Append-only daily log of impression-delivery estimates for private-marketplace (PMP) deals. Each daily
run writes one row per currently-delivering PMP deal with an estimated `avg_daily_impression_rate`, a
`win_rate`-adjusted version, distinct-IP reach, and yesterday's raw inventory count. Reach for it to see
how a specific PMP/partner deal has been sized/paced over time, or to reconstruct the inputs the bidder
used to forecast PMP deal delivery. `silver.core.private_marketplace_deal_impression_rates_log` is a
thin `SELECT *` view over the physical bronze CDC table.

## Grain & keys
- **Grain:** one row per **(partner_deal_id, log_time)** — a per-deal snapshot emitted once per daily
  run. Verified: `COUNT(DISTINCT CONCAT(partner_deal_id, log_time))` = row count = 13,850 (no dupes).
- **Primary key:** `private_marketplace_deal_impression_rate_id` — surrogate, unique per row (13,850
  distinct = 13,850 rows).
- **Join column:** `partner_deal_id` (STRING) → `private_marketplace_deals.partner_deal_id`.
- **Coverage:** 125 distinct deals across 355 distinct `log_time` runs, spanning 2025-08-18 → 2026-07-29.
  Only ~125 of the 1,073 deals in `private_marketplace_deals` ever appear here (the delivering subset),
  and ~77–79 deals per daily run.

## Column meanings (only the non-obvious ones)
- **log_time** — TIMESTAMP (UTC, sub-second precision) of the daily run. Runs land ~17:10 UTC most days;
  it is the business snapshot time and equals `TIMESTAMP_MILLIS(datastream_metadata.source_timestamp)`.
  Because it carries fractional seconds, do NOT filter with a whole-second literal equality
  (`= TIMESTAMP('2026-07-19 17:10:15')` returns 0 rows) — use `DATE(log_time)` or a range.
- **win_rate** — STRING decimal. **Run-level GLOBAL constant, NOT per-deal.** It has been exactly
  `0.1324` for every row across the entire table history (min = max = 0.1324; 1 distinct value per run).
  Treat it as a fixed multiplier the pipeline applies uniformly, not a measured per-deal win rate.
- **avg_daily_impression_rate** — STRING decimal, **per-deal**. Estimated raw average daily impression
  rate for the deal over its data window. **Unbounded — not a probability** (observed range 0.1429 to
  77.0). Cast to FLOAT64/NUMERIC before any math.
- **adj_avg_daily_impression_rate** — STRING decimal, per-deal. The win-rate-adjusted rate:
  `adj_avg_daily_impression_rate = avg_daily_impression_rate × win_rate` holds for **all 13,850 rows**
  (residual < 0.0002). i.e. it is just the raw rate scaled by the global 0.1324 win_rate.
- **days_with_data** — INT. Number of days of data in the averaging window for that deal (mostly 7, but
  1–2 for sparse/new deals). Nearly run-level (1–2 distinct values per run).
- **distinct_ips** — INT, per-deal. Distinct IPs observed for the deal over the window (reach).
- **yesterdays_inventory** — INT, per-deal. Raw impression inventory available for the deal on the prior
  day (the un-averaged one-day figure).
- **datastream_metadata.source_timestamp** — INT64 CDC-capture epoch in **MILLISECONDS**
  (`TIMESTAMP_MILLIS(source_timestamp) = log_time` to the ms; confirmed 1784481015776 → 2026-07-19
  17:10:15). CDC capture time, not a distinct business time here since it equals log_time.
- **datastream_metadata.uuid** — Datastream CDC row identifier.

## Joins & relationships
- **→ `core.private_marketplace_deals`** on `partner_deal_id` (STRING). Partner side is **unique** on
  `partner_deal_id` (1,073 rows = 1,073 distinct partner_deal_id = 1,073 distinct PK), so this log →
  deals is **N:1, no fan-out**; all 125 log deals match (100%). Through the deals dim you reach
  `advertiser_id`, `campaign_group_id`, `partner_id`, `dsp_partner_id`, `floor_price`, `channel_id`
  (8=CTV / 1=display), `private_marketplace_family_id`, `private_marketplace_level_id`, `active`.
  `private_marketplace_deals` has no `deleted`/`is_test` columns — use `active = TRUE` for live deals.
- This log is the **N (many)** side over time: many daily snapshot rows per deal. For a point-in-time
  view pick a single `log_time` / `DATE(log_time)` before joining.

## Gotchas
- **Rate columns are STRING** (`win_rate`, `avg_daily_impression_rate`, `adj_avg_daily_impression_rate`)
  — CAST to FLOAT64/NUMERIC for arithmetic or ORDER BY, else you get lexical sorting.
- **`win_rate` is a single global constant (0.1324), not a per-deal measurement** — do not aggregate or
  interpret it per deal; and `adj_avg_daily_impression_rate` is fully determined by
  `avg_daily_impression_rate × win_rate`, so it carries no independent information beyond that scaling.
- **`avg_daily_impression_rate` is unbounded** (up to 77.0) — never treat it as a 0–1 rate/probability.
- **Append-only log:** no `deleted`, `is_test`, `create_time`, or `update_time` columns; rows are
  historical snapshots and are never soft-deleted. Do not apply the `deleted=FALSE AND is_test=FALSE`
  dimension filter (those columns don't exist here).
- **`log_time` has fractional seconds** — filter on `DATE(log_time)` or a range, not `=` a truncated
  literal.
- **Only the delivering subset of deals appears** (~125 of 1,072); a PMP deal absent from a run had no
  logged rate that day — do not read absence as zero delivery without checking `private_marketplace_deals`.

## Cost & partitioning notes
- **Physical:** real TABLE `dw-main-bronze.integrationprod.core_private_marketplace_deal_impression_rates_log`
  (not a view/UNION chain). **No time or range partitioning.** Clustered by
  `(private_marketplace_deal_impression_rate_id, log_time)`. `numBytes` = 1,848,317 (~1.76 MiB),
  `numRows` = 13,850.
- **The one filter to apply:** there is no partition to prune on, so cost control here is column
  selection, not partition filtering — but the whole table is tiny. Filter `DATE(log_time)` / a
  `log_time` range for a point-in-time slice (the `log_time` cluster key helps range scans marginally).
- **Cost (labeled):** `SELECT *` full scan = 1,848,317 bytes (~1.76 MiB, ~0.0017 GB) — the entire table. At this size partition/cluster pruning is immaterial; even a full scan
  is well under 0.01 GB billed.

## Example queries
```sql
-- latest snapshot per PMP deal with its advertiser/campaign_group context
WITH latest AS (
  SELECT * EXCEPT(rn) FROM (
    SELECT r.*, ROW_NUMBER() OVER (PARTITION BY partner_deal_id ORDER BY log_time DESC) rn
    FROM `dw-main-silver.core.private_marketplace_deal_impression_rates_log` r
  ) WHERE rn = 1
)
SELECT l.partner_deal_id, d.name, d.advertiser_id, d.campaign_group_id, d.channel_id,
       CAST(l.avg_daily_impression_rate AS FLOAT64) AS avg_daily_rate,
       CAST(l.adj_avg_daily_impression_rate AS FLOAT64) AS adj_daily_rate,
       l.distinct_ips, l.yesterdays_inventory, l.days_with_data, l.log_time
FROM latest l
JOIN `dw-main-silver.core.private_marketplace_deals` d USING (partner_deal_id)
ORDER BY adj_daily_rate DESC;
```
