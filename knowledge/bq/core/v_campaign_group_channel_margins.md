# core.v_campaign_group_channel_margins

## Purpose
Small dimension holding the **margin / pricing configuration** for a campaign group on a specific
channel — the budget margin, platform fee, target CPM, ad-buying CPM, and data margin MNTN applies
when pricing that campaign group's delivery. Reach for it to answer "what margin/CPM config is set
for this campaign group on CTV vs display?" It is a **per-campaign-group override** table: a row exists
only where a campaign group has an explicit channel-level margin config (624 rows across 130
advertisers). Where no row exists, application logic falls back to channel-level defaults in
`core.channel_margins` — **this view does NOT perform that fallback** (see Gotchas).

> **SENSITIVE — take rates / margins are private.** Document schema, grain, keys only. Do **not**
> sample, print, or share actual `budget_margin` / `platform_fee` / `target_cpm` / `data_margin` /
> `ad_buying_cpm` values or any example row containing them.

## Grain & keys
- **Grain:** one row per **(campaign_group_id, channel_id)** margin override. Verified 2026-07-29: 624
  rows, 624 distinct (cg, channel) combos, 612 distinct campaign_groups (a campaign group may hold up to
  2 rows — one per channel; 12 groups carry both), 130 distinct advertisers.
- **Primary key:** `campaign_group_channel_margin_id` (surrogate; 624/624 distinct — unique). It is the
  clustering key on the physical base table.
- **Join / foreign keys:** `advertiser_id`, `campaign_group_id`, `channel_id`, `margin_source_id`.

## Column meanings (only the non-obvious ones)
- `campaign_group_channel_margin_id` — surrogate PK; also the clustering column on the base physical.
- `channel_id` — which channel this margin config applies to. Domain observed (2026-07-29): **8 = CTV**
  (612 rows), **1 = display** (12 rows). Matches the org-wide `channel_id` convention (8=CTV / 1=display).
  Config is overwhelmingly CTV today.
- `margin_source_id` — FK to `core.margin_sources` naming the system/source that set the margin.
  Domain: **1 = DTR, 2 = MSS**. Every current row uses `margin_source_id = 2` (MSS).
- `create_time` / `update_time` — native `TIMESTAMP` business times (row created / last updated), **not**
  epoch integers, so no unit ambiguity. Both non-NULL across all rows. The CDC-capture timestamp lives
  in `datastream_metadata` on the base table, which this view **drops** (see Gotchas).
- `budget_margin`, `platform_fee`, `target_cpm`, `data_margin`, `ad_buying_cpm` — `NUMERIC` pricing/margin
  fields (the budget margin, platform fee, target CPM, data-cost margin, and ad-buying CPM applied to
  the campaign group on this channel). **SENSITIVE — values private; do not reproduce.**

## Joins & relationships
This is the join *fact-of-record* for a campaign group's channel margin; it points outward to four dims:
- `advertiser_id` → `core.advertisers` (PK `advertiser_id`, 1 row/advertiser). This side is **N:1** (many
  margin rows per advertiser) — safe, no fan-out. Join to `advertisers.company_name` for a label
  (`fpa_advertiser_verticals.advertiser_name` is unreliable per data_knowledge).
- `campaign_group_id` → `core.campaign_groups` (PK `campaign_group_id`, 1 row/group). **N:1** from this
  view — safe. Reverse direction (campaign_groups → margins) is **1:N**: a campaign group can have up to
  2 rows here (one per channel), so filter/scope by `channel_id` to avoid double-counting a group.
- `channel_id` → channel dim (8=CTV / 1=display). N:1, safe.
- `margin_source_id` → `core.margin_sources` (PK `margin_source_id`, 2 rows: DTR/MSS). N:1, safe.
- **Sibling tables:** `core.campaign_group_channel_margins` is the *base* table — identical rows plus a
  `datastream_metadata` column this view omits. `core.channel_margins` holds channel-level **default**
  margins (per `channel_id`, with `partner_id`/`partner_margin`) used as a fallback when no per-group
  override row exists here.

## Gotchas
- **`v_` prefix is misleading.** Despite the view-name convention, in BQ this resolves (via
  `integrationprod.core_v_campaign_group_channel_margins` → SQLMesh physical → base table) to a **pure
  column projection** of `core_campaign_group_channel_margins` — it does **NOT** coalesce with
  `channel_margins` defaults. A campaign group with no row here has no margin in this view; the
  channel-default fallback happens in application logic, not in this view.
- **No `deleted` / `is_test` columns.** The standard `deleted=FALSE AND is_test=FALSE` dimension filter
  does **not** apply — there is no soft-delete flag to filter on. All 624 rows are live as far as this
  table exposes.
- **CDC capture time is stripped.** `datastream_metadata` (source_timestamp) exists on the base
  `core.campaign_group_channel_margins` but not on this view. For CDC ordering use the base table; for
  business time use `create_time` / `update_time` here.
- **SENSITIVE.** Margin/CPM/fee values are private — never sample rows or export values.
- Skewed domains: essentially CTV-only (2 display rows) and MSS-only (`margin_source_id=2`) today — do
  not assume even coverage across channels or sources.

## Cost & partitioning notes
- **No partition** (624-row dimension). Physical base `TABLE` is clustered on
  `campaign_group_channel_margin_id`. TTL: none.
- Trivial to scan: `SELECT *` over the full view is ~65 KB (dry-run, all 12 columns).
  Backing storage `numBytes` = 92,880 bytes (~91 KB, 2026-07-29). No date filter needed — there is no
  partition and the table is tiny.
- For point lookups, filter/cluster-prune on `campaign_group_channel_margin_id` (PK/cluster col), or
  filter `campaign_group_id` / `advertiser_id` for a group's or advertiser's config.

## Example queries
```sql
-- Margin config for one campaign group, both channels (schema/keys only — do not export rate values)
SELECT campaign_group_id, channel_id, margin_source_id, create_time, update_time
FROM `core.v_campaign_group_channel_margins`
WHERE campaign_group_id = @cg_id;

-- Count of override rows per advertiser (no rate values exposed)
SELECT advertiser_id, COUNT(*) AS n_channel_margins
FROM `core.v_campaign_group_channel_margins`
GROUP BY advertiser_id ORDER BY n_channel_margins DESC;
```
