# core.select_margins

## Purpose
Thin silver view (`SELECT *`) over the CDC dimension `bronze.integrationprod.core_select_margins` — the
**global default pricing-margin config for MNTN Select**. Holds the three Select take-rate levers
(`budget_margin`, `data_margin`, `platform_fee`) applied as defaults, tagged with which source set them
(`margin_source_id`). Reach for it when you need the default Select margin/fee config; reach for its sibling
`core.select_advertiser_margins` for **per-advertiser** Select overrides.

**SENSITIVE.** Margin/fee columns are private take-rate data. Document schema/grain/keys only — never sample,
print, or reproduce the actual margin/fee VALUES. Shareable cost work uses media/data_spend lenses only
(see `feedback_take_rates_sensitive`).

## Grain & keys
- **Grain:** one row per Select margin config, keyed by `select_margin_id`. This is a **config/reference dim**,
  not a per-advertiser or time-series table — the physical currently holds a **single global default row**
  (bq show numRows=1). Do NOT expect one row per advertiser here (that's `select_advertiser_margins`).
- **Primary key:** `select_margin_id` (also the sole clustering key on the physical).
- **Foreign keys:** `margin_source_id` → `core.margin_sources.margin_source_id` (N:1);
  `margin_reason_id` → `core.margin_reasons.margin_reason_id` (N:1, nullable — NULL on current row).

## Column meanings (only the non-obvious ones)
- **`budget_margin`, `data_margin`, `platform_fee`** (NUMERIC) — the three Select pricing/take-rate levers:
  margin taken on media budget, margin taken on data cost, and the platform-fee component, respectively.
  **SENSITIVE — do not print or reproduce these values or any row containing them.**
- **`margin_source_id`** (INT) — FK identifying which source set this config. Live domain (from
  `core.margin_sources`, 2-row lookup): **`1 = DTR`, `2 = MSS`**. (The single current default row uses `2 / MSS`.)
- **`create_time` / `update_time`** (TIMESTAMP) — business audit times (row created / last updated). These are the
  real business time columns; the current row's `update_time` matches its CDC capture time exactly.
- **`datastream_metadata.source_timestamp`** (INT64) — Datastream **CDC-capture epoch in MILLISECONDS**
  (verified: raw `1779235213724` → `TIMESTAMP_MILLIS` = `2026-05-20 00:00:13` = `UNIX_MILLIS(update_time)`;
  `TIMESTAMP_MICROS` yields 1970 = wrong). This is capture time, **not** business time — prefer `update_time`.
  `datastream_metadata.uuid` (STRING) = the Datastream CDC row uuid.
- **`user_id`** (INT64, nullable) — audit id of the user who set/last-changed this margin config. **NULL on the
  current default row** (verified 2026-07-29); do not assume populated.
- **`margin_reason_id`** (INT64, nullable) — FK → `core.margin_reasons.margin_reason_id` (the reason/justification
  enum for why this margin config was set). **NULL on the current default row** (verified 2026-07-29).

## Joins & relationships
- **`margin_source_id` → `core.margin_sources.margin_source_id`** — N:1 lookup; partner is a 2-row enum
  (`1=DTR`, `2=MSS`). No fan-out risk.
- **Sibling: `core.select_advertiser_margins`** — the **per-advertiser** counterpart (carries `advertiser_id`
  + the same `budget_margin`/`data_margin`/`platform_fee` columns, but **no** `margin_source_id`). Conceptual
  relationship: this table = the global Select default; `select_advertiser_margins` = advertiser-specific
  overrides (join that table's `advertiser_id` → `core.advertisers.id` for names). There is no direct join key
  between the two margin tables — `select_margins` has no `advertiser_id`.
- Both margin tables are tiny CDC dims (1 row each currently) — no fan-out concerns from either.

## Gotchas
- **Single-row config, not per-advertiser.** The physical has exactly 1 row (a global default). Anyone expecting
  advertiser-level Select pricing here is in the wrong table — use `core.select_advertiser_margins`.
- **No `deleted` / `is_test` columns exist** — the standard `deleted=FALSE AND is_test=FALSE` live-row filter
  for core dims does **not** apply here (those columns are absent). Every row is a live config row.
- **SENSITIVE take-rate values.** `budget_margin` / `data_margin` / `platform_fee` are private. Do not print,
  export, or paste rows containing them into shareable artifacts. (`feedback_take_rates_sensitive`.)
- **`datastream_metadata.source_timestamp` is CDC-capture time in ms**, not business time; use `create_time` /
  `update_time` for when the config was set/changed.

## Cost & partitioning notes
- **No partition** (physical `timePartitioning=null`, `require_partition_filter=null`), clustered on
  `select_margin_id`. The silver view is a plain `SELECT *` over a **126-byte / 1-row** physical, so there is no
  partition column to filter and no cost trap — clustering is irrelevant at this size.
- **The "always apply" filter is N/A** (single-row config). Just select the columns you actually need.
- **Measured cost:** each of the two probe queries above (reading all columns of this 1-row table and the 2-row
  `margin_sources`) billed the **tier-1 minimum ~0.01 GB / 0s slot** — i.e. any query here costs the BQ floor.
  `approx_logical_bytes = 126` from `bq show numBytes` on the physical (real backing storage, not a column estimate).

## Example queries
```sql
-- Default Select margin config joined to its source label (SENSITIVE: keep margin cols internal-only)
SELECT sm.select_margin_id, ms.name AS margin_source, sm.create_time, sm.update_time
       -- , sm.budget_margin, sm.data_margin, sm.platform_fee  -- private take-rate values
FROM `dw-main-silver.core.select_margins` sm
LEFT JOIN `dw-main-silver.core.margin_sources` ms USING (margin_source_id);
-- No partition/date filter needed: 1-row config table.
```
