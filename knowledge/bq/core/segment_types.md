# core.segment_types

## Purpose
Static enum/lookup dimension that names the **audience segment types** MNTN uses (13 rows, IDs 1-13).
It is the decode table for `segment_type_id` carried on `core_audiences`: given an audience's
`segment_type_id`, this table supplies the human `name` (e.g. `Cart`, `High Intent B`, `Ego`,
`Control Group Audience`). Thin silver view over the bronze CDC dimension
`dw-main-bronze.integrationprod.core_segment_types` (no SQLMesh).

## Grain & keys
- **Grain:** one row per audience segment type — 13 rows total, `segment_type_id` 1 through 13.
- **Primary key:** `segment_type_id` (also the sole cluster key on the physical).
- **Foreign key (out):** `segmentation_default_id` → `core_segmentation_defaults.segmentation_default_id` (nullable).

## Joins & relationships
- **`core_audiences`.segment_type_id → `segment_types`.segment_type_id** (many-to-one; **audiences fan out**). This is the primary consumer: join FROM `audiences` TO this dim to attach the type `name`. The N:1 direction (audiences → segment_types) is the safe, fan-out-free direction — one type row per audience. Reverse direction (segment_types → audiences) fans out to many audiences per type.
- **`segment_types`.segmentation_default_id → `core_segmentation_defaults`.segmentation_default_id** (many-to-one; partner is a **7-row** dim, trivial fan-out). Enriches a segment type with its default segmentation expression; only the 7 rows with a non-null `segmentation_default_id` join.
- `core_audiences` also carries its own `segmentation_default_id` and `audience_type_id` — do not confuse `audience_type_id` (a different enum) with `segment_type_id`.

## Gotchas
- **No `deleted` / `is_test` columns exist** on this dim, so the standard `deleted=FALSE AND is_test=FALSE` live-row filter is N/A — treat all 13 rows as live. It is a static config enum, not a soft-deleting table.
- **`datastream_metadata.source_timestamp` is milliseconds and is a load-time constant** across every row (see column meanings) — it is CDC-capture metadata, not business time. Use `create_time`.
- **Frozen table:** last row created 2023-01-13; no partition or freshness concerns. Any new segment type would appear as a new low-cardinality `segment_type_id`.
- `name` is user-facing free text (mixed case, spaces, abbreviations like `5+ PV`) — match on `segment_type_id`, not `name`, in joins.

## Example queries
```sql
-- Decode segment_type_id on audiences (safe N:1 direction; audiences is the fanned-out side)
SELECT a.audience_id, a.segment_type_id, st.name AS segment_type_name
FROM `dw-main-silver`.core.audiences AS a
LEFT JOIN `dw-main-silver`.core.segment_types AS st USING (segment_type_id);

FROM `dw-main-silver`.core.segment_types
ORDER BY segment_type_id;
```
