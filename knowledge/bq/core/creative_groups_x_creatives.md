# core.creative_groups_x_creatives

## Purpose
Junction/bridge table that resolves the many-to-many-shaped link between **creative groups** and **creatives** — i.e. which creatives are members of which creative group. It is the middle node of the creative-setup chain: `advertisers → campaign_groups → campaigns → creative_groups → creative_groups_x_creatives → creatives`. Reach for it whenever you need to expand a creative group into its member creatives (or find which group a creative belongs to). It also carries a handful of rarely-used per-mapping URL/tracking override columns.

## Grain & keys
- **Grain:** one row per `(group_id, creative_id)` creative-to-group mapping. Verified: 5,680,119 total rows == 5,680,119 distinct `(group_id, creative_id)` pairs, zero NULL keys — the pair is a clean composite primary key (no dupes).
- **Key(s) / join columns:** composite PK `(group_id, creative_id)`. `group_id` → `core.creative_groups`; `creative_id` → `core.creatives`. Both are the clustering keys of the physical table.

## Column meanings (only the non-obvious ones)
- **group_id** — FK to `core.creative_groups.group_id` (the creative group). Physical clustering key #1.
- **creative_id** — FK to `core.creatives.creative_id` (the creative). Physical clustering key #2.
- **active** — soft-delete/soft-active flag for the mapping. 5,679,840 TRUE / 279 FALSE / 0 NULL. This table has **no `deleted` / `is_test` columns**, so `active=FALSE` is the soft-delete equivalent — filter `active=TRUE` for live mappings (only 279 rows are inactive).
- **click_url** — optional per-mapping click-through URL override for this creative within this group. ~99.98% NULL (5,678,931 NULL + 289 empty-string; only ~900 rows carry a real override). The authoritative click URL lives on the creative itself — this column is a rare exception, not the source of truth.
- **url_prefix / url_suffix** — optional strings prepended/appended to the click/landing URL for this mapping. ~99.9% NULL (5,676,772 / 5,676,012 NULL).
- **dpp_id** — dynamic-product-placement/feed identifier for the mapping (STRING). Essentially unused — only 36 non-NULL rows, 0 empty-string.
- **impression_tracking** — optional per-mapping impression-tracking pixel/URL override. ~99.94% NULL (5,676,825 NULL; ~3,294 populated).
- **dpp_filter** — STRING. **100% NULL across all 5,680,119 rows — dead/unused column.**
- **user_id** — INT64. **100% NULL across all rows (0 distinct values) — dead/unused column** (likely an audit "who created the link" field the CDC source never populates).
- **datastream_metadata.source_timestamp** — Datastream **CDC capture** epoch in **UNIX MILLISECONDS** (empirically confirmed: `TIMESTAMP_MILLIS(source_timestamp)` → 2026-07-20, matching the physical table's ms `creationTime`; interpreting as MICROS wrongly yields 1970). It is **not** business create/update time — this table has no `create_time`/`update_time`, so `source_timestamp` is the only timestamp, and it should be read as "last CDC touch," not when the mapping was made.

## Joins & relationships
- **`group_id` → `core.creative_groups` (PK `group_id`, 945,751 rows, 1 row/group).** This bridge holds **N rows per group** — avg 6.05 creatives/group; 938,843 of 945,751 groups appear here (the rest have no creatives). **Joining `creative_groups` → this bridge FANS OUT ~6x.** `creative_groups.group_id` in turn links to `campaigns` (campaign_id).
- **`creative_id` → `core.creatives` (PK `creative_id`, 5,722,718 rows, 1 row/creative).** avg_groups_per_creative = 1.0 → each creative maps to ~1 group, so **bridge → `creatives` is effectively 1:1 (no fan-out).** 42,731 creatives (5,722,718 − 5,679,987) are not members of any group. `creatives.creative_id` links to `advertisers` (advertiser_id).
- **Full chain:** `advertisers → campaign_groups → campaigns → creative_groups → creative_groups_x_creatives → creatives`. Use this table to expand a group to its member creatives or to attribute a creative up to its group/campaign.

## Gotchas
- **No `deleted`/`is_test` columns** — the standard `deleted=FALSE AND is_test=FALSE` dimension filter does not apply here. Use `active=TRUE` for live mappings (only 279 rows are FALSE).
- **Most attribute columns are empty overrides.** `click_url`, `url_prefix`, `url_suffix`, `impression_tracking`, `dpp_id` are NULL for ~99.9%+ of rows; `dpp_filter` and `user_id` are **100% NULL (dead columns)**. Do not treat this table as the source of a creative's click URL/tracking — those live on `core.creatives`; this table only carries rare per-group overrides.
- **`source_timestamp` is CDC-capture (ms), not row create/update time.** There is no `create_time`/`update_time`. Don't use it to date when a mapping was created.
- **Grain is exactly one row per `(group_id, creative_id)`** — safe to treat the pair as a composite PK; no de-dup needed.
- **Joining from `creative_groups` fans out ~6x** — aggregate/COUNT accordingly; the `creatives` side does not fan out.

## Cost & partitioning notes
- **Unpartitioned physical TABLE** (`timePartitioning: None`) — there is no partition column and no date filter is possible; every query full-scans. Cheap because the table is tiny.
- **Real backing storage (numBytes):** 359,957,000 bytes (~343 MiB).
- **Dry-run, labeled by column set:** `SELECT *` (all 11 columns) = 359,957,000 bytes (~0.34 GiB, equals numBytes); `SELECT group_id, creative_id` (2 clustering cols) = 90,881,904 bytes (~0.087 GiB). `SELECT *` is ~4x the 2-column scan — **prune to the columns you need**.
- **Clustered on `(group_id, creative_id)`** — filter/join on `group_id` (then `creative_id`) to leverage clustering. No TTL (it's a dimension).

## Example queries
```sql
-- Expand a creative group into its live member creatives
SELECT x.group_id, x.creative_id
FROM `dw-main-silver.core.creative_groups_x_creatives` x
WHERE x.group_id = @group_id
  AND x.active;

-- Count creatives per group (bridge fans out ~6x from creative_groups)
SELECT group_id, COUNT(*) AS n_creatives
FROM `dw-main-silver.core.creative_groups_x_creatives`
WHERE active
GROUP BY group_id;
```
