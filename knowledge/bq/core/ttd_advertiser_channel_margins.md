# core.ttd_advertiser_channel_margins

## Purpose
Holds the per-advertiser, per-channel **budget margin** applied for **TTD (The Trade Desk)** buying.
Thin silver VIEW (`SELECT *`) over the Postgres-CDC replica
`dw-main-bronze.integrationprod.core_ttd_advertiser_channel_margins` (no SQLMesh). This is a small
config/lookup dimension — 71 rows — not an event or fact table. Reach for it only when you need the
margin config that was in force for a TTD advertiser+channel; **it is legacy/frozen** (last
`update_time` is May 2022 — see Gotchas). **SENSITIVE:** `budget_margin` is a private take-rate value;
document schema/grain/keys only, never reproduce example rows or margin values.

## Grain & keys
- **Grain:** one row per **(advertiser_id, channel_id)** TTD margin config. Verified unique — 71 rows =
  71 distinct `advertiser_channel_margin_id` = 71 distinct (advertiser_id, channel_id) combos. 58
  distinct advertisers (some carry a row for both channels).
- **Primary key:** `advertiser_channel_margin_id` (also the cluster key on the physical table).
- **Foreign keys:** `advertiser_id` → `core.advertisers.advertiser_id`; `channel_id` →
  `core.channels.channel_id`.
- **No `deleted` / `is_test` columns exist** on this dim, so the standard
  `deleted=FALSE AND is_test=FALSE` live-row filter does **not** apply here — all 71 rows are live.

## Column meanings (only the non-obvious ones)
- **`budget_margin`** (NUMERIC) — the TTD budget margin / take-rate for this advertiser+channel.
  **SENSITIVE — private take-rate value; do not print or sample.** Always populated (0 NULLs across all
  71 rows). Not a percentage-vs-decimal call documented here on purpose (would require sampling values).
- **`channel_id`** (INT64) — FK to `core.channels`. Domain present in this table is just **{1, 8}**
  (a 2-value subset of the 10-value `channels` enum): `1 = Multi-Touch (display/web)`,
  `8 = Television (CTV)`. No Email/In-App/etc. rows exist here.
- **`create_time` / `update_time`** (TIMESTAMP) — native business timestamps for the config row. Range
  observed: min `create_time` 2020-03-03, max `update_time` 2022-05-06 — this dim is effectively frozen
  (see Gotchas). Prefer these over the CDC capture time for any "when did the config change" question.
- **`datastream_metadata`** (STRUCT<uuid STRING, source_timestamp INT64>) — Datastream CDC-capture
  metadata, **not business time**. `source_timestamp` is epoch **MILLISECONDS**
  (`TIMESTAMP_MILLIS(1766121466991)` = 2025-12-19; MICROS/SECONDS give nonsense dates). All 71 rows
  share the **same** `source_timestamp` → the table was populated in a single CDC snapshot/backfill, not
  streamed incrementally. Never use `source_timestamp` as a business event time.

## Joins & relationships
- **`advertiser_id` → `core.advertisers` (`advertiser_id`)** — partner grain 1 row/advertiser; this side
  is the many side (up to 2 rows/advertiser, one per channel). Joining advertisers → this table fans out
  1:N (≤2). No fan-out risk joining this table → advertisers (N:1).
- **`channel_id` → `core.channels` (`channel_id`)** — tiny 10-row enum, strict N:1, no fan-out.
- This is a config dim: joining it to any impression/spend fact keyed on (advertiser, channel) is N:1
  from the fact side and safe. It does **not** itself reference any event/fact table.

## Gotchas
- **Legacy / frozen:** no `update_time` newer than **2022-05-06**. Treat as historical TTD config, not a
  live margin source. Do not assume it reflects current billing. Related live margin config lives in the
  sibling `core.*margin*` views (`advertiser_channel_margins`, `channel_margins`,
  `campaign_group_channel_margins`, `select_margins`, `select_advertiser_margins`, and their `v_*`
  variants) — this `ttd_`-prefixed one is TTD-integration-specific.
- **SENSITIVE take-rate:** `budget_margin` values are private. Never print, sample, or paste example rows
  containing it (this doc was enriched from schema + aggregate counts only — no rows read).
- **No soft-delete columns** — `deleted`/`is_test` do not exist; do not add that filter (it would error).
- **CDC snapshot artifact:** all rows carry one identical `datastream_metadata.source_timestamp`
  (2025-12-19) — a backfill artifact, not a real per-row capture time.

## Cost & partitioning notes
- **No partition, no partition filter required.** Physical `dw-main-bronze.integrationprod.core_ttd_advertiser_channel_margins`
  is a 71-row / **7,242-byte** unpartitioned TABLE, clustered by `advertiser_channel_margin_id`. There is
  no date column to filter and no scan cost trap — a full `SELECT` of the non-sensitive columns
  dry-runs/bills in the sub-10 MB tier-1 floor (measured: 0 GB processed / 0.01 GB billed on the
  aggregate query used to enrich this doc — a `MIN/MAX/COUNT` over `create_time`, `update_time`,
  `source_timestamp`, and the id columns; `budget_margin` deliberately excluded).
- The **one filter to always apply** is `channel_id` when you only care about display (1) or CTV (8) —
  it's the only column with a meaningful sub-domain here — but at 71 rows it changes cost nothing; it's a
  correctness filter, not a cost filter.
- `approx_logical_bytes` = 7242 (physical `numBytes`, whole table). Not a single-column figure.
