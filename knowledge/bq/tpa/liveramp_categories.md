# tpa.liveramp_categories

## Purpose
The **LiveRamp third-party audience taxonomy** — the full hierarchical tree of buyable 3P audience
categories (name, human path, ancestor path, CPM pricing, deprecation flag). Reach for it to resolve a
LiveRamp `data_source_category_id` to its name / path / price, to browse the category hierarchy, or to
enumerate available 3P segments. It is a **versioned import table**: the same category recurs once per
import batch (`import_timestamp`), so the table accumulates history — take the **latest `import_timestamp`
per `data_source_category_id`** for the current state. As of 2026-07-29: **734,339 rows across ~862 import
batches (2022-03-30 → 2026-07-27), ~429,276 distinct category IDs.**

Distinguish from two siblings: `tpa.categories` is the multi-source category table (data_source_id 35 =
LiveRamp current, 11 = LiveRamp legacy); `tpa.liveramp_categories_advertiser_mapping` maps custom LiveRamp
categories to the advertisers entitled to them. This table is the LiveRamp-specific taxonomy + pricing.

## Grain & keys
- **Grain:** one row per LiveRamp category **per import batch**. `data_source_category_id` is **NOT unique** (734,339 rows / 429,276 distinct IDs) — a category reappears each time LiveRamp re-imports it, with possibly-updated details (name, deprecated, cpm). `(data_source_category_id, import_timestamp)` narrows it (656,781 distinct pairs) but still is not fully unique (some categories land twice in one batch).
- **Natural key of the current view:** `data_source_category_id` **after** deduping to the latest `import_timestamp`.
- **Join column:** `data_source_category_id` → `tpa.categories.data_source_category_id` (with `data_source_id=35` for the LiveRamp current name) and → `tpa.liveramp_categories_advertiser_mapping.data_source_category_id`.
- **`parent_id`** is a self-reference to another `data_source_category_id` (the parent node in the tree).

## Column meanings (only the non-obvious ones)
- **`data_source_category_id`** — the LiveRamp category ID. Not unique across rows (versioned by import — see Grain).
- **`name`** — the category's leaf/relative name path, e.g. `TV > Automotive Dealerships > BMW > Recent` or `Arts & Entertainment > Comics & Animation`.
- **`names`** — JSON of the full breadcrumb of names, e.g. `{"names": ["ROOT", "ShareThis", "Arts & Entertainment > Comics & Animation"]}` — includes ROOT and the data-provider node.
- **`path`** — full human-readable path including the provider, e.g. `ShareThis for TV > Arts & Entertainment > Comics & Animation`.
- **`path_from_root`** — JSON array of **ancestor category IDs** from the root, e.g. `{"pathFromRoot": [0, 127, 1009050921]}`. Use with `parent_id` to walk the tree.
- **`parent_id`** — the parent node's `data_source_category_id` (self-reference).
- **`partner_id`** — the LiveRamp data-provider/partner ID (e.g. 127). Often equals the second element of `path_from_root` (the provider node).
- **`description`** — free-text marketing description of the segment/provider (e.g. the ShareThis blurb).
- **`is_leaf_node`** — TRUE if the category is a leaf (directly targetable) rather than an interior/navigation node.
- **`navigation_only`** — TRUE if the node exists only for navigation (not itself targetable).
- **`custom`** — stored as a **STRING** `"true"`/`"false"` (not a BOOL) — flags a custom/private segment.
- **`use_restrictions` / `permitted_advertisers`** — usage-restriction text and permitted-advertiser list; mostly NULL in sampled rows.
- **`digital_cpm` / `tv_cpm`** — NUMERIC CPM pricing for digital vs TV/CTV activation of the segment (observed values 0.5, 1.25, 2). Often one is NULL when a category is single-channel (e.g. TV-only categories have `tv_cpm` set, `digital_cpm` NULL).
- **`source`** — INT64 internal source enum. Observed distribution: `1` (732,885 rows ≈ 99.8%), `2` (97 rows), NULL (1,357 rows). Meaning of the codes is not labeled by a lookup in this catalog — filter to `source=1` for the mainstream LiveRamp feed.
- **`deprecated`** — BOOL; TRUE marks a retired category. A large share of historical rows are deprecated (≈516K of the 732K `source=1` rows across all versions) — dedupe to the latest `import_timestamp` and check `deprecated=FALSE` for currently-buyable categories.
- **`created_date` / `updated_date`** — DATE the category was created / last updated at the source. Range of `created_date` 2022-03-30 → 2026-07-27.
- **`import_timestamp`** — TIMESTAMP of the import batch that produced the row; the **versioning key** (~862 distinct batches). Latest per category = current.

## Joins & relationships
- **→ `tpa.categories`** on `data_source_category_id` (add `AND data_source_id=35` for the current LiveRamp name; 11 = legacy). Use for the canonical current name/path if you prefer that table.
- **→ `tpa.liveramp_categories_advertiser_mapping`** on `data_source_category_id` — attaches the advertiser(s) entitled to a (usually custom) category. That side fans out (a category can map to several advertisers).
- **Self-join** `parent_id` → `data_source_category_id` to build the tree; `path_from_root` gives the full ancestor chain without recursion.
- **Fan-out warning:** because rows are versioned, **any join on `data_source_category_id` fans out across all import versions** — always dedupe to the latest `import_timestamp` per category first (see Example queries), or the join multiplies rows ~1.7x on average (far more for long-lived categories).

## Gotchas
- **Versioned, not a clean dimension.** `data_source_category_id` repeats across import batches. Never treat a raw `COUNT(*)` as a category count, and never join without first deduping to the latest `import_timestamp` per category — otherwise every downstream row multiplies.
- **`custom` is a STRING** (`"true"`/`"false"`), not a BOOL — compare to the string literal.
- **`source` codes are unlabeled** — no lookup dim resolves 1/2/NULL in this catalog; `source=1` is the ~99.8% mainstream feed.
- **`deprecated=TRUE` dominates the raw history** — most historical rows are deprecated; filter on the latest version and `deprecated=FALSE` for buyable categories.
- **`digital_cpm` / `tv_cpm` are frequently NULL** for single-channel categories — coalesce/handle NULLs when pricing.
- **`path_from_root` / `names` are JSON strings**, not native arrays — parse with `JSON_EXTRACT_ARRAY` / `JSON_QUERY` if you need the elements.
- **Not tiny.** ~734K rows / ~417 MB logical — unlike the `integrationprod` dims, a `SELECT *` here is a real scan (see Cost).

## Cost & partitioning notes
- **BASE TABLE**, no partition, no clustering. `bq show`: `type=TABLE`, `numRows=734339`, `numBytes=437514251` (~417 MB), `timePartitioning=None`, `clustering=None`, no TTL.
- **No partition to prune** — a full scan reads ~417 MB. `SELECT *` is wide (20 cols, long `description`/`path`/JSON strings) — select only needed columns and always narrow to the latest `import_timestamp` slice.
- Prefer projecting `data_source_category_id, name, path, digital_cpm, tv_cpm, deprecated` and deduping before joining.

## Example queries
```sql
-- current (latest-version) LiveRamp taxonomy, buyable leaves only
WITH latest AS (
  SELECT *, ROW_NUMBER() OVER (
           PARTITION BY data_source_category_id ORDER BY import_timestamp DESC) AS rn
  FROM `dw-main-bronze.tpa.liveramp_categories`
  WHERE source = 1
)
SELECT data_source_category_id, name, path, digital_cpm, tv_cpm
FROM latest
WHERE rn = 1 AND deprecated = FALSE AND is_leaf_node = TRUE
LIMIT 100;
```
