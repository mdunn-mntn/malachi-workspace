# reporting.lift__ghost_bid_results

## Purpose
Per-campaign, per-stratum incremental-lift **results** for MNTN's always-on ghost-bid holdout experiment (BER-2250 / INCR line, owned by Matt Brorby). Each row is one campaign's measured lift within a stratum — overall, per intent `score_band`, per `bid_count` frequency bucket, or a pooled estimator — carrying the treatment vs ghost-holdout visit rates, the ITT effect (absolute + relative), its SE/CI/z/significance, the conversion analogs, and a battery of **validity/bias flags**. It is the gold aggregate computed FROM the silver subject table `dw-main-silver.enriched.lift__ghost_bid_visits` (already time-boxed with the entry-cohort + drop-left-censored-day logic, reproducing the windowed silver calc to the digit). Reach for it to read a ready-made per-campaign lift, to check the intent-band (`score_band`) composition of an audience, or to diagnose whether a per-campaign negative is a real effect or a flagged bias artifact. For an advertiser- or campaign-group-weighted rollup (with `level`/`entity_id`, MH-stratified estimator) use the sibling `reporting.lift__ghost_bid_rollup`.

## Grain & keys
- **Grain:** one row per **`campaign_id` × `stratum_type` × `stratum_value`**. In current data `campaign_id` and `campaign_group_id` are **1:1** (2,710 distinct each; 1,435 advertisers; 2 partner legs), so a row is effectively per **campaign_group × stratum** — filter either id to slice one campaign's strata.
- **Natural key:** `(campaign_id, stratum_type, stratum_value)`.
- **Foreign keys / join columns:** `campaign_group_id` → `dw-main-silver.public.campaign_groups.campaign_group_id` (PK column is `campaign_group_id`, NOT `id`; picks up `product_id`); `advertiser_id` → advertisers; `campaign_id` → campaigns; `partner_id` = bidder leg (8 = Beeswax/JVM, 79 = MNTN Rust).

## Column meanings (only the non-obvious ones)
- **`stratum_type` / `stratum_value`** — the slice this row summarizes. Verified value sets:
  - `overall` / `all` — the headline per-campaign lift (one row per campaign).
  - `score_band` / {`High`, `Mid`, `PP`, `MaxReach`, `no_score`} — per intent band (the persuadables gradient; `no_score` = untargeted reach, `PP`=predicted-purchaser, MaxReach = broadest scored band).
  - `bid_count` / {`1`, `2-3`, `4-10`, `11+`} — frequency (bid-multiplicity) buckets; a diagnostic for `ghost_frac` inflation (holdout IPs over-accumulate at high bid counts).
  - `score_band_ivw` / `combined` — inverse-variance-weighted pool across score bands (the correct cross-band aggregate).
  - `score_band_mh` / `combined` — Mantel-Haenszel stratified pool across score bands.
- **`n_treatment` / `n_holdout`** — subject (bid-IP) counts in the submitted-treatment arm vs the ghost-holdout arm. Holdout is a fixed ~10% platform-wide slice, so `n_holdout ≈ 0.10 × n_treatment` on clean data.
- **`vis_treatment` / `vis_holdout`** — visits (pixel-fire within 7d of first bid) in each arm. `rate_* = vis_* / n_*` (verified to the digit).
- **`abs_itt`** — absolute ITT effect = `rate_treatment − rate_holdout` (percentage-point difference in visit rate). Bid-grain ITT, diluted by win rate — scale by win rate for a served-user ATT.
- **`rel_itt`** — relative lift = `abs_itt / rate_holdout` (the headline % lift). Read magnitude/relative lift + sign, NOT `z` (see Gotchas).
- **`incremental_visits`** — `abs_itt × n_treatment` (raw COUNT of incremental visits over the treated arm, verified to the digit). This is the **sanctioned denominator for cost-per-incremental-visit (CPIV)** (Matt Brorby, 2026-07-29). SUM of this is **volume-weighted** (emphasizes high-spend campaigns) and answers a different question than IVW-pooling `abs_itt` ("average campaign-level lift") — pick one basis per table.
- **`abs_tot`** — compliance-adjusted absolute effect = `abs_itt / ip_compliance` (verified on 3 rows). Scales the ITT up to a treatment-on-treated / per-exposed basis (households actually reached).
- **`se`** — standard error of `abs_itt`; `z = abs_itt / se`; `abs_ci_low/abs_ci_high` = 95% CI on `abs_itt`; `significant_95` = `|z| ≥ 1.96`. **`z` is N-inflated** (bid-grain, bids within an IP are correlated → SE understated) — treat significance as a floor, not a truth.
- **`ghost_frac`** — distinct-IP fraction of the subject pool that is holdout. Design = 0.10; `ghost_frac_inflated` = TRUE flags bid-multiplicity contamination (the dominant bias: holdout IPs never win → re-enter auctions → over-accumulate at high bid counts, `ghost_frac` 0.10 @1 bid → 0.47 @11+ on the Beeswax leg, manufacturing a spurious NEGATIVE). Clean gate keeps `ghost_frac ∈ ~[.09,.11]`.
- **`arm_score_imbalance` / `arm_imbalance_suspect`** — intent-score imbalance between arms and its TRUE flag. **Marks imbalance RISK, not direction** (worked example: adv 59460 Select side is `arm_imbalance_suspect=true` yet reads +262%; its non-Select side is clean yet reads −13.8% noise).
- **`has_valid_holdout`** — TRUE when a usable holdout arm exists for the row.
- **`ip_compliance`** — fraction of bid IPs that actually win an impression (~40–50%). Households reached ≈ `ip_compliance × n_treatment`; low compliance dilutes the ITT toward zero.
- **`holdout_won_rate`** — rate at which ghost/holdout bids actually won (leakage); should be ~0 (verified ≈0.0005 on samples). Non-trivial values indicate a broken counterfactual.
- **`meets_min_n` / `meets_min_compliance`** — reliability gates (sufficient sample / sufficient compliance).
- **`conv_*`** — conversion analogs of the visit block (`conv_treatment/holdout`, `conv_rate_*`, `conv_abs_itt`, `conv_rel_itt`, `conv_se`, `conv_z`, `conv_significant_95`). Rare-outcome; gate per-campaign conv `rel%` behind ≥20 holdout conversions and lead with z.

## Joins & relationships
- **`campaign_group_id` → `dw-main-silver.public.campaign_groups.campaign_group_id`** (PK column is `campaign_group_id`, not `id`) → picks up `product_id` (1=PTV / 2=Select / 3=QF). N:1, no fan-out.
- **`advertiser_id` → advertisers**, **`campaign_id` → campaigns** — standard dimension lookups (N:1). Prefer `advertisers.company_name` for display.
- **`partner_id`** = bidder leg, 1:1 with product: `79` = MNTN Rust (Select, product 2, ~97%), `8` = Beeswax/JVM (PTV/non-Select, product 1, ~100%). No campaign_group is split across legs, so `all_facts` spend maps cleanly to a CG's single leg.
- **Source `dw-main-silver.enriched.lift__ghost_bid_visits`** — the per-IP subject table this view aggregates (one row per dt × advertiser × campaign_group × campaign × ip, one `arm` each). Reconstruct/audit `_results` from it for custom windows.
- **Sibling `reporting.lift__ghost_bid_rollup`** — advertiser & campaign_group weighted rollup (`level` ∈ {advertiser, campaign_group}, `entity_id`, MH-stratified estimator, conversions). Use `_rollup` for a per-CG one-liner; use `_results` (this table) for per-stratum rows.

## Gotchas
- **Flags mark RISK, not direction.** `arm_imbalance_suspect` / `ghost_frac_inflated` say "this row may be biased," not "the lift is negative/positive." A per-campaign negative that clears nominal significance is usually NOISE around ~0 (N-inflated z + low `ip_compliance` diluting ITT), not real suppression. All flags clean → noise, not a flagged artifact. A genuine causal negative at bid-grain prospecting is essentially never the real story.
- **Read magnitude, not z.** At millions of IPs a ~0 magnitude yields large z; `z`/`significant_95` are a floor. Report absolute pp + relative lift + sign.
- **Bid-grain ITT, win-rate-diluted.** `abs_itt`/`rel_itt` are per-bid-IP, not per-served-household. Scale by win rate (`ip_compliance`) for a served-user ATT; `abs_tot` is the compliance-adjusted version.
- **Cross-stratum/campaign pooling must be inverse-variance-weighted** (`SUM(abs_itt/se²)/SUM(1/se²)`), NOT a naive count pool (`SUM(vis)/SUM(n)`) which is Simpson-confounded (naive gave `no_score` +29%; IVW → ~0). Use the pre-pooled `score_band_ivw` / `score_band_mh` rows instead of rolling your own.
- **"Excludes high intent" ≠ "targets mid intent."** Check the `score_band` strata — an audience can be ~100% `no_score` (the incrementally-dead reach band), so ~0 lift is the EXPECTED result, not merely underpowered.
- **Standard clean gate:** `has_valid_holdout AND meets_min_n AND meets_min_compliance AND NOT ghost_frac_inflated AND NOT arm_imbalance_suspect AND se>0`.
- **Data floor ≈ 2026-06-22, no backfill.** Time-boxed correctly (entry-cohort + drop left-censored first day) as of AUDI-1148 (2026-07-22), reproducing the windowed silver calc to the digit; visit window is a fixed 7-day-from-first-bid → a conservative floor vs advertisers' 30–45d attribution. A matured 30-day window becomes feasible ~September 2026.
- **SQLMesh physical metadata is versioned.** The view resolves to `sqlmesh__reporting.reporting__lift__ghost_bid_results__3132856389`; the hash suffix changes on model rebuilds — re-resolve via `INFORMATION_SCHEMA.VIEWS`, don't hard-code it.

- **Tiny table — cost is a non-issue.** Physical table is ~23.9K rows / ~5.6 MB, **unpartitioned, unclustered, no TTL**. A full `SELECT *` scans ~5 MB. `require_partition_filter: false` (there is no partition column). Filter `stratum_type` / `campaign_group_id` for clarity, not for bytes.

## Example queries
```sql
-- Per-campaign headline lift for one campaign_group, clean-gated
SELECT campaign_group_id, rel_itt, abs_itt, se, abs_ci_low, abs_ci_high, z, significant_95,
       incremental_visits, ip_compliance, ghost_frac
FROM `dw-main-gold.reporting.lift__ghost_bid_results`
WHERE stratum_type = 'overall'
  AND campaign_group_id = 126905;

-- Intent-band composition + per-band lift for an audience (persuadables gradient)
SELECT stratum_value AS score_band, n_treatment, rel_itt, abs_itt, se, z
FROM `dw-main-gold.reporting.lift__ghost_bid_results`
WHERE stratum_type = 'score_band'
  AND campaign_group_id = 126905
  AND has_valid_holdout AND meets_min_n AND meets_min_compliance
  AND NOT ghost_frac_inflated AND NOT arm_imbalance_suspect AND se > 0
ORDER BY n_treatment DESC;
```
