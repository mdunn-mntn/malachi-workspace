# summarydata.freshpaint_advertisers

## Purpose
Eligibility / routing lookup for **Freshpaint** — the third-party pixel/CDP vendor that lands page-view
and conversion telemetry into MNTN as **data source 41 (DS41)** (see `logdata.page_view_signal_log`, whose
entire live window is DS41=Freshpaint, and the `Freshpaint (Imp Attr)` / `Freshpaint (Visit Attr)` /
`Competing Visit - Freshpaint` rows in `core.attribution_models`). The physical model's own description is
*"Track advertisers with Freshpaint visits or conversions."* Reach for it to answer **"which advertisers
have Freshpaint telemetry, and do they have Freshpaint visit signals (vs conversions only)?"** — typically
to decide whether Freshpaint visit-based attribution is applicable for an advertiser. It is a tiny static
config dimension (21 rows), **never** a fact/event table.

## Grain & keys
- **Grain:** one row per advertiser that has **any** Freshpaint (DS41) activity (a visit signal OR a
  conversion). An advertiser absent from the table has no Freshpaint telemetry.
- **Primary key:** `advertiser_id` — verified unique (21 rows = 21 distinct `advertiser_id`, 0 NULLs).
- **Join column:** `advertiser_id` → the advertiser dim (`core.advertisers` / `integrationprod.advertisers`).

## Column meanings (only the non-obvious ones)
- **`advertiser_id`** — MNTN advertiser id; the primary key. Includes obvious **test / sentinel ids**
  (`1, 123, 222, 456, 123123, 12341234`) — filter these out before any real analysis; genuine MNTN
  advertiser ids are 5-digit (e.g. `37963`, `68027`).
- **`has_visits`** (BOOL, never NULL) — TRUE ⇒ the advertiser has Freshpaint **visit / page-view signals**
  (DS41 rows in `page_view_signal_log`); FALSE ⇒ the advertiser is in the table for Freshpaint activity
  but has **no visit signals** — i.e. **conversions-only**. Empirically verified: over a recent 7-day
  Freshpaint visit window, every advertiser that appeared was a `has_visits=TRUE` row and **zero**
  `has_visits=FALSE` advertisers had any visit rows. Present split: 8 TRUE / 13 FALSE (of 21). Note the
  flag reflects the model's full lookback, so a `has_visits=TRUE` advertiser need not have visits in any
  given recent window (e.g. `37963`, `42473` had none in the last 7 days).

## Joins & relationships
- **`core.advertisers` / `integrationprod.advertisers`** on `advertiser_id` — dim is **1:1**, this table is
  1:1 on `advertiser_id`; **no fan-out**. Filter the dim `deleted=FALSE AND is_test=FALSE` (which also
  removes the sentinel ids above). Use for advertiser name/vertical.
- **`logdata.page_view_signal_log`** (raw: `dw-main-bronze.raw.page_view_signal_log`) on `advertiser_id` —
  this is the DS41 Freshpaint visit event stream; **1:N, heavy fan-out** (thousands–tens-of-thousands of
  visit rows per advertiser). This lookup is the small side; join only to *filter* the event log to
  Freshpaint advertisers, never expect one row back.
- **Conversion side** — `has_visits=FALSE` advertisers are present via Freshpaint conversions; those land in
  the conversion pipeline (`ui_conversions` / conversion_log, DS41). This table does not carry conversion
  counts — it is a boolean eligibility flag only.

## Gotchas
- **Not a fact table, no time dimension.** There is no timestamp/epoch column and no partition; you cannot
  slice it by date. It is a full-refresh snapshot of *current* Freshpaint eligibility (SQLMesh FULL model,
  materialized to 21 rows / 189 logical bytes).
- **Test ids inflate the row count** — 6 of 21 rows are sentinels (see Column meanings). Real Freshpaint
  advertiser universe here is ~15 rows.
- **`has_visits=FALSE` ≠ "no Freshpaint" ** — the advertiser IS a Freshpaint advertiser (has conversions);
  it just has no visit signals. Absence from the table is the "no Freshpaint at all" condition.
- **Membership vs recent activity mismatch** — the flag is over the model's build lookback, not "last N
  days"; do not infer live visit volume from `has_visits` (confirm against `page_view_signal_log`).

## Cost & partitioning notes
- **Unpartitioned, unclustered, 21 rows.** There is no partition column and none is needed — scan freely.
- **THE ONE FILTER TO ALWAYS APPLY:** none required for cost; add `WHERE advertiser_id NOT IN
  (1,123,222,456,123123,12341234)` for correctness (drop test ids).
- Measured (labeled by exact column set): `SELECT *` = **`SELECT advertiser_id, has_visits`** (both columns)
  = **189 bytes** processed (dry-run), billed at the 10 MB tier-1 minimum. `approx_logical_bytes` = 189 =
  physical `numBytes` (real active backing storage).

## Example queries
```sql
-- Real (non-test) Freshpaint advertisers and whether they have visit signals
SELECT advertiser_id, has_visits
FROM `summarydata.freshpaint_advertisers`
WHERE advertiser_id NOT IN (1,123,222,456,123123,12341234)
ORDER BY has_visits DESC, advertiser_id;

-- Use as a filter against the Freshpaint (DS41) visit event log (prune the raw table by _PARTITIONTIME)
SELECT v.advertiser_id, COUNT(*) visit_rows
FROM `dw-main-bronze.raw.page_view_signal_log` v
JOIN `summarydata.freshpaint_advertisers` f USING (advertiser_id)
WHERE v._PARTITIONTIME >= TIMESTAMP('2026-07-12') AND f.has_visits
GROUP BY 1 ORDER BY 2 DESC;
```
