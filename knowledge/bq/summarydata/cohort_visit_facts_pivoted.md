# summarydata.cohort_visit_facts_pivoted

## Purpose
Day-since-impression **cohort retention curve** for attributed site visits. Where `visit_facts`
keys visits by the impression `hour` and spreads the lag across a handful of wide day-bucket
columns (`first_day_visits` … `seventh_day_visits`), this view **unpivots** that structure into
one row per `day_number` (1 … ~130), generalizing the 7-day window to a full multi-month sales
cycle. Reach for it to answer "of the visits that landed on date X, how many days after their
impression cohort did they convert to a visit?" — i.e. sales-cycle / days-to-visit lag curves,
per advertiser / campaign_group / campaign / creative, under any attribution model.

Straight pass-through view: `SELECT * FROM sqlmesh__summarydata.summarydata__cohort_visit_facts_pivoted__4254728508`
(view ≡ physical table, 1:1, no re-keying).

## Grain & keys
- **Grain:** one row per **(advertiser_id, campaign_group_id, campaign_id, creative_id, hour, day_number)**.
  Empirically unique — for `visit_date = 2026-07-10`, distinct(full key) = row count = 708,567.
- **Partition key:** `visit_date` (DATE) — the date the **attributed visit** occurred (the later event).
- **Cohort anchor:** `hour` (DATETIME) — the **impression / exposure** hour (the earlier event), truncated to top-of-hour.
- **Lag dimension:** `day_number` — integer days from impression to visit.
- **Join keys out:** `advertiser_id`, `campaign_group_id`, `campaign_id`, `creative_id` → the respective bronze dims.

## Column meanings (only the non-obvious ones)
- **`visit_date`** — DATE the attributed visit landed. This is the **partition** and the "later"
  event. NOT the impression date.
- **`hour`** — DATETIME of the **impression/exposure** cohort, UTC, truncated to the hour
  (minutes/seconds always 0; verified all 708,567 rows top-of-hour). It is the "earlier" event and
  typically lies days-to-months *before* `visit_date` (for visit_date 2026-07-10, `hour` ranged
  2026-03-06 → 2026-07-11). Nullable in schema but observed non-null.
- **`day_number`** — days elapsed from impression to visit; **1-based** (min observed = 1, no
  `day_number = 0` rows), ceiling ~126–131 (a ~4-month cohort window). Computed in a **US-local
  timezone**, so `day_number ≈ DATE_DIFF(visit_date, DATE(hour), DAY)` on the raw UTC `hour` is off
  by 0 or +1 (60% of rows sit at datediff+1, 40% at exact, 0% below) — an evening-UTC impression
  falls on the prior local calendar day. Do NOT recompute the lag from UTC `hour`; trust `day_number`.
- **Attribution-model metric families** (all scalar INT64 visit counts, NOT HLL sketches):
  - **`cohort_visits`** — default/deterministic attributed visits for the cell.
  - **`cohort_new_visitors`** — first-time visitors.
  - **`cohort_last_touch_visits`** / **`cohort_last_tv_touch_visits`** — last-touch and last-TV-touch deterministic variants.
  - **`cohort_visits_assist`** — multi-touch **assist** credit.
  - **`cohort_competing_*`** — the **industry_standard / competing** (first-touch competitor) attribution variant of each metric.
  - **`cohort_probattr_*`** — **probabilistic**-attribution variant of each metric.
  (These prefixes mirror the documented `visit_facts` / `all_facts` semantics: `*_assist` = multi-touch, `competing_*` = industry-standard first-touch, `probattr_*` = probabilistic.)
- **`cohort_probattr_*_arr` (ARRAY<STRING>, never NULL, often empty)** — the **exact list of
  probabilistically-attributed visitor IPv4 addresses** for that cell (e.g. `["146.75.248.160"]`),
  NOT HLL sketches and NOT serialized blobs. Small (max array length 4 in the sampled day) and
  sparse (only 1,674 of 708,567 rows non-empty). Three roles — `_site_visitors_arr` (all attributed
  site visitors), `_new_site_visitors_arr` (first-time), `_existing_site_visitors_arr` — plus the
  `_competing_*` mirrors. Use these for exact set/dedup work on the probattr path; the matching
  `cohort_probattr_*` INT columns are the counts.

## Joins & relationships
- **`advertisers`** (`advertiser_id` → `id`): dim, **N:1** (many cohort rows per advertiser). Filter
  `deleted=FALSE AND is_test=FALSE`; use `company_name` (the verticals `advertiser_name` is empty).
- **`campaigns`** (`campaign_id` → `id`): dim, **N:1**. Use `funnel_level` for stage (objective_id unreliable).
- **`campaign_groups`** (`campaign_group_id` → `id`): dim, **N:1**. `product_id` 1=PTV / 2=Select / 3=QuickFrame.
- **`creatives`** (`creative_id`): dim, **N:1**.
- **Sibling `visit_facts`** (same physical family, `visit_facts__427634656`): the non-pivoted source
  shape (impression-`hour` grain with wide `first_day…seventh_day_visits` buckets). Same underlying
  attribution, **different grain** — this table trades the wide day columns for a `day_number` row
  dimension and re-partitions on the visit date. Reconcile totals via a day_number roll-up, not a direct join.
- **IP arrays:** no IP→IP bridging in BQ (external-only); use the `*_arr` IPs for in-result set ops only.

## Gotchas
- **Attribution-model double count.** `cohort_visits`, `cohort_last_touch_visits`,
  `cohort_last_tv_touch_visits`, `cohort_visits_assist`, `cohort_competing_*`, and `cohort_probattr_*`
  are competing views of the **same** visits under different models. Never sum across model families —
  pick one column. Summing one model's column across `day_number` (and/or `hour`) for a given
  `visit_date` is safe (each visit is one cohort cell).
- **`day_number` is not a raw UTC datediff** — it is US-local and 1-based (see column notes). Recomputing
  the lag from `DATE(hour)` mislabels ~60% of rows by one day.
- **`hour` is the impression, `visit_date` is the visit** — the opposite of the intuitive read for a
  view named `*visit_facts` and partitioned by `visit_date`. The anchor/cohort event is `hour`.
- **`*_arr` are exact IP arrays, not HLL** — `ARRAY_LENGTH()` / `UNNEST()` them directly; never feed
  them to `HLL_COUNT.*`. Mostly empty because probattr is a rare attribution path.
- **No `require_partition_filter`** — an unfiltered query silently scans all 566 partitions (94 GB on
  `SELECT *`). Always add a `visit_date` predicate yourself.
- **Freshness:** partitions run 2025-01-01 → 2026-07-20 with a partition present for the *next* day
  (attribution writes future `visit_date` cells as visits land); no partition TTL, so history is retained in full.

## Cost & partitioning notes
- **Always filter `visit_date`** (the partition). No `require_partition_filter` guard, no partition TTL.
- Clustered `advertiser_id, campaign_group_id, campaign_id, day_number` — cuts bytes at **runtime**
  only; it does **not** lower a `--dry_run` upper-bound estimate (a dry-run *rises* slightly because it
  must also read the added cluster-key column to evaluate the predicate).
- Dry-run figures (each labeled by its exact column set; only same-column-set figures are comparable):
  - `SELECT *`, **no filter** → **94,192,763,140 B (94.19 GB)** — equals physical `numBytes` (= approx_logical_bytes).
  - `SELECT *`, **one `visit_date` day** → **130,445,746 B (~130 MB)**.
  - `SUM(cohort_visits)` (one INT col), **no filter** → **4,091,462,832 B (~4.09 GB)**.
  - `SUM(cohort_visits)` (one INT col), **one `visit_date` day** → **11,337,072 B (~11.3 MB)** → ~360× prune vs the unfiltered one-column scan (confirms `visit_date` is the partition).
  - `SUM(cohort_visits)`, one day **+ `advertiser_id`** → **17,005,608 B (~17 MB)** — larger than the day-only figure because the dry-run must read the `advertiser_id` cluster column; the real saving from clustering shows up only at runtime.
- ~511M rows, 566 partitions, ~166 MB/partition average.

## Example queries
```sql
-- Days-to-visit cohort curve for one advertiser over a visit-date window (default attribution)
SELECT day_number, SUM(cohort_visits) AS visits, SUM(cohort_new_visitors) AS new_visitors
FROM `dw-main-silver.summarydata.cohort_visit_facts_pivoted`
WHERE visit_date BETWEEN '2026-07-01' AND '2026-07-10'
  AND advertiser_id = 31357
GROUP BY day_number
ORDER BY day_number;

-- Exact probattr visitor IPs attributed on a single day
SELECT advertiser_id, campaign_id, day_number, ip
FROM `dw-main-silver.summarydata.cohort_visit_facts_pivoted`,
     UNNEST(cohort_probattr_site_visitors_arr) AS ip
WHERE visit_date = '2026-07-10'
  AND ARRAY_LENGTH(cohort_probattr_site_visitors_arr) > 0;
```
