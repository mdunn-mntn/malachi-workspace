# summarydata.last_tv_touch_conversions__copy_data

## Purpose
This is **not** a copy of the `last_tv_touch_conversions` data despite the `__copy_data` name. It is a
**singleton status/watermark table** written by the SQLMesh export job that dumps the **last 3 days** of
`summarydata.last_tv_touch_conversions` to GCS as Parquet, using an atomic staging-prefix swap. The one
row records **when the export last ran** (`last_run`) and a human-readable success **message** (`status`)
naming the GCS destination. Reach for it only to check whether/when the export job last succeeded — the
actual conversion rows live in the stable sibling view and in GCS, never here. (Physical-table
description, verified live 2026-07-19: "Exports the last 3 days of last_tv_touch_conversions to GCS as
Parquet using an atomic staging-prefix swap.")

## Grain & keys
- **Grain:** one row total — a singleton overwritten in place on each export run (numRows = 1, verified via `bq show`).
- **Key(s) / join columns:** none. No entity/time key; it is not joinable to fact tables. Do not join it to anything.

## Column meanings (only the non-obvious ones)
- **`last_run`** — native BigQuery `TIMESTAMP` (UTC, no epoch conversion needed) of the last successful export run. Sample value `2026-07-20 06:20:47` UTC (≈ 2026-07-19 23:20 PST), i.e. a nightly job. This is an export *watermark*, not a data timestamp — it does **not** describe the max `time` of the exported conversions.
- **`status`** — free-text success message, not an enum. Sample: `"last_tv_touch_conversions exported to gs://mntn-analytics-curated/bq-export/summarydata/last_tv_touch_conversions/"`. Names the GCS Parquet destination prefix. Treat as an informational log string, not a machine-parseable status code.

## Joins & relationships
- **Not a join target.** No key columns; the single row carries no advertiser/campaign/ip/time key.
- **Provenance link (documentation, not a SQL join):** it tracks the export of the stable sibling
  **`summarydata.last_tv_touch_conversions`** (VIEW → `sqlmesh__summarydata.summarydata__last_tv_touch_conversions__1806020579`, a real physical **TABLE**, partition DAY on `time`, row-level conversions attributed to the last TV ad touch; `impression_ip` is STRING). For actual last-TV-touch conversion data, query that sibling — never this table.
- **Destination:** rows are exported to GCS at `gs://mntn-analytics-curated/bq-export/summarydata/last_tv_touch_conversions/` (Parquet). Fan-out: N/A (singleton).

## Gotchas
- **The name lies.** `__copy_data` reads like a staging/experimental copy of the conversions data; it is actually an **export-job control/watermark table** with only `last_run` + `status`. Anyone expecting conversion rows here will find one status row.
- **Overwritten in place.** No history is retained — each run replaces the single row. There is no audit trail of past exports beyond the current `last_run`. (Time-travel physical bytes exist but that's just default 7-day time-travel, not a designed history.)
- **`status` is free text, not an enum.** `SELECT DISTINCT status` yields one message string; do not build logic on parsing it.
- **`last_run` is UTC** and can read as "tomorrow" relative to a PST wall clock — a nightly UTC run near midnight lands on the next UTC date. Not a data-freshness bug.
- **Staleness of this table ≠ staleness of the sibling.** A stale `last_run` means the *export* stalled, not that `last_tv_touch_conversions` is stale. Check the sibling's own `max(time)` for data freshness.
