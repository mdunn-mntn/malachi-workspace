# summarydata.conversion_signal_impressions

## Purpose
Per-impression **CTV conversion-signal feed**: each row is a served MNTN CTV/OTT ("Television") impression, decorated with the resolved consumer identity (SHA-256 hashed email, a third-party identity-graph id, IP, and postal/geo) so a downstream **offline conversion-signal partner** can match the impression against real-world/offline conversions. Every row carries `offline_conversion_signal_data_source_id = 45` — this view is the materialized export for that one signal source. Reach for it when you need "which hashed identity saw which CTV ad on which app/network," CTV identity-match coverage, or to reconcile offline-conversion measurement inputs. Small, batch-materialized table (~40K rows, ~17 MB); NOT a general impression log — for full impression/cost data use the `logdata` impression tables.

## Grain & keys
- **Grain:** one row per **served CTV impression**. Verified: `COUNT(*) = COUNT(DISTINCT ad_served_id) = COUNT(DISTINCT impression_id) = 39,846` (both are row-unique).
- **Row-unique keys:** `ad_served_id` and `impression_id` — both unique per row but they are **different values** (`ad_served_id != impression_id`; do not equate them). `impression_id` is a ~41–42-char numeric-prefixed string.
- **Identity key (repeats — NOT the grain):** `impression_guid` (36-char UUID) is an **identity/person key**, not a per-impression id: 15,157 distinct guids over 39,846 rows (avg 2.63 rows/guid, max 56), and a single guid spans up to **6 different advertisers**. It aligns ~1:1 with `hashed_email_sha256` (15,233 distinct) and `third_party_identity_id` (15,236 distinct). Use `ad_served_id`/`impression_id` to dedupe rows; use `impression_guid`/`hashed_email_sha256` to group by person.

## Column meanings (only the non-obvious ones)
All figures below verified over the full live table (2026-03-02 → 2026-07-19, 39,846 rows).
- **`hashed_email_sha256`** — 64-char hex = SHA-256 of the consumer email. 100% populated. Primary identity join key to the offline-conversion partner. PII (hashed) — do not expose raw values in shareable artifacts.
- **`third_party_identity_id`** — third-party identity-graph id, a **variable-length numeric string** (seen lengths 7/11/12). 100% populated; 15,236 distinct (≈ one per person). Also a cluster key.
- **`xdd_partner_ids`** — cross-device data ("xdd") partner id(s). **Constant `"1"` for every row** in current data — treat as a present-but-uninformative flag, not a real multi-partner list, until it varies.
- **`ip`** — resolved IP for the identity. 100% populated; 15,296 distinct (≈ one per person, not per impression).
- **`impression_guid`** — 36-char UUID **person/identity key** (see Grain & keys), NOT the row grain.
- **`ad_served_id` / `impression_id`** — two distinct row-unique impression identifiers (see Grain & keys); neither equals the other.
- **`type`** — creative/channel type; **constant `"Television"`** (this is a CTV-only feed).
- **`viewed_on`** — CTV delivery surface: `SET_TOP_BOX` (~60%) or `CONNECTED_TV` (~40%). No other values observed.
- **`network_site`** — the CTV app/network/genre the ad ran on (e.g. Peacock, NBC, HBO Max, Tubi, Paramount Streaming - Drama, Samsung TV+, Roku, LG, Vizio, CNN). 164 distinct; a display/publisher label, not an id.
- **`offline_conversion_signal_data_source_id`** — the offline-conversion signal source. **Constant `45`** — this view is scoped to that one source.
- **`campaign_group_name` / `creative_group_name`** — denormalized human names carried inline (100% populated); avoids a dim join for labeling.
- **`group_id`** — 397 distinct, exactly matching `creative_id`'s 397 distinct — behaves as a **creative/ad group** id (aligned with the creative), distinct from `campaign_group_id` (45 distinct). Do not confuse `group_id` with `campaign_group_id`.
- **`impression_time`** — TIMESTAMP the impression was served; **the partition column** (DAY). Use for all date filtering.
- **`inserted_at`** — SQLMesh/ETL **load** timestamp, always ≥ `impression_time` (0 rows insert-before-impression). Large, backfill-style lag: avg ≈ 511 h (~21 days), max ≈ 1,911 h (~80 days); earliest `inserted_at` = 2026-05-19 for impressions dating to 2026-03-02. This is a batch/backfilled feed, not real-time — do NOT treat `inserted_at` as event time.

## Joins & relationships
This table is always the **many (N) side** against MNTN dimension tables — joining to the 1-side dims does not fan out. Every listed key is 100% populated.
- **`advertiser_id`** → `bronze.integrationprod` advertisers dim (1:N; dim is 1). Only **11** distinct advertisers present (a curated/limited feed, not all advertisers).
- **`campaign_id`** → `campaigns` dim (1:N). 92 distinct.
- **`campaign_group_id`** → `campaign_groups` dim (1:N). 45 distinct; also surfaced inline as `campaign_group_name`.
- **`creative_id`** (and creative-level **`group_id`**) → creatives dim (1:N). 397 distinct.
- **Identity match (external):** `hashed_email_sha256` / `third_party_identity_id` are the keys handed to the offline-conversion partner (data source 45); the match happens outside BQ. Within BQ, `impression_guid` / `hashed_email_sha256` group rows to one person (fan-out: one identity → many impression rows, up to 56).
- Dim joins are not live-verified in this pass (standard `integrationprod` dims); remember dim hygiene filter `deleted=FALSE AND is_test=FALSE`.

## Gotchas
- **`require_partition_filter = TRUE`**: any query without an `impression_time` predicate hard-errors ("Cannot query over table … without a filter over column(s) 'impression_time'"). This also empirically confirms `impression_time` as the partition column.
- **`inserted_at` lags event time by weeks** (avg ~21 d, up to ~80 d) — it is the batch load time, not when the impression happened. Never use it as event time or as a freshness proxy for `impression_time`.
- **`impression_guid` is a person key, not an impression key** — grouping/deduping on it collapses ~2.6 rows and can cross advertisers. Use `ad_served_id`/`impression_id` for per-impression uniqueness.
- **`ad_served_id != impression_id`** even though both are row-unique — pick one consistently; don't join them to each other.
- **Constant columns in current data**: `type`="Television", `offline_conversion_signal_data_source_id`=45, `xdd_partner_ids`="1". Don't build filters that assume these vary.
- **Small, narrow-scope feed**: only 11 advertisers and ~40K rows since 2026-03-02 (table created ~2026-05-05). Not representative of overall CTV delivery — do not use for volume/coverage claims beyond this signal source.

## Example queries
```sql
-- Per-person CTV impression coverage for one advertiser, last 30 days
SELECT advertiser_id,
       COUNT(*)                          AS impressions,
       COUNT(DISTINCT impression_guid)   AS people,
       COUNT(DISTINCT network_site)      AS apps
FROM `summarydata.conversion_signal_impressions`
WHERE impression_time >= TIMESTAMP_SUB(CURRENT_TIMESTAMP(), INTERVAL 30 DAY)
  AND advertiser_id = <AID>
GROUP BY advertiser_id;

-- Hashed-identity export rows for offline-conversion matching (one day)
SELECT hashed_email_sha256, third_party_identity_id, ad_served_id,
       network_site, viewed_on, impression_time
FROM `summarydata.conversion_signal_impressions`
WHERE impression_time >= '2026-07-01' AND impression_time < '2026-07-02';
```
