# summarydata.waypoints_sp_impressions

## Purpose
Impression-grain source feed for the **Waypoints Selective-Performance (SP)** product. One row per
served impression, restricted to advertisers enrolled in Selective Performance, carrying the full
advertiser spend of that impression. It is the impression leg that feeds the SP aggregation/attribution
views (`summarydata.waypoints_sp_aggregation`, `summarydata.waypoints__selective_performance`), which
tie impressions to the advertiser's selected performance events. Reach for it when you need
impression-level spend attribution for an SP advertiser's journey — **not** for platform-wide impression
analysis (see Gotchas: it is scoped to a tiny advertiser set).

Rows are derived from `logdata.cost_impression_log` (same `ad_served_id`, `guid`, `campaign_id`, `ip`,
`time`), filtered to SP advertisers, with `total_spend` pre-summed from the impression's spend columns.

## Grain & keys
- **Grain:** one row per served impression. `ad_served_id` is unique — on 2026-07-15, 279,194 rows =
  279,194 distinct `ad_served_id` (0 nulls on `ad_served_id`, `guid`, `ip`, `total_spend`).
- **Primary key:** `ad_served_id` (random per-impression UUID, v4).
- **Cluster keys:** `ip`, `guid` (filtering/joining on either prunes within a day-partition).
- **Foreign keys:** `campaign_group_id` → flight, `campaign_id` → line item, `guid` → household/identity,
  `ip` → served IP.

## Column meanings (only the non-obvious ones)
- **total_spend** (BIGNUMERIC, full precision): advertiser-billed dollars for this single impression =
  `cost_impression_log.media_spend + data_spend + platform_spend` (verified exact to full precision on
  every sampled row, 2026-07-19). This is **gross advertiser spend including the platform + data markup —
  NOT the raw media buy cost** (`cost_impression_log.media_cost`, e.g. $0.0075, is much lower). The long
  repeating decimals (e.g. `0.023076923…` = 0.30/13-family) come from the margin markup applied to
  media_cost. Typical CTV range here ≈ $0.005–$0.13 / impression; `SUM(total_spend)` reconstructs gross
  campaign spend (2026-07-15: ≈ $9,009 across 279K imps; 7-day per-cg ≈ $53.6K / $5.6K / $5.6K).
  Take-rate-sensitive — for shareable cost work use the media/data_spend lenses, not the blended total.
- **guid** (STRING): deterministic household/identity GUID (UUID v3 format, e.g. `…-32c5-…`), carried
  from `cost_impression_log`. N:1 to rows — repeats across a household's impressions (140,707 distinct
  guids over 144,522 distinct IPs on 2026-07-15). Distinct in kind from `ad_served_id` (the v4 random
  impression id).
- **ad_served_id** (STRING): random per-impression UUID (v4), the grain key. Joins 1:1 to
  `cost_impression_log.ad_served_id`.
- **time** (TIMESTAMP): native impression timestamp — **the partition column** (DAY,
  `require_partition_filter = TRUE`). Not an epoch int; no unit conversion needed.
- **campaign_group_id** / **campaign_id** (INT64): MNTN flight (campaign group) and line-item (campaign)
  ids. On this feed all rows are product_id = 1 (PTV / CTV).

## Joins & relationships
- **`logdata.cost_impression_log`** (the source) — join on `ad_served_id`. **1:1** (unique impression;
  `guid` and `campaign_id` also match). This feed already carries `total_spend`, so the join is usually
  unnecessary — and cil is very large (see cost note). Both tables carry `guid`.
- **`dw-main-bronze.integrationprod.campaign_groups`** — join on `campaign_group_id`
  (col name is `campaign_group_id`, **not** `id`). **N:1** (many impressions per group; fan-out on the
  wp side, none on the cg side). Gives `name`, `product_id`, `advertiser_id`.
- **`campaigns`** (bronze.integrationprod / silver.core) — join on `campaign_id`. **N:1**.
- **`guid` / `ip`** — identity/graph joins are many-to-many and CGNAT-limited; no IP→IP bridging in BQ
  (external only). Treat `ip`/`guid` as clustering/filter keys, not clean join keys to identity tables.

## Gotchas
- **Scoped to Selective-Performance advertisers only — currently a SINGLE advertiser.** Over 2026-07-09→15
  the entire table is advertiser **34114 = Taskrabbit**, 3 campaign groups (`US_MNTN_Web_CorMom_PRS`
  prospecting, `US_MNTN_Web_CorMom_RT` retargeting, `US_MNTN_Web_SF_PRS`), all `product_id = 1` (PTV).
  Do **not** use this for platform-wide impression/spend analysis — use `logdata.cost_impression_log`.
- **`require_partition_filter = TRUE` on `time`.** Any query without a `time` filter errors
  (`Cannot query … without a filter over column(s) 'time'`). Always bound `time`.
- **TTL = 130 days** (partition expiration `11232000000` ms). Populated from **2026-04-01** to today
  (110 daily partitions, 26,067,209 rows as of 2026-07-19); older partitions age out.
- **`total_spend` is gross (media+data+platform), not media_cost.** Don't treat it as the raw media buy;
  it embeds MNTN margin. Take-rate-sensitive.
- **SQLMesh view** → versioned physical hash. Query the clean name `summarydata.waypoints_sp_impressions`;
  the physical `…__3277888085` will change on rebuild.

## Cost & partitioning notes
- **Always filter `time`** (DAY partition, `require_partition_filter = TRUE`); cluster `[ip, guid]` prunes
  further when you also filter/join on `ip` or `guid`.
- Measured dry-runs (2026-07-19), one day = 2026-07-15:
  - `SELECT *` (all 7 cols), 1 day → **41.0 MB** (upper bound).
  - `SELECT ip` (1 col), 1 day → **6.4 MB**.
  - No `time` filter → **error** (partition filter required).
- Physical backing storage: **~3.83 GB** (`numBytes` 3,830,518,346; 26,067,209 rows; single physical
  table, not a UNION).
- **Joining to `cost_impression_log` is expensive** on the cil side — a 2-partition day-span join (a few
  cols) billed **≈ 12.2 GB** (64M cil rows scanned). Since this feed already carries `total_spend`,
  avoid the cil join unless you need columns cil has and this table lacks.

## Example queries
```sql
-- Daily gross spend + impressions per campaign group (SP advertiser)
SELECT campaign_group_id, COUNT(*) AS impressions, SUM(total_spend) AS gross_spend
FROM `summarydata.waypoints_sp_impressions`
WHERE time >= TIMESTAMP('2026-07-15') AND time < TIMESTAMP('2026-07-16')
GROUP BY campaign_group_id
ORDER BY gross_spend DESC;
```
