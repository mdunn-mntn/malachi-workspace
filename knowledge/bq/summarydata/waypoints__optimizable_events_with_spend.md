# summarydata.waypoints__optimizable_events_with_spend

## Purpose
The event-level backbone of the **Waypoints** product (event-based campaign optimization). Each row is a
single site or delivery event fired by a visitor who was served an MNTN ad, with the advertiser's **media
spend joined on** (the "with_spend" in the name). Reach for it to see the raw user-journey events behind a
served impression — page URLs visited, named site events ("Viewed Home Page", "Viewed Recommendations
Page"), and which of those are the advertiser's **optimizable** (goal) events — alongside the attributed
spend. It is the granular source that feeds Waypoints optimization/reporting rollups.

**Scope caveat:** only advertisers with the Waypoints/GA-Rokt site integration appear here — ~16
advertisers / 50 campaign groups on a sample day (2026-07-15), not the full MNTN advertiser base. Data
begins **2026-05-01** (no earlier history). Treat as a limited-cohort event stream, not a universe.

## Grain & keys
- **Grain:** one row per **received Waypoints event beacon** = (advertiser_id x `ad_served_id` served
  impression x visitor x `raw_event_name` x `event_type` x microsecond `epoch`). A single pageview emits
  **multiple rows** — one `event_type='URL'` row carrying the URL path, plus one or more `event_type='DLV'`
  rows for the named events fired on that page.
- **Not a unique key:** ~**24%** of rows on 2026-07-15 collided on
  (advertiser_id, ad_served_id, epoch µs, raw_event_name, event_type, ip) — i.e. the same event beacon is
  logged more than once. There is **no dedup key**; treat this as a raw append log and dedup before
  counting distinct events/sessions.
- **Join / identity columns:** `ad_served_id` (served-ad/impression UUID, 0% null), `advertiser_id`,
  `campaign_id`, `campaign_group_id`, `guid` (identity, 0% null), `user_key`, `ip`.

## Column meanings (only the non-obvious ones)
- **`time`** — event timestamp (UTC). `day` = `DATE(time)` and is the partition.
- **`epoch`** — **MICROSECONDS** since Unix epoch = `UNIX_MICROS(time)` (verified: epoch
  `1784076804902826` == `UNIX_MICROS(time)`, not ms/ns). Per-table unit — differs from
  `bidder_bid_events` (ms) and `spend_log` (ns).
- **`raw_event_name`** — the event label as received. When `event_type='URL'` it is the **URL path**
  (`"/"`, `"/profile/marco-m--67"`); when `event_type='DLV'` it is a **named/semantic event**
  (`"Loaded a Page"`, `"Viewed Home Page"`, `"roktInitComplete"`, `"Viewed Recommendations Page"`).
- **`event_type`** — 2-value code (live DISTINCT over 2026-07-13..15 = only these two):
  - `URL` = a page-URL / pageview event; **the row that carries attributed `total_spend`**.
  - `DLV` = a named "delivered" site event; `total_spend` = 0; source of the **optimizable** events.
- **`ad_served_id`** — UUID of the served ad / impression the event is attributed to (**0% null** — every
  row is tied to a served ad).
- **`guid`** — MNTN identity guid (device/household); **0% null** here (unusually complete for MNTN tables).
- **`ga_client_id`** — Google Analytics client id, format `"<random>.<firstSeenEpochSec>"`, from the
  advertiser's GA/Rokt site integration. **`ga_session_id`** — GA session id (~2.6% null).
- **`user_key`** — composite visitor key `"<advertiser_id>|<ga_client_id>"` (cluster key #3).
- **`session_key`** — session identity; null rate tracks `ga_session_id` null (~2.6%).
- **`from_verified_impression`** — nullable BOOL, **three-valued**: `true` = event resolved to a verified
  ad impression; **NULL** (~0.76%) = not resolved. Don't assume true/false only.
- **`optimizable_event_name`** — the advertiser's configured optimization-goal event name;
  **non-null ONLY when `is_optimizable_event=true`**, else NULL.
- **`is_optimizable_event`** — BOOL; `true` only on `DLV` named events matching the advertiser's
  configured optimizable event (classification comes from
  `attr_advertiser_waypoints_event_mapping` / `attr_advertiser_selective_performance_config`). All
  `is_optimizable_event=true` rows carry `total_spend = 0`.
- **`total_spend`** — BIGNUMERIC MNTN **media spend attributed to the event** (the join that names the
  table). **Non-zero only on `URL`/pageview rows** (~6–10% of URL rows > 0); `0` on `DLV` and on
  optimizable events. Values are fractional repeating decimals (e.g. `0.018131868…`) → spend is
  **apportioned across a served ad's events**; BIGNUMERIC preserves the precision.

## Joins & relationships
- **`ad_served_id` → served-ad / impression tables** (impression-log / bidder win-impression keyed by the
  served-ad UUID). Partner grain **1 served ad : N event rows** — joining events→impression is N:1 (safe);
  impression→events **fans out** (many waypoint rows per impression). Dedup the ~24% duplicate beacons
  first.
- **`advertiser_id` → `advertisers` / `campaigns` dims** (`bronze.integrationprod`). N:1. Filter
  `deleted=FALSE AND is_test=FALSE`; `advertiser_name` in `fpa_advertiser_verticals` is unreliable — use
  `advertisers.company_name`.
- **`campaign_id` → `campaigns`** (use `funnel_level` for stage, not `objective_id`); **`campaign_group_id`
  → `campaign_groups`** (= cg_id; `product_id` 1=PTV / 2=Select / 3=QuickFrame). N:1 each.
- **`raw_event_name` / `optimizable_event_name` classification ←
  `attr_advertiser_waypoints_event_mapping` + `attr_advertiser_selective_performance_config`** (event-name
  classification per advertiser; carries a `deleted` flag on the waypoints mapping). N:1 per
  advertiser x event name. (Partner tables live-unverified in this pass.)
- **`guid` → identity graph; `ip` → IP-keyed tables** — no IP→IP bridging in BQ (external only).

## Gotchas
- **~24% duplicate event beacons** on (advertiser, ad_served_id, epoch µs, raw_event_name, event_type,
  ip). No dedup key — **dedup before counting** events/sessions/visits.
- **Multiple rows per pageview:** each page = one `URL` row (path) + one or more `DLV` rows (named events).
  Naively counting rows over-counts pageviews and visits.
- **Limited advertiser cohort:** ~16 advertisers/day (Waypoints/GA-integrated), **not** all MNTN
  advertisers. Never treat this table as the advertiser universe.
- **History starts 2026-05-01** — no data before; recent table (physical created ~2026-06).
- **`epoch` is MICROSECONDS** — differs from other event tables (bidder_bid_events=ms, spend_log=ns).
  Anchor: `UNIX_MICROS(time)`.
- **`total_spend` is 0 on DLV & optimizable rows** — spend lives only on `URL`/pageview rows. To total
  advertiser spend, do **not** filter to optimizable events; sum across the whole day.
- **`from_verified_impression` is nullable (three-valued)** — ~0.76% NULL; handle NULL explicitly.
- **`require_partition_filter = TRUE`** — a query without a `day` filter **errors** (not just expensive).

## Cost & partitioning notes
- **Partition = `day` (DATE, DAY, require_partition_filter=TRUE)** — confirmed on the physical table
  (`timePartitioning.field=day`). **Cluster = `advertiser_id, campaign_group_id, user_key`.** No TTL /
  partition expiration set. **Always filter `day`** (required), then add `advertiser_id` (lead cluster key)
  when possible.
- Dry-run figures (labeled by exact column set — only same-column-set numbers are comparable):
  - **`SELECT *` WHERE `day='2026-07-15'`** (all 19 cols, 1 partition) = **0.361 GB** (387,618,607 bytes).
  - **`SELECT advertiser_id` WHERE `day='2026-07-15'`** (1 narrow col, 1 partition) = **0.0205 GB**
    (20,477,632 bytes) — **~19x cheaper** than `SELECT *`; project only needed columns.
  - **`SELECT *` full table** (all ~80 days) = **23.1 GB** (23,104,383,689 bytes = full backing storage);
    pruning to one `day` partition cuts **~98.4%**.
- `approx_logical_bytes` = 23,104,383,689 (physical `numBytes`); `approx_rows` = 76,724,722.

## Example queries
```sql
-- Optimizable (goal) events for one advertiser on one day
SELECT day, advertiser_id, campaign_group_id, optimizable_event_name, COUNT(*) AS events
FROM `summarydata.waypoints__optimizable_events_with_spend`
WHERE day = '2026-07-15' AND advertiser_id = 34114 AND is_optimizable_event
GROUP BY 1,2,3,4 ORDER BY events DESC;

-- Attributed media spend per campaign group (spend lives on URL rows; dedup beacons first)
SELECT campaign_group_id, ROUND(SUM(total_spend),2) AS spend
FROM (
  SELECT DISTINCT campaign_group_id, ad_served_id, epoch, raw_event_name, event_type, ip, total_spend
  FROM `summarydata.waypoints__optimizable_events_with_spend`
  WHERE day BETWEEN '2026-07-13' AND '2026-07-15'
)
GROUP BY 1 ORDER BY spend DESC;
```
