# summarydata.waypoints

## Purpose
The granular **event stream of "waypoints"** — every tracked event a visitor fires on an advertiser's
site (a URL pageview, or a named delivery/goal event like `conversion`, `pageview`, `cookie_consent_marketing`),
captured by the MNTN/SteelHouse pixel or partner tags. About one row in five is **attributed to an ad
impression** (the winning impression + first/last touch served-ad, attribution model, channel/device are
stamped on — ~20–27% of rows, varies by day). Reach for it when you need per-event journey detail behind visit-verification (VV) and
conversion attribution — the fine-grained layer under the daily `visits`/`ui_visits` rollups. It is NOT a
daily rollup; it is one row per raw event, so it is large (~3.5–13M rows/day).

## Grain & keys
- **Grain:** one row per **tracked site event per visitor**. A single page-load fans out to multiple rows —
  one `event_type='URL'` row (the page URL) plus one `event_type='DLV'` row per named event fired on that
  page. `guid` + `ip` are populated on 100% of rows (verified 2026-07-15). There is **no single
  primary-key column** — rows can repeat verbatim (exact-duplicate `DLV` rows observed), so treat as an
  append-only event log, not a deduped fact.
- **Event-type domain (`event_type`, verified 2026-07-15):** `URL` (~52%), `DLV` (~48%). URL = a pageview
  whose `raw_event_name` is the URL path; DLV = a named event whose `raw_event_name` is the event label.
- **Attribution keys (populated only on the ~20–27% attributed rows):** `impression_id`,
  `ad_served_id`, `first_touch_ad_served_id`, `attribution_model_id`, `campaign_id`, `channel_id`,
  `device_type`, `is_pa`, `is_competing`, `source_type`.
- **Dim keys:** `advertiser_id`, `campaign_id` (also the cluster keys).

## Column meanings (only the non-obvious ones)
- **`epoch`** — event time in **MICROSECONDS**. Verified: `epoch = UNIX_MICROS(time)` exactly
  (1784124501870185 for `time=2026-07-15 14:08:21`). `time` is the same instant as a TIMESTAMP and is the
  partition column.
- **`event_type`** — `URL` (pageview; `raw_event_name` = URL path) or `DLV` (named event;
  `raw_event_name` = event label). Only these two values.
- **`raw_event_name`** — the pixel event string. For URL rows, a path like `/accounts/checking/free-checking`;
  a special value `/__sh_vv_1/channelid/{cid}/cid/{campaign}/cgid/{cgroup}` is the **SteelHouse
  view-verification (VV) beacon** (the numeric segments are channel / campaign / campaign-group ids). For
  DLV rows, labels like `conversion`, `pageview`, `Loaded a Page`, `roktInitComplete`, `cookie_consent_marketing`.
  Classified per-advertiser via `attr_advertiser_waypoints_event_mapping` (see Joins).
- **`source_type`** — attribution touch type: `NULL` (~72–73% — unattributed event), `visits`
  (attributed to a display/site-visit touch), `last_tv_touch_visits` (attributed to the last CTV touch).
  Verified domain 2026-07-15, re-confirmed 2026-07-29.
- **`impression_id`** — the attributed impression id, format `{micros}.{n}.{n}.steelhouse`; NULL on
  unattributed rows. Many waypoint rows share one `impression_id` (the URL row and every DLV row of the
  same visit carry it).
- **`ad_served_id` / `first_touch_ad_served_id`** — served-ad UUIDs for the **last-touch** and
  **first-touch** ad credited to this event; NULL when unattributed.
- **`ip` vs `impression_ip`** — `ip` = the visitor's event IP; `impression_ip` = the IP of the attributed
  impression (equal in practice for IP-matched attribution). No IP→IP bridging in BQ.
- **`is_pa` / `pa_model_id`** — performance-attribution (PA) flag + PA model id; `is_pa=false` /
  `pa_model_id=NULL` on the standard-model rows sampled. Populated for PA-credited events.
- **`is_competing`** — whether the attributed impression is counted as a **competing** (overlapping /
  multi-advertiser) touch under the industry-standard/last-touch lens; NULL when unattributed.
- **`from_verified_impression`** — the attributed impression was view-verified (VV).
- **`attribution_model_id` / `attribution_model_type_id`** — id + type of the attribution model applied
  (e.g. 10 / 3 on sampled rows); NULL when unattributed.
- **`channel_id`** — 8 = CTV, 1 = display; NULL when unattributed.
- **`device_type`** — STRING in silver here (e.g. `SET_TOP_BOX`), unlike the INT encoding in bronze; NULL
  when unattributed.

## Joins & relationships
Waypoints is a many-per-entity **event log**; almost every join fans OUT of the partner dimension.
- **`advertiser_id` → `advertisers.id`** (silver dim, or `bronze.integrationprod.core_advertisers`).
  Partner grain 1 row/advertiser; **N:1** from waypoints (millions of events per advertiser). Filter dim
  `deleted=FALSE AND is_test=FALSE`.
- **`campaign_id` → `campaigns.id`.** Partner 1 row/campaign; **N:1**. Use `campaigns.funnel_level` (not
  `objective_id`) for stage. Populated on attributed rows and most URL/DLV rows.
- **`impression_id` → the impression/attribution log** (SteelHouse impression identifier, `*.steelhouse`
  format). Partner 1 row/impression; **N:1 and fan-out within waypoints too** — one impression maps to many
  waypoint rows (URL + every DLV of the visit), so COUNT(*) over a waypoints↔impressions join
  over-counts impressions. Live-unverifiable here (partner impression table not confirmed this pass) — treat
  as a fan-out warning only.
- **`ad_served_id` / `first_touch_ad_served_id` → ad-serving log** (served-ad UUID). Last-touch vs
  first-touch credit; **N:1**.
- **`raw_event_name` (+ `advertiser_id`) → `attr_advertiser_waypoints_event_mapping`** — per-advertiser
  event-name classification (has a `deleted` flag); companion `attr_advertiser_selective_performance_config`.
  This is the config that turns raw event labels into scored/attributed events. Config dim, **N:1**.
- **`ip` → visit/VV IP** — relates to `visits`/`ui_visits` (the attributed subset, `source_type='visits'`,
  is the fine-grained layer under those rollups). No IP→IP bridging in BQ; IP joins are lossy.

## Gotchas
- **Not deduped.** Exact-duplicate rows exist (identical `DLV` rows for the same impression observed
  2026-07-15). No primary key. If you need distinct events, dedup explicitly; do not assume 1 row = 1 event.
- **One page-load = many rows.** A visit produces a `URL` row plus one `DLV` row per named event, all
  sharing `impression_id`. Counting rows ≠ counting visits or conversions.
- **~72–73% of rows are unattributed** (`source_type IS NULL`) and carry NULL for the whole attribution block
  (`impression_id`, `channel_id`, `device_type`, `attribution_model_id`, `is_pa`, `is_competing`,
  `from_verified_impression`). Filter on `source_type` / `impression_id IS NOT NULL` before treating a row
  as an attributed touch, or your denominators break.
- **`device_type` is a STRING here** (`SET_TOP_BOX`, …), not the bronze INT encoding — don't join it
  numerically.
- **New table, ~5 months of history.** Physical backfilled from **2026-02-10**; no data before that.
- **No TTL** (no partition expiration) — the table grows unbounded; always bound `time`.
- **SQLMesh view.** `summarydata.waypoints` is a view over the hashed physical
  `sqlmesh__summarydata.summarydata__waypoints__2844282736`; the hash changes on model rebuild — query the
  clean `summarydata.waypoints` name, never the hash.

## Cost & partitioning notes
- **Partition = `time` (DAY), NOT enforced (`require_partition_filter=false`) — but always filter it.**
  Cluster = `[advertiser_id, campaign_id, time]`; add advertiser/campaign predicates to prune further.
- **Empirical partition proof (dry-run, `SELECT epoch` only — same one-column set both sides):**
  no filter = **4.51 GB**; `WHERE time >= '2026-07-15' AND time < '2026-07-16'` = **0.103 GB** → ~44× prune.
  Confirms `time` is the partition.
- **Wide scans are expensive:** `SELECT *` for a single day = **2.90 GB** (dry-run), ~28× the one-column
  day. Project only the columns you need. An 11-column, 1-day GROUP BY billed **0.487 GB** (actual).
- **Physical storage** (real backing, single physical, straight `SELECT *` view): **304.96 GB /
  706,535,440 rows** (2026-07-29; was 218.47 GB / 564M on 2026-07-19) across daily partitions
  (2026-02-10 → present); ~3.5–17M rows/day (recent days larger, 16.5M on 2026-07-27).
- **The one filter to always apply:** a bounded `time` range. Add `advertiser_id` / `campaign_id` for
  further cluster pruning.

## Example queries
```sql
-- Attributed events only (a "touch"), one advertiser, one day — prunes partition + cluster
SELECT event_type, raw_event_name, source_type, channel_id, device_type,
       impression_id, ad_served_id, is_competing
FROM `summarydata.waypoints`
WHERE time >= '2026-07-15' AND time < '2026-07-16'
  AND advertiser_id = 36583
  AND source_type IS NOT NULL          -- drops the ~72% unattributed rows
```
