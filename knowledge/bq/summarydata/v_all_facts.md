# summarydata.v_all_facts

## Purpose
The **BQ→ClickHouse reporting EXPORT view** over `summarydata.all_facts`. This is the object the
`airflow-reporting` `load_reporting_data.load_all_facts` DAG reads (BQ → GCS Parquet → external
`v_ext_all_facts` → ClickHouse `all_facts_local_daily`), which then serves R2 / CHAPI metrics
(`graph.usersreached`, `graph.sitevisitors`, CPM, imps/IP). It is **not a fresh table** — it is a thin
view (VIEW → VIEW → the `all_facts` physical TABLE) that reshapes `all_facts` for export in two ways:
1. **Drops test campaigns** — the campaign-attributed rows are INNER-joined to
   `bronze.integrationprod.public_campaigns` and filtered `is_test = FALSE` (64,400 of 548,673 campaigns
   are test → their rows are excluded).
2. **NULL-coalesces every `*_arr` array** — `COALESCE(x_arr, [CAST(NULL AS STRING)])` so the exported
   array container is never NULL (ClickHouse `Array(Nullable(String))` cannot ingest a NULL array).

**When to reach for it:** only when you need the exact rows R2/CHAPI/ClickHouse sees (reconciling a
`graph.*` number, debugging the reporting export). For any internal analysis prefer
`summarydata.all_facts` (identical columns + grain, keeps test campaigns, no array reshaping) or the
narrow fact tables (`impression_facts`, `visit_facts`, `spend_facts`, `conversion_facts`, `site_facts`).

## Grain & keys
- **Grain:** one row per **(`hour` × the 19 `all_facts` dimension keys)** — same grain as `all_facts`.
  It is a `UNION ALL` of two legs: **(leg 1)** campaign-attributed rows (`campaign_id` present, non-test
  campaign) and **(leg 2)** `campaign_id IS NULL` rows (the site-only / conversion-only rows from
  `all_facts`' `site_facts`/`conversion_facts` legs, which have no campaign to join). Empirically one day
  (2026-07-10) = 55.69M rows, of which 55.50M carry a `campaign_id` and 0.19M are `campaign_id IS NULL`;
  145K rows carry a `conversion_source_id`/`conversion_type` (conversion leg).
- **19 dimension keys:** `hour, advertiser_id, campaign_group_id, campaign_id, channel_id, objective_id,
  group_id, creative_id, private_marketplace_id, country, metro_id, region, city, postal_code, domain,
  supply_vendor, device_type, pa_model_id, conversion_source_id`.
- **Partition / join key:** `hour` (DATETIME, DAY partition). Join to dims on `advertiser_id`,
  `campaign_id`, `campaign_group_id`.

## Column meanings (only the non-obvious ones)
- **`hour`** — DATETIME (NOT TIMESTAMP; older catalog notes calling `all_facts.hour` a TIMESTAMP are
  stale — the current physical is DATETIME). Hourly bucket; values are UTC wall-clock. This is the DAY
  partition column.
- **HLL sketch columns (BYTES):** `uniques`, `visitors`, `site_visitors`, `new_site_visitors`,
  `existing_site_visitors`, `new_users_reached`, `existing_users_reached`, `raw_new_site_visitors`,
  `raw_existing_site_visitors`, and the `competing_*`/`probattr_*` `*_site_visitors` variants are
  **HLL++ sketches stored as BYTES** — `SUM()` errors ("cannot coerce BYTES"); use
  `HLL_COUNT.MERGE(col)` for a daily unique count, `HLL_COUNT.MERGE_PARTIAL` to re-aggregate.
- **`uniques`** (= `graph.usersreached`, "Households Reached") — HLL over a **channel-conditional
  IP-OR-GUID key** on the SAME served `cost_impression_log`:
  `CASE WHEN channel_id=8 OR objective_id IN (5,6) THEN ip ELSE guid END`. CTV/video → distinct served
  `ip`; display → distinct cookie `guid`. It **over-counts the served universe ~2× via display GUIDs**
  (WGU 30d: `uniques`=32.1M vs served-IP=15.7M). For a served-IP denominator use
  `cost_impression_log` distinct `ip`, NOT `uniques`.
- **`*_arr` columns (ARRAY<STRING>, NOT NULL):** raw-ID array twins of the HLL sketches
  (`uniques_arr`, `site_visitors_arr`, `users_reached_ip_arr`, the `*_visitors_arr`, day-1..7 arrays,
  `*_tail_arr`, `competing_*_arr`, `probattr_*_arr`). In v_all_facts these are `COALESCE`d so
  NULL→`[NULL]` (hence the `NO`/NOT-NULL mode in the schema). **These, not the BYTES HLL sketches, are
  what R2/CHAPI actually uses** — BQ HLL++ is not ClickHouse-mergeable, so the sketch columns are dead
  downstream; ClickHouse rebuilds reach via `uniqArrayMerge(uniques_arr)` over the window.
  `users_reached_ip_arr` is the newer IP-only reach array (`ARRAY_AGG(ip)`).
- **`competing_*` columns** — the **FIRST-TOUCH** attribution measures (CHAPI labels them
  FirstTouchVisits / FirstTouchConversions / FirstTouchOrderValue). The UI's `industry_standard` /
  "NEW" reporting style = last-touch cols **+ `competing_*`**; Verified Visits =
  `clicks + views + competing_views` (reproduces the UI exactly). Legacy `last_touch` advertisers drop
  `competing_*`.
- **`probattr_*` columns** — probabilistic-attribution measures, keyed to `pa_model_id`.
- **Spend columns (whole USD, NOT micros — do NOT ÷1e6):** `media_spend`, `data_spend`,
  `platform_spend`, `ctv_spend`, `unlinked_spend` (BIGNUMERIC); `media_cost` (NUMERIC);
  `view_order_value`, `click_order_value` and the `*_order_value` variants (NUMERIC, = revenue).
  `ctv_spend`/`media_spend` are advertiser-billed CPM spend (~2× `media_cost`, MNTN's media cost).
  `legacy_spend` (INT64) is a deprecated/legacy field.
- **Scalar INT counts (SUM fine):** `views`, `clicks`, `view_conversions`, `click_conversions`,
  `display_impressions`, `ctv_impressions`, `new_visitors`, `first_touch_visits`, `raw_visits`,
  `raw_conversions`, `visits_assist`, the `first_day_visits..seventh_day_visits` + `visits_tail`
  post-impression decay buckets, and their `competing_*` twins.
- **`raw_visits`** — raw (un-deduped, un-attributed) visit events; very large (~295M/day) — NOT the
  attributed visit count. Attributed visits come from `views`/`clicks`/`competing_views`.
- **`bids`** — always **0** (comment in the model: "No bid_facts in SQLMesh"). Do NOT read as a bid
  stream.
- **`channel_id`** — 8 = CTV (Beeswax Television), 1 = display. **`objective_id`** — prospecting =
  1,5,6; obj 5/6 also route `uniques` to the IP key. **`domain`** — CTV domains are rewritten via
  `to_domain()` when `channel_id = 8`.
- **`conversion_type` / `conversion_source_id`** — populated only on the conversion-leg rows.

## Joins & relationships
- **Internal (baked into the view):** `all_facts.campaign_id = public_campaigns.campaign_id`.
  `bronze.integrationprod.public_campaigns` is **1 row per `campaign_id`** (548,673 rows / 548,673
  distinct, max 1 row/campaign) → **1:1, NO fan-out**; the join is a pure filter that drops test-campaign
  rows (`is_test = FALSE`) and any campaign_id missing from the dim.
- **Downstream (1:1 hourly copy):** exported to ClickHouse `summarydata.all_facts_local_daily`
  (`replace_partitions`, hourly) → CHAPI → R2 `graph.*`. Faithful copy — no re-keying — so the mixed
  IP/GUID reach behavior is inherited verbatim.
- **To dims (all 1:1, safe):** `advertiser_id` → `advertisers.company_name` (use this, NOT
  `fpa_advertiser_verticals.advertiser_name` which is empty since 2025-12); `campaign_id` →
  `campaigns` (`campaigns.name`, funnel_level authoritative for stage); `campaign_group_id` →
  `campaign_groups` (`product_id` 1=PTV/2=Select/3=QuickFrame).
- **Fan-out warning:** joining v_all_facts to a CDC dim that is NOT deduped (e.g. an `archives_*` table)
  will fan out — dedup the dim to one-row-per-key first. The dims above are already 1:1.
- **Underlying physical:** current `all_facts` physical is `summarydata__all_facts__3194417682` (the
  `data_catalog.md` hash `__2291495033` is stale — SQLMesh rebuilt it).

## Gotchas
- **v_all_facts ≠ all_facts.** It EXCLUDES test-campaign rows and NULL-coalesces the `*_arr` arrays. Row
  counts, and any all-advertiser aggregate, will differ slightly from `all_facts`. For clean internal
  analysis use `all_facts` (or the fact tables), not this export view.
- **HLL BYTES columns break `SUM()`** — use `HLL_COUNT.MERGE()`. The `*_arr` twins are the mergeable
  form (and the only reach columns that survive to ClickHouse).
- **`uniques` mixes IP + cookie namespaces** and over-counts display ~2× — wrong denominator for a
  served-IP MDE/IVR baseline (use `cost_impression_log.ip`).
- **Spend is whole USD, not micros.** `ctv_spend`/`media_spend` ≈ 2× `media_cost` (advertiser-billed vs
  MNTN cost).
- **`bids = 0` always** — no bid_facts in SQLMesh.
- **`hour` is DATETIME (no zone), values UTC** — cast with `DATE(hour)`; don't assume TIMESTAMP.
- **Ownership:** SQLMesh model + this export view are owned by the **BER (Backend Reporting)** squad;
  the CHAPI/ClickHouse load DAGs are `SteelHouse/airflow-reporting` (data-platform). Route
  `graph.*`/`all_facts`/reporting-metric change requests to a BER Jira ticket; metric-definition
  questions → #reporting_helpdesk_ask_anything (Ray).

## Cost & partitioning notes
- **Always filter `hour`** (DAY partition). Not enforced (`require_partition_filter = false`), but a full
  scan is ~1.71 TB.
- **Empirical dry-run cost (labeled by column set):**
  - `SELECT hour ... WHERE hour = 1 day` → **0.89 GB** dry-run / 0.83 GB actual (this minimal set still
    reads `campaign_id` too, because the view's internal `campaign_id IS NULL` / join filter references
    it) — vs **1.71 TB** with no `hour` filter (same column set). `hour` filter prunes ~1900×, confirming
    `hour` is the partition.
  - `SELECT ~20 scalar measures ... WHERE hour = 1 day` (grain sample) → **8.31 GB** billed. Wide
    column sets and especially the `*_arr` arrays are far more expensive than the partition-check set —
    pull only the columns you need, never `SELECT *`.
- **Clustering** on the base `all_facts` physical = `(advertiser_id, campaign_id)`; filtering
  `advertiser_id`/`campaign_id` *can* prune, but because v_all_facts is a UNION-of-JOIN view the cluster
  pruning is not guaranteed to pass through — verify with `--dry_run` if relying on it.

## Example queries
```sql
-- daily spend + win impressions for a campaign group (whole USD, no /1e6)
SELECT DATE(hour) AS day,
       SUM(CAST(media_spend AS FLOAT64) + CAST(data_spend AS FLOAT64) + CAST(platform_spend AS FLOAT64)) AS spend,
       SUM(display_impressions + ctv_impressions) AS win_impressions
FROM `dw-main-silver.summarydata.v_all_facts`
WHERE hour >= '2026-07-10' AND hour < '2026-07-11'
  AND advertiser_id = 31460 AND campaign_group_id = 117407
GROUP BY 1 ORDER BY 1;

-- daily unique households reached (graph.usersreached) — HLL merge, NOT SUM
SELECT DATE(hour) AS day, HLL_COUNT.MERGE(uniques) AS households_reached
FROM `dw-main-silver.summarydata.v_all_facts`
WHERE hour >= '2026-07-10' AND hour < '2026-07-11' AND advertiser_id = 31460
GROUP BY 1;

-- UI "Verified Visits" (industry_standard / first-touch style) = last-touch + competing_*
SELECT SUM(clicks + views + competing_views) AS verified_visits
FROM `dw-main-silver.summarydata.v_all_facts`
WHERE hour >= '2026-07-10' AND hour < '2026-07-11' AND advertiser_id = 31460;
```
