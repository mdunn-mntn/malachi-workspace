# summarydata.waypoints__optimizable_event_aggregated

## Purpose
Daily aggregation of **Waypoint** site-events — the intermediate/mid-funnel events (page-URL hits and named dataLayer events) fired on an advertiser's site — rolled up per advertiser x campaign x event, with a **Selective Performance** (`sp_*`) optimization overlay. A "waypoint" here is a tracked on-site event (e.g. a URL path like `/get-started/loans/606/email` or a dataLayer event like `Viewed Recommendations Page`); the campaign can designate one as the **optimizable event** that Selective Performance bids toward instead of the final conversion. Reach for this when analyzing Waypoint/Selective-Performance mid-funnel event volume, ad-served counts, and per-event cost for the beta advertisers on that feature. **Not** a general all-advertiser site-event table (see Gotchas).

## Grain & keys
- **Grain:** one row per `day` x `advertiser_id` x `campaign_id` x `campaign_group_id` x `sp_campaign_group_id` x `event_type` x `raw_event_name` x `event_name` x `optimizable_event_name` x `is_optimizable_event` x `from_verified_impression`. Verified empirically on 2026-07-17: 15,524 groups, max 1 row/group, 0 duplicate groups.
- **Key(s) / join columns:** `advertiser_id` (→ advertisers), `campaign_id` (→ campaigns / line item), `campaign_group_id` (→ campaign_groups / parent), `sp_campaign_group_id` (Selective Performance campaign group — sparse). No surrogate PK column.
- **Note:** `from_verified_impression` and `campaign_id` are part of the grain — the same event splits into multiple rows (verified vs unverified, and per campaign). A naive `GROUP BY advertiser, event` must also collapse these to avoid double-reading a dimension.

## Column meanings (only the non-obvious ones)
- **`day`** — DATE partition column; the event/aggregation day. `require_partition_filter=true` (every query must filter it).
- **`event_type`** — live domain `{URL, DLV}` (SELECT DISTINCT, one week). `URL` = page-URL/path waypoint — `raw_event_name`/`event_name` is the path, e.g. `/get-started/loans/606/loan-details`. `DLV` = named **dataLayer** event — `raw_event_name` is a human label, e.g. `Viewed Recommendations Page`. Matches the `attr_advertiser_waypoints_event_mapping` event-name classification config.
- **`raw_event_name` / `event_name`** — `raw_event_name` = event key as captured (URL path or dataLayer event name); `event_name` = mapped/display name (equal to `raw_event_name` in all sampled URL and DLV rows).
- **`optimizable_event_name`** — non-NULL **only** when `is_optimizable_event = true` (NULL for ~99.97% of rows — 100,010 of 100,042 over a week); equals the `event_name` of the waypoint that the campaign's Selective Performance optimizes toward.
- **`is_optimizable_event`** — BOOL true/false. `true` marks the tiny subset of waypoint events designated as the Selective Performance optimization target (32 of ~100K rows over the sampled week).
- **`from_verified_impression`** — BOOL with observed values **`true` or NULL only — never `false`**. `true` = event attributed to a verified/served ad impression; `NULL` = not tied to a verified impression. It is a **grain dimension**: the same event appears as separate `true` and `NULL` rows. To get the full event total, aggregate over both; `NULL` is not `false`, so `WHERE from_verified_impression = true` silently drops the unverified rows.
- **`sp_campaign_group_id`** — the Selective Performance campaign group id; populated (non-NULL) **only** on optimizable/SP rows, NULL for the vast majority. Observed equal to `campaign_group_id` on SP rows but is a distinct field.
- **`campaign_id` vs `campaign_group_id`** — `campaign_group_id` = parent campaign group (cg_id); `campaign_id` = child campaign / line item. They never coincide (0 rows with `campaign_id = campaign_group_id`).
- **Measures — full vs SP subset.** `event_count` = total waypoint-event occurrences; `selective_performance_event_count` = subset counting toward Selective Performance (== `event_count` on optimizable rows). `ad_served_count` / `sp_ad_served_count` = ads served (all vs SP subset); `user_count` / `session_count` = distinct users / sessions (both broadly populated). `total_spend` (BIGNUMERIC) = spend — **never NULL but frequently 0** (only ~31% of rows > 0 on 2026-07-17); `sp_spend` = Selective-Performance-attributed spend (very sparse, only SP rows; tiny fractional dollars, e.g. 0.97). `cost_per_event` = `total_spend / event_count` (>0 exactly when `total_spend`>0). `sp_cost_per_event`, `sp_cost_per_selective_performance_event`, `sp_cost_per_optimizable_event` = high-precision SP cost ratios (BIGNUMERIC, sparse/0 outside SP rows).
- **`sp_user_count`** — **always 0** (empirically 0 across the sampled week). Column exists but is unpopulated — do not use it.

## Joins & relationships
All dimension joins have this table on the **"many"** side (N:1), so no fan-out from the dim; fan-out risk only if you join two event tables together on `advertiser_id`. Filter `bronze.integrationprod` dims with `deleted=FALSE AND is_test=FALSE`.
- **`advertiser_id` → `integrationprod.advertisers`** — partner grain 1 row/advertiser; **N:1** (many event rows per advertiser). Join to `company_name` for advertiser label.
- **`campaign_group_id` → `integrationprod.campaign_groups`** — 1 row/group; **N:1**. `product_id` (1=PTV/2=Select/3=QuickFrame) and channel context live here.
- **`sp_campaign_group_id` → `integrationprod.campaign_groups`** — same partner; **N:1**, but null-safe / SP-rows-only join (sparse column).
- **`campaign_id` → `integrationprod.campaigns`** — 1 row/campaign; **N:1**. `funnel_level` (on `campaigns`) is authoritative for funnel stage — not any objective_id here.
- **Event classification config:** `attr_advertiser_waypoints_event_mapping` + `attr_advertiser_selective_performance_config` define the event-name → type mapping (deleted flag on waypoints) that produces `event_type`/`event_name`. These are config, not fact tables — no direct row join by count.

## Gotchas
- **NEW + limited scope.** Data begins **2026-05-01** (~90 daily partitions to 2026-07-29); only **~16 advertisers/day**. This is the Waypoint / Selective Performance **beta** aggregation, not a general site-event table — do not treat its coverage as all advertisers.
- **`require_partition_filter = true`** — a query without a `day` filter **errors**. Always filter `day`.
- **`from_verified_impression` is `true`/NULL only** (never `false`). `NULL` = unverified; filtering `= true` drops it. Aggregate over both for totals.
- **`sp_*` columns are sparse** — populated only on the tiny `is_optimizable_event = true` / SP subset (~0.03% of rows). NULL/0 elsewhere. `sp_user_count` is **always 0**.
- **`total_spend` is non-NULL but often 0** (~69% of rows on the sample day); `cost_per_event` is 0 in lockstep. A zero here means no spend attributed, not missing data.
- **`optimizable_event_name` is NULL for ~99.97% of rows** — non-NULL iff `is_optimizable_event = true`.
- **Grain multiplicity.** Because `from_verified_impression` and `campaign_id` are grain columns, `SUM(event_count)` grouped only by advertiser+event still sums across the verified/unverified and per-campaign splits — that's correct for a grand total, but be explicit when you want a single split.

## Cost & partitioning notes
- **Always filter the `day` partition** (required; `PARTITION BY day`, `require_partition_filter=true`, DAY granularity). Cluster keys `[advertiser_id, campaign_group_id, sp_campaign_group_id, event_name]` accelerate advertiser/group/event filters.
- **Whole table is tiny** — `numBytes` = 354,922,174 (~338 MB), 1,202,034 rows, no TTL.
- Dry-run figures (actual `--dry_run`, labeled by column set):
  - **One day, `SELECT *` (all 23 cols, 2026-07-17):** 4,550,782 bytes ≈ **4.55 MB** (0.00424 GB).
  - **Full range, `SELECT *` (all cols):** ≈ **338 MB** (0.33 GB) — the whole table (`numBytes` 354,922,174).
  - **One day, 3 narrow cols** (`advertiser_id, event_name, event_count`): 914,382 bytes ≈ **0.91 MB** — ~5x cheaper than same-day `SELECT *`. The BIGNUMERIC spend/cost columns and long URL `event_name` strings dominate width, so column pruning matters even on this small table.

## Example queries
```sql
-- Waypoint-event volume per advertiser for one day (verified + unverified combined)
SELECT advertiser_id, event_type, event_name,
       SUM(event_count) AS events, SUM(ad_served_count) AS ads_served, SUM(user_count) AS users
FROM `dw-main-silver.summarydata.waypoints__optimizable_event_aggregated`
WHERE day = '2026-07-17'
GROUP BY 1,2,3
ORDER BY events DESC
LIMIT 100;

-- Selective Performance optimizable events only, with SP cost
SELECT day, advertiser_id, campaign_group_id, sp_campaign_group_id, optimizable_event_name,
       selective_performance_event_count, CAST(sp_spend AS STRING) AS sp_spend,
       CAST(sp_cost_per_optimizable_event AS STRING) AS sp_cpoe
FROM `dw-main-silver.summarydata.waypoints__optimizable_event_aggregated`
WHERE day BETWEEN '2026-07-11' AND '2026-07-17'
  AND is_optimizable_event = TRUE
ORDER BY selective_performance_event_count DESC
LIMIT 100;
```
