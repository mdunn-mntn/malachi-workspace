# summarydata.metros

## Purpose
Static geo dimension mapping a **Nielsen DMA code** (`metro_id`) to a human-readable market name and a country. It is the lookup you join to any delivery/summary fact that carries `metro_id` — chiefly impression-grain `logdata.cost_impression_log` (CIL) — to turn a numeric DMA into "New York, NY". No facts, no measures, no time series — pure dimension.

## Grain & keys
- **Grain:** one row per `metro_id` (Nielsen DMA code). 237 rows, `metro_id` is unique (237 distinct) → it is the primary key.
- **Key(s) / join columns:** `metro_id` (INT64) — the sole join key everywhere it is referenced.

## Column meanings (only the non-obvious ones)
- **`metro_id`** — a **Nielsen DMA code**, NOT the internal `geo.location_data.location_id`. This distinction is the #1 source of geo-join bugs (see Joins). Domains observed: US DMAs `500`-`881`; GB regions `100`-`122`; plus two sentinels `-1` and `0` (both name/country = `"unknown"` = unmapped geo). Worked check: New York = `501`, Los Angeles = `803` (Nielsen) — whereas the internal `location_id` for the same markets is 541 / 606.
- **`name`** — market label. US rows read like "New York, NY" / "Portland-Auburn, ME"; GB rows are ITV/broadcast-region names ("Granada", "STV", "YTV Yorkshire", "Anglia East"). 236 distinct names over 237 rows — the one collision is the two sentinels, both named "unknown".
- **`country`** — ISO-2 country code. Distribution: `US` (212), `GB` (23), `unknown` (2 sentinels). NOTE: this table is **not US-only** — it carries 23 UK DMAs, so filter `country = 'US'` when you want US markets only.

## Joins & relationships
- **`metro_id` ↔ `logdata.cost_impression_log.metro_id`** — CIL is the only impression-grain fact carrying `metro_id` (row = impression, `media_cost` = spend). `metros` is the **dim side (unique `metro_id`)**, so this is a safe 1:N enrichment lookup: exactly one market name per CIL row, **no fan-out**. `metros` must always be the one-side, never the many-side.
- **`metro_id` ↔ `geo.location_data.metro_id`** — both are Nielsen codes, so this bridges `metros` to the internal geo dim. **Trap:** `geo.location_data` also has an internal `location_id` whose value DIFFERS from `metro_id` (audience expressions use `location_id`; delivery/summary tables use the Nielsen `metro_id`). Bridge ONLY on the Nielsen `metro_id` — never join a summary `metro_id` to `location_data.location_id`. (TI-1037 module 12b, 2026-07-02.)
- **Does NOT join to `summarydata.sum_by_region_by_day`** — that table's grain is STATE (`region`), not DMA. There is no DMA-grain fact table WITH history; CIL is the only DMA-grain source (retains to the 2025-01-01 GCP floor, not 90-day TTL).

## Gotchas
- **Nielsen, not internal.** `metro_id` here is a Nielsen DMA code. Do not join it to `geo.location_data.location_id` (internal id, different value) — join to `geo.location_data.metro_id`.
- **Two sentinel rows.** `metro_id` `-1` and `0` are both name = country = `"unknown"` (unmapped geo). Exclude them (`metro_id > 0`) for real-market analysis; a fact row with `metro_id` 0 or -1 = geo could not be resolved.
- **Mixed-country.** Contains 23 GB DMAs alongside 212 US DMAs. Filter `country = 'US'` if the analysis is US-only.
- **Static dim, no history.** No time/partition column, no CDC / change_log sibling — a slowly-changing lookup, not a fact/rollup like the `sum_by_*` tables.

## Cost & partitioning notes
- **No partition, no cluster, no TTL** — it is a 237-row base table. Full `SELECT *` (all 3 columns) = **7,729 bytes** (`--dry_run`, 2026-07-19) = the entire table; still billed at the 10 MB tier-1 minimum. Nothing to prune.
- **The one rule:** there is no partition filter to apply — just always use it as the dim (one) side of a join, never the fact (many) side.

## Example queries
```sql
-- Enrich impression-grain delivery with readable DMA names (metros is the safe 1:N dim side)
SELECT m.name AS dma, m.country, SUM(c.media_cost) AS spend, COUNT(*) AS impressions
FROM `logdata.cost_impression_log` c
JOIN `summarydata.metros` m USING (metro_id)
WHERE DATE(c.time) BETWEEN '2026-06-01' AND '2026-06-30'
  AND m.metro_id > 0          -- drop the -1 / 0 unknown sentinels
  AND m.country = 'US'        -- US DMAs only
GROUP BY dma, country
ORDER BY spend DESC
```
