# summarydata.publisher_adsize_metrics

## Purpose
The bid-price source for the bidder. It holds the recent average price paid **per publisher x ad size**, which the bidder uses (a) as the base **bid price** for open-market (non-deal) inventory and (b) as the value compared against the **Publisher Price threshold** (`dso.cpm_thresholds`). It is a small current-state lookup, not an event log — SQLMesh fully rebuilds it each run from `coredw/lds/functions/populate_publisher_adsize_metrics.sql`. The serving copy lives in Aerospike as `rtb.price`. Reach for it when you need "what did MNTN pay for this publisher x creative size lately" or to reason about open-market pricing / bid-drop behavior.

## Grain & keys
- **Grain:** one row per **site (publisher) x ad_format / creative_size**, plus `duration` distinguishing video lengths (15/30s). ~163K rows total: ~22.8K video (`duration>0`) + ~140K display (`duration IS NULL`).
- **Key / join columns:** `(site, width, height, duration)` — the same `width:height:duration` key used by the `rtb.price` serving map. No surrogate id.
- **Special key value:** `site = "default"` = the **cross-publisher fallback** row (one per ad size, ~9 rows). Used when no price exists for the requested publisher x ad size — the bidder falls back to the all-publisher average CPM for that size.

## Column meanings (only the non-obvious ones)
- **site** — publisher identifier: app bundle or domain (e.g. `peacock_ax`, `tubi.entertainment`, `com.odv.nbcu`, `plutotv.comedy`). The literal `"default"` means the cross-publisher fallback row (see Grain & keys).
- **ad_format / creative_size** — both are the `"WIDTHxHEIGHT"` string (e.g. `"1920x1080"`, `"300x250"`); `creative_size` duplicates `ad_format`. NULL on rows with no declared size.
- **width / height** — ad dimensions in px, mirror `ad_format`; NULL when `ad_format` is NULL.
- **duration** — video ad length in **seconds** (15/30). **NULL (not 0) for display/banner** rows — filter `duration IS NULL` for display, `duration > 0` for CTV/video.
- **avg_cpi / min_cpi / max_cpi** — CPI = cost per **single** impression, in **micro-dollars** (integer-valued NUMERIC). Verified exactly `avg_cpi = avg_cpm * 1000` (0/163178 violations); `avg_cpi` always within `[min_cpi, max_cpi]`. **`avg_cpi` is the field the bidder uses** for the base bid price and the Publisher Price threshold.
- **avg_cpm / min_cpm / max_cpm** — cost per **1000** impressions, in **dollars** (NUMERIC, e.g. `9.9222`). `avg_cpm = avg_cpi / 1000`.
- **recommended_cpm** — the CPM recommended to bid; **mirrors `avg_cpm`** in current data.
- **impressions** — impression count backing the averages over the computation window (very large on `default`/major-publisher rows; it is a windowed rollup count, not a single-day count).
- **viewable_impressions** — subset of `impressions` that were viewable; always `<= impressions`.
- **viewability_rate** — FLOAT **percent, 0-100** = `viewable_impressions / impressions * 100`. CTV rows ~100; display lower. Note: the bidder reads the **`logdata.publisher_adsize_metrics`** variant for the viewability threshold, not this column.
- **partner_id** — DSP/partner id; **constant `8`** across the entire current snapshot — not a useful filter.
- **score** — publisher performance score that (per bidder docs) feeds the Publisher Performance threshold. **100% NULL in this summarydata snapshot** (0/163178 populated); the populated score lives in the sibling `logdata.publisher_adsize_metrics` / serving store, not here.
- **video_length** — STRING; **always empty `""`** in current data (superseded by numeric `duration`).
- **last_refresh_date** — TIMESTAMP, **per-row** watermark of when that site x adsize row was last recomputed. NOT a single global snapshot time: values span many days (bulk 2026-07-20 & 2026-07-16 plus a long tail back through older dates); rows for inactive publishers keep stale timestamps.

## Joins & relationships
- **`rtb.price` (Aerospike, serving — non-BQ):** this view is the **source** of that cache; `rtb.price` is an `avg_cpi` map keyed `width:height:duration`. 1:1 conceptually.
- **`logdata.publisher_adsize_metrics` (sibling VIEW):** same column shape, but it is the **viewability** source (`viewability_rate`) and carries the populated **`score`**. Distinct from this (price) view — **do not conflate**.
- **`dso.cpm_thresholds`:** Publisher Price threshold compared against `avg_cpi`. **`dso.publisher_performance_thresholds` + `dso.network_performance_threshold`:** compared against `score` (which is NULL here — see gotcha). **`dso.viewability_score_thresholds`:** compares `viewability_rate` (from the logdata variant).
- **`sync.creative_metadata`:** the base price from this table is scaled per-campaign by `pace_multiplier` (default 1; DCO updates it) to produce the final bid.
- **Joining bid/impression logs on ad size:** key is `(site, width, height, duration)`. This is a small dimension lookup — **1:1 per (publisher x adsize) key** (~163K keys), no fan-out risk. But there is **no date/partition key**, so it can only be a broadcast lookup (join on ad-size dimensions, then optionally match `site` against the publisher/app-bundle field in the log).

## Gotchas
- **No partition, no clustering, no history.** It is a current-state snapshot fully rebuilt by SQLMesh (physical: 163,178 rows / 33,082,554 bytes, `timePartitioning=None`, `clustering=None`). There is **no date column to filter** — `last_refresh_date` is a per-row freshness watermark, not a partition.
- **`score` is entirely NULL** in this summarydata view — for a populated publisher-performance score use the `logdata` variant / serving store.
- **`partner_id` is constant `8`** and **`video_length` is always empty** — neither is a useful filter; use `duration` for video length.
- **`duration IS NULL` (not 0) for display** — a `duration = 0` filter returns nothing.
- **Two views named `publisher_adsize_metrics`:** `summarydata` = **price** (this doc), `logdata` = **viewability + score**. Pick the right one.
- **Rolling-window drift (prose):** the CPM average window is described inconsistently in prose — "last 3 days" (BP Confluence bidder page) vs "~7-day" (Abbas, #production-ops). The authoritative window is defined in `coredw/lds/functions/populate_publisher_adsize_metrics.sql` (not queryable from BQ); the wide `last_refresh_date` spread confirms rows persist beyond the averaging window until recomputed. Treat the exact window as unverified from BQ.
- **Open-market bid-drop:** if MNTN's average publisher CPM here is **below the publisher's impression floor**, the bid is dropped **on MNTN's side** (not sent to Beeswax). PMP deals use fixed pricing and are exempt. Prices are historical win-based, so they do not self-adjust upward when market floors rise.

## Cost & partitioning notes
- **Unpartitioned**, so there is no partition filter to apply — the only cost lever is **column pruning**. The whole table is tiny.
- **Measured dry-runs (label = column set):** `SELECT *` (all 20 cols) = **33,082,554 bytes (~0.031 GB)**; single column `SELECT avg_cpi` = **2,610,848 bytes (~0.0025 GB)**. Same-column-set comparison shows ~13x savings from pruning to one column, but every scan is sub-0.04 GB regardless. `approx_logical_bytes` = 33,082,554 (physical `numBytes`).
- Practically: full scans are cheap; still avoid `SELECT *` and name the columns you need. There is no partition column to filter on.

## Example queries
```sql
-- Latest avg price for a publisher x ad size (CTV example)
SELECT site, avg_cpm, avg_cpi, impressions, last_refresh_date
FROM `summarydata.publisher_adsize_metrics`
WHERE site = 'tubi.entertainment' AND width = 1920 AND height = 1080 AND duration = 30;

-- Cross-publisher fallback prices (one per ad size)
SELECT ad_format, duration, avg_cpm, impressions
FROM `summarydata.publisher_adsize_metrics`
WHERE site = 'default'
ORDER BY impressions DESC;
```
