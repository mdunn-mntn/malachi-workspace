# summarydata.cohort_visit_facts

## Purpose
Cohort-style **visit-attribution rollup**: for each ad-exposure hour (the cohort), it counts the site visits that landed on each subsequent day, sliced by the full campaign / geo / supply / creative / PMP dimension set. Reach for it to answer "how many attributed visits did exposures in hour H generate, and how did they accrue over the N days after exposure?" — i.e. visit-lag / retention curves, day-N attribution, and side-by-side attribution models (deterministic last-touch, last-**TV**-touch, assist, competing/industry-standard, and probabilistic). It is the pre-aggregated backbone for visit-based performance reporting; the competing + last-touch tracks feed the "industry-standard" attribution view surfaced in the client UI (CHAPI). Because it is already aggregated, use it instead of scanning raw impression/visit logs for visit counts by day-since-exposure.

## Grain & keys
- **Grain:** one row per **exposure `hour` x `visit_hour` x day_number x full dimension tuple** (advertiser_id, campaign_group_id, campaign_id, channel_id, objective_id, group_id, creative_id, private_marketplace_id, country, metro_id, region, city, postal_code, domain, supply_vendor, device_type). Verified unique — for one advertiser x one day, 690 dimension groups = 690 rows, max duplicate count = 1.
- **Natural key:** (`hour`, `visit_hour`, all dims). `day_number` is **derived** from `hour` + `visit_hour` (see below), so it is redundant with the natural key, not an independent grain axis.
- **No surrogate/id column** — this is a rollup; measures are the `cohort_*` count columns.

## Column meanings (only the non-obvious ones)
**Time / cohort axis**
- `hour` — **exposure (impression) hour**, DATETIME hour-truncated (minutes/seconds always 00). This is the **partition column** (DAY-truncated for partitioning) and the cohort anchor. Wall-clock; treat as the reporting timezone used across summarydata (not verifiable as UTC from this table alone).
- `visit_hour` — hour the **site visit** occurred, DATETIME hour-truncated. Always `>= hour` (only 2 of 1.14M rows in a sampled day had visit_hour < hour, i.e. boundary noise).
- `day_number` — **1-indexed days-since-exposure bucket** = `FLOOR((visit_hour - hour) in hours / 24) + 1`. Day 1 = visit within 24h of the exposure timestamp, day 2 = 24–48h, etc. 98.6% of rows match the hour-truncated formula exactly; the ~1.4% off-by-one are pure hour-truncation boundary effects (the un-truncated timestamps decide the bucket). Range starts at 1; the max grows with elapsed time (see Gotchas — forward-accrual).

**Measure tracks** (all INT64 counts; a single row can populate several tracks). Four attribution lenses over the same visits:
- `cohort_visits` — total **deterministically-attributed** site visits credited to this exposure cell.
- `cohort_new_visitors` — subset of `cohort_visits` that were **first-time** site visitors (new to the advertiser's site).
- `cohort_last_touch_visits` — visits credited under **last-touch** attribution (this exposure was the last ad touch before the visit).
- `cohort_last_tv_touch_visits` — visits credited under **last-TV-touch** attribution (last CTV/TV touch specifically).
- `cohort_visits_assist` — **assist** credit: this exposure assisted a visit but was not the last touch.
- `cohort_competing_*` (`_views`, `_last_touch_views`, `_last_tv_touch_views`, `_visits_assist`, `_new_visitors`) — the **"competing" track**: visits where a competing (non-MNTN / competitor) ad touch was also present. `last_touch + competing_*` is the basis of the **industry-standard** attribution model shown in the client UI. Use to gauge how much credit MNTN would/would-not get under competitive last-touch rules.
- `cohort_probattr_*` — **probabilistic-attribution** track (modeled, not deterministically matched). This is a **separate** track: rows commonly show `cohort_visits = 0` while `cohort_probattr_views = 1`. Includes `_views`, `_new_visitors`, `_last_touch_views`, `_competing_views`, `_competing_last_touch_views`, `_competing_new_visitors`.

**ARRAY columns** (`ARRAY<STRING>`, declared NON-nullable → empty array `[]` when none, never NULL): the probabilistic-attribution **visitor-identity lists** — each element is a **visitor IP address** (e.g. `146.75.223.231`). Array length tracks the matching `cohort_probattr_*` count.
- `cohort_probattr_site_visitors_arr` / `_new_site_visitors_arr` / `_existing_site_visitors_arr` — all / new / returning probabilistically-attributed visitors.
- `cohort_probattr_competing_site_visitors_arr` / `_competing_new_site_visitors_arr` / `_competing_existing_site_visitors_arr` — same, competing track.

**Dimensions**
- `channel_id` — **8 = CTV, 1 = display** (only these two observed; CTV ≈ 2/3 of rows and visits).
- `private_marketplace_id` — STRING PMP **deal id** (e.g. `IXIVPMNTNDISPLAYUS`, `MNTN-PLU-US-INDEX-ALL`); sentinel **`-3` = open-exchange / non-PMP**. Never NULL.
- `device_type` — STRING (silver-side), e.g. `SET_TOP_BOX` (not the bronze INT encoding).
- `objective_id` — campaign objective (1 = prospecting observed). **Unreliable for funnel stage** per the workspace-wide gotcha — use `campaigns.funnel_level` for stage.
- `domain` — the streaming app / publisher label for CTV (e.g. `Hulu`, `Peacock`, `HBO Max`), site domain for display.
- Geo (`country`, `metro_id`, `region`, `city`, `postal_code`) — populated on essentially all rows (may carry sentinels rather than true NULLs).

## Joins & relationships
This is a fully-aggregated rollup — join it only to **dimension** tables (fact is the N side, dims the 1 side; no fan-out from the dim join):
- `advertiser_id` -> `bronze.integrationprod.core_*` / `advertisers` (1:1 dim). `advertiser_name` on some dims is unreliable — get the name from `advertisers.company_name`.
- `campaign_group_id` -> `campaign_groups` (1:1). `product_id` there gives PTV/Select/QuickFrame.
- `campaign_id` -> `campaigns` (1:1). Use `campaigns.funnel_level` for stage (authoritative), not `objective_id`; `campaigns.name` for label.
- `group_id` -> ad group, `creative_id` -> `creatives` (1:1 dims).
- **Do NOT** join back to raw impression/visit logs at row grain to recompute visits — the counts are already rolled up here; re-deriving from logs double-counts.
- **ARRAY explode:** `UNNEST(cohort_probattr_site_visitors_arr)` produces one row per visitor IP; fan-out = the array length of each row. Only unnest after filtering `hour` and the dims you need.

## Gotchas
- **Forward-accrual / incomplete recent partitions (most important):** the partition is the **exposure** hour, but `visit_hour` runs forward from it. A partition for a recent `hour` keeps gaining rows (higher `day_number`) as visits land over the following days. Sampled exposure `hour = 2026-07-10` (9 days old) showed `day_number` maxing at 11 — the cap is set by *elapsed time*, not the attribution window. **Do not treat the last ~14–30 exposure-day partitions as final**; day-N visit curves are only complete once N days have elapsed since exposure.
- **`hour` vs `visit_hour`:** filtering the partition `hour` selects by **exposure** time, which does NOT bound when the visits happened. To bound visits you must also constrain `visit_hour` — but note `visit_hour` is not the partition, so it does not prune bytes.
- **Probabilistic vs deterministic are distinct universes:** never add `cohort_visits` and `cohort_probattr_views` — they measure different (modeled vs matched) events and `cohort_visits` is frequently 0 where probattr fires. Pick one attribution track per analysis.
- **Attribution double-count:** `cohort_visits`, `cohort_last_touch_visits`, `cohort_last_tv_touch_visits`, `cohort_visits_assist` are overlapping lenses on the same underlying visits — summing across tracks over-counts. Sum within one track only.
- **`day_number` is hour-truncation-derived** — ~1.4% of rows sit one bucket off a naive recompute from the truncated `hour`/`visit_hour`; trust the stored `day_number`, don't recompute it from the truncated columns.
- **Arrays hold IPs, and can be large** — the `*_arr` columns dominate the row byte size; `SELECT *` pulls them and is far more expensive than selecting scalar measures.
- **WGU (advertiser_id 31357)** appears heavily (≈30% of MNTN spend) — exclude or treat as an outlier for representative analysis.

## Cost & partitioning notes
- **Always filter `hour`** (partition, DAY). It is not `require_partition_filter`-enforced (`false`), so an unfiltered query silently full-scans — add the filter yourself.
- Partition `hour` (DAY), cluster **[advertiser_id, campaign_group_id, campaign_id, day_number]** — adding an `advertiser_id` (and then campaign) predicate prunes further *within* the day via clustering.
- **Measured (dry-run, upper bound):**
  - `SELECT *`, one day (`hour` in [2026-07-10, 2026-07-11)): **~360 MB** (0.360 GB).
  - `SELECT *`, no filter (full table): **~312 GB** (312,449,947,680 bytes) — the `hour` filter prunes ~870x.
  - Scalar-only single-day scans run **~18–65 MB** (measured across the sample queries above); avoiding the `*_arr` columns is the single biggest byte saver vs `SELECT *`.
- Physical backing: `sqlmesh__summarydata.summarydata__cohort_visit_facts__3728990658`, TABLE, **995,797,558 rows / 312,449,947,680 bytes**, **566 daily partitions spanning 2025-01-01 -> present**, **no TTL** (no expiration). The `summarydata.cohort_visit_facts` view is a pass-through `SELECT *` over it.

## Example queries
```sql
-- Day-N visit accrual curve for one advertiser, exposures in a date window
SELECT day_number,
       SUM(cohort_visits)             AS visits,
       SUM(cohort_new_visitors)       AS new_visits,
       SUM(cohort_last_touch_visits)  AS last_touch_visits
FROM `summarydata.cohort_visit_facts`
WHERE hour >= '2026-07-01' AND hour < '2026-07-08'   -- partition prune (exposure hour)
  AND advertiser_id = 36794                            -- cluster prune
  AND channel_id = 8                                   -- CTV only
GROUP BY day_number
ORDER BY day_number;

-- Explode probabilistic-attribution visitor IPs for one exposure day
SELECT advertiser_id, campaign_id, ip
FROM `summarydata.cohort_visit_facts`,
     UNNEST(cohort_probattr_site_visitors_arr) AS ip
WHERE hour >= '2026-07-10' AND hour < '2026-07-11'
  AND advertiser_id = 31357;
```
