# summarydata.publisher_adsize_metrics_v1

## Purpose
Publisher inventory pricing & quality reference: for each publisher **site** (CTV app bundle / domain) and **ad size** (`ad_format` = WxH), the observed **CPM range** (avg/min/max), **impression volume**, **viewability**, and a **recommended CPM**. Reach for it to answer "what does a given ad slot on a given publisher typically clear at, and how viewable / high-volume is it?" — i.e. to set or sanity-check bid prices / floor guidance per publisher x creative size. Only one partner's inventory is present (`partner_id` ≡ 8; see gotchas).

## Grain & keys
- **Grain:** one metrics **snapshot row** per (`site`, `ad_format` = `width` x `height`, `duration`) written at each refresh. This is an **accumulating history**, not a current-state table: the same logical key appears once per refresh (`valid_from` ≈ `last_refresh_date`), and on top of that ~2.7M row-groups are **fully-identical duplicates**. 19.47M physical rows vs 13.07M distinct (site, ad_format, w, h, duration, valid_from) combos — so no column set is a natural unique key as stored.
- **To get "current" metrics per slot:** partition by (`site`, `ad_format`, `width`, `height`, `duration`) and take `MAX(last_refresh_date)` (equivalently latest `valid_from`), then `DISTINCT`/`ROW_NUMBER` to collapse the exact duplicates. **Do not** filter on `valid_to` (see gotchas).
- **Logical key columns:** `site` + `ad_format` (or `width`,`height`) + `duration` + `partner_id`. `site="default"` (717 rows) is a **cross-site fallback bucket** (aggregate pricing when no site-specific row exists), not a real publisher.

## Column meanings (only the non-obvious ones)
- **`site`** — publisher inventory identifier: reverse-DNS **app bundle ID** for CTV (e.g. `com.odv.nbcu`) or a domain; the literal `"default"` is a fallback/aggregate bucket (717 rows), not a publisher. 99,605 distinct values.
- **`ad_format`** — creative size string `"WxH"` (e.g. `1920x1080`, `300x250`, `320x50`, `728x90`, `160x600`, `300x600`, `300x50`, `1080x1920`). 8 IAB-standard sizes plus a **NULL bucket** (3.13M rows / 53.5K sites) = site-level rows with no size breakdown. When `ad_format IS NULL`, `width` and `height` are also NULL and `creative_size` is empty too (they move together — creative_size is NOT a fallback for ad_format).
- **`width` / `height`** — parsed from `ad_format`; NULL exactly when `ad_format` is NULL (3.13M rows).
- **`duration`** — video ad length in **seconds** (dominant value 30; also 15). NULL for **display** sizes (~15.55M rows / 80%). A tiny handful (~290 rows) carry ms-scale values (`15015`, `30072`) — data-quality outliers.
- **`avg_cpi` / `min_cpi` / `max_cpi`** — cost **per single impression** in **micro-dollars** (millionths of a dollar). Empirically `avg_cpi = avg_cpm x 1000` (ratio 1000.01). So `avg_cpi 8652` ⇔ `avg_cpm 8.6519`. Use `*_cpm` for human-readable dollars-per-1000.
- **`avg_cpm` / `min_cpm` / `max_cpm`** — observed clearing price range, **dollars per 1000 impressions**.
- **`recommended_cpm`** — the suggested CPM. **Redundant: exactly equals `avg_cpm` for 100% of rows** (all 19.47M). Treat as a copy of `avg_cpm`, not an independent signal.
- **`viewability_rate`** — percent, **0–100 scale** (not a 0–1 fraction). `= viewable_impressions / impressions x 100`.
- **`impressions` / `viewable_impressions`** — impression counts backing the metric window; `viewable_impressions ≤ impressions`.
- **`partner_id`** — **constant = 8 for every row** (only one distinct value). A single source/partner is represented; not a usable filter/join dimension here.
- **`creative_size`** — duplicate of `ad_format` when present; empty/NULL when `ad_format` is NULL.
- **`video_length`** — STRING, **empty (`""`) for 100% of rows** — defined but never populated. Use `duration` for video length.
- **`score`** — INT64, **NULL for 100% of rows** — defined-but-empty column. Do not use.
- **`last_refresh_date`** — TIMESTAMP when the snapshot row was computed/written; the de-facto version timestamp and the correct key for "latest". Range 2025-04-25 → present (3,698 distinct values).
- **`valid_from` / `valid_to`** — DATETIME intended as an SCD-2 validity window. **`valid_from` ≈ `last_refresh_date` (98.6% exact match)** and is reliable. **`valid_to` is NOT reliable**: it precedes `valid_from` for 9.3% of rows and does not form clean contiguous intervals (initial versions carry `valid_from = 1970-01-01` epoch sentinel). Never use `valid_to` to pick the active version.

## Joins & relationships
- **No enforced FK columns in this table.** `site` is a publisher app-bundle/domain string — it can join to bid/impression/publisher tables that carry the same app-bundle/site string, but there is **no numeric publisher/partner id to join on** here (`partner_id` is the constant 8).
- Because this is an **accumulating snapshot with duplicates**, any join **must first collapse to one row per (site, ad_format, width, height, duration)** (latest `last_refresh_date` + `DISTINCT`) or it fans out massively (up to 8,192 rows for a single key+valid_from). Treat the un-deduped view as **N:many** on every key.
- No live-verifiable partner table was needed for the core claims (all confirmed against this physical); leaving as a reference/pricing lookup rather than a join hub.

## Gotchas
- **Not partitioned, not clustered, no TTL.** The physical is a flat ~4 GiB table; every query full-scans the columns you select (a `WHERE last_refresh_date > ...` filter does **not** prune — verified: it read both columns fully). Prune by **column projection**, never expect date pruning.
- **Duplicate rows are pervasive** — ~2.7M fully-identical row-groups. Always `DISTINCT`/`ROW_NUMBER` before counting, summing, or joining.
- **`valid_to` is unreliable** (precedes `valid_from` 9.3% of the time; not contiguous). Use `last_refresh_date` / `valid_from` to select the latest version, never the `[valid_from, valid_to]` interval.
- **`score`, `video_length` are always empty; `recommended_cpm` always equals `avg_cpm`; `partner_id` always 8** — four columns carry no information. Don't build logic on them.
- **`avg_cpi` is micro-dollars-per-impression**, not a CPM — 1000x the `avg_cpm` value. Don't mix `*_cpi` and `*_cpm` in the same comparison.
- **`viewability_rate` is 0–100**, not 0–1 — a bare value of `100` means fully viewable.
- **`site="default"`** is a synthetic fallback bucket carrying huge aggregate impression totals; **exclude it** when profiling real publishers or it dominates any `ORDER BY impressions`.
- **NULL ad_format/width/height** (3.13M rows) = site-level rows without a size breakdown — filter them out for size-specific analysis.
- Physical `creationTime` ≈ `lastModifiedTime` (rebuilt wholesale each SQLMesh run), so the whole history is re-materialized every refresh — `numRows`/`numBytes` are real (not the usual SQLMesh 0 sentinel).

## Cost & partitioning notes
- **No partition column — cost lever is column projection only.** Dry-run figures (labeled by column set), full-table each:
  - `SELECT *` → **4,345,325,287 bytes (~4.05 GiB)** = full physical `numBytes`.
  - `SELECT site` (1 narrow STRING col) → **416,878,983 bytes (~397 MiB)**.
  - `SELECT site WHERE last_refresh_date > TIMESTAMP('2026-01-01')` (site + last_refresh_date, 2 cols) → **572,639,079 bytes (~546 MiB)** — the filter added the second column's bytes and pruned **nothing**, empirically confirming no partitioning.
  - Overview aggregate over 6 date/dim cols → **~0.99 GB** billed (actual run).
- **approx_logical_bytes = 5,170,021,682** (single physical `numBytes` as of 2026-07-29; ~4.82 GiB, ~23.12M rows). The accumulating snapshot grew ~19% since 2026-07-19 (was 4,345,325,287 B / 19.47M rows), so the dated 2026-07-19 dry-run byte figures above are now lower bounds.
- **Always:** select only the columns you need; add `WHERE site != "default"` and/or `WHERE ad_format IS NOT NULL` to scope to real per-size publisher rows; dedup to latest `last_refresh_date` before aggregating.

## Example queries
```sql
-- Latest CPM/viewability per publisher site x ad size (dedup + latest version)
SELECT site, ad_format, width, height, duration,
       avg_cpm, min_cpm, max_cpm, recommended_cpm,
       impressions, viewable_impressions, viewability_rate
FROM (
  SELECT *,
         ROW_NUMBER() OVER (
           PARTITION BY site, ad_format, width, height, duration
           ORDER BY last_refresh_date DESC
         ) AS rn
  FROM `summarydata.publisher_adsize_metrics_v1`
  WHERE site != 'default' AND ad_format IS NOT NULL
)
WHERE rn = 1
```
