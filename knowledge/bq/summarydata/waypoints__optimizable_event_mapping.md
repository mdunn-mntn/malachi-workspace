# summarydata.waypoints__optimizable_event_mapping

## Purpose
Atomic, **row-level event stream** for the **Waypoints** funnel/optimization product. One row per raw on-site tracked event (a page URL match or a GTM `dataLayer` variable match fired by the Waypoints/conversion pixel), attributed to the impression that drove the visit (`ad_served_id`, `from_verified_impression`) and to the advertiser/campaign/user-session. Each raw event is then **classified against the advertiser's Selective-Performance config**: `is_optimizable_event` / `optimizable_event_name` flag whether that event is one the advertiser has designated as an "optimizable event" (an event MNTN's optimizer bids toward). Reach for it when you need event-grain Waypoints activity (individual events, per-user/per-session sequences, ad_served_id-level attribution) rather than daily counts. For daily rollups use the sibling **`waypoints__optimizable_event_aggregated`** — this table is its atomic source. Data begins **2026-05-01** (new product; ~2.5 months of history as of 2026-07-19).

## Grain & keys
- **Grain:** one row per **raw tracked-event emission** = advertiser x user-session x page/URL-or-dataLayer event, at microsecond `time`. There is **no unique row-id column**, and the table is **NOT deduplicated** — the same event can appear as multiple identical rows: 3,377,299 rows collapse to 1,793,899 distinct `(epoch, guid, ad_served_id, raw_event_name)` on 2026-07-17 (~47% duplication). Use `COUNT(DISTINCT ...)` / `GROUP BY` for unique-event counts; never `COUNT(*)` raw.
- **Key(s) / join columns:** `ad_served_id` (impression UUID -> event_log/clickpass_log/ui_visits, 1:N), `advertiser_id` / `campaign_id` / `campaign_group_id` (dims), `user_key` = `advertiser_id|ga_client_id`, `session_key` = `advertiser_id|ga_client_id|ga_session_id`, `guid` (deterministic user UUID).

## Column meanings (only the non-obvious ones)
- **`time`** — TIMESTAMP of the event.
- **`epoch`** — the same instant as `time` in **microseconds**: `epoch == UNIX_MICROS(time)` exactly (verified 2026-07-19, e.g. 1784246627723060 == UNIX_MICROS('2026-07-17 00:03:47')). Not millis/seconds. Redundant with `time`.
- **`day`** — DATE **partition column** (see Cost). Truncation of `time`. A small `day IS NULL` partition exists (only reachable via `WHERE day IS NULL`); normal date partitions have 0 NULLs.
- **`event_type`** — detection method of the raw event, only two values (verified): **`URL`** = matched by visited page URL path; **`DLV`** = matched by GTM **dataLayer variable**. Uppercased mirror of `waypoint_event_mapping.pattern_type` (`url`/`dlv`). ~81% DLV / ~19% URL on 2026-07-17.
- **`raw_event_name`** — the raw event label as fired: advertiser-defined, high-cardinality, free-text — page paths (`/get-started`, `/member`), pixel event names (`Track`, `conversion`, `LandingPage`, `SecondPage`), or funnel/interest labels (`SelfStatedAmount10Kplus`). Not a shared enum.
- **`optimizable_event_name`** — canonical label of the event when it is an optimizable event; **NULL otherwise**. Set **iff** `is_optimizable_event = true` (perfect biconditional, verified: 17,089 true rows all non-null, 3,360,210 false rows all null on 2026-07-17). In samples it equals `raw_event_name` (the raw event promoted to optimizable).
- **`is_optimizable_event`** — BOOL; true only for the small subset of events the advertiser designated for Selective-Performance optimization (~0.5% of rows, 17K/3.38M on 2026-07-17). Derived from advertiser config, not the raw event itself.
- **`from_verified_impression`** — BOOL, observed values **`true` or NULL only** (never `false`). `true` = event tied to a verified impression; NULL = not attributed to a verified impression. Use `= true` for verified-impression attribution (NULL-safe: `IS NOT TRUE` excludes).
- **`user_key`** — `advertiser_id|ga_client_id` (advertiser-scoped user identity, e.g. `34114|100801674.1784328596`). Never NULL. Also a **cluster key**.
- **`session_key`** — `advertiser_id|ga_client_id|ga_session_id` (advertiser-scoped session). NULL in a small share (~0.4-2%) when `ga_session_id` is missing.
- **`guid`** — deterministic per-user UUID (v3-style hash), advertiser-scoped user identity parallel to `user_key`.
- **`ga_client_id`** / **`ga_session_id`** — Google Analytics client id (`100801674.1784328596`) and session id (unix-seconds-like `1784328597`); the building blocks of `user_key`/`session_key`.
- **`ad_served_id`** — UUID of the impression this event is attributed to (join key to event_log/clickpass_log/ui_visits). Populated for both event types.
- **`campaign_group_id`** — the MNTN **campaign-group** id (= `cg_id`); also a **cluster key**.

## Joins & relationships
- **`waypoints__optimizable_event_aggregated`** (1:N; this table is the atomic source) — the daily rollup GROUPs this stream by `day x advertiser_id x campaign_id x campaign_group_id x event_type x raw_event_name x optimizable_event_name x is_optimizable_event x from_verified_impression`, adding `event_count / user_count / session_count / *_spend / sp_*`. Prefer the aggregate for daily counts; use this table only for event-grain work.
- **Impression tables via `ad_served_id`** (event_log / clickpass_log / `CAST(ui_visits.ad_served_id AS STRING)`) — one impression -> many events, **1:N**. Fan-out is compounded here because this table itself carries ~47% duplicate rows; dedup this side (`GROUP BY`/`DISTINCT`) before joining or counts inflate. Use `from_verified_impression = true` to restrict to verified-impression events.
- **Dims** `advertiser_id` / `campaign_id` / `campaign_group_id` -> integrationprod `advertisers` / `campaigns` / `campaign_groups` (filter `deleted=FALSE AND is_test=FALSE`); N events per dim key.
- **Config lineage** — the `is_optimizable_event` / `optimizable_event_name` classification derives from advertiser Selective-Performance config; related config/dimension tables: `waypoint_event_mapping` (URL/dataLayer -> funnel event config) and `attr_advertiser_selective_performance_config` (event-name classification). This view does not physically join to them at read time.

## Gotchas
- **`requirePartitionFilter = true`** — a query without a `WHERE day ...` predicate **errors** ("Cannot query over table ... without a filter over column(s) 'day'"). Always filter `day`.
- **NOT deduplicated** — ~47% of rows are exact duplicates of another row; never `COUNT(*)` for event counts. Dedup on `(epoch, guid, ad_served_id, raw_event_name)` or aggregate.
- **`epoch` is redundant** with `time` (microseconds) — don't treat it as a distinct signal.
- **`from_verified_impression` is tri-state in schema but binary in data** (true / NULL, no false) — a naive `= false` filter returns nothing; use `IS NOT TRUE` to get the complement.
- **`optimizable_event_name` NULL ≠ missing data** — it is NULL by design for every non-optimizable event (the vast majority). Filter `is_optimizable_event = true` to get the optimizable subset.
- **Small, recent product** — history starts 2026-05-01; only ~16 advertisers active/day (2026-07-17). Not representative of all MNTN advertisers.
- **SQLMesh view** — query the clean name `summarydata.waypoints__optimizable_event_mapping`; it is a `SELECT *` over the versioned physical `sqlmesh__summarydata.summarydata__waypoints__optimizable_event_mapping__258721018` (hash changes on rebuild).

## Cost & partitioning notes
- **Partition = `day` (DATE, DAY, requirePartitionFilter=TRUE); cluster = [advertiser_id, campaign_group_id, user_key]; no TTL.** Physical: ~112.7M rows / **30.25 GB** (`bq show` numBytes 30,250,874,468, whole table). Partitions span **2026-05-01 -> 2026-07-29** (~91 partitions incl. a `__NULL__` day partition).
- **Always filter `WHERE day = '<date>'`** (or a small `day` range) — the query errors otherwise. Then narrow further on the cluster keys `advertiser_id` / `campaign_group_id` / `user_key`, and select only needed columns.
- Dry-run cost, one day 2026-07-17 (~3.38M rows), by column set:
  - `SELECT *` → **901,614,572 bytes (~0.90 GB)**
  - `SELECT day` (one narrow column) → **27,018,392 bytes (~27 MB)** — ~33x cheaper than `SELECT *`, illustrating column pruning.
  - `SELECT event_type, is_optimizable_event, from_verified_impression` (three cols) → ~0.047 GB.
- A no-`day`-filter probe **fails** (requirePartitionFilter) — confirming `day` is the partition empirically.

## Example queries
```sql
-- Optimizable events for one advertiser on one day (uses partition + cluster keys)
SELECT time, raw_event_name, optimizable_event_name, ad_served_id, user_key, from_verified_impression
FROM `summarydata.waypoints__optimizable_event_mapping`
WHERE day = '2026-07-17' AND advertiser_id = 34114 AND is_optimizable_event = TRUE
LIMIT 100;

-- Deduped event counts by type (never COUNT(*) — table has ~47% dup rows)
SELECT event_type,
       COUNT(DISTINCT FORMAT('%t|%s|%s|%s', epoch, guid, ad_served_id, raw_event_name)) AS unique_events
FROM `summarydata.waypoints__optimizable_event_mapping`
WHERE day = '2026-07-17'
GROUP BY event_type;
```
