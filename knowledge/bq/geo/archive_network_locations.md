# geo.archive_network_locations

## Purpose
Versioned archive of the IP-network → geolocation map for the native BigQuery geo pipeline: every IP
network block (CIDR) MNTN resolves, snapshotted biweekly, with the block's resolved location
(`geoname_id`, city/region/country, lat/long, DMA). Reach for it to resolve an IP address to a place
**as of a given date** (IP→geo enrichment, geo backfills, auditing how a network's location changed over
time). It is a MaxMind GeoIP2-"blocks"-style feed keyed on CIDR, with MNTN's internal metro id
(`metro_id_cil`) merged in. Pair with `geo.location_data` / `analytics_curated.static_combined_lat_long_data`
(keyed on `geoname_id`) to turn the resolved id into MNTN's location hierarchy.

## Grain & keys
- **Grain:** one row per (`network` CIDR block, `geo_version` snapshot). Confirmed: ~209M rows across
  **23 versions**, each version ~9M network blocks.
- **Natural key (within a version):** `network` (the CIDR string, e.g. `43.226.224.0/22`).
- **Version key:** `geo_version` (epoch seconds) = `geo_version_ts` (TIMESTAMP, the DAY partition).
- **Foreign / join columns:** `geoname_id` → `geo.location_data.geoname_id` /
  `analytics_curated.static_combined_lat_long_data.geoname_id` (MaxMind/GeoNames id);
  `metro_id` = MaxMind DMA id; `metro_id_cil` = MNTN-internal (CIL) metro id.

## Column meanings (only the non-obvious ones)
- `network` — the CIDR block this row describes (e.g. `43.226.224.0/22`). Lookup is by **CIDR
  containment** (does the IP fall in the block), not equality.
- `bits` — the CIDR prefix length / netmask bits (the `/N`: observed 22, 24, 32). Pairs with `network`.
- `network_first_8_bits` — first octet as INT (e.g. `43`); coarse range index.
- `network_first_16_bits` — first two octets as STRING (e.g. `"43.226"`); **cluster key #2** — filter on
  it (with `country_iso_code`) to prune blocks within a version.
- `geoname_id` — MaxMind/GeoNames id of the resolved location; the join key into the location
  dimensions. Many networks can share one `geoname_id`.
- `metro_id` — MaxMind DMA/metro id; sparse (NULL outside US and for many US blocks).
- `metro_id_cil` — MNTN-internal (CIL = Client IP Location) metro id mapping; sparse (NULL for most rows
  in the sample).
- `accuracy_radius` — MaxMind location accuracy radius in km (e.g. `1000` for a coarse country-level
  resolution).
- `latitude` / `longitude` — NUMERIC coordinates of the block's resolved location.
- `region` / `region_iso_code` — subdivision-1 (state/province); `subdivision_2_*` = subdivision-2
  (county-level). Often NULL for coarse blocks.
- `locale_code` — language locale of the human-name strings (city/region/country).
- `is_in_european_union` — MaxMind EU flag (BOOL).
- `geo_version` — snapshot version = **epoch seconds** of the version date (`1785110400` = 2026-07-27).
- `geo_version_ts` — same instant as a TIMESTAMP; **the DAY partition column** (filter this).

## Joins & relationships
- **IP→location dimensions:** `geoname_id` → `geo.location_data.geoname_id` and
  `analytics_curated.static_combined_lat_long_data.geoname_id` to walk MNTN's location hierarchy /
  attach names. One `geoname_id` → many `network` rows (this table is the "many" side of geoname).
- **Fan-out warning — versions.** Every `network` appears once **per `geo_version`** (23 versions ≈ 23×
  fan-out). Always pin a single version (`geo_version_ts = <one date>` or `= (SELECT MAX(geo_version_ts) …)`)
  before joining or counting, or IP lookups will match 23 rows per block.
- **IP resolution is range/containment**, not an equi-join: narrow candidates with
  `network_first_8_bits` / `network_first_16_bits` (or `NET.IP_FROM_STRING` range logic), then test CIDR
  containment on `network` + `bits`.

## Gotchas
- **View metadata is misleading; the physical table is the truth.** The view reports itself
  unpartitioned/unclustered; the resolved physical `sqlmesh__geo.geo__archive_network_locations__2382992909`
  is **partitioned by `geo_version_ts` (DAY)**, **clustered `[country_iso_code, network_first_16_bits]`**,
  ~209M rows. (SQLMesh metadata here is fresh — 209M rows reported, not the usual stale `numRows: 0`.)
  Empirically confirmed: an unfiltered scan of a few columns = ~8.67 GB; a single-`geo_version_ts` filter
  prunes it (one absent day → 0 bytes; one present version ≈ 0.4 GB).
- **`require_partition_filter` is NOT enforced** (false). A naive query silently scans all 23 versions
  (~209M rows). Always add a `geo_version_ts` filter yourself.
- **Versions are biweekly with gaps.** 23 versions loaded, ~every 14 days, from **2025-08-11** to
  **2026-07-27** (latest). There is a gap (no version between 2025-09-08 and 2025-11-06). Don't assume
  a fixed cadence or that a specific date exists — check the loaded set.
- **Coarse blocks have sparse geography.** Many `/22`–`/24` blocks resolve only to country (city /
  region / postal NULL, `accuracy_radius` ~1000). Don't treat NULL city as a data error.
- **`metro_id` vs `metro_id_cil`.** `metro_id` = MaxMind DMA; `metro_id_cil` = MNTN internal metro. Both
  sparse; pick the one matching the join target's id space.

## Cost & partitioning notes
- **Always filter `geo_version_ts`** (TIMESTAMP, DAY partition; the version date at 00:00 UTC).
  `require_partition_filter: false` — the filter is on you. Pin the latest version with
  `geo_version_ts = (SELECT MAX(geo_version_ts) FROM …)` for "current" IP→geo.
- **Clustered on `country_iso_code`, then `network_first_16_bits`** (source order). Filtering
  `country_iso_code` (leading key) and/or `network_first_16_bits` prunes blocks within a version.
- Full-table (all 23 versions) scan of a few columns ≈ **8.67 GB**; one version ≈ **0.4 GB**. Avoid
  `SELECT *` — the table is wide (25 columns). Project only what you need.

## Example queries
```sql
-- Current (latest-version) IP→geo for a country slice, cluster-pruned
SELECT network, bits, geoname_id, city, region_iso_code, country_iso_code,
       latitude, longitude, accuracy_radius, metro_id_cil
FROM `dw-main-bronze.geo.archive_network_locations`
WHERE geo_version_ts = (SELECT MAX(geo_version_ts)
                        FROM `dw-main-bronze.geo.archive_network_locations`)
  AND country_iso_code = 'US'
  AND network_first_16_bits = '43.226';

-- List loaded snapshot versions (partition inventory)
SELECT DATE(geo_version_ts) AS ver_date, geo_version, COUNT(*) AS n_networks
FROM `dw-main-bronze.geo.archive_network_locations`
GROUP BY 1, 2 ORDER BY 1;
```
