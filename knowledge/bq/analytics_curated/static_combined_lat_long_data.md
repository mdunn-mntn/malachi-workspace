# analytics_curated.static_combined_lat_long_data

## Purpose
Static geo-location dimension with lat/long merged in: every place in MNTN's location hierarchy
(countries, regions, cities, postal codes) as one row, plus its coordinates. It is the "combined
lat/long" companion to the CoreDW geo location dimension, exported to Parquet in GCS and exposed as a
BigQuery **external** table. Reach for it to turn a `location_id`, `geoname_id`, or `old_location_id`
into a name, country, time zone, DMA, ancestry path, and coordinates in a single lookup. It mirrors the
column shape of `geo.location_data` (same hierarchy) but adds `lat`/`long` and drops the versioning
columns — it is a **static snapshot**, not versioned.

## Grain & keys
- **Grain:** one row per `location_id` (a node in the geo hierarchy). Confirmed: 663,088 rows =
  663,088 distinct `location_id`; 6 distinct `location_type_id`.
- **Primary/natural key:** `location_id` (unique).
- **Foreign / join columns:** `parent_location_id` → `location_id` (self-reference, immediate parent);
  `hierarchy` = nested list of ancestor `location_id`s root→self; `old_location_id` → legacy CoreDW
  `geo.locations` id; `geoname_id` → MaxMind/GeoNames id (bridge to
  `geo.archive_network_locations.geoname_id`); `metro_id` → DMA metro id.

## Column meanings (only the non-obvious ones)
- `location_id` — stable unique id for this place; the join key everything else references.
- `location_type_id` — the tier of the location. 6 distinct values observed. Inferred from the sibling
  `geo.location_data` (confirm against a `location_types` lookup before hard-coding): `2` = country,
  `5` = region/subdivision, `6` = city, `7` = postal/sub-city (sample also showed `5`/`6`/`7`).
- `parent_location_id` — immediate parent's `location_id`; NULL at the country root.
- `hierarchy` — the full ancestry path root→self, stored as the **Parquet 3-level list encoding**
  `STRUCT<list ARRAY<STRUCT<element INT64>>>` (NOT a flat `ARRAY<INT64>`). Access via
  `UNNEST(hierarchy.list)` then `.element`; `ARRAY_LENGTH(hierarchy.list)` = ancestry depth.
- `location` — the place's own name, or the postal code string for postal-tier rows ("75068").
- `sub_location1` / `sub_location2` — denormalized ancestor names for display: `sub_location1` ≈
  region/state, `sub_location2` ≈ country. Populated only for lower tiers; NULL for countries/regions.
- `iso_code` — ISO code of the location itself (populated for country/region rows; NULL for cities).
- `country_iso_code` — 2-letter ISO country code of the row's country ancestor (e.g. "US"). Use THIS to
  filter to a country, not `iso_code`.
- `time_zone` — IANA tz name (e.g. "America/Chicago"); populated for lower tiers, NULL for coarse ones.
- `metro_id` — DMA (Designated Market Area) metro id; sparse.
- `geoname_id` — MaxMind/GeoNames identifier; the bridge to the IP-network feed.
- `old_location_id` — legacy CoreDW `geo.locations` id, for mapping to pre-migration data.
- `lat` / `long` — coordinates as **BIGNUMERIC** (not FLOAT). Frequently **NULL** — postal rows tend to
  carry them; region/country rows often do not. Cast/guard for NULL.

## Joins & relationships
- **Self-join for hierarchy:** `parent_location_id` → `location_id` walks up one level; `hierarchy`
  gives the whole path (UNNEST `hierarchy.list`, read `.element`).
- **IP→geo bridge:** `geoname_id` → `geo.archive_network_locations.geoname_id` resolves an IP-network's
  `geoname_id` to this hierarchy node (with coordinates).
- **Sibling dimension:** same hierarchy/columns as `geo.location_data`; this one adds `lat`/`long` and
  is a static snapshot (no `geo_version` columns).
- **Fan-out warning:** joining a fact on a **coarse** tier (`country_iso_code`, `metro_id`) fans out —
  many `location_id`s share them. Join on `location_id` (or `geoname_id`/`old_location_id`) for a 1:1
  lookup; anything coarser is one-to-many.

## Gotchas
- **EXTERNAL table over Parquet in GCS** (`gs://mntn-analytics-curated/coredw/geo/static_combined_lat_long_data/*.parquet`,
  `sourceFormat=PARQUET`, `autodetect=true`). `bq show` reports `numRows: 0` / `numBytes: 0` — that is
  the external-table metadata floor, **not** the real size. Actual = 663,088 rows. Cost = bytes read from
  the Parquet files (column-projected), not BQ-managed storage.
- **Query in `us-central1`** — the bucket is us-central1; a US-multiregion job would bill on-demand. The
  `bq_run.sh` wrapper defaults the location correctly.
- **`hierarchy` is nested Parquet list encoding**, not a flat array — `UNNEST(hierarchy.list)` → `.element`.
- **`lat`/`long` are BIGNUMERIC and often NULL** — handle nulls; don't assume every row has coordinates.
- **`iso_code` vs `country_iso_code`.** `iso_code` is the location's own ISO (country/region rows);
  `country_iso_code` is always the country ancestor. Filter countries on `country_iso_code`.
- **`location_type_id` enum is inferred** from the sibling `geo.location_data`, not confirmed against a
  lookup here. Verify tier labels before hard-coding.
- **"static" = a point-in-time snapshot, not versioned** (no `geo_version` column). Freshness depends on
  when the Parquet was last exported; check the bucket / `creationTime` before relying on it as current.
  For production geo lookups the CoreDW copy `analytics_curated.geo_location_data` is the current
  authoritative source (see `geo.location_data`).

## Cost & partitioning notes
- **Unpartitioned external dimension** (`partition_by: none`, `require_partition_filter: false`). No
  date filter to apply. Cost is dominated by **which columns you project** from the Parquet files —
  a narrow projection reads little; `SELECT *` reads all 15 columns for 663k rows.
- No clustering. Filter on `location_id` / `location_type_id` / `country_iso_code` as needed; there is
  no block pruning, so keep projections tight and pre-filter to the tier you need before joining facts.

## Example queries
```sql
-- Resolve a location_id to name, country, tz, coordinates, and ancestry depth
SELECT location_id, location_type_id, location, sub_location1, sub_location2,
       country_iso_code, time_zone, metro_id, lat, long,
       ARRAY_LENGTH(hierarchy.list) AS hier_depth
FROM `dw-main-bronze.analytics_curated.static_combined_lat_long_data`
WHERE location_id = 311636;

-- US cities with coordinates present
SELECT location_id, location AS city, sub_location1 AS state, metro_id, lat, long
FROM `dw-main-bronze.analytics_curated.static_combined_lat_long_data`
WHERE location_type_id = 6 AND country_iso_code = 'US'
  AND lat IS NOT NULL
ORDER BY city;
```
